# A04 DeFi 协议评估：按协议类型下手

> 学习目标：读完本章，你能——
> 1. 用一张"通用 + 分类型"的清单评估借贷、DEX/AMM、稳定币、金库、质押、跨链、永续、账户抽象八类协议。
> 2. 评估协议的经济安全和外部依赖,而不只是代码正确性。
> 3. 区分"自研协议"与"接入第三方协议"两种评估目标。

## 1. 一句话理解

**DeFi 协议的评估分两层:代码会不会被攻破,规则会不会被套利。前者有清单可查,后者要把整个协议和它依赖的市场一起建模。**

> 🎯 打个比方:评估 DeFi 协议像**检查一座水坝**。
>
> - 先看坝体有没有裂缝（代码漏洞:重入、溢出、权限）。
> - 再看设计:上游水位暴涨时泄洪能力够不够,上游另一座坝垮了会不会连锁（经济安全与外部依赖）。
> - 坝体完好、设计也对,还要看谁能开闸、开闸要几个人同意（权限与治理）。
>
> 比喻的局限:水坝的上游是固定的。DeFi 协议的"上游"（预言机、被依赖的协议、抵押资产）会变,评估要考虑它们未来恶化的情况。

## 3. 分类型清单

通用清单之上,每类协议有自己的高发点。

### 3.1 借贷协议

- [ ] 预言机:抵押品估值用什么价格?低流动性 / 自有代币作抵押品的供应上限与抵押率?(Venus XVS、Inverse)
- [ ] 清算:极端行情下清算是否仍有利可图?清算折扣有上限?坏账由谁承担?
- [ ] 健康检查:**所有**减少抵押品或增加债务的路径最后都检查健康因子?(Euler 的 `donateToReserves`)
- [ ] 利率模型:利率是否可被操纵?利用率跳变是否可被闪电贷诱发?
- [ ] 分叉来源:是否分叉自 Compound/Aave?改了哪些地方?(Fei Rari 改了转账方式)

### 3.2 DEX / AMM

- [ ] 不变量:每次交换后 `x·y≥k`（或对应不变量）是否成立?(Uranium)
- [ ] 舍入:集中流动性的 tick 边界、再投资计算的舍入方向?(KyberSwap)
- [ ] 回调:swap 回调是否校验调用者为**计算出的**真实池子?(Sushi RouteProcessor2,见 [code/snippets/08](../../code/snippets/08-RouterCallback.sol))
- [ ] 手续费与价格读数:LP 价格是否可被用作抗操纵预言机?(不能直接用储备算)
- [ ] 代币兼容:收税、变基、无返回值代币能否破坏池子记账?

### 3.3 稳定币

- [ ] 锚定机制:超额抵押、算法、法币储备?极端脱锚时的清算与赎回路径?
- [ ] 预言机:锚定价格来源;抵押品价格的熔断上下限?(Venus LUNA)
- [ ] 铸造 / 销毁权限:谁能增发?有无上限与时间锁?
- [ ] 死亡螺旋:抵押品与稳定币相关时的反身性(算法稳定币的历史教训)。

### 3.4 金库 / 收益聚合（ERC-4626）

- [ ] 首存者通胀攻击:虚拟份额 / 死份额 / 内部记账?(见 [vault-inflation-lab](../interactive/vault-inflation-lab.html))
- [ ] 份额价格:`totalAssets` 是否读 `balanceOf`,可被捐赠操纵?(Harvest、Cream)
- [ ] 策略切换:策略合约能否被替换为恶意合约?谁有权限?
- [ ] 奖励计算:是否用余额差,且加了重入锁?(Penpie)

### 3.5 质押 / 流动性质押 / 再质押

- [ ] 凭证脱锚风险;赎回延迟队列;延迟期内谁能暂停?(mETH,见 [C03](../chains/C03-mantle.md))
- [ ] 多层叠加(质押→再质押→抵押)的风险传导;清算路径是否依赖凭证的二级市场价格?
- [ ] Slashing(罚没)风险如何传导给凭证持有人?

### 3.6 跨链 / 桥

- [ ] 消息格式:含源链、源合约、目标链、目标合约、nonce?逐项校验?(Wormhole、Poly)
- [ ] 验证方式与信任假设:多签阈值与独立性?证明验证代码审计?(Ronin、Token Hub)
- [ ] 零值 / 初始化:未证明消息不会被当作已证明?(Nomad)
- [ ] 存款伪造:原生币与 ERC-20 路径分离?无代码地址检查?(Qubit)
- [ ] 限额与对账:单笔 / 单位时间上限?两侧供应量对账?

### 3.7 永续 / 衍生品

- [ ] 标记价格 / 资金费率的操纵:指数价格来源抗操纵?
- [ ] 强平与保险基金:极端行情下的自动减仓(ADL)机制?保险基金耗尽时?
- [ ] 预言机延迟:L2 排序器宕机时的清算?(见 [08](../chapters/08-oracle-flashloan.md) 5.1)

### 3.8 账户抽象（ERC-4337 / EIP-7702）

- [ ] ERC-4337:Paymaster 能否被耗尽?UserOp 的签名验证?bundler 的 DoS?
- [ ] EIP-7702:委托目标的安全;不再用 `tx.origin==msg.sender`、`code.length==0` 判断调用者(见 [C00](../chains/C00-ethereum.md) 第 3 节)。

## 4. 经济安全评估

代码清单查不出经济攻击。经济评估要单独做:

1. **写出协议级不变量**(偿付、总量守恒),并用不变量测试验证(见 [A08](A08-reproduce-attacks.md))。
2. **把外部市场纳入模型**:假设某个预言机、某个被依赖的协议、某个抵押资产出现极端情况,协议会怎样?
3. **闪电贷视角**:攻击者一笔交易内有无限本金。任何"按当前余额 / 价格"计算的量都是攻击者的输入。
4. **治理视角**:投票权能否被借?提案能否被同交易执行?(Beanstalk)
5. **参数边界**:抵押率、费率、清算折扣、供应上限在边界值和极端值下是否仍安全?

> 💡 注意:经济攻击常常"每一步都合法"。审查要问的不是"这步对不对",而是"把这些步骤按攻击者喜欢的顺序和规模组合,会怎样"。

## 5. 外部依赖评估

协议依赖的东西出问题,协议跟着出问题。列一张依赖表:

| 依赖 | 类型 | 失效影响 | 评估 |
|---|---|---|---|
| 预言机 | Chainlink / TWAP / 自研 | 价格错 / 停更 | 时效、上下限、备用源、排序器状态 |
| 被集成的协议 | 借贷 / DEX / 桥 | 对方被攻破或暂停 | 集成点:回调、价格、暂停、升级 |
| 代币 | 抵押品 / 交易对 | 代币可暂停 / 黑名单 / 升级 / 脱锚 | 代币权限;是否映射资产 |
| 库 | OpenZeppelin / Solmate 等 | 库 bug | 版本锁定;关注已知 bug |
| 编译器 | solc / Vyper | 编译器 bug | 版本锁定(Vyper 2023) |
| 基础设施 | RPC / 子图 / keeper | 服务中断 | 降级路径 |

## 6. 两种评估目标

| | 自研协议 | 接入第三方协议 |
|---|---|---|
| 你能改代码吗 | 能 | 不能 |
| 评估重点 | 全量:代码 + 经济 + 依赖 | 集成点 + 对方的信任假设 |
| 关键问题 | 上线前把问题修掉 | 对方被攻破 / 暂停 / 跑路时,我们的资金和用户受什么影响,怎么退出 |
| 结论 | 完整报告 + 门禁 | 接入风险评估 + 限额 + 退出预案 |

> ⚠️ 警告:接入第三方协议时,你继承了对方的全部风险,却没有修复能力。评估要假设对方某天会出事,并设计限额、监控和退出机制,而不是依赖"它看起来很大、很成熟"。

## 7. 术语表

| 术语 | 英文 | 定义 |
|---|---|---|
| 不变量 | Invariant | 任何操作后都必须成立的条件 |
| 健康因子 | Health Factor | 加权抵押品价值与借款价值之比 |
| 反身性 | Reflexivity | 价格变化通过机制反过来强化价格变化 |
| 自动减仓 | ADL | 保险基金不足时强制减少盈利方仓位 |
| 集成点 | Integration Point | 本协议调用外部协议的具体位置 |
| 退出预案 | Exit Plan | 外部依赖出事时撤出资金的预设流程 |

## 8. 思考题

1. 一个借贷协议新增了一个"一键循环杠杆"功能。按 3.1 的清单,你会重点检查哪几项?为什么循环杠杆是高风险功能?
2. 你要评估是否把交易所的理财资金接入某个成熟的收益协议。按第 6 节,你的结论应该包含哪些内容?
3. 一个金库协议说"我们用内部变量记账,不读 balanceOf,所以没有通胀攻击"。你还需要验证什么才能认同这个结论?
