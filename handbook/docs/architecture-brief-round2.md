## 1. 为什么扩充

第一轮（X01–X27）给每个保护域写了一章"设计"。用户给出一张交易所总体架构图，把每个业务域分成四层：**业务需求层**（明确保护目标）、**架构逻辑层**（划分授权与核验）、**工程技术层**（控制实现与验收）、**运营服务层**（发现、处置与恢复）。X10–X16 主要覆盖前两层。本轮补：

1. **纵深章（X28–X43）**：每个交易所保护域各加"工程验收"和"运营与恢复"两章，再加一章域间交接、一章储备与偿付。

## 3. 两类章节的写法

### 3.1 纵深章 · 工程验收（X28、X30、X32、X34、X36、X38）

读者是**要证明控制真的有效**的安全工程师或 QA。在 architecture-brief-round1.md §3 模板的基础上，必须有：

- **验收用例库**：表格，列 `用例 ID | 控制项 | 前置条件 | 操作（只写在测试环境怎么做）| 预期结果 | 证据`；至少 20 条，覆盖正常、边界、越权、重放、并发、故障注入。用例 ID 用本章前缀加 `-T` 序号（例如 `IAV-T01`），控制项指向对应 X 设计章的控制 ID（如 `IAM-3`），本章自己的检查项另用 `前缀-n`。
- **回放验收方法**：怎样用历史或合成数据回放，对照"标准答案"算召回与误报；给 1 段可运行的 Python / SQL 示例（数据结构用示意表，注明"示例"）。
- **验收环境与数据**：测试环境应该长什么样、怎样不碰生产、怎样造数据。
- **验收报告模板**：通过标准、不符合项分级、整改闭环与复测。
- **上线门禁**：哪些用例未通过不得上线（P0）。
- 与对应设计章（X11/X12/X13/X14/X15/X16）的分工：设计章讲"怎么设计"，本章讲"怎么证明做到了"，不重复设计内容，需要时链接。

### 3.2 纵深章 · 运营与恢复（X29、X31、X33、X35、X37、X41）

读者是**事件发生后要把业务安全恢复**的运营与安全人员。必须有：

- **恢复状态机**（stateDiagram-v2）：从"正常 → 发现 → 限制 → 处置 → 验证 → 分阶段恢复 → 复盘"，标出每个状态的进入条件、退出条件、谁有权推动。
- **决策矩阵**：影响范围 × 恢复条件 × 授权人 × 时间窗。
- **恢复清单**：可直接勾选，含"恢复前必须核对什么"（对账、证据保全、风险复评、对外沟通）。
- **演练剧本**：2 个 30–45 分钟桌面推演（背景、注入、评分），不需要真实系统。
- **对外沟通**：用户公告、监管通报、合作方通知模板（至少 2 种）。
- 与对应设计章、X05、X06 的分工。

### 3.3 X42 域间交接、X43 储备与偿付

按各自规格写，沿用 architecture-brief-round1.md 模板，并同时具备"验收用例"与"恢复清单"两类内容的精简版。

## 5. 各章规格

### X28 客户身份与访问·工程验收
验收对象：认证与会话（登录、MFA、Passkey 降级、设备绑定）、账户找回、API Key（权限、白名单、提币默认关闭）、机构子账户与四眼、客服与内部工具。覆盖：越权测试（水平 / 垂直、IDOR）、会话固定与撤销、找回流程的绕过测试（只写如何验证防线，不写攻击步骤）、冷静期与新设备限制是否真生效、MFA 重置后提币限制、API Key 权限变更后的生效时间、客服工具能否绕过风控。风险信号规则的回放（用 X11 的信号）。

### X29 客户身份与访问·运营与恢复
账户接管事件的分级与处置：单账户、批量撞库、找回通道被利用、SIM 劫持、API Key 泄露；处置权限（谁能冻结、强制登出、重置、撤销 Key）；批量重置的节奏与用户沟通；被盗账户的恢复（证据、身份重验、冷静期、赔付判断）；客服恢复流程防二次社工；复盘与规则回灌。

### X30 资产与市场准入·工程验收
验收对象：分级准入开关（展示 / 现货 / 充值 / 提币 / 杠杆 / 抵押）是否真能独立开关；上币配置与链上事实核对（合约地址、精度、确认数、最小充值、手续费）；风险评分输入是否准确；上币信息保密控制与内幕交易检测回放；下架与暂停开关演练；跨链资产路由；双人复核。

### X31 资产与市场准入·运营与恢复
异常资产处置：合约被攻击、可升级合约被改、精度或规则变更、分叉与空投、改名与迁移、发行方冻结、桥资产脱锚；暂停充提 → 评估 → 迁移 / 下架 / 复牌的状态机与授权；用户资产与未结订单的处理；复牌条件；对外公告；与 X12、A05 分工。

### X32 交易、结算与信用·工程验收
对应图中"回放撤权、撤单与异常价格；核订单序号、成交、分录与估值"。验收用例：订单序号连续性、撮合日志与成交回报一致、成交与账务分录借贷平衡、冻结与解冻对称、手续费、估值与标记价、价格带与熔断、异常成交拦截、撤单与撤权（撤销权限后的订单行为）、幂等与重放、并发与竞态、强平与穿仓计算。包含"对账与差异分类"方法。

### X33 交易、结算与信用·运营与恢复
对应图中"复市、过载保撮合、切主验停写停发、恢复授信"。内容：撮合过载保护（限流、保撤单优先、降级）；主备切换的停写停发验证（脑裂防护、序号接续、未确认订单处理）；异常价格与事故后复市条件（凭单据重放与行情记录批准）；强平与穿仓善后、保险基金；恢复授信（信用风险核已发贷款与抵押品净回收额）；分阶段复市（只撤单 → 只平仓 → 限价 → 全面）；与 X13 分工。

### X34 钱包、财资与支付·工程验收
对应图中"回放越权签名、假回执与切主；核拒签、额度占用与外部流水"。验收用例：签名服务拒签（无审批单、地址不符、金额超限、重复请求、调用方身份）；额度占用与释放（预留 → 实付）；假回执与链上确认的核对；冷 / 温 / 热调拨的审批与时间窗；链上外部流水与账务对账；银行渠道回拨确认与账户变更；切主时签名服务不重复签。含回放方法。

### X35 钱包、财资与支付·运营与恢复
对应图中"复付"：恢复支付前核对权益、渠道头寸与未决款项。内容：钱包事故（冻结、迁移、密钥轮换）；热钱包补充与"复付"的阶段（先小额、再批量）；渠道方事故（银行、支付、稳定币）；未决款项处理；恢复后的限额回调；事后对账；与 X14、X25 分工。

### X36 生产环境与数据·工程验收
验收：核心系统隔离是否真实（网络与身份）；特权访问与变更控制抽查；数据分级与导出控制；日志不可篡改与时间同步抽样；备份可恢复性与恢复数据可信校验；第三方访问范围核对。给出可执行的抽样与证据方法、云与 K8s 示例检查命令。

### X37 生产环境与数据·运营与恢复
对应图中"生产基础设施与数据安全：生产权限、证据保全、可用性与恢复（过载保撤单、切主验停写停发）"。内容：证据保全流程（先保全后处置、哈希、保管链）；数据泄露与篡改的恢复；从备份恢复的数据可信校验；可用性事件（DDoS、云故障、数据库故障）的降级与恢复；与 X33 的衔接；演练。

### X38 反欺诈、合规与安全运营·工程验收
验收：规则回放（召回、误报）、阈值变更控制、处置授权（谁能冻结、解冻）在系统里是否强制、限制措施落地（冻结后能否提币 / 交易 / 转内部）、制裁与 Travel Rule 命中后的行为、案件系统留痕。含回放脚本示例。

### X41 反欺诈、合规与安全运营·运营与恢复
对应图中"调查取证、处置授权、执行与复核"。内容：调查流程（核身份、成交和资金归属）；处置授权矩阵（风控批止付、合规裁定法定限制）；执行与复核（业务端回报限制与解除结果）；案件生命周期、证据链、执法协助；解除限制与申诉；对外沟通；与 X16 分工。

### X42 域间交接
对应图中"交易与账务 ↔ 钱包与支付"：原单、预留与批准（交易账务 → 钱包支付）；实收、实付及未决状态（钱包支付 → 交易账务）。内容：提币全流程状态机（申请 → 预留 → 批准 → 签名 → 广播 → 确认 → 记账，含失败、超时、重放、重广播）；充值全流程（入账确认、回滚、重组）；未决状态的账务处理；幂等键与对账键设计；常见不一致与处置；验收用例精选。

### X43 储备与偿付能力
负债侧（用户余额、未决、借贷、衍生品盈亏）与储备侧（链上、银行、托管）的口径；对账频率与差异分级；储备证明（Merkle 树负债证明、签名证明地址所有权、第三方鉴证）的做法与局限；偿付能力指标；抽取与挤兑的运营准备；信息披露；审计与鉴证；失效案例（独立查证）。

### X44 NFT、GameFi 与元宇宙项目

### X45 预测市场与链上衍生品

### X46 再质押、流动性质押与 AVS
