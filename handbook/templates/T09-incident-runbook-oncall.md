# T09 事件响应 Runbook 与值班手册

> 用途：给机构一份可以直接改写的事件响应骨架和值班手册。第 1–6 部分是 runbook（事故中使用），第 7–9 部分是值班手册（日常运营使用）。
> 配套：[X05 检测与响应工程](../architecture/X05-detection-response-engineering.md)（分级、值班、SOAR、证据保全）、[X16 反欺诈、合规与安全运营](../architecture/X16-cex-fraud-compliance-secops.md)（处置权限）、[X06 韧性与验证](../architecture/X06-resilience-validation.md)（演练、复盘）、[X36 漏洞披露与赏金](../architecture/X36-disclosure-bounty-ops.md)（对外协作）、[A09 应急响应](../assessment/A09-incident-response.md)、[T10 桌面推演剧本与评分表](T10-tabletop-script-scorecard.md)
> 说明：带"示例"的数值和角色名需要替换成自家的。表中空白处由使用者填写。

## 使用方法

1. 把本文复制成自家的 runbook。把"（填）"替换成真实姓名、电话、系统链接。
2. 打印一页"事故中速查卡"（第 1、2、3 部分的精简版），放在值班人员手边。
3. 每季度检查一次本模板的检查表（第 10 部分）。联系人清单过期的，按 ❌ 处理。
4. "状态"填 ✅ / ⚠️ / ❌ / N/A。"证据"写可复核的链接。
5. 标 ★ 的是**红线项**。任一红线项为 ❌，本季度应急就绪结论为"不通过"。

## 1. 事件分级

| 级别 | 判据（示例） | 首次响应时限（示例） | 指挥官 | 通知对象 |
|---|---|---|---|---|
| P1 | 资金正在流出；签名或密钥疑似泄露；全站不可用 | 5 分钟内确认；15 分钟内成立指挥组 | 事件指挥官 | 管理层、法务、合规 |
| P2 | 已确认入侵但无资金流出；单链或单业务受影响；重要数据疑似泄露 | 30 分钟内确认；1 小时内成立指挥组 | 值班负责人 | 安全负责人、受影响业务负责人 |
| P3 | 可疑活动待确认；单用户账号被盗；单个漏洞报告 | 4 小时内确认 | 值班工程师 | 安全负责人（日报） |
| P4 | 低风险告警、误报、信息收集 | 下一个工作日 | 值班工程师 | 无 |

定级规则：

1. 拿不准时，按高一级处理。
2. 只有事件指挥官可以降级。降级要写原因。
3. 级别可以随事实升高。升高后，重新计算首次响应时限。

## 2. 指挥体系与角色

| 角色 | 职责 | 主责 | 备份 1 | 备份 2 | 电话（填） |
|---|---|---|---|---|---|
| 事件指挥官（IC） | 唯一决策人；决定暂停、升级、对外沟通时机 | （填） | | | |
| 技术负责人（Tech Lead） | 调查、遏制、恢复；核对对外事实 | | | | |
| 记录员（Scribe） | 实时时间线；记录每个决策、时间、决策人 | | | | |
| 钱包 / 托管负责人 | 暂停提币、轮换密钥、调拨 | | | | |
| 风控 / 合规负责人 | 冻结账户、通知监管、制裁与链上追踪 | | | | |
| 法务 | 审核通报与公告措辞；证据与取证合规 | | | | |
| 沟通负责人 | 对外公告、客户通知、媒体 | | | | |
| 联络人（Liaison） | 联系交易所、发行方、桥、SEAL 911、执法 | | | | |
| 客服负责人 | 客服话术、用户咨询分流 | | | | |

指挥规则：

1. 一次事件只有一名 IC。接手时说一句："我现在是指挥官。"
2. IC 不亲自操作。IC 只决策和协调。
3. 所有决策由记录员写入时间线。没有记录的决策视为没有发生。
4. 通话时间超过 4 小时，IC 必须交接。交接内容见第 8 部分。
5. 角色人员失联超过 10 分钟，按备份顺序顶替。

## 3. 处置权限矩阵

> 💡 注意：这是骨架示例。权限的详细设计见 X16 第 4 节。每个机构必须按自己的法律与业务情况修改。

| 动作 | 可执行人 | 批准人 | 决策时限（示例） | 必须记录 | 可逆性 |
|---|---|---|---|---|---|
| A1 对单笔提币挂起复核 | 风控分析师、值班安全 | 无（直接执行） | 立即 | 原因码 | 可逆 |
| A2 暂停单个 API Key 或单用户提币 | 值班安全、风控负责人 | 无；超过 24 小时转 A3 | 立即 | 原因码、证据引用 | 可逆 |
| A3 冻结单个用户账户 | 风控负责人 | 合规官 | 4 小时 | 原因码、证据引用、申诉路径 | 可逆，有申诉义务 |
| A4 暂停单链或单币种提币 | 值班安全（预授权） | IC 事后 15 分钟内追认 | 立即执行 | 触发条件、追认时间 | 可逆 |
| A5 暂停全站提币 | IC | 安全负责人加一名高管 | 10 分钟 | 决策理由、顺位 | 可逆，代价高 |
| A6 暂停交易或全站停服 | IC | 高管二人 | 10 分钟 | 同上 | 可逆，代价最高 |
| A7 通知监管、报警 | 合规官 | 法务 | 按辖区法定时限；内部目标 4 小时内首次通知（示例） | 通知内容、时间、接收人 | 不可逆 |
| A8 对外公告 | 沟通负责人 | IC 加法务；技术负责人核对事实 | 按事件而定 | 公告版本、核对记录 | 不可逆 |
| A9 向发行方、交易所请求冻结 | 联络人 | IC | 立即 | 版本化的地址清单 | 难撤回 |
| A10 密钥轮换与资金迁移 | 钱包负责人 | IC | 按事件而定 | 新旧地址、签名人、独立解码记录 | 不可逆 |

规则：

1. 预授权的动作，值班人员先做，事后追认。不允许等审批。
2. 高影响动作必须双人。批准人失联时，按顺位顶替。
3. 不可逆的对外动作必须经过法务。技术人员不直接对外发布。
4. 所有 A3、A9 动作写入防篡改日志，月度抽检。

## 4. 响应流程（速查）

| 阶段 | 步骤 | 负责人 | 完成标志 |
|---|---|---|---|
| 1 确认 | 1. 确认告警真实。2. 定级。3. 开事件频道，指定 IC。 | 值班 | 事件频道已开；级别已写入 |
| 2 遏制 | 1. 按权限矩阵执行 A1–A6。2. 隔离受影响系统。3. 撤销泄露的凭证。 | Tech Lead | 资金或数据不再扩散 |
| 3 保全 | 先快照，再清理。按第 6 部分执行。 | Tech Lead | 哈希已记录 |
| 4 调查 | 建立时间线；确定入口、范围、受影响资产。 | Tech Lead | 范围结论已写入 |
| 5 通报 | 按第 5 部分发出内部、客户、监管、公告。 | 沟通 / 合规 | 各渠道已确认发出 |
| 6 恢复 | 分阶段恢复；每阶段设验证点和回退条件。 | IC | 恢复检查表通过 |
| 7 复盘 | 5 个工作日内召开无责复盘。 | IC | 复盘文档已归档（见 T10 第 3 部分） |

## 5. 通报模板

### 5.1 内部通报（事件开始 15 分钟内）

```
【事件通报 #（编号）】级别：P（填）
时间：（UTC，精确到分钟）
状态：调查中 / 已遏制 / 恢复中 / 已关闭
已确认事实：（只写已确认的，每条标来源）
未确认：（明确写"尚未确认"）
已执行动作：（动作编号、执行人、时间）
影响范围：（资产、用户、系统；金额写"约"并注明估值时点）
指挥官：（姓名）  下一次更新：（时间）
```

### 5.2 客户通知（示例，需法务审核后发送）

```
我们发现（简述事实）。我们已经暂停（具体服务）。
目前确认：（事实）。尚未确认：（事实）。
你需要做的：（具体步骤，一步一个动作）。
我们不会通过电话、私信或邮件向你索要密码、助记词或验证码。
下一次更新时间：（时间）。官方渠道：（域名与账号）。
```

### 5.3 监管 / 执法首次通知

| 字段 | 内容 |
|---|---|
| 机构名称与牌照编号 | （填） |
| 事件发现时间（UTC） | |
| 事件类型 | 资金被盗 / 数据泄露 / 服务中断 / 其他 |
| 已确认影响 | 金额约（估值时点）；用户数；系统 |
| 已采取措施 | |
| 相关地址、交易哈希 | （版本化清单） |
| 联系人（24 小时） | |
| 下次更新时间 | |

### 5.4 公告（示例结构，法务与 IC 批准后发布）

| 部分 | 内容 |
|---|---|
| 发生了什么 | 只写已核对的事实 |
| 影响谁 | 范围与用户资金状态 |
| 我们正在做什么 | 暂停、调查、联系执法与合作方 |
| 用户要做什么 | 具体步骤 |
| 下一次更新 | 时间与渠道 |

> ⚠️ 警告：公告中不推测攻击者身份，不承诺未经决策的赔付，不写未核对的金额。

## 7. 值班手册：编排与升级路径

| 项 | 内容（示例，填写自家值） |
|---|---|
| 值班模式 | 主值班 + 备值班；周轮换；7×24 |
| 人数 | 至少 3–4 人轮值（示例） |
| 主值班确认时限 | P1 告警 5 分钟内确认（示例） |
| 备值班接管 | 主值班 10 分钟无确认，自动呼叫备值班 |
| 升级电话 | 备值班 10 分钟无确认，呼叫安全负责人 |
| 联系链测试 | 每季度非工作时间发一次测试 P1，记录确认时间 |

升级路径：

| 条件 | 升级给 | 方式 | 时限 |
|---|---|---|---|
| P1 告警 | 主值班 → 备值班 → 安全负责人 → IC 顺位 | 电话，不仅短信 | 每级 10 分钟 |
| 主值班判断需要暂停提币 | 按 A4 直接执行，并通知 IC | 电话 + 事件频道 | 立即 |
| 涉及客户资金或数据 | 合规官、法务 | 电话 | 30 分钟内 |
| 涉及外部合作方 | 联络人 | 电话 + 邮件 | 1 小时内 |
| 值班人员需要休息 | 事件指挥官安排交接 | 当面或语音 | 见第 8 部分 |
