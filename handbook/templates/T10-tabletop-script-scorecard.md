# T10 桌面推演剧本、评分表与复盘模板

> 用途：主持一次 30–60 分钟的桌面推演。第 1 部分是剧本模板，第 2 部分是填好的短示例，第 3 部分是 100 分评分表，第 4 部分是复盘模板。
> 配套：[X06 韧性与验证](../architecture/X06-resilience-validation.md)（桌面推演、无责复盘）、[X05 检测与响应工程](../architecture/X05-detection-response-engineering.md)（告警演练）、[X13 反欺诈、合规与安全运营](../architecture/X13-cex-fraud-compliance-secops.md)（处置权限、恢复提币）、[X11 钱包、财资与支付渠道](../architecture/X11-cex-wallet-treasury-payment.md)、[T09 事件响应 Runbook](T09-incident-runbook-oncall.md)
> 说明：示例剧本是虚构场景，不对应任何真实机构或事故。

## 使用方法

1. 推演前一周：选剧本，确定主持人、记录员、观察员。参与人不提前看注入内容。
2. 推演中：主持人按"注入"逐条发出信息。每次注入后，参与人说出"我做什么、谁批准、多久做完"。
3. 观察员按第 3 部分打分。记录员写时间线。
4. 推演后 5 个工作日内，用第 4 部分开复盘。
5. 标 ★ 的是**红线项**。任一红线项得 0 分，本次推演结论为"不通过"，无论总分多少。
6. 一年至少做 2 次推演，每次换剧本。

注入设计规则：

1. 每次注入只给一条新事实。
2. 至少一次注入给出"相互矛盾或不完整"的信息。
3. 至少一次注入要求使用高影响动作（如暂停全站提币）。
4. 至少一次注入要求对外沟通。
5. 至少一次注入考验"关键人失联"，要求使用顺位。

### 1.3 主持人手册

| 问题 | 主持人在何时问 |
|---|---|
| 你现在知道什么？不知道什么？ | 每次注入后 |
| 谁有权做这个决定？ | 参与人要执行 A4 及以上动作时 |
| 你会怎么验证这条信息？ | 信息来自单一来源时 |
| 对外怎么说？谁批准？ | 注入涉及用户或媒体时 |
| 如果这个人电话关机呢？ | 至少一次 |

## 2. 示例剧本（虚构，30 分钟）

### 2.1 示例：热钱包异常流出

| 项 | 内容 |
|---|---|
| 剧本名称 | 示例：周六凌晨热钱包异常流出 |
| 目标 | 测量"告警到确认"和"确认到暂停单链提币"的时间；检验追认流程 |
| 范围 | 热钱包签名服务、链上监控、值班、指挥官 |
| 前置假设 | 机构有单链熔断（A4）预授权 |

| # | 时间点 | 注入内容（主持人读出） | 期望决策 | 期望时限（示例） | 观察要点 |
|---|---|---|---|---|---|
| 1 | T+0 | 周六 03:10。链上监控告警：热钱包 A 在 5 分钟内转出 3 笔，合计约为日常日均的数倍（示例）。目的地址不在白名单。值班电话响起。 | 值班确认告警，判定为 P1 | 5 分钟内确认 | 是否先看日志再决定？是否定级偏低？ |
| 2 | T+7 | 账务系统里没有对应的提币单号。签名服务日志显示请求来自一个不常见的内部服务账号。 | 执行 A4：暂停该链提币，并通知 IC | 立即执行 | 值班是否等待批准？是否记录追认时间？ |
| 3 | T+12 | IC 电话无人接听。备份 IC 在休假。 | 按顺位找到可决策人 | 10 分钟 | 顺位清单是否在线可用？ |
| 4 | T+18 | 社交媒体出现帖子："某交易所被盗"。客服收到 40 条询问（示例）。 | 沟通负责人准备声明；法务审核；技术核对事实 | 30 分钟内发出首次声明 | 是否推测原因？是否有核对环节？ |
| 5 | T+25 | 技术发现该服务账号的凭证在 2 小时前被用于登录。需要保全证据，同时需要轮换凭证。 | 先快照、再轮换 | | 是否先保全后清理？ |

主持人结束语：请参与人回答——"如果这是真的，现在有哪三件事还没做？"

## 3. 评分表（100 分）

| 维度 | 分值 | 评分要点 | 得分 | 观察记录 |
|---|---|---|---|---|
| A 发现与定级 | 15 | 告警在时限内确认（8 分）；定级正确，拿不准时按高一级（4 分）；事件频道和记录员立即到位（3 分） | | |
| B 指挥与决策 | 20 | 唯一指挥官（5 分）；决策时限达标（8 分）；失联时按顺位顶替（4 分）；所有决策有记录（3 分） | | |
| C 处置权限 ★ | 15 | 预授权动作直接执行，不等审批（6 分）；高影响动作双人批准（5 分）；不可逆动作经过法务（4 分） | | |
| D 遏制与证据 | 15 | 遏制措施有效且最小（6 分）；先保全后清理（6 分）；记录保管链和哈希（3 分） | | |
| E 沟通与通报 | 15 | 内部通报格式完整（4 分）；对外声明只写已核对事实（6 分）；监管通知有人负责且有时限（5 分） | | |
| F 协作与外部联络 | 10 | 联络人联系发行方、交易所或 SEAL 911 的时机和材料（6 分）；客服获得统一口径（4 分） | | |
| G 恢复与复盘 | 10 | 恢复分阶段，有验证点和回退条件（6 分）；说出行动项和负责人（4 分） | | |
| 合计 | 100 | | | |

红线项（得分为 0 则本次不通过）：

| # | 红线 | 状态 | 观察 |
|---|---|---|---|
| ★1 | 没有人明确担任指挥官，或指挥官无权暂停业务 | | |
| ★2 | 预授权的最小动作被拖延超过时限，原因是"等批准" | | |
| ★3 | 对外发布了未核对的事实，或承诺了未经决策的赔付 | | |
| ★4 | 在保全证据之前清理了受影响系统 | | |

结论口径（本模板约定）：

| 总分 | 结论 |
|---|---|
| ≥ 85 且无红线 | 通过 |
| 70–84 且无红线 | 附条件通过：行动项 30 天内关闭并复测 |
| < 70 或任一红线 | 不通过：60 天内重新推演 |
