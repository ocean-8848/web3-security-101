# T01 评估受理资料清单

> 用途：每次评估开始前，让申请方（项目方、业务线、合作方）填写。缺项就是第一批发现。
> 配套：[A01 评估方法论](../assessment/A01-methodology.md)、[A07 外部审计](../assessment/A07-external-audit-bounty.md)

## 1. 基本信息

| 字段 | 填写 |
|---|---|
| 项目 / 合约名称 | |
| 评估类型 | A 交易所自有 / B DeFi 协议 / C 上币与合作尽调 |
| 申请人 / 业务负责人 | |
| 期望完成日期 / 上线日期 | |
| 涉及资金量级（预估 TVL / 托管额） | |
| 目标链 | 以太坊 / BNB / TRON / Mantle / 其他 |

## 2. 代码与部署

- [ ] 仓库地址与**提交哈希**（不是分支名）
- [ ] 范围内文件清单；范围外文件及理由
- [ ] 编译器版本、依赖及版本（OpenZeppelin 等）
- [ ] 已部署合约地址（如已部署）与源码验证状态
- [ ] 部署脚本与初始化参数
- [ ] 是否分叉自其他项目；改了什么

## 3. 文档与规格

- [ ] 设计文档 / 白皮书 / 架构图
- [ ] 关键不变量（“什么必须永远成立”）
- [ ] 角色与权限表（谁能做什么）
- [ ] 外部依赖清单：预言机、被集成协议、代币、桥

## 4. 权限与运营

- [ ] 所有特权地址：类型（EOA / 多签 / 时间锁）、阈值、持有人
- [ ] 升级机制与时间锁时长
- [ ] 暂停机制与持有人
- [ ] 密钥管理方式（硬件 / MPC / HSM）
- [ ] 前端托管、域名、依赖管理

## 5. 既有安全工作

- [ ] 已有审计报告（版本、范围、发现与修复状态、已确认风险）
- [ ] 内部测试：覆盖率、模糊/不变量测试
- [ ] 漏洞赏金计划
- [ ] 已知问题与已接受风险
- [ ] 内部威胁模型与自评发现（交给审计方，不隐瞒已知问题）

## 6. 受理结论

|---|---|

| 评估范围 | |
| 评估深度 | 完整审查 / 重点审查 / 快速尽调 |
| 预计工时 | |
