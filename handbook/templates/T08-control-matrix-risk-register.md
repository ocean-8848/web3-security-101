# T08 控制矩阵与风险登记表

> 用途：把"资产 → 威胁 → 控制"落成一张可验证的矩阵，并用风险登记表和已接受风险记录管理"暂时不做"的事。首次建立用一次，之后每季度复核一次。
> 配套：[X01 安全体系怎么搭](../architecture/X01-security-program-controls.md)（控制矩阵、风险登记）、[X02 标准与合规映射](../architecture/X02-standards-compliance-map.md)、[X06 韧性与验证](../architecture/X06-resilience-validation.md)（安全月报中的未关闭风险）、[T06 运营安全自查清单](T06-ops-security-self-check.md)
> 说明：表中带"示例"的行是填写示范，不是任何真实机构的数据。使用时删除。

## 使用方法

1. 先填第 1 节资产清单，按"丢了会怎样"给每项资产定级（L1–L3）。
2. 对每个 L1、L2 资产，在第 2 节写出威胁和控制。一条控制只对应一个威胁。
3. 每条控制必须有"怎么验证"和"验证频率"。写不出验证方法的控制，按"未实施"处理。
4. 控制未实施或验证失败时，在第 3 节登记风险。不允许口头"先放着"。
5. 决定暂不整改的风险，进入第 4 节，由风险所有人和管理层签字，并写明到期日。
6. 标 ★ 的是**红线项**。任一红线项为 ❌，本次复核结论为"不通过"。
7. "状态"填 ✅ 通过 / ⚠️ 部分通过 / ❌ 未通过 / N/A。"证据"写可复核的链接或文件名。没有证据按 ❌ 处理。

## 4. 已接受风险记录

> ⚠️ 警告：接受风险不是关闭风险。每条记录必须有到期日。到期后必须重新决定，不允许自动续期。

| | | | | | | | | | | |

接受规则：

1. 风险所有人必须是能决定该业务是否继续的人。安全团队不能替业务接受风险。
2. 涉及 L1 资产的高风险，由管理层成员批准，不由部门负责人批准。
3. 必须写出补偿控制。没有补偿控制的，不得接受。
4. 到期日不超过 6 个月（示例，可按制度调整）。
5. 同一风险连续接受两次，自动升级到董事会或同级机构汇报。
