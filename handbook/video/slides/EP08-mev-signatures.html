MEV

交易在打包前是公开的，打包顺序由别人决定

签名重放

签名用过之后仍然存在，能否再用取决于你签了什么
  1. 大家好，欢迎来到主线第8集，MEV 与签名安全。一句话理解分两半。交易在被打包之前是公开的，打包的顺序由别人决定。签名在被使用之后仍然存在，能否再次使用，取决于你签了什么。
  2. 第一半是 MEV，最大可提取价值。区块生产者或者搜索者，通过调整、插入、排除交易，获得额外收益。
  3. 第二半是签名安全。链下签名用过之后不会消失，如果它绑定的字段不全，就能被重放。本集讲 MEV 的三种形态、防御，签名必须绑定的五个字段，以及签名界面的安全。

你签了一张"付 100 元"的支票
没写日期、收款行、编号

比喻不准的地方：拍卖会上你能看到谁插了队。链上三明治和你的交易在同一个区块里，普通用户往往只看到"成交价比预期差"。
  1. 打个比方。MEV 像拍卖会上，你举牌之前就大声说出了你的最高出价。旁边的人抢先用低一点的价格买下，再加价转卖给你。这是三明治。
  2. 签名重放，像你签了一张付100元的支票，却没写日期、没写收款银行、没写支票编号。拿到支票的人可以复印它，去每一家银行各兑一次。
  3. 比喻不准的地方在于，拍卖会上你能看到谁插了队。链上的三明治交易，和你的交易在同一个区块里，普通用户往往只看到成交价比预期差了一点。
MEV

抢跑、三明治、尾随

类型顺序利用什么受害者
抢跑攻击者 → 受害者受害者交易的信息（如先到先得的奖励）原交易者
三明治攻击者买 → 受害者 → 攻击者卖受害者的滑点容忍度交易者
尾随受害者 → 攻击者受害者制造的价差或清算机会通常无直接受害者
  1. MEV 有三种形态。抢跑，攻击者把自己的交易排在受害者前面，利用受害者交易里的信息，比如先到先得的奖励。受害者是原来的交易者。
  2. 三明治，攻击者在受害者前面买，后面卖，把受害者夹在中间，利用的是受害者设置的滑点容忍度。
  3. 尾随，攻击者把交易排在受害者后面，利用受害者交易制造出的价差或者清算机会。尾随通常没有直接的受害者，比如正常的套利和清算。重点看三明治。
三明治 · 数字为示例

滑点设得越宽，被夹得越狠

  1. 看三明治的机制。受害者向公开内存池提交一笔交易，用10个 ETH 换 USDC，设置最少得到19000 USDC，也就是允许5%的滑点。这笔交易在打包前是公开的。
  2. 搜索者发现了它，构造一个捆绑，顺序是，自己先买，受害者的交易夹在中间，自己最后卖。
  3. 第一步，搜索者买入，推高了价格。第二步，受害者以更差的价格成交，刚好满足最小输出19000。注意，受害者的交易没有失败，只是以允许范围内最差的价格成交了。
  4. 第三步，搜索者卖回，赚取差价。搜索者的最大利润，由受害者的最小输出决定。滑点设得越宽，被夹得越狠。如果受害者设的是19800，搜索者的操作空间就小得多。
防御 · 分四层

minOut = 0 等于"我接受任何价格"

层级措施
用户设置合理滑点；用私有交易通道
前端默认滑点保守；按池深动态计算
合约交换函数必须有 minOut 和 deadline；不要在合约内部用现货价算 minOut
协议设计提交-揭示；批量拍卖统一价格清算
金库、自动复投、清算合约常犯：内部调用 DEX 时写 minOut = 0 → 等于告诉全世界"我接受任何价格"。
  1. 防御分四层。用户层，设置合理滑点，用私有交易通道，这样搜索者在打包前看不到交易。前端层，默认滑点要保守，按池子深度动态计算。
  2. 合约层，所有交换函数必须接受最小输出和截止时间两个参数。但注意一个关键点，不要在合约内部用现货价计算最小输出，那等于没有保护，因为现货价本身就能被操纵。协议设计层，可以用提交揭示，或者批量拍卖，同一批订单统一价格清算。
  3. 最常见的错误是，金库、自动复投合约、清算合约，在内部调用 DEX 时，把最小输出写成零。这等于告诉全世界，我接受任何价格，是三明治的活靶子。
链差异 · 截至 2026 年公开资料

"没有公开内存池"不等于"没有 MEV"

链谁决定顺序对 MEV 的影响
BNB Chain验证者轮流出块，出块约 0.75 秒有公开内存池和构建者市场；出块更快，抢跑窗口更短，三明治仍在
TRON27 个超级代表轮流出块能量价格固定，没有优先费，不能靠"出更高 gas"插队；但出块者仍可决定顺序
Mantle单一中心化排序器排序器按自己的规则排序；L2BEAT：运营者可抢跑用户交易提取 MEV
  1. 三条链的排序机制不同。BNB Chain 由验证者轮流出块，出块约0.75秒，有公开内存池和区块构建者市场。出块更快，抢跑窗口更短，但三明治依然存在。
  2. TRON 由27个超级代表轮流出块。它的能量价格是固定的网络参数，没有优先费，所以不能靠出更高的 gas 价来插队。但出块者本身，仍然可以决定顺序。
  3. Mantle 是单一的中心化排序器，按自己的规则排序。L2BEAT 列出的风险是，运营者可以抢跑用户交易来提取 MEV。所以，没有公开内存池，不等于没有 MEV，它只是把排序权从市场，集中到了一个运营者手里。用户依赖运营者的诚实。
签名安全 · 一份签名能被用几次

少绑一个字段，就多一种重放

EIP-712 把 chainId、合约地址合成"域分隔符"，把消息结构合成"类型哈希"，一次解决后四个字段。
  1. 链下签名在 DeFi 里很常见，免 gas 授权、元交易、订单、跨链验证、空投凭证。一份安全的签名，必须绑定五个字段。第一，nonce，每用一次递增。缺了它，同一个签名可以在同一个合约反复提交。
  2. 第二，chainId，链的编号。缺了它，签名在分叉链或者多链部署上同样有效，可以跨链重放。
  3. 第三，验证合约地址。缺了它，同一份代码部署两次，签名在两个合约上都有效，可以跨合约重放。
  4. 第四，deadline，过期时间。缺了它，签名永久有效，用户即使改了主意，签名仍能被用。第五，函数意图。缺了它，为 A 函数签的数据，被拿去调用 B 函数。
  5. EIP-712 标准，把链 ID 和合约地址合成一个域分隔符，把消息结构合成一个类型哈希，正确使用就能一次解决后面四个字段。加上 nonce，五个字段就齐了。
签名陷阱

零地址、可塑性、编码碰撞

① ecrecover 零地址

无效签名 → 返回 address(0)，不回滚
admin 未初始化（也是 0）→ 任何无效签名通过

② 签名可塑性

(r, s) 和 (r, n−s) 都有效
用"签名字节"做已用标记 → 翻转 s 得到"新"签名
修复：用 nonce / 消息哈希标记，拒绝高 s

③ encodePacked 碰撞

packed("ab","c") == packed("a","bc")
签多个动态类型 → 用 abi.encode
  1. 签名有三个经典陷阱。第一，ecrecover 返回零地址。签名无效时，它不回滚，而是返回零地址。如果你比较的 admin 变量从没初始化，默认也是零，那么任何无效签名都能通过。所以一定要加零地址检查。
  2. 第二，签名可塑性。对同一个消息，一个签名和它的翻转版本都有效。如果你用签名本身的字节做已使用标记，攻击者翻转一下，就得到一个查不到的新签名。修复是用 nonce 或消息哈希做标记，并使用拒绝高 s 值的库。
  3. 第三，编码碰撞。encodePacked 把 ab 和 c 拼起来，和把 a 和 bc 拼起来，结果相同。签多个动态类型时，用 abi.encode，不用 encodePacked。
permit · 免 gas 授权

便利的另一面是风险

抢跑型 DoS

用户提交 permitAndDeposit(签名)
攻击者从内存池复制签名，先单独调 permit
→ 用户交易因 nonce 已用而回滚
修复：permit 包在 try/catch，失败后检查授权是否已够

钓鱼

permit 是链下签名，不花 gas
钱包界面常只显示一段十六进制
用户签下后，攻击者可随时执行
  1. 免 gas 授权 permit 很方便，但有两面。第一是抢跑型拒绝服务。用户提交一个组合交易，先授权再存款，签名在里面。攻击者从内存池复制这个签名，抢先单独调用授权函数。授权的 nonce 被用掉了，用户的交易因此回滚。修复是把授权包在 try catch 里，失败后检查授权额度是不是已经够了。
  2. 第二是钓鱼。permit 是链下签名，不花 gas，钱包界面常常只显示一段十六进制数据，用户看不懂。用户签下后，攻击者可以随时拿去执行。所以钱包解析签名内容、显示人类可读信息，很重要。
链差异 · 据 TRON 官方开发文档

合约层的防重放仍要自己实现

差异影响
CHAINID 返回创世区块后 4 字节（主网 728126428）域分隔符仍能区分链；别写死以太坊风格链 ID
账户没有 nonce，交易用 TAPOS 防重放，默认 60 秒过期交易层防重放不同；合约层签名的 nonce 仍要自己实现
地址在链边界带 0x41 前缀，VM 内部是 20 字节签名工具和合约对地址的编码必须一致

  1. 部署到 TRON，签名有几个差异。第一，TRON 的链 ID 返回的是创世区块的后4字节，主网是一个很大的数。域分隔符仍然能区分链，但不要在代码里写死以太坊风格的小整数链 ID。
  2. 第二，TRON 账户没有 nonce，交易层用一种基于区块的机制防重放，默认60秒过期。但这是交易层的，合约层签名的防重放，仍然要你自己实现 nonce。

真实案例 · 2025-02 · 据公开分析

签名再安全，签名人也可能签错东西

  1. 签名本身再安全，签名人也可能签错东西。看 Bybit，以下据公开分析。攻击者篡改了多签前端的代码，只针对 Bybit 冷钱包的多签地址生效。
  2. 签名人看到的，是一笔正常的转账。但实际签名的交易，是一个委托调用，指向攻击者的合约，要把多签钱包的实现替换成恶意合约。
  3. 多签阈值满足后，钱包的实现被替换，攻击者转走约40万 ETH 及其他资产，总计约15亿美元。多签防的是单把私钥被盗，它防不了所有签名人看到同一个假界面。
  4. 防御是什么？用硬件钱包逐字段核对交易，用独立工具解码调用数据。看到委托调用，或者修改实现地址的操作，就是高危信号，要设白名单或额外审批。正常转账不需要委托调用。同类事故不罕见，2024年 WazirX 也是这样，约2.3亿美元。这部分在评估篇第3集深入讲过。
审计清单

八个检查点

① 交换函数有 minOut 和 deadline，且不是内部用现货价算的
② 签名验证用 EIP-712，含 nonce、chainId、合约地址、deadline、typehash
③ 用 OpenZeppelin ECDSA，拒绝零地址和高 s 值
④ 已用标记基于 nonce 或消息哈希，不基于签名字节
⑤ permit 调用有抢跑容错
⑥ 动态类型签名用 abi.encode
⑦ TRON 上签名工具链与合约对 chainId、地址格式处理一致
⑧ 特权操作的签名流程有独立解码与核对
  1. 审计检查点八个。第一，交换函数有最小输出和截止时间，而且不是在合约内部用现货价算出来的。第二，签名验证用 EIP-712，包含五个字段。
  2. 第三，用 OpenZeppelin 的 ECDSA 库，拒绝零地址和高 s 值。第四，已使用标记基于 nonce 或消息哈希，不基于签名字节。
  3. 第五，permit 调用有抢跑容错。第六，动态类型的签名用 abi.encode。
  4. 第七，部署到 TRON 时，签名工具链和合约对链 ID、地址格式的处理一致。第八，特权操作的签名流程，有独立的交易解码与核对步骤。
练一练 · 暂停视频想一想

自动复投金库每小时换币，minOut = 现货价 × 99%

这个保护有效吗？
参考
无效。现货价本身可被同一笔交易操纵。攻击者先推高/压低现货价，minOut 就跟着变成一个"离谱但自洽"的值，保护形同虚设。
修复：minOut 用外部抗操纵价格计算，或由发起方在链下传入。
  1. 来练一练。一个自动复投金库，每小时把奖励代币换成本金，最小输出用池子当前的现货价乘以99%计算。这个保护有效吗？
  2. 参考答案。无效。因为现货价本身可以被同一笔交易操纵。攻击者先推高或压低现货价，最小输出就跟着变成一个离谱但自洽的值，保护形同虚设。这正是第5集合约层那条警告。修复是，最小输出用外部的抗操纵价格计算，或者由发起方在链下传入。
小结

记住三件事

  • 交换函数必有 minOut 和 deadline；不能内部用现货价算。
  • 签名绑定五个字段；用 EIP-712 + ECDSA，查零地址和高 s。
  • "没有公开内存池"≠ 没有 MEV；界面被篡改比私钥被盗更难防。
