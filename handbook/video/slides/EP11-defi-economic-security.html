自有代币作抵押品的反身性
  1. 大家好，欢迎来到主线第11集，DeFi 经济安全。一句话理解，经济攻击不依赖代码 bug。攻击者严格按照协议规则操作，只是组合了设计者没想到的顺序、规模或时间。
  2. 看三起事故，以下据公开报道。2023年，Euler 约1.97亿美元，根因是一个函数漏了健康检查。
  3. 2022年，Beanstalk 约1.8亿美元，根因是投票权能借，提案又能当场执行。
  4. 2021年，Venus 的 XVS 事件，用自己的治理代币作抵押品，坏账超过9500万美元。这些都不是代码写错了，是规则本身可以被套利。
一句话理解 · 打个比方

"7 天无理由退货，按当前标价退款"

规则本身没有 bug
退货退款，合情合理
但如果能先让标价翻倍
退货前操纵价格；或同一天买入、改价、退货（闪电贷）
超市就亏钱
比喻不准的地方：超市可以改规则、拒绝可疑退货。合约规则一旦部署，只能靠升级或治理修改 —— 而治理本身也可以被攻击。
  1. 打个比方。一家超市规定，任何商品7天无理由退货，退货时按当前标价退款。这条规则本身没有 bug，退货退款合情合理。
  2. 但如果有人能在退货前让标价翻倍，也就是操纵价格，或者在同一天买入、改价、退货，也就是闪电贷，超市就会亏钱。注意，他没有违反任何规则。
  3. 比喻不准的地方在于，超市可以修改规则并拒绝可疑退货。合约规则一旦部署，只能靠升级或者治理修改，而治理本身也可以被攻击。
借贷协议 · 核心不变量

资产永远要盖得住债权

  1. 借贷协议有两条核心不变量。对每个账户，加权后的抵押品价值，要大于等于借款价值，否则这个账户可以被清算。这个比值就是健康因子，小于1时账户可被清算。
  2. 对整个协议，所有资产的总和，要大于等于所有存款人的债权，否则协议资不抵债。
  3. 坏账从哪里来？看这张图。抵押品价格快速下跌，或者预言机延迟熔断，都会让健康因子小于1。这时如果清算及时，协议安全。
  4. 但如果清算不及时，或者抵押品流动性不足，清算人无法以合理价格卖出，抵押品的真实价值就跌破了借款，产生坏账，由存款人或保险基金承担。注意，坏账不一定来自攻击，市场暴跌也会产生。
案例 · 2021-05 · Venus XVS · 据公开报道

价格涨 → 借款增 → 卖压增 → 价格跌

  1. 先看一类特别的风险，反身性。Venus 允许用户用自己的治理代币 XVS 作为抵押品。XVS 的价格在短时间内，从约76美元涨到约144美元。
  2. 抵押能力随之上升，有人借出了大量 BTC 和 ETH。
  3. 然后 XVS 价格回落。抵押品价值跌破借款，清算超过2亿美元，仍然留下超过9500万美元的坏账。项目方称价格可能被操纵。
  4. 这就是反身性，价格上涨让借款增加，借出后产生卖压，卖压又让价格下跌，形成循环。协议自己的治理代币作抵押品，是典型的反身性风险。低流动性抵押品，必须有供应上限和更低的抵押率。
案例 · 2023-03 · 据公开复盘

每个函数单独看都"正确"

  1. 看 Euler，以下据公开复盘。Euler 有一个捐赠函数，允许用户把自己的存款捐给协议储备。但这个函数，没有检查捐赠之后账户的健康因子。
  2. 来看被打破的不变量。一个正常账户，抵押品减债务后是正的，健康。
  3. 当有人通过这个捐赠函数，捐出大量存款，账户的抵押品减少了，而债务不变。账户变得严重资不抵债，健康因子远小于1。
  4. 而 Euler 的清算折扣，随着资不抵债的程度增大。于是用另一个账户去清算这个账户，就能以极大的折扣拿走抵押品。攻击者获利约1.97亿美元，后来归还了大部分。
  5. 关键在于，每个函数单独审计都正确。漏洞在于，这个新增的捐赠函数，改变了账户状态，却没有走所有其他函数都会走的健康检查。记住，任何会减少抵押品或增加债务的路径，都必须在结束时检查健康因子。
案例 · 2022-04 · 据公开复盘 · 数字为示例

投票权按当前存款算，提案又能当场执行

  1. 治理攻击，是攻击者获得足够的投票权，通过一个恶意提案，合法地转走协议资产。看 Beanstalk，以下据公开复盘。攻击者提前一天，提交了一个恶意提案，因为紧急执行有一天的最短等待期。
  2. 一天后，攻击者用闪电贷借入约10亿美元的资产，存入协议，瞬间获得了多数投票权。因为投票权是按当前存款计算的，没有历史快照。
  3. 在同一笔交易里，攻击者用紧急通道通过并执行了提案，把国库资产转出，然后归还闪电贷。获利约8000万美元，协议损失约1.8亿美元。
  4. 两个缺陷叠加，投票权按当前存款算，而且有可以同一笔交易执行的紧急提案通道。修复是，投票权用过去区块的快照，提案通过后必须经过时间锁才能执行。这样，借来的票就不算数，执行前也有反应时间。
治理防御

五条

风险防御
闪电贷借票投票权快照在提案创建之前的区块
低投票率下被少数人通过法定人数要求
恶意提案通过后立即执行执行时间锁 + 守护者否决
提案内容难以理解附带可读的 calldata 解码
治理代币集中在交易所监控大额转入和委托变化
  1. 治理防御五条。闪电贷借票，防御是投票权快照取在提案创建之前的区块，借来的票不算数。低投票率下被少数人通过，防御是设法定人数要求。
  2. 恶意提案通过后立即执行，防御是执行时间锁，加上守护者否决。提案内容难以理解，防御是提案必须附带可读的调用数据解码，让投票者知道自己在投什么。
  3. 还有一点，治理代币如果大量集中在交易所，攻击者可能借到，要监控大额转入和委托变化。
奖励分发

"存入即领奖"是活靶子

缺陷说明修复
存入即领奖按存款时点余额算，闪电贷存入、领奖、取出奖励随时间累积；存入后最短锁定期
奖励代币 = 质押代币balanceOf 同时含奖励和质押，份额算错质押量用内部变量记录
奖励速率可被调用者影响按本区块成交量或池价算奖励参数由治理设定，不读可变数据
按 LP 价值铸币PancakeBunny公平储备定价
  1. 奖励分发也容易被无风险套利。第一个缺陷，存入即领奖。奖励按存款时点的余额计算，攻击者就用闪电贷存入、领奖、取出，一笔交易薅走奖励。修复是奖励随时间累积，存入后设最短锁定期。
  2. 第二，奖励代币和质押代币相同。合约的余额同时包含奖励和质押，计算份额就出错。修复是质押量用内部变量记录，不读余额，这和第6集金库通胀是一个道理。
  3. 第三，奖励速率可被调用者影响，比如按本区块成交量或池子价格算。修复是参数由治理设定，不读一笔交易内可变的数据。第四，按 LP 价值铸币，就是 PancakeBunny，要用公平储备定价。
流动性质押 · Mantle mETH · 据公开报道

延迟把"攻击时间"从一笔交易拉长到几小时

  1. 最后讲一个正面的设计，延迟作为安全参数。流动性质押里，用户质押 ETH，拿到可交易的凭证。凭证可以在 DEX 交易，好处是用户无需等待就能退出，风险是凭证可能脱锚。
  2. 而赎回有一个延迟队列。这对用户体验是负面的，要等待。但它给协议留出了反应时间。
  3. 2025年 Bybit 被盗后，攻击者把部分资产换成 Mantle 上的重质押凭证，尝试赎回。mETH 协议有8小时的提款延迟，让团队有时间暂停合约，追回了约4300万美元。
  4. 所以，延迟是一种安全参数，不只是体验问题。它把攻击者完成攻击的时间，从一笔交易，拉长到若干小时，让监控和人工响应有机会介入。代价是正常用户也要等待。
审计清单

七个检查点

① 写出协议级偿付不变量，用不变量测试验证
② 所有减少抵押或增加债务的路径，最后都检查健康因子
③ 清算奖励在极端行情仍有吸引力；清算折扣有上限
④ 低流动性抵押品有供应上限；自有代币作抵押有额外限制
⑤ 投票权用历史快照；提案执行经过时间锁
⑥ 奖励计算不依赖一笔交易内可变的数据
⑦ 提款/赎回是否需要延迟？延迟期内谁能暂停？
  1. 审计检查点七个。第一，写出协议级的偿付不变量，用不变量测试验证。第二，所有减少抵押品或增加债务的路径，最后都检查健康因子，这是 Euler 的教训。
  2. 第三，清算奖励在极端行情下仍有吸引力，清算折扣有上限。第四，低流动性抵押品有供应上限，协议自有代币作抵押品时有额外限制。
  3. 第五，投票权用历史快照，提案执行经过时间锁。第六，奖励计算不依赖一笔交易内可变的数据。
  4. 第七，提款和赎回是否需要延迟，延迟期内谁能暂停。

  1. 来练一练。Euler 的捐赠函数，如果在最后加一行，要求调用者的健康因子大于等于1，攻击还能成功吗？还需要检查什么？
  2. 参考答案。这一行确实能挡住这条路径，捐赠后账户资不抵债就回滚。但要系统地防，还得问两件事。第一，所有其他会减少抵押品或增加债务的入口，都检查了吗？第二，清算折扣有上限吗？修一个函数不够，要修的是这一类不变量，确保它在每个入口都成立。这就是经济安全和单点修补的区别。
小结

记住三件事

  • 经济攻击"每步都合法"；先写出偿付不变量，再验证每个入口都守住它。
  • 投票权用历史快照，提案经时间锁执行；奖励不读可变数据。
  • 延迟是安全参数；自有代币作抵押品有反身性风险。
