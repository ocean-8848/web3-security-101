# 第 01 章：分段制作说明

整集标题：合约安全全景：为什么代码就是金库。全片约 11.6 分钟（696.9 秒，不含段间间隔），分 6 个工程：seg1–seg6（都在 `hf/ep01/` 下）。讲稿 `script.json`，逐句时间在 `timing/<seg>.json`。

统一视觉、颜色语义、字幕、讲解规则、事实规则：见 `../PIPELINE.md` 第 0 节；工程里已有什么、交付要求、运动参数：照 `../ep29/BRIEF-FULL.md` 第 2、3、5 节。下面只写本集特有的内容。

## 0. 本集骨架

**一句话核心观点**：智能合约是一段公开、不可撤回、直接控制资金、任何人都能用任意参数和任意顺序调用的代码，所以安全要从"攻击者能控制什么"出发；而近年最大的损失已经转到代码之外（跨链桥与运营安全）。

**支撑结构**
1. 钩子：Bybit 的 Safe 合约没有被利用的代码漏洞，钱照样丢了（第 ⑥ 类：前端和签名界面失守）。
2. 合约 = 广场上的售货机：公开、全天候任人操作、装好不能修、吐错钱追不回；比喻的局限是可组合性和一笔交易内反复调用。和 Web2 / CEX 的三个关键区别：谁能调用、能否回滚、攻击成本。
3. 攻击面地图：一笔交易经过的环节；五个信任边界；回调箭头（重入）；顺序可被利用；图的局限（共识与节点）。六大类漏洞，真实事故多类叠加；第 ⑥ 类拆成"链与基础设施"和"人、设备、流程"。
4. 损失趋势：早期是代码漏洞，近年最大损失转向跨链桥和运营安全；数学类没有消失（Balancer V2）。
5. 防御方法：威胁建模，先列攻击者能做的 7 件事和通常做不到的 3 件事，再按 6 步建模，以不变量为锚点。
6. 收尾：按角色给一件事；回答开头问题。

**关键术语**：智能合约、外部账户（EOA，画面上可以出现，讲稿未念）、可组合性、升级代理、闪电贷、内存池、区块构建者/排序器、信任边界、重入、威胁建模、不变量、六大类（控制流、权限、数学、数据可信度、经济设计、系统与运营）。

**成立条件、例外与风险**
- 售货机比喻不成立的地方：一笔交易内可被同一人反复、嵌套调用，还能与其他合约组合（讲稿 seg2 L11–L13 已说）。
- 攻击面图不含链的共识层和节点（seg3 L11–L12）。
- 攻击者"通常不能"的三件事都有例外：私钥泄露或验签写错；共识被攻破；代码用了 `tx.origin` 或错误的 meta-tx 逻辑（讲稿说成"用错了身份判断的方式"，画面标签可写 `tx.origin`）。
- 威胁建模依赖想象力；经济攻击超出单个合约边界（seg5 L26–L27）。
- "合约忠实执行"这一结论的依据是公开分析，不是最终的独立结论（seg6 L8）。

**不确定之处 / 口径**
- 损失数字：公开报道和安全公司年度统计，事发时美元估值，约数（seg4 L1 已念出口径，画面角落常驻灰标签"公开报道 · 事发时美元估值 · 约数"）。
- Binance 约 63.4 亿美元为项目方口径；"超过此前任何单起事故的 4 倍"按此口径（灰标签"项目方口径"）。
- Balancer V2：项目方口径约 9480 万美元，早期报道约 1.28 亿美元，两个数并列显示。
- Bybit：手册只写"前端被篡改，交易替换了多签实现合约，约 15 亿美元"，以及"公开分析没有指向 Safe 合约代码漏洞"。画面不要加入手册第 01 章没写的细节（不画 S3、AWS 令牌、只针对某一钱包等，那些属于第 29 章那一集）。
- "最关键的区别有三个"是从手册六个维度里挑的（解读）；"签名时看到的屏幕也可能被篡改"是从 Bybit 推出的用户侧提醒（解读）。画面上这两处不需要单独标签，但不要写成"手册称"。

## 1. 本集的世界与主角

- **一个连续的广场**。所有段都在同一个等距世界里，镜头移动，不硬切。建议世界布局（第一个做的人在 `SPEC.md` 里记下坐标，其他段对齐）：
  - 西北角：**Bybit 区**（seg1、seg6）：Safe 冷钱包保险柜 + 三位签名人 + 一台显示 Safe 钱包网页的浏览器窗口。
  - 中央：**广场中央的售货机**（seg2 起全片主角，代表"智能合约"）。
  - 从西南到东北：**交易之路**（seg3）：用户 → 钱包与前端 → 内存池 → 区块构建者 → 售货机（目标合约）→ 外部合约群 / 维修门（代理与实现）/ 跨链桥 → 对岸另一台售货机。
  - 东南角：**损失长廊**（seg4）：一排年份立柱，每根立柱旁是点阵。
  - seg5 回到售货机旁，攻击者小人站在它面前，身边摆出"能力清单"物件。
- **需要补的拟物物件（库里没有，按同一投影自己画）**
  1. **自动售货机（= 智能合约）**：高约 300、宽约 200 的立柜，正面（+v 面）上半是玻璃橱窗，橱窗里一层层摆着金条和硬币（合约余额，金色）；右侧是按钮面板（一列圆形按钮）和投币口；下方是出货口。−u 面（左侧窄面）贴着一张电路图纸（青蓝细线，表示"代码公开"）。背面或侧面有一扇带锁的小**维修门**（默认不存在，seg2 L9 才出现，`ID-door` 可开）。状态：normal 有绿色地光；被攻击时出货口吐出红色硬币。要做成可复用：`vending(o,{id,maintDoor,glass,coins})`。
  2. **内存池（等候区）**：一块带栏杆的排队区（像机场排队的伸缩隔离带围成的蛇形通道），上方挂牌"Mempool"，里面排着几封信封（交易）。
  3. **区块构建者 / 排序器**：一台带传送带的分拣机，信封从内存池进来，被机械臂排好顺序后放进一个区块（可接 `chain` 的区块）。
  4. **外部合约群**：三台更小的售货机，分别贴图标：代币（硬币图案）、DEX（两个箭头互换）、预言机（顶上一个表盘的报价机，指针可动）。
  5. **跨链桥**：真正的拱桥，跨过一条浅蓝色的"河"，桥头有一个小岗亭（消息层/验证），对岸是另一台售货机（另一条链上的合约）。
  6. **防火墙**：一段砖墙加一个门禁闸机（seg2 对比用，Web2 一侧）。
  7. **闪电贷柜台**：一个银色小柜台，台面上瞬间出现一大堆金条，又在同一笔交易结束时收回（用一个交易框框住"借—用—还"）。
  8. **天平（= 不变量）**：黄铜（金色允许，作为器物）秤杆、两只托盘；左盘"合约 USDT 余额"，右盘"用户存款之和"，左边不轻于右边。被打破时秤杆倾向错误一侧、立柱出现红虚线框。
  9. **两块对岸的"拆分牌"**：seg3 L21 用，一块写"链与基础设施"，一块写"人、设备和流程"，做成插在地上的木牌（木色允许，作为标牌）。
  10. **时间锁**：一个带计时转盘的挂锁（可从 `padlock` 改，锁体上加一个小表盘）。
- **库里直接用的物件**：`safe`（Bybit 冷钱包、"实现合约（锁芯）"换芯）、`person`（签名人、攻击者、工程师）、`browserWin`（Safe 钱包网页）、`laptop`（钱包与前端）、`key`（升级密钥）、`padlock`、`dbLedger`（Web2 数据库/交易所内部账本）、`ledgerBook`、`chain`（区块、共识）、`rpc`（节点）、`envelope`（交易）、`doc`（签下的交易、密码纸条）、`magnifier`、`seal`（签名）、`shield`、`rack`（Web2 后端服务器）、`desk`（供应商终端）、`checkpoint`（不需要七道关，只在 seg3 当"签名界面"岗哨也可以不用）、`clock`、`beacon`。
- **点阵**：seg4 统一"每个点 = 1 亿美元"。The DAO 约 0.6 个点（画成一个缺了 40% 的点）。
- **六大类告示牌**：seg3 L13 起出现一排 6 块挂牌，① 控制流 ② 权限 ③ 数学 ④ 数据可信度 ⑤ 经济设计 ⑥ 系统与运营，青蓝描边。之后各段复用（seg4 给事件贴类别号，seg6 点亮 ⑥）。

## 4. 各段分镜（按句写；L 号见 timing.json 的 lines，从 0 开始）

### seg1 ① 一笔日常签名（51.9 秒）
目标：观众记住"签名人签了一笔看起来正常的交易，约 15 亿美元没了"，并带着问题往下看：Safe 合约有没有代码漏洞？
- 段首 0–1.6 s：标题卡"① 一笔日常签名"，副标题"合约安全全景"；右上角胶囊切到 ①。
- L0 2025 年 2 月，签了一笔看起来正常的交易：镜头在 Bybit 区。Safe 冷钱包保险柜（门关着，铭牌"COLD"）、三位签名人（墨色）围着一台浏览器窗口，页面是"新交易 · 确认签名"，绿色按钮。一份交易文件（`doc`）放在签名人面前。标签"2025 年 2 月"、"Bybit 冷钱包 · Safe 多签"。公章盖下（`KIT.stamp`），印痕用墨色（红色留给失败和攻击者）。

- L2 替换了多签的实现合约：镜头推近保险柜，门打开 105°，露出蓝色锁芯，标签"实现合约（锁芯）"；`KIT.swap` 把蓝锁芯换成红色攻击者锁芯。**本段关键画面**：签名人的章 → 红色虚线 `dashCurve` 连到被换的锁芯。

- L8 问题二（从哪进来）：第 2 张卡片"攻击从哪里进来？"，西南的道路轮廓亮一下。

### seg2 ② 代码就是金库（148.2 秒）
目标：观众能说出"合约 = 公开、不可撤回、控制资金、任何人可用任意参数和顺序调用"，知道售货机比喻在哪里不成立，并说出和 Web2 / CEX 的三个关键区别。
- 段首：标题卡"② 代码就是金库"，胶囊切到 ②。
- L0 准确的定义：镜头落在广场中央空地。
- L1 部署在链上、自动执行、持有并转出资产：先出现一段区块链（`chain`，3 块）铺在地面，**售货机从区块上长出来**（`KIT.grow`）；橱窗里金条和硬币亮起；标签"智能合约"。一枚硬币从出货口转出，标签"可以转出资产"。
- L2 一句话：四个特征用四个小标签依次挂在售货机四周：公开 / 不可撤回 / 直接控制资金 / 任何人可调用（关键词，不写整句）。
- L3 任意参数、任意顺序：一排按钮被不同的手（小人剪影）以乱序按下，按钮上闪出 `f(1)`、`f(99999)`、`f(0)` 这样的参数（示意）。标签"任意参数 · 任意顺序"。
- L4 打个比方：画面不换，只在售货机头顶弹一个小牌"比喻：广场上的售货机"。
- L5 真金白银 = 合约余额：橱窗推近，金条发光（不加特效，金色即可），标签"合约余额"。
- L6 电路图贴在外壳上：镜头绕到 −u 面，看见贴着的电路图纸；放大镜扫过，图纸上标"字节码：一定公开""源码：通常公开"（两个标签，第二个用灰描边表示"通常"）。
- L7 全世界全天候来投币、拍打：售货机周围依次出现 6–8 个不同颜色的小人（墨、青蓝，再加一个红色攻击者），有的投币、有的按钮、有的拍打（机身轻微抖一下）；旁边 `clock` 指针快转一圈，标签"全天候"。
- L8 装好不能打开维修：售货机背面所有接缝画上铆钉，一个扳手图标靠近后被挡开（灰色"✕ 不可修改"）。
- L9 留了维修门 = 升级代理，钥匙成了攻击目标：售货机侧面长出一扇小维修门（标签"升级代理"），门上挂锁，旁边出现一把黄铜钥匙（标签"升级密钥"）；红色攻击者小人转头盯着钥匙，红色虚线从攻击者指向钥匙。
- L10 吐错钱追不回，交易不可逆：出货口吐出一串硬币滚走；画面里一个"客服"窗口（小岗亭）挂着"无人"牌；标签"交易不可逆"。
- L11 比喻不成立：标签"比喻在这里不成立"（灰描边），真实售货机前只排一个人。
- L12 同一笔交易里反复、嵌套调用：用一个青蓝描边的长方形框表示"一笔交易"，框里同一个小人连续按了三次按钮，第二次按下时又从机器里伸出一个调用再按一次（嵌套，画成一个按钮套一个按钮的小循环箭头）。
- L13 拼几十台、可组合性，漏洞来源：售货机两侧长出几台小售货机，彼此用管道连起来（像积木），标签"可组合性"；管道接口处出现一个红色虚线小圈，标签"漏洞常出在这里"。
- L14 和 Web2、交易所比，三个区别：镜头拉远，广场左边出现两个对照小场景：Web2 后端（服务器机柜 `rack` + 数据库 `dbLedger`，前面一段**防火墙**砖墙加门禁闸机），交易所（一栋小楼 + 内部账本 `ledgerBook` + 门口 KYC 柜台）；右边是售货机。三列顶部各一个牌子：Web2 后端 / 中心化交易所 / 智能合约。下方预留三行"谁能调用 / 能否回滚 / 攻击成本"。
- L15 第一，谁能调用：第一行亮起。Web2 门禁闸机只放有工牌的人（绿勾），交易所 KYC 柜台检查证件（绿勾）。
- L16 任何地址、任何合约；public 函数 = 对全世界开放的 API：售货机前没有闸机，人和小合约（小机器）都直接走过来；售货机按钮面板上浮出标签 `public 函数 = 对全世界开放的 API`。
- L17 第二，能否回滚：第二行亮起。Web2 数据库里一行被改回（橡皮擦动画），交易所账本里一行被划掉重写，各一个绿勾"可回滚"。
- L18 合约不可逆，只能升级或社会共识，没有权限就修不了：售货机那一列：一枚已吐出的硬币上盖一个"不可逆"的灰章；两条出路分支：维修门（升级）/ 一群人举手（社会共识）；维修门上的锁没有钥匙时，红叉"无升级权限 → 修不了"。
- L19 第三，攻击成本：第三行亮起。Web2 前面的防火墙、交易所前面的门禁，攻击者小人要翻墙（画成攀爬中，标签"绕过防火墙 / 攻破内部系统"）。
- L20 合约只要一笔 gas，闪电贷借到上亿本金：售货机前，攻击者往投币口投一枚很小的硬币（标签"一笔交易的 gas"）；旁边**闪电贷柜台**在一个"一笔交易"框里瞬间推出一大堆金条，标签"闪电贷 · 上亿美元 · 同一笔交易内借还"。
- L21 能升级 = 修复能力也是攻击面，密钥可能被盗：回到维修门；同一把钥匙左边标绿"修复能力"，右边标红"攻击面"；红色攻击者的手伸向钥匙（不画偷走的过程，只画伸手）。**本段关键画面**：同一把钥匙两种颜色的标签。
