# 第 29 章完整版：分段制作说明

全片约 10.3 分钟，分 7 个工程：seg1（开场，已完成，在 `hf/s7-vivid`）、seg2、seg3a、seg3b、seg4、seg5a、seg5b（都在 `hf/ep29/` 下）。每个工程单独渲染，最后用 ffmpeg 拼接。你只负责分给你的那一段。

## 1. 一句话核心观点（全片）

私钥保护回答"谁拿着钥匙"，签名路径回答"谁决定钥匙盖在什么文件上"。2024 年以来的大额事件里，攻击者多半控制的是后者。防御靠三条：每一层重新检查；关键输入有多个独立来源；响应覆盖链上状态。

## 2. 你的工程里已经有什么（不要改）

- `assets/narration.wav`：本段配音（段首有 1.6 秒静音，留给章节标题）。
- `timing.json`：`lines`（每句的起止）、`words`（逐词时间，`line` 是句号，从 0 开始）、`captions`（字幕组）、`total`（本段时长）。画面在说到某个词时出现：用 `words` 里那个词的 `start`。
- `compositions/captions.html`：字幕，已生成，白色圆角字幕卡，底部 84 px。字幕不含句号逗号，不要改。
- `index.html`：根，时长等于 `total`；`compositions/story.html` 是占位，换成你的画面。可拆成多个场景文件，但**整段保持一个连续的等距世界和一台镜头**，不要硬切。
- 字体已声明：Noto Sans SC（100–900）、JetBrains Mono。

## 3. 统一视觉（必须遵守）

- **视觉库**：`hf/ep29/kit/`（`README.md` 先读）。所有物件都从 `objects.mjs` 取，都是**拟物**的等距小模型：保险柜、笔记本、硬件钱包、服务器机柜、加密机、RPC 节点、检查站（岗亭 + 道闸）、广播塔、区块链、浏览器窗口、S3 桶、工位、手机、人物、熔断闸刀、警报灯、沙漏、盾牌、放大镜、公章、文件、账本、信封。库里没有的物件，按同样的投影和画法自己补，补的物件也要拟物。
- 风格样张：`hf/ep29/kit/showcase.png`；完成度参考：`hf/out/s7-vivid.mp4`（开场 47 秒，就是 seg1）。
- 颜色语义全片不变：绿 #1f9d55 = 正常/通过；红 #e0453a = 失败/攻击者/被攻破；青蓝 #2aa3c9（实底 #1d93ba）= 中性组件与标签；墨 #1c1c1c；纸底 #efebe3 + 等距网格 #e2ddd3。金条可用金色。不用黄色荧光笔。

- 段首 0–1.6 秒：章节标题卡（白色圆角大卡，"③ 断在哪一关"这样的编号 + 标题，Noto Sans SC 900 约 80 px），同时右上角胶囊切到本段；1.6 秒后标题卡缩成胶囊或让位给世界。seg3b、seg5b 是同一章节的后半段，不用大标题卡，用一个小标签过渡。
- 段尾：最后约 1 秒画面落定、静止（方便拼接）。
- 讲解规则（AI 解读）：一个镜头只讲一个想法；新物件从已有物件生长、变形或沿路出现，不要凭空堆满；画面承担论证，屏幕上的字只写关键词、数字、字段、标签，不重复字幕整句；每个难点最多一个比喻，比喻之后马上回到准确的机制。
- 事实口径：屏幕上出现"项目方称""第三方分析""未确认"时用灰色小标签标明来源层级。只用本说明和讲稿里的事实；不写具体地址、哈希、签名人人数、ETH 数量。数字后面加"约"。
- 字号：要读的字 ≥ 30 px；标题 ≥ 72 px。底部 160 px 留给字幕卡。右上角约 560×80 px 留给胶囊。
- 运动：镜头 power2.inOut 0.9–1.2 s；物件从地面长出 scaleY 0→1（0.45 s back.out(1.4)）；标签弹出 0.25 s；信封/文件沿弧线飞 0.6–0.9 s；落定的东西不再漂移；无 Math.random、无 repeat:-1。
- 全片固定的"主角"：**一封提现信封 / 一张提现单**沿检查站道路前进；**七个检查站**（① 业务意图 ② 请求构造 ③ 风控与审批 ④ 显示与解码 ⑤ 签名 ⑥ 广播 ⑦ 链上状态）+ 第 ⑤ 关旁边的支线"数据源 RPC"。seg2 建立这条路，seg3a/seg3b/seg4 在同一条路上标记断点，seg5a 把它升级成防御架构。

## 4. 各段分镜（按句写；句号见 timing.json 的 lines，从 0 开始）

### seg2 ② 七道关（87.5 秒）
目标：观众能自己说出七关的名字，并理解"每个箭头都是一次信任传递"。
- L0 先把这条路画出来：一条空的等距道路从左下伸向右上，道路尽头是一座小区块链（链上）。
- L1 用户提 2 万 USDT（示例）：道路起点出现一个人物 + 手机，手机屏幕"提现 20,000 USDT"，灰标签"示例"。
- L2 第一关业务意图：检查站 ① 从地面长出；账本翻开，新增一行"提现单 #示例"，一张提现单从账本飞出，变成主角信封。
- L3 第二关请求构造：检查站 ② + 钱包后台服务器；信封进入服务器，出来时信封上多了一张"待签交易"的封条（字节条纹）。
- L4 第三关风控与审批：检查站 ③，岗亭上盾牌亮起，道闸抬起；一个审批人物在旁边按下"批准"。
- L5 第四关显示与解码：检查站 ④，一台显示器把一串十六进制字节（示意）"翻译"成一行中文"转账 20,000 USDT → 用户地址"，放大镜扫过。
- L6 第五关签名：检查站 ⑤，旁边三种签名者依次出现：服务器机柜（MPC 节点）、加密机（HSM）、几位多签签名人；公章盖在信封上，留下红色印痕。
- L7 第六关广播：检查站 ⑥ + 广播塔发出信号弧线，信封飞上链。
- L8 第七关链上状态：检查站 ⑦，区块链方块亮起；旁边一个账户卡片三行"余额 / 代码 / 权限"，余额数字变化；说到"代码和权限"时这两行轻闪一次。
- L9 支线数据源：从第 ⑤ 关侧面伸出一条小路到 RPC 节点（小服务器 + 天线），数据包沿小路流向第 ⑤ 关。
- L10 注意每一个箭头：镜头拉远看全路；关与关之间出现箭头，每个箭头上弹出一个小标签"已检查 ✓"（青蓝），表示下游默认上游已检查。
- L11 这条链路叫签名路径：全路描一圈青蓝描边，大标签"签名路径"。
- L12 私钥只在第五关：其他关变浅，第 ⑤ 关高亮，岗亭里出现钥匙 + 挂锁；最后一句"签出他想要的东西"时公章旁出现红色问号（攻击者的目标）。段尾静止。

### seg3a ③ 断在哪一关（142.3 秒）
目标：五起事件各自落在路上的哪一关，以及每起的事实层级（项目方 / 第三方 / 未确认）。
- 版式：上方是七关道路的缩小全景（同 seg2 的路，镜头拉远），每讲一起事件，镜头推到那一关，展开一个"事件小场景"，讲完缩回去，在那一关上插一面红色小旗（事件名 + 年月 + 金额）。路的右侧有一列"事件卡"逐张累加（Bitget、WazirX、Bybit、Drift、KelpDAO），每张卡：名称、年月、约多少美元、断在第几关、来源层级灰标签。
- L0 六起事件放到路上：道路全景出现，右侧事件卡栏空槽 ×6（第 6 张留给 seg3b 的 Binance）。
- L1–L4 Bitget（第 ② 关）：推近 ②；一个"第三方安全产品"盒子出现裂缝（零日），内部凭证（钥匙卡）从裂缝掉出，被攻击者小人捡走；攻击者用工具（扳手图标的定制工具）伪造一封提现信封塞进 ② 号服务器，信封红色；"私钥和冷钱包未受影响（项目方称）"：保险柜完好绿勾；"产品名未公开"灰标签。插旗。
- L5–L7 WazirX（第 ④ 关）：推近 ④；托管方界面的显示器上写"正常交易"，旁边真实交易文件是红的、不同；两个对话气泡："WazirX：显示和实际不一致""Liminal：我们没被攻破"，中间一个灰色"说法冲突 · 未见独立报告"标签。插旗。
- L8–L12 Bybit（第 ④ 关，深讲）：同一关插第二面旗。小场景：开发者工位电脑出现红叉 → 一把"AWS 会话令牌"钥匙卡从电脑飞到 S3 桶 → S3 桶里的 JS 文件变红（被改）→ 浏览器窗口（Safe{Wallet}）读取被改的 JS → 只有一个保险柜（Bybit 冷钱包）被红色瞄准线锁定，其他保险柜灰色不受影响 → 计时器"约 2 分钟后"→ JS 文件变回原色。L12：三位签名人看着同一个浏览器，没有第二块屏幕（画一个空着的、打问号的第二块屏幕虚线框）。
- L13–L16 Drift（第 ⑤ 关）：推近 ⑤；五个人物围着一张桌子（安全委员会），其中两人亮起即可签名（2-of-5）；"迁移后无时间锁"：一个时间锁图标被划掉；成员在没看懂的文件上盖章（文件内容模糊）；沙漏：持久 nonce，签名不会过期；攻击者把这些签好的文件放进抽屉，"等待"（时钟快转），然后提交。"第三方分析"灰标签。插旗。
- L17–L21 KelpDAO（数据源支线）：推近支线；跨链桥（一座小桥）上只有一个验证者岗亭（1 个验证者）；它依赖的两个 RPC 节点被换成红色；其他 RPC 节点被 DDoS（被一堆小红信封淹没、熄灯）；验证者被迫切换到红色节点；红色节点给验证者一张假数据单，给其他人真数据；验证者诚实地盖章（绿色的章盖在红色的假单上——这是本段关键画面）。"LayerZero 称""责任有争议 · 诉讼中"灰标签。插旗。
- 段尾：镜头拉远，五面旗插在 ②、④（两面）、⑤、支线上，事件卡 5/6，最后一个空槽闪一下（留给 Binance）。

### seg3b ③ 断在哪一关 · Binance（71.4 秒）
目标：Binance 同时断在第 ⑤ 关和第 ⑦ 关；"暂停提现不等于撤销权限"。
- L0 最大的一起：事件卡第 6 槽亮起，标签"最大的一起"。
- L1 63.4 亿美元（项目方口径）：点阵"每个点 = 1 亿美元"，63 个点 + 半个点（约 63.4）快速填满（9×7），旁边对比 Bybit 15 个点（缩小参照），"项目方口径"灰标签。
- L2 假面试作业：工程师 B 的工位，屏幕上一份"面试作业.zip"被打开，电脑变红。
- L3–L4 部署令牌：工程师 A 的工位旁放着"容器部署令牌"钥匙卡；攻击者小人拿走令牌，一个红色集装箱（容器）被部署进机房，伸出一根线接到签名服务器机柜。
- L5 第五关：推近第 ⑤ 关检查站，签名服务器"自己"在文件上盖章（钥匙一直锁在柜里，绿勾）——"不是偷钥匙，是让它替他签"。
- L6–L7 50 笔交易、7702 委托：一叠 50 张小文件（数字 50 滚动），每张印"nonce / 7702 委托"；以太坊热钱包（热钱包保险柜变体）的锁芯被换成红色的"攻击者代码"，热钱包上挂一条红色委托链子。
- L8–L9 第七关：Binance 的"暂停提现"按钮被按下（绿色开关拨到关）、"热钱包服务"服务器关灯；但链上（第 ⑦ 关区块链）那条红色委托链子还在，资金继续从热钱包流出（金条/硬币流走）——左右对照：链下开关全关 vs 链上委托仍在。
- L10 存活约 3 小时 50 分：沙漏/时钟从 20:20 走到次日 00:10（UTC，灰标签"按公开时间"），链子在 00:10 才断开。
- L11 未说清：两个灰色问号卡片"告警时间？""AI 工具如何被利用？"+"完整报告待发布"。段尾：全路六面旗齐了，第 ⑤、⑦ 关各多一面 Binance 旗。

### seg4 ④ 三个共同点（69.2 秒）
目标："看懂了"的那一刻：把六个断点叠起来，抽出三个共同点，翻成三条原则。
- L0 六个位置、结果一样：全路六面旗；每面旗下方的检查站都在"正常运行"（道闸照常抬起、绿灯），但出来的信封都是红的。
- L1 叠在一起：六个事件卡飞到画面中央叠成一摞，然后分出三束光（不要发光特效，用三条青蓝细线）指向三张"共同点卡"。
- L2 共同点一（校验放错位置）：一个检查站岗亭里的人只看信封的格式（尺子量信封尺寸，绿勾），信封里面的内容（真实业务）是红的没人看。
- L3 共同点二（单一来源）：四个"独苗"图标排成一行：一块屏幕、一组 RPC、一个发布包、一条审批路径，每个下面只有一根细线连着，线一剪就断。
- L4 共同点三（响应只管链下）：链下的开关全部拨到关（灯灭），链上的区块里那条红链子仍然连着。
- L5–L6 金句：画面中央一枚公章和一把钥匙：钥匙（"谁拿着钥匙"→私钥保护）安全地挂在保险柜里；公章正要盖向一份文件（"谁决定盖在什么文件上"→签名路径）；文件被一只红手套换掉。这是全片最重要的比喻画面，要清楚、稳、停留够久。
- L7–L9 三条原则：三张共同点卡依次翻面，背面是原则：①"每一层重新检查，不继承上一层的结论"（每个检查站都有自己的放大镜）；②"多个独立来源，对不上就拒签"（两组 RPC/两块屏幕，结果不一致时道闸放下、红灯）；③"响应覆盖链上状态：暂停提现 ≠ 撤销权限"（≠ 号做大）。段尾三张原则卡并排静止（这里允许并排，因为它们是同一组概念的总结；但卡片样式要像三块挂在检查站上的告示牌，不是平面三卡）。

### seg5a ⑤ 怎么守（132.1 秒）
目标：示例架构长什么样；四个重点各自挡住了哪起事件。
- L0 示例架构：灰标签"本手册示例架构 · 不是任何交易所公布的方案"，一直挂在角落直到 L3。
- L1 架构生长：沿着原来的七关道路，检查站升级成机房里的设备，依次出现：账本（数据库 + 账簿）→ 意图签发服务 → 策略引擎（盾牌）→ 审批（人物 + 按钮）→ 签名集群（服务器机柜）→ 广播（塔）→ 链上（区块链）→ 独立监控（警报灯 + 摄像头样的监视器，用虚线回连广播层和签名集群）。说到哪个名字，哪个长出来。
- L2 禁止的路线：一个开发者工位，一条红色虚线试图连向签名集群，中途被一堵墙/断开的网线截断，红叉，标签"禁止：没有网络路由"。
- L3–L5 重点一 账本绑定：推近账本和签名集群之间；签名服务手里一张提现单，对照账本：存在 ✓ 状态正确 ✓ 金额一致 ✓ → 盖章；同一张单第二次来，账本里这一行已标"已签"→ 拒绝。伪造的红色信封（Bitget 那种）来了，账本里查不到 → 道闸落下，红叉，小旗"挡住：伪造指令"。
- L6–L9 重点二 策略读原始字节、默认拒绝：盾牌策略引擎把信封拆开，读里面的原始字节（不是信封外面贴的说明标签）；一张"规则表"告示牌：operation 只允许 0；1 只能指向批量调用合约（MultiSendCallOnly）；链上 Guard 再拦一次（保险柜门口多一道小闸）。Bybit 那封 operation = 1 的信封到达，被盾牌弹回，小旗"挡住：Bybit 这类交易"。
- L10 7702：一份"EIP-7702 授权"文件到达热钱包策略，被拒，小旗"如果覆盖：Binance 那批委托签不出来"（这是解读者的判断，标灰色小字"解读"）。
- L11–L12 重点三 分链熔断：三条链各有一个熔断闸刀；某条链流出异常（金条快速流出）→ 只有这条链的闸刀断开；账本里没有对应订单的流出 → 所有闸刀一起断开；闸刀的控制线连到一个独立的小控制箱（不是连到被攻破的系统），标签"独立通道"。
- L13–L15 重点四 紧急撤销：热钱包上那条红色委托链子；一条独立的、平时锁着的"撤销路径"（玻璃罩里的红色按钮 break-glass，预先批准的签名）；提交"委托地址 = 零地址"的新授权 → 链子断开；日历上每季度一次演练、秒表记录用时；最后一个放大镜查"账户代码"→ 结果"空"✓。
- L16 局限：一个红色小人试图独自通过 → 需要三把钥匙同时转动（多人共谋）才能打开，标签"挡不住所有内部人 · 把单人作恶变成多人共谋"。段尾静止在完整架构全景。

### seg5b ⑤ 怎么守 · 你今天能做什么（67.6 秒）
目标：每个角色带走一个今天就能做的动作；回到开场问题收尾。

## 5. 交付（每段相同）

1. 在你的工程目录写 `SPEC.md`（按 HyperFrames 的 spec 模板，写具体数字和每个镜头的时间）。
2. 画面做成可重生成的：建议 `src/build-story.mjs` 生成 `compositions/story.html`（import `../../kit/iso.mjs`、`../../kit/objects.mjs`、`../../kit/pills.mjs`），在 `index.html` 引用 `kit/kit.css` 时要复制到你工程的 `assets/` 再引用（HyperFrames 只能读工程内文件）。
3. `npx hyperframes check --json`：修掉所有 error，认真看 warning。
4. 自审：`npx hyperframes snapshot --at ...`，每句话至少看一帧（取该句中点），外加段首 0.8 秒、段尾最后 0.5 秒。逐帧检查：物件是否拟物、一眼认得出；画面是否在讲这句话；字是否 ≥ 30 px、没被裁切、没压字幕卡和胶囊；颜色语义；事实与讲稿一致。发现问题就改，再截图确认。写 `REVIEW.md`（发现了什么、改了什么、还剩什么）。
5. 渲染：`npx hyperframes render -o renders/<段 id>.mp4`，ffprobe 确认时长等于 `total`、有音轨，复制到 `hf/ep29/out/<段 id>.mp4`。
6. 只改你自己的工程目录（和 `hf/ep29/out/` 里你自己的文件）。需要给 kit 补物件时，把新物件写在你自己的工程 `src/` 里，不要改 `kit/`。不提交 git，不发布。
7. 最终回复（中文，简短）：成片路径、每句一帧的代表帧路径（或一张拼图）、自审改了什么、仍存在的问题。
