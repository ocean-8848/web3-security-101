# ep28 分镜：事故案例库：同样的错误，换个名字再来

统一视觉（画面、物件、颜色、字幕、术语卡、结束卡、版面分区、独立成片）见 `PIPELINE.md` 第 0 节，这里不重抄。讲稿 `script.json`，多音字表 `pron.json`（本集条目都加在 `tools/pron.json`）。

## 1. 本集骨架

- **一句话核心观点**：大多数事故不是新漏洞，而是旧漏洞在新环境里复发：新链、新分叉、新版本、新的组合方式。认出它靠的是模式和识别信号，不是事故名字。
- **支撑结构**：
  1. 钩子：The DAO（2016-06，约 6000 万美元，先转账后更新余额）→ Curve / Vyper（2023-07，约 7000 万美元，编译器把重入锁实现错了）→ Penpie（2024-09，约 2700 万美元，领奖函数无锁）：三个名字，同一个错误。两个问题：修过的漏洞为什么回来？读旧事故能不能提前认出下一起？
  2. 准确表述 → 航空事故报告比喻（不成立处：航空调查由独立机构完成；链上复盘多由项目方或安全公司发布，可能不完整、有争议 → 只采信多方一致的事实）→ 按"根因类别 + 链"归档 → 六面展墙 → 八种模式。
  3. 代码里的三种：① 先交互后记账（Fei Rari）② 零值有含义（Nomad、Qubit）③ 一笔交易内可变的数据当事实（bZx、PancakeBunny、Cream）。每种：案例 → 识别信号 → 防御。
  4. 改动与盲签：④ 新函数绕过检查（Euler）⑤ 改动过的分叉未重审（Uranium）⑥ 盲签（WazirX、Bybit、TRON 权限诈骗）。
  5. 钥匙与人：⑦ 密钥集中（Ronin、Multichain、Drift）+ 反例 mETH 靠延迟和暂停追回 ⑧ 人是入口（DMM、Radiant、Coinbase 客服）+ NFT 与 GameFi 三处来源。
  6. 写一份复盘：模板 → 练习方法与核对原则 → 两种角色各一件事 → 回答两个问题（成立条件：只能认出旧模式）→ 收束。
- **关键术语**：重入锁、回调、编译器、复盘、分叉、根因、跨链桥、零地址、预言机、健康检查、不变量测试、盲签、delegatecall、验证者、MPC、时间锁、调用树、不变量。
- **成立条件、例外和风险**：比喻不成立处 seg2 L7–L11。解读（灰标签"解读"）：seg1 L9（三起归为同一模式是资料八种模式图的归类，"三种写法"是解读）、seg3 L17、seg6 L7–L13。**只讲机制与防御**：重入只画"先转出、后记账"的顺序和锁，不画利用合约；Nomad、Qubit 只画"零被当成合法值"；Bybit 只画"界面显示 ≠ 实际签下"。
- **不确定之处**：见文末"事实口径"。
