## 1. 概要

- **一句话核心观点**：用户不读合约，用户读页面；页面是一条供应链（开发者电脑、依赖、构建、托管、CDN、域名、第三方脚本）的最后一站，任何一环被攻破，用户就会对着审计过的合约签下攻击交易，而合约审计看不到这些环节。
- **支撑结构**：钩子（Curve 域名对、锁在、合约没变）→ 用户读页面 → 供应链地图 → 逐环案例：DNS（Curve 两次）、依赖（Ledger Connect Kit）、CDN（BadgerDAO）→ 关键洞见：前端可以对每个人说不同的话（Bybit 精准篡改）→ 页面之外的防线 → 回答。
- **关键术语**：前端、供应链、DNS 劫持、注册商锁 / 注册局锁、依赖包投毒、lockfile、SRI、CDN 边缘脚本、CSP、构建产物哈希比对、DELEGATECALL。
- **目标观众**：DApp 开发与运维、多签签名人、审计人员。
- **时长**：6 分 51 秒（411.3 秒，9 个场景，48 个镜头）。

## 3. 叙事结构

1. **钩子**（hook）：2022 年 8 月 curve.fi，域名对、锁在、合约没变，损失约 57 万美元。问题"合约没变，钱怎么没的？"钉在左上角。
2. **铺垫**（idea）：用户读页面，钱包签页面构造的交易；比喻：换掉柜台玻璃上的账号贴纸；比喻不成立处：千里之外即可完成，并且可以只给一个人看。
3. **逐步构建**：
   - chain：原文第 2 节链路图，每个方框都是信任环节；合约审计一个都看不到。
   - dns：攻击者控制注册商账号 → DNS → 克隆页面；锁只说明连上了当前解析到的服务器；2025 年同一家注册商再出事；防线。
   - deps：Ledger Connect Kit：前员工 npm 权限漏回收、3 个恶意版本、DApp 加载 latest。具体数字一步步算：约 40 分钟修复，约 5 小时（300 分钟）清除缓存，300 − 40 ≈ 260 分钟修好后仍在暴露。
   - cdn：BadgerDAO：未授权 API Key → 边缘脚本只对部分用户弹授权 → 约 1.2 亿美元。
4. **关键洞见**（target）：Bybit：被篡改的脚本只对一个多签生效，约 2 分钟后换回；前端可以对每个人说不同的话；同一个网页是多签的单点，加签名人解决不了。
5. **防线**（defend）：线上与构建产物的哈希比对（只覆盖一个时刻一个位置，所以要多点反复比对）、CSP、哈希与访问日志、签名人独立解码。
6. **回顾**（answer）：用户信的是页面，页面是供应链的最后一站；成立条件：签名前在页面之外核对；域名正确 ≠ 页面可信。预告第 21 集。

## 5. 材料的观点与解读者的判断

- **材料的观点**（第 20 章原文）：用户不读合约、读页面，攻击者改页面即可让用户对着审计过的合约签攻击交易；银行贴纸比喻及其局限；第 2 节链路图与"每个方框都是信任环节、合约审计覆盖不到"；DNS 劫持时地址栏检查失效、锁只说明连上了当前解析到的服务器；注册商本身是风险；锁版本、SRI、不加载 latest；CDN 账号是前端的信任根；精准投放与事后换回；所有签名人用同一个网页前端即单点，增加签名人不能解决；哈希比对只覆盖比对时刻与位置；各案例数字。
- **解读者的判断**（视频的取舍，不是原文）：
  - 钩子问题改写为"域名对、锁也在、合约没变，钱怎么没的？"，对应 README 第 4 节"合约没变，页面变了"。
  - "300 − 40 ≈ 260 分钟"由原文"约 40 分钟内发布修复版本"与"约 5 小时后才完全清除"相减得出，两个输入都是约数，原文没有给出这个差值。
  - 柜台贴纸上的账号 `6222 …`、哈希 `0x3fa9…d20c` / `0x91b7…44ea`、时间条比例、6 个观察点中有 2 个看到改写都是示意。
  - BadgerDAO 场景里"8 个用户中 3 个被注入"是示意；原文只说"只对部分用户"。
  - chain 场景用 DNS 节点被攻破来演示"任何一环"，选择哪个节点是示意。
  - Bybit 的入侵链（开发者运行恶意 Docker → AWS 会话令牌 → S3 上的脚本）来自 Safe 的初步报告（项目方说法），画面注明"据 Safe 初步报告"；Sygnia 的判断（S3 / CloudFront 账号或 API Key 很可能泄露）未单独讲。

## 6. 成立条件、例外和风险

- 金额是事发时美元估值约数。Bybit 约 15 亿美元为 FBI 口径，各方估算在 14–15 亿美元之间；视频说"约 15 亿美元"。
- Curve 2022 年事件项目方称"很可能是 DNS 服务商被黑"；2025 年事件是"攻击者进入同一家注册商的系统"。视频把两次都归为"域名这一环"，没有断言第一次的具体入口。
- "锁只说明连上了当前解析到的服务器"的前提是攻击者能通过常见的域名验证方式申请证书（原文开场）；视频没有讲证书透明度监控之外的细节。
- "哈希比对一致"不能完全证明用户拿到的页面没被改：边缘脚本可以只改写部分用户的响应（原文 4.3 节后的思考）。
- 锁版本只能挡住"新版本投毒"；被锁定的版本本身有恶意代码时需要依赖审查（原文 3.2 节局限）。
- 签名人独立解码的前提是解码工具本身独立于被篡改的前端，且签名设备干净（第 18、21 章）。
- 图里没有画浏览器扩展和用户电脑本身（原文第 2 节局限），视频也没有。
