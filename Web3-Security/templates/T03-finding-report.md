# T03 发现与评估报告模板

> 用途：单条发现的格式 + 整份报告的结构。严重度口径见 [A02](../assessment/A02-risk-rating-reporting.md)，可用[评级计算器](../interactive/severity-calculator.html)。

## 一、单条发现

```
ID:            F-01
标题:          （一句话，说明问题而不是现象）
严重度:        严重 / 高 / 中 / 低 / 信息
可能性:        高 / 中 / 低        影响: 高 / 中 / 低
位置:          文件:行号 / 合约地址
类别:          重入 / 权限 / 算术 / 外部调用 / 预言机 / 签名 / 升级 / 经济 / 运营 / 其他

描述:          发生了什么，被打破的假设是什么
影响:          最坏情况下损失什么，谁受影响
触发条件:      需要什么前提（权限、资金、时机）
证据:          代码引用 / 链上读数 / 测试（不得包含可直接利用的攻击代码）
建议:          具体修复建议
状态:          未处理 / 已修复 / 部分修复 / 已接受风险 / 无法复现
验证方式:      已读代码 / 回归测试 / 不变量 / 分叉验证 / 未验证
```

## 二、整份报告结构

1. **摘要**：结论（可上线 / 附条件 / 暂缓 / 否决）、发现统计、三句话风险概述。
2. **范围与版本**：提交哈希、文件、链、评估日期、方法与工时。
3. **架构与信任假设**：角色、权限、依赖。
4. **中心化风险**：特权角色能做什么，是否有时间锁。
5. **发现列表**：按严重度排序，使用上方格式。
6. **签名流程 / 运营安全评估**（A 类必填）。
7. **经济与依赖风险**（B 类必填）。
8. **已接受风险**：每项需业务负责人签字。
9. **范围外说明**：未覆盖的部分，需其他团队跟进的项。
10. **上线条件与监控需求**。
11. **附录**：测试清单、地址、读数、免责声明。

> 报告原则：结论先行；每条发现可复核；剩余风险写清楚；不写无法被证据支持的断言。
