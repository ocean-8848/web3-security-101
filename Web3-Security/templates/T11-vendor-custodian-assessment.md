# T11 第三方、托管商与钱包 / 支付渠道供应商安全评估

> 用途：新引入或年度复核一家供应商（托管商、钱包 / MPC 供应商、支付与法币渠道、外包客服等）时使用。分 8 个域提问，要求证据，设红线，最后评分。
> 配套：[X35 托管机构安全](../arch/X35-custodian-security.md)（机构客户评估托管商）、[X34 钱包供应商安全](../arch/X34-wallet-vendor-security.md)、[X36 支付、OTC 与法币渠道安全](../arch/X36-payment-otc-fiat-security.md)、[X01 安全体系怎么搭](../arch/X01-security-program-controls.md)、[T05 上币尽调问卷](T05-listing-dd-questionnaire.md)、[T06 运营安全自查清单](T06-ops-security-self-check.md)
> 说明：本表是机构评估供应商用的。供应商填"回答"，评估方填"证据核验"与"状态"。

## 使用方法

1. 评估方先填第 1 部分，确定供应商类型和触及资产的级别。
2. 把第 2–9 部分发给供应商。供应商在"回答"栏作答，并附证据文件。
3. 评估方核验证据，在"状态"栏填 ✅ 通过 / ⚠️ 部分通过 / ❌ 未通过 / N/A。**没有证据的回答，按 ❌ 处理。**
4. 标 ★ 的是**红线项**。任一红线项为 ❌，结论为"不可引入"，除非管理层书面接受并登记风险（见 T08 第 4 部分）。
5. 按第 10 部分计分。分数不能替代红线。
6. 证据要求：报告要看范围、期间、例外项，不能只看"已通过"的封面。

## 10. 评分与结论

每项 ✅ 得 2 分、⚠️ 得 1 分、❌ 得 0 分，N/A 不计入分母。

| 域 | 权重（示例，可调整） | 得分 / 满分 | 加权得分 |
|---|---|---|---|
| 1 治理与独立审计 | 10 | | |
| 2 资产隔离与密钥管理 | 25 | | |
| 3 客户策略与访问控制 | 15 | | |
| 4 应用、终端与发布安全 | 15 | | |
| 5 数据保护与隐私 | 10 | | |
| 6 监控、事件响应与通报 | 10 | | |
| 7 财务、保险与持续经营 | 10 | | |
| 8 退出与迁移 | 5 | | |
| 合计 | 100 | | |

加权得分 = 域权重 × 域得分 ÷ 域满分。

| 条件 | 结论 |
|---|---|
| 任一红线 ❌ | 不可引入；或管理层书面接受并登记风险（T08），并约定整改期限 |
| 无红线，总分 ≥ 85 | 可引入 |
| 无红线，总分 70–84 | 附条件引入：列出整改项和期限，期限到期复核 |
| 无红线，总分 < 70 | 不建议引入 |

> 💡 注意：阈值为本模板的示例，按自家风险偏好调整。资产级别为 L1 的供应商，建议提高阈值。
