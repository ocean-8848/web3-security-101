# T12 新系统 / 新业务安全架构评审单

> 用途：新系统、新业务、新链、新渠道上线前，由安全架构评审人与业务负责人共同填写。覆盖信任边界、数据流、控制映射、上线门禁和遗留风险签字。
> 配套：[X07 交易所安全架构总览](../arch/X07-cex-architecture-overview.md)（信任边界、数据流、六个保护域、成熟度）、[X01 安全体系怎么搭](../arch/X01-security-program-controls.md)（控制矩阵）、[X11 钱包、财资与支付渠道](../arch/X11-cex-wallet-treasury-payment.md)、[X05 检测与响应工程](../arch/X05-detection-response-engineering.md)、[X06 韧性与验证](../arch/X06-resilience-validation.md)、[T04 上线门禁清单](T04-go-live-gate.md)（合约类上线）、[T02 威胁模型](T02-threat-model.md)
> 说明：示例行标"示例"，使用时删除。

## 使用方法

1. 设计阶段开始评审。上线前一周才开始的评审，只能作为"补救"。
2. 业务负责人填第 1–3 部分。安全架构评审人填第 4–6 部分。
3. "状态"填 ✅ / ⚠️ / ❌ / N/A。"证据"写可复核的链接：架构图、配置、测试记录。没有证据按 ❌ 处理。
4. 标 ★ 的是**红线项**。任一红线项为 ❌，不得上线，除非走第 7 部分遗留风险签字，且管理层成员批准。
5. 设计变更后，受影响的部分重新评审。上线版本必须与评审版本一致。

## 7. 遗留风险签字

> ⚠️ 警告：遗留风险不是"以后再说"。每条必须有补偿控制、到期日和管理层签字。没有补偿控制的，不得带着上线。

| 风险 ID（对照 T08） | 遗留风险描述 | 关联红线项 | 补偿控制 | 剩余影响（1–5） | 到期日 | 风险所有人 | 管理层批准人 | 签字日期 |
|---|---|---|---|---|---|---|---|---|
| R-101（示例） | 如果渠道方的退款接口被滥用，可能造成重复退款；渠道侧暂无限额 | 6.4 | 我方每日退款上限；每日对账 | 3 | （填，建议不超过 90 天） | （填） | （填） | |
| | | | | | | | | |

签字规则：

1. 红线项带来的遗留风险，必须由管理层成员批准。
2. 风险所有人必须是能决定业务是否继续的人。
3. 到期日必须有对应的整改任务。到期未整改的，自动重新评审。
4. 所有遗留风险同步登记到 T08 第 3、4 部分。
