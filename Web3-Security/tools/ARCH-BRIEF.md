## 1. 目标与读者

- 新增侧栏父级「Web3 安全架构与运营」，共 4 组 24 章，文件在 `Web3-Security/arch/`，文件名 `Xnn-slug.md`，文档 id 为 `xnn`。
- 读者：想做安全工程师、要在交易所 / 公链 / 项目方 / 钱包 / 托管 / 支付等机构里**落地安全体系**的人。
- 深度：由浅入深。读完一章，读者能在真实组织里**第一周就开始动手**：知道该画什么图、查什么清单、写什么规则、配什么告警、跟谁开什么会。
- 与现有章节分工：现有 01–30 章讲"攻击怎样发生、怎样防"；本组讲"一个机构怎样把防御建成体系并持续运营"。不要重写已有内容：需要时写一句摘要并链接到已有章节（`../23-custody-exchange-ops.md` 这样的相对路径写法，见现有章节）。

- 章节数不是硬性：一章只讲一个主题，不拆上下篇。长就长，但要删重复。
- 可以按章节内容合并或调整小节（例如把第 3 节与第 6 节穿插），但这些要素都要有：信任边界图、控制清单、分级落地、运营、失效案例、评估检查点、上手路径、动手练习。

## 4. 质量要求

1. **深度与落地**：每章必须有"可直接用"的东西：至少 3 段配置 / 规则 / 查询 / 脚本 / 流程模板（用围栏代码块，标语言；与真实产品相关的片段写成示意，注明"示例"）。控制清单每项给"怎么验证"。
2. **深浅梯度**：第 1–2 节任何新人能读懂；第 3–6 节给工程细节；第 7–10 节给运营与上手路径。
3. **原创**：本章内容完全原创，自由取舍和重组结构；不复制任何外部文章的措辞，不需要标注"参考某文"。事实性内容（事故、数字、日期、标准条款、监管要求）必须独立查证公开来源。
4. **事故案例**：每个案例单独用 WebSearch / WebFetch 查公开来源（项目方复盘、安全公司分析、官方文档、监管文件、L2BEAT 等）；金额写"约 / 事发时美元估值"；归因写"公开报道归因于"；查不到可靠来源的案例不写。微信公众号链接抓不到，不要依赖。
5. **时效内容**（标准版本、监管条款、产品功能、阈值）写"截至 2026 年公开资料"，并在章首写 `> 最后核对：<今天日期>`；核对不了就写成"以官方最新文档为准"。
6. **数字**：示例数值标"示例"；不要编造统计数字；不要编造产品名、公司内部做法。业界通用做法标"通用做法"，本章推荐写"建议"。
7. **安全边界**：只写机制、检测与防御，不写针对真实系统可直接照做的攻击步骤。
8. **图**：至少 3 张 Mermaid（flowchart / sequenceDiagram / stateDiagram-v2），每张图后写 2–4 行"读图要点"。图内文字短，节点名 ≤ 14 字。
9. **链接**：用相对路径链接已有章节：`[23 托管、充提与合规安全](../23-custody-exchange-ops.md)`（arch/ 下的文件要加 `../`）。链接别的 X 章写 `X07-cex-architecture-overview.md`（同目录）。只链接确实存在的文件。可链接的已有章节：01–30（`../NN-*.md`）、评估篇 `../assessment/A0x-*.md`、模板 `../templates/T0x-*.md`、链专题 `../chains/C0x-*.md`、训练营 `../bootcamp/Bxx-*.md`。链接前 `ls` 确认文件名。
10. **篇幅**：约 9000–15000 个中文字符（含代码和表格）。一章一个主题，不拆。
11. **术语**：沿用现有术语（热钱包、冷钱包、多签、MPC、签名服务、风控引擎、提币 / 提现统一写"提币"）。首次出现的术语给英文和一句定义。

## 5. 动手练习的写法

练习只用笔记本能完成的东西：画架构图、填控制矩阵、写检测规则（用 Sigma / SQL / 伪代码）、读一段日志找异常、做 30 分钟桌面推演、审一份示例配置。**不要**创建需要真实云账号或在线服务的练习。如果某章适合配一个可运行小工具（如规则回放脚本），在章末写"建议配套（后续在 L3 训练营实现）"，不要自己创建 `practice-example-code/` 文件。

## 6. 各章规格（必须覆盖的内容）

### X01 安全体系怎么搭
资产清单与分级（密钥、资金、用户数据、代码、基础设施、品牌渠道）；威胁建模落到控制矩阵（STRIDE 之外的 Web3 增补：签名路径、链上权限、共识外依赖）；"控制"的六种类型（预防、检测、响应、恢复、阻断扩散、证据保全）；纵深防御与"失陷即常态"假设；组织：CISO / 安全负责人汇报线、安全工程、AppSec、SecOps、GRC、合规、风控的分工与 RACI；预算与优先级（P0/P1/P2 判据）；首年路线图（90 天 / 180 天 / 365 天）；风险登记与已接受风险；度量（覆盖率、MTTD、MTTR、红线项）。配套模板：控制矩阵表、风险登记表。

### X02 标准与合规对照
CCSS（CryptoCurrency Security Standard）、ISO/IEC 27001 与 27002、SOC 2（TSC 五项）、NIST CSF 2.0、PCI DSS（涉及卡支付时）、CIS Controls；监管对安全的要求：欧盟 MiCA 与 DORA、美国 NYDFS 500、香港 VATP 指引、新加坡 MAS、迪拜 VARA 等（只写与安全 / 运营韧性直接相关的条款，核对来源）；一张"标准 × 控制域"映射表；怎样用一套控制矩阵同时满足多个标准（一次实施，多次映射）；审计流程与证据准备（证据清单、抽样、常见不符合项）；渗透测试、红队、外部审计的区别与采购；认证路线（先 SOC 2 Type I → Type II / ISO 27001 的取舍）。

### X03 生产基础设施安全
云账号与组织结构（多账号、SCP / 组织策略、最小权限、分环境）；身份：SSO + MFA + 硬件密钥，人员与机器身份分离；特权访问（JIT、堡垒机 / PAM、会话录制、break-glass 流程）；网络分段与零信任；K8s 加固（Pod Security、NetworkPolicy、准入控制、镜像策略、Secret 管理）；机密管理（Vault / KMS / HSM 的角色、轮换、不落盘）；主机与终端（EDR、基线、全盘加密、禁止个人设备）；日志与配置漂移（CSPM、IaC 扫描）；一张"核心签名系统与普通业务系统隔离"的参考图；常见云配置错误清单与检查命令（示例）。

### X04 软件交付与供应链
SDLC 里的安全关口（需求 / 设计评审 → 代码评审 → SAST / SCA / Secret 扫描 → 构建 → 签名 → 发布 → 回滚）；CI/CD 加固（runner 隔离、短期凭证、OIDC、分支保护、必需评审、环境审批）；依赖治理（锁文件、私有镜像、SBOM、版本固定、新依赖评审、typosquatting）；制品签名与来源证明（Sigstore / SLSA 级别）；合约发布门禁（审计、形式化 / 不变量、测试网演练、多签升级、时间锁、发布后监控）；前端发布（SRI、CSP、DNS / 注册商锁、CDN 配置变更审批）；合约与前端、服务、基础设施的"发布权限与签名权限分离"；开发者终端与 npm / PyPI 投毒案例；对应现有章节 `20`、`27`、`B62`。

### X05 检测与响应工程
日志源清单（云、主机、应用、数据库、交易系统、签名服务、链上）；日志标准化与保留期；SIEM 架构与告警分级（P1–P4，含值班升级）；检测工程方法（威胁 → 检测假设 → 规则 → 回放测试 → 上线 → 调优；MITRE ATT&CK 与 Web3 增补）；链上检测（大额流出、授权异常、新合约交互、治理提案异常、预言机偏离、桥消息异常；用 Forta / 自建 indexer 的思路，不依赖具体产品）；链下检测（异常登录、提现异常、API Key 滥用、内部数据导出）；检测规则示例（Sigma 或 SQL，至少 5 条，写清假阳性和调优）；响应：事件分级、指挥体系、通信模板、证据保全、取证流程；SOAR 自动化的边界（哪些动作可自动：暂停提币、冻结账户；哪些必须人工）；值班制度与演练；度量：MTTD / MTTR / 假阳性率 / 覆盖率。

### X06 韧性与验证
业务连续性与灾备（RTO / RPO、热 / 温 / 冷备、多区域、密钥与签名服务的灾备、恢复演练）；"安全暂停开关"设计（分级暂停、谁能按、怎么恢复）；红队 / 紫队 / 渗透测试 / 攻防演练的区别与节奏；桌面推演（脚本、注入、评分，给 3 个可直接复用的剧本：提币异常、签名服务被控、前端被篡改）；混沌与故障注入在 Web3 里的做法（节点故障、RPC 分叉、预言机停更）；安全度量与汇报（给管理层的月报模板，红线项、趋势、未关闭风险）；复盘方法（无责复盘、根因五问、行动项追踪）；保险与责任（网络保险、托管保险的边界，只写通用事实）。

### X07 交易所安全架构总览
一家中心化交易所的系统分区（接入层、账户与身份、撮合与交易、账务与清结算、钱包与资金、风控与反欺诈、数据与分析、办公与研发、第三方与渠道）；六个保护域（客户身份与访问、资产与市场准入、交易结算与信用、钱包财资与支付、生产与数据、反欺诈合规运营）及其关系；信任边界图与数据流图（用户 → 接入 → 账户 → 交易 → 账务 → 钱包 → 链）；"局部失陷不扩散"的设计原则（隔离、最小权限、独立校验、双人 / 多方控制）；攻击面总图：十年事故按保护域归类（引用已有 `28`、`23`、`29`，不重复复盘）；架构成熟度模型（L1–L4）与自评表；X08–X13 导读。

### X08 客户身份、账户与访问
认证（密码、MFA 方式对比、Passkey、设备绑定、风险认证）；账户全生命周期（注册、KYC、登录、找回、冻结、注销）；账户接管攻击路径与对策（凭证填充、钓鱼、SIM 劫持、会话劫持、找回流程社工）；账户找回设计（找回是最大的后门：冷静期、多因素、人工复核的边界）；API Key 管理（权限分级、IP 白名单、提币权限默认关闭、泄露应对、异常调用检测）；子账户与机构账户权限（RBAC、四眼原则、提币白名单与延迟生效）；客服与内部工具的访问控制（客服不能绕过风控）；登录与提币的风控信号；用户侧防护。检测规则与指标（接管率、找回成功率、被盗申诉量）。

### X09 资产与市场准入

### X10 交易、结算与信用
