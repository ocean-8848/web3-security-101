## 1. 概要

- **一句话核心观点**：EVM 是单线程的栈式计算机，合约各有代码和存储，靠消息调用通信，每次调用都可能把控制权交给别人；`msg.sender` 每一跳都在变，`tx.origin` 从头到尾不变，所以权限要看 `msg.sender`。
- **支撑结构**：两类账户 → 政务大厅比喻（及其不成立处：重入）→ 沿 用户 → A → B → C 看四个上下文变量 → call / delegatecall / staticcall 与低级 call 返回 false → 存储槽的打包规则（一步步算 20 + 1 + 12）→ 槽位错位与 private 公开 → 几个易误解的特性。
- **关键术语**（全片同名）：EVM、外部账户、合约账户、消息调用、tx.origin、msg.sender、msg.value、address(this)、call、delegatecall、staticcall、槽位（slot）、打包、代理合约、实现合约、函数选择器。
- **钩子说明**：本章开场是"示例场景"，不是真实事故；视频第一句就说明了这一点，画面左上角也标了"示例场景 · 非真实事故"。

## 3. 叙事结构

1. **钩子**（hook）：示例场景——管理员访问钓鱼页面、调用攻击者合约，攻击者合约调用金库；金库 `require(tx.origin == owner)`，能通过吗？核心问题：一次调用里，谁是 msg.sender？钉在左上角。
2. **铺垫**（machine）：EVM、合约 = 代码 + 存储、两类账户、消息调用交出控制权、EIP-7702。
3. **比喻**（hall）：一个窗口的政务大厅；不成立处：B 中途可以回头找 A —— 重入（下一集）。
4. **逐步构建**：
   - context（关键洞见）：沿 用户 → A → B → C 逐站填表，msg.sender 每一站都在变，tx.origin 不变。
   - calls：call / delegatecall（清空 A 的 0 号抽屉）/ staticcall；低级 call 失败只返回 false。
   - slots：**一步步算**：20 + 1 = 21 放得下，21 + 12 = 33 放不下；改 uint88 后 20 + 1 + 11 = 32，total 挪槽。
   - risk：代理与实现变量顺序不一致；中间插入变量导致错位；private 不保密。
   - traps：转 ETH 会执行代码、余额可被强制转入、block.timestamp、函数选择器碰撞。
5. **回顾**（answer）：msg.sender 是直接调用者（攻击者合约），tx.origin 是管理员，检查能通过；规则：看 msg.sender，不看 tx.origin；前提：分清 call / delegatecall；EIP-7702 的补充。预告 EP04。

## 5. 材料的观点与解读者的判断

- **材料的观点**（第 03 章原文）：开场示例场景与"能通过"的答案；一句话理解；政务大厅比喻及其局限（重入）；两类账户与 EIP-7702 注意；四个调用上下文变量及 A → B → C 表；三种调用方式与低级 call 不回滚；槽位规则与 `Layout` 示例（含 uint88 变体）；存储布局风险表；8 个易误解特性中的 receive/fallback、合约余额、block.timestamp、函数选择器。
- **解读者的判断**（视频的取舍，不是原文）：
  - 槽位画成"从右往左填"（低位先放），这是 Solidity 打包的真实方向，原文没有画方向；字节数、槽号与原文一致。
  - 代理风险的槽位内容（slot 0 实现地址 / slot 1 owner / slot 2 余额 1000）、"0x…03e8"（1000 的十六进制）、`0x5f3c…9a1e`、余额柱 100 → 130、两个"函数签名 甲 / 乙"都是示意。原文只写"实现合约写 owner，实际改写了代理的 implementation""余额被当成地址读取"。EIP-1967 固定槽位没有进视频。
  - delegatecall 的抽屉例子用 `slot0 = 0` 表示"把第 0 号抽屉清空"。
  - msg.value 一行写成"用户转给 A 的 / A 转给 B 的 / B 转给 C 的"，原文表里只给了 C 那一列。

## 6. 成立条件、例外和风险

- "看 msg.sender，不看 tx.origin"的前提：每一跳是 call；delegatecall 会把 msg.sender 原样带到被调用代码里（代理、库合约正是靠这一点）。
- EIP-7702（2025 年 5 月 Pectra 上线）之后，`extcodesize(addr) == 0` 和 `msg.sender == tx.origin` 都不能证明调用者是普通用户；视频说了，原文 2.1 节有详细说明。
- 低级 call 失败只返回 false，这是 Solidity 低级调用的行为；高级调用（直接调用接口函数）失败会冒泡回滚（原文第 5 节），视频没有展开。
- 打包规则：相邻变量"剩余空间能否放下"才打包；常量和 immutable 不占槽；mapping 元素位置是 `keccak256(abi.encode(k, p))`，画面简写为 `keccak256(k, 3)`。
- 函数选择器碰撞是 Poly Network 事故的"关键一步"，完整机制在第 12 章；视频没有展开，也没有给出可用的碰撞签名。
- block.number 的出块时间因链而异（BSC 0.45 秒等），视频没有讲；用区块数算时间的风险留给 C01、C03。
