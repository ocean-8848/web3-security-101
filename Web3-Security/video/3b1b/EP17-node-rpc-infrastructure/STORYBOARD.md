## 1. 概要

- **一句话核心观点**：你的系统从来没有直接读过"链"，它读的是某个节点、RPC、索引器告诉它的链；所以数据源要按运营方多源校验、超时不降级、冲突就暂停。出块一侧，验证者最大的风险是自己的运维（同一把密钥两处签名），MEV relay 是必须信任的中间人。
- **主干**：本章很长，视频以"你读到的是谁的链"为主线：数据路径上的各层失败点 → 多源校验的门槛与降级（关键洞见，一步步算）→ 节点自己被蒙住（日蚀）→ 节点配置事故；再用两个场景讲"谁在签名出块"：罚没与 relay。
- **关键术语**：RPC 节点、索引器、多源校验 / 法定数（k）、降级、运营方独立性、BGP 劫持、日蚀攻击、Engine API / JWT、罚没、防罚没数据（EIP-3076）、分身检测、MEV-Boost relay、构建者、ePBS。
- **时长**：6 分 57 秒（417.1 秒，9 个场景，47 个镜头）。

## 3. 叙事结构

1. **钩子**（hook）：2026-04 LayerZero 验证者的两个 RPC 节点程序被替换，只对验证者返回伪造数据；DDoS 干净 RPC 迫使切换；约 2.9 亿美元；监控看到一切正常。问题"你读到的是谁的链？"钉在左上角。
2. **铺垫**（window）：系统从没直接读过链；窗与屏幕的比方及其局限（没有第二扇窗）。
3. **逐步构建**：
   - layers：数据路径各层的失败点（Infura 2020、单一 RPC、BGP 劫持三案）。
   - quorum（关键洞见）：3 源 2 票的示例；DDoS 掉两个干净源后，自动降级让伪造数据通过；不降级则暂停；独立性按运营方算。
   - eclipse：日蚀攻击；状态看起来正常；研究数字；与不同运营方比对。
   - harden：8545 端口 38,642 ETH；RPC 绑内网、Engine API + JWT；RPC 节点不放私钥。
   - slash：罚没规则；A/B 双签场景；三起罚没；公章比方及其局限；迁移流程。
   - relay：MEV-Boost 的盲签；2023-04 relay 漏洞约 2,000 万美元与修复；构建者集中度；ePBS。
4. **回顾**（answer）：你读到的是告诉你的那个节点的链；监控为何没发现；比对验证者实际收到的数据；五条规则；预告第 18 集。

## 5. 材料的观点与解读者的判断

- **材料的观点**（第 17 章原文）：
  - 开场：2026-04，两个 RPC 节点程序被替换，只对验证者返回伪造数据，DDoS 干净 RPC 迫使切换，约 2.9 亿美元；"先猜再看"：监控查询同样的节点看到真实数据，发现需比对验证者实际收到的结果与不同运营方的数据源。5.2.1 节补充：媒体统计约 2.92 亿美元、LayerZero 声明约 2.9 亿美元。

## 6. 成立条件、例外和风险

- 金额为事发时美元估值约数；LayerZero 事件的责任归属有争议（原文 12 章 4.6 节），视频只讲 RPC 这一环。
- 多源校验只有在数据源来自不同运营方、且不同源不共享同一上游时才有效；超时不降级会带来可用性代价（暂停入账），需要人工确认流程。
- 日蚀攻击的数字来自研究论文，本书未查到公开归因于日蚀并造成资金损失的案例；它的防线与 RPC 多源校验相同。
- 分身检测在 A 观察期内恰好没有活动、或 B 未开启检测时挡不住双签，只能是最后一道防线。
- 构建者与 relay 份额是 2026 年 11 月 8 日的单日快照，波动很大，只用于说明集中程度。
- ePBS 的上线时间未定；在它上线前，提议者仍须信任 relay 发布完整区块并付款。
- 用户侧：钱包默认 RPC 是第三方服务，余额显示异常时换一个 RPC 或浏览器交叉确认（原文第 7 节），视频未展开。
