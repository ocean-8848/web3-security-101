## 场景 1：开场

**画面标题**：只锁了保险柜， 没锁保险柜所在的房间（逐步动画）

**[1.0]** 大家好，欢迎来到评估篇第6集，运营与密钥安全。合约审计覆盖的是，代码会不会出错。但近年最大的损失，几乎都不在代码里。

**[1.1]** 以下据公开报道。2025年，Bybit 损失约14.6亿美元，签名流程被攻破。

**[1.2]** 2024年，日本交易所 DMM Bitcoin 损失约3.05亿美元。入口是一次假招聘，员工的电脑被控制了。

**[1.3]** 2021年，DeFi 协议 BadgerDAO 损失约1.2亿美元，前端网页被注入了恶意脚本。评估不覆盖链下，等于只锁了保险柜，没锁保险柜所在的房间。

## 场景 2：保险柜与整栋楼

**画面标题**：合约是保险柜，运营安全是整栋楼（逐步动画）

**[2.0]** 打个比方。合约是保险柜，用最好的钢材做的，也审计过了。运营安全是保险柜所在的整栋楼。保安被收买，对应私钥和签名出问题。门禁系统被改，对应前端被注入。

**[2.1]** 送货通道被人掉包，对应依赖库和供应链被投毒。保洁被冒充，对应社会工程。这些情况发生时，保险柜再硬也没用。

**[2.2]** 比喻不准的地方在于，楼里出了事，还有保险公司理赔，有警察追回。链上资产一旦被转走，多数情况下追不回来。

## 场景 3：四类链下根因

**画面标题**：社会工程常常是入口（逐步动画）

**[3.0]** 链下根因可以分四类。第一类是私钥与签名，包括多签签名流程被攻破，以及签名终端和基础设施被入侵。

**[3.1]** 第二类是前端与供应链。前端被注入恶意脚本，依赖库被投毒，还有域名被劫持。

**[3.2]** 第三类是部署与运维，部署和升级的流水线被污染，持续集成的密钥泄露。第四类是社会工程，假招聘、假承包商、钓鱼邮件。

**[3.3]** 四类常常组合出现。社会工程是入口，导致私钥、终端或者流水线被攻破。公开报道多指向有国家背景的长期团队。所以评估要按对方会渗透几个月来设防。

## 场景 4：四种密钥方案

**画面标题**：每种方案，都有要评估的风险（逐步动画）

**[4.0]** 先看私钥与签名。常见的密钥方案有四种。单签的个人地址只有一把私钥，简单，但是单点，绝不能用于金库。

**[4.1]** 多签合约是链上的 M 选 N，成熟透明。要评估签名流程、module 这样的扩展点，以及合约能否被升级。

**[4.2]** MPC 是多方计算，私钥被拆成分片，多方协同签名，完整私钥从不出现。链上看起来是一个普通的单签地址。要评估分片放在哪里，实现方是否可信，以及审批流程。

**[4.3]** HSM 是硬件安全模块，私钥在硬件内保管并签名，不出硬件。要评估的是，谁能让它签名，访问控制和物理安全怎样。

## 场景 5：MPC 与 HSM 没解决什么

**画面标题**：私钥不落地 ≠ 签的东西是对的（逐步动画）

**[5.0]** MPC 和 HSM 解决的是，私钥不以完整形态落地。它们没有解决两个问题，谁来授权签名，签的到底是什么。

**[5.1]** 来看一个示例。一个 MPC 方案，3个分片，任意2片就能签名。分片 A 和 B 放在两台服务器上，分片 C 在一名员工的手机里。看起来，攻击者要攻破两个地方。

**[5.2]** 但 A 和 B 两台服务器，都听同一个审批服务的指令。审批服务说签，它们就签。

**[5.3]** 攻击者只要攻破这个审批服务，就同时驱动了 A 和 B，满足了2片的门槛。名义上是3选2，实际上是一个单点。

**[5.4]** Bybit、WazirX、Radiant 的问题，都不是私钥被直接偷走，而是合法的签名人被骗着授权了恶意交易。所以上一集的签名流程评估，对任何密钥方案都适用。

## 场景 6：私钥与签名评估清单

**画面标题**：六个问题（逐步动画）

**[6.0]** 私钥与签名的评估清单有六个问题。签名人是否独立，实际有几方在控制。签名终端是不是专机专用，能不能收文件、装软件、上网。

**[6.1]** 签名人看到的和签的是否一致，有没有用独立工具核对。升级、换签名人、委托调用这些高危操作，有没有额外审批和带外确认。

**[6.2]** 大额转出有没有时间锁，单位时间的提币有没有上限和告警。最后一项常被忽略，密钥和权限的轮换与撤销。员工离职或换岗后，权限有没有及时撤销。后面会看到，一个没撤销的账号，就足以引发一次供应链攻击。

## 场景 7：前端与供应链评估

**画面标题**：前端被攻破，用户直接授权给攻击者（逐步动画）

**[7.0]** 合约再安全，用户也是通过前端交互的。前端被攻破，用户就会直接把授权给攻击者。评估清单的前两项，前端托管，谁能修改线上代码，CDN 和托管平台的访问控制怎样。依赖锁定，npm 库有没有锁定到具体版本，是不是从第三方 CDN 动态加载最新版。

**[7.1]** 第三项，子资源完整性。页面引用外部脚本时，写上这个脚本内容的哈希值。浏览器下载后先算哈希。

**[7.2]** 如果有人在 CDN 上把脚本换掉了，哪怕只改了一个字符，哈希就对不上，浏览器拒绝执行。这样，托管方被入侵，也注入不了恶意代码。

**[7.3]** 第四项，域名和监控。域名注册商账户要有强保护，DNS 记录的变更要审批。还要监控异常授权，比如大量用户突然授权给同一个陌生地址。

## 场景 8：案例：两种供应链攻击

**画面标题**：一个改了网页，一个改了依赖库（逐步动画）

**[8.0]** 来看两种供应链攻击，以下据公开报道。先看 BadgerDAO，2021年12月。攻击者获取了前端托管服务账户的 API 密钥。

**[8.1]** 他们用这个密钥向前端注入了恶意脚本。用户打开网站，正常操作时，会被诱导给攻击者的地址一个无限授权。

**[8.2]** 大约500个钱包中招，损失约1.2亿美元。对应的评估项，是前端托管的访问控制，钱包授权时的清晰展示，以及授权激增的告警。

**[8.3]** 再看 Ledger Connect Kit，2023年12月。这是一个很多 DeFi 网站都在用的钱包连接库。一名前员工的 npm 账户被钓鱼。问题是，他离职后，这个账户的发布权限并没有撤销。

**[8.4]** 攻击者用它发布了1.1.5到1.1.7三个恶意版本。凡是动态加载最新版的网站，都把盗币脚本带给了自己的用户。

**[8.5]** 直接损失约60万美元，不算大，但波及面极广。对应的评估项，依赖锁定版本，离职权限撤销，以及子资源完整性校验。

## 场景 9：部署与运维

**画面标题**：流水线也是攻击面（逐步动画）

**[9.0]** 第三类根因是部署与运维。第一，部署要用经过评审的脚本，部署和初始化要在同一笔交易里完成，不给别人抢先初始化的机会。

**[9.1]** 第二，部署后验证。在浏览器上验证源码，逐项读取关键参数核对，确认权限已经移交给多签。

**[9.2]** 第三，持续集成的密钥。部署私钥和 API 密钥绝不能进代码库，要用密钥管理服务，并且给最小权限。

**[9.3]** 第四，升级要经过时间锁，公开，部署后跑验证脚本，并保留回滚方案。第五，任何链上变更都要有审批、有记录、可以追溯。

## 场景 10：社会工程

**画面标题**：人仍是最软的一环（逐步动画）

**[10.0]** 第四类根因是社会工程。技术防御再强，人仍是最软的一环。先看 DMM Bitcoin，以下据公开报道。攻击者冒充招聘者，在职业社交平台上接触了 DMM 的钱包服务商的一名员工。

**[10.1]** 对方被诱导运行了一段所谓入职测试的代码。他的电脑因此被控制，攻击者进而操纵了交易请求，损失约3.05亿美元。

**[10.2]** 再看 Radiant。攻击者冒充一名前承包商，在即时通讯软件里发来一份看似正常的报告文件。文件里带着木马，开发者的电脑中招。

**[10.3]** 这份文件还被转发给了同事，扩散到多个签名人。注意这个细节。攻击者不需要逐个攻破签名人，只要让他们彼此信任地转发一份文件。

## 场景 11：社会工程评估与权重

**画面标题**：让"一个人被攻破"不足以造成损失（逐步动画）

**[11.0]** 社会工程的评估要点有四个。团队，尤其是开发和签名人员，有没有反社会工程的培训。有没有硬性规定，签名和部署用的电脑上，不打开任何外部文件、链接，不运行外部代码。

**[11.1]** 招聘、承包和合作流程，有没有身份核验。高危操作是否要求多人和带外确认。目标是，单个人被攻破，不足以造成损失。

**[11.2]** 运营安全在三类对象里的权重不同。交易所自有合约和钱包最高，签名流程和密钥管理是第一重点。自研协议要看部署、升级权限、前端和监控。上币尽调通过问卷了解，深度合作时要提高权重。很多项超出了合约评估的传统边界，但报告要明确列出需要安全团队跟进的项，而不是写一句不在范围内就略过。

## 场景 12：练一练

**画面标题**：前端从第三方 CDN 加载一个钱包连接库（逐步动画）

**[12.0]** 来练一练。你的前端从第三方 CDN 加载一个钱包连接库。请列出至少三个降低供应链风险的措施。可以先暂停想一想。

**[12.1]** 参考答案。第一，锁定版本，不加载最新版，把库随自己的构建一起发布。第二，加上子资源完整性校验，脚本被篡改就不执行。

**[12.2]** 第三，自托管，把库放进自己的域名和构建流程，减少对第三方的依赖。第四，前端完整性监控，加上授权激增的告警。Ledger 那次事件里，恶意代码正是通过动态加载最新版传播的。前三条做到任何一条，都能挡住这类攻击的大部分路径。

## 场景 13：小结与预告

**画面标题**：记住三件事（逐步动画）

**[13.0]** 小结三点。第一，最大的损失在链下，四类根因是私钥签名、前端供应链、部署运维和社会工程。

> 画面：最大的损失在链下：私钥签名、前端供应链、部署运维、社会工程。

**[13.1]** 第二，MPC 和 HSM 让私钥不落地，但没有解决谁来授权、签的是什么。签名流程评估对任何方案都适用。

> 画面：MPC 和 HSM 让私钥不落地，但没解决谁授权、签的是什么。

**[13.2]** 第三，锁定依赖、子资源完整性校验、离职即撤权。目标是让一个人被攻破，不足以造成损失。

> 画面：锁定依赖、SRI、离职即撤权；让一个人被攻破不足以造成损失。
