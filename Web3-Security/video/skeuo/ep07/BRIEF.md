## 1. 本集骨架

- **一句话核心观点**：每一个外部调用都是把命运交给别人；对方可能失败、撒谎、拖延，甚至根本不存在。外部调用的返回只是对方的说法，要证明钱到了，就核对余额的变化。
- **支撑结构**：
  1. 钩子：Qubit 跨链桥（2022 年 1 月）没收到 ETH 却铸出 qXETH；猜题"call 一个无代码地址返回 true 还是 false"。
  2. 低级调用四个陷阱：不查返回值、目标无代码、返回数据炸弹、gas 不足型失败；快递比喻和它不成立的地方；Qubit 五步根因（零地址 + 兼容妥协 + 缺原生币检查）。
  3. 非标准代币：八种行为一览；TRON USDT 成功返回 false → 推送回滚、用余额差修复；收税代币按参数记账 → 资不抵债，按实收记账 + 重入锁；没有库能防住所有怪代币。
  4. 外部调用导致的 DoS：拍卖退款被拒收合约卡死 → 拉取式支付；无界循环、冻结地址卡住批量、强制余额等式、TRON 80 毫秒 CPU 上限；Akutars 案例。
  5. 授权：approve 竞态（100 改 50 → 150）及缓解；无限授权；钓鱼签名；任意调用 + 授权；Sushi RouteProcessor2；今天能做的事 + 回答开头。
- **关键术语**：外部调用、低级调用（`call` / `delegatecall` / `staticcall`）、返回值、无代码地址 / 零地址、返回数据炸弹、gas 不足型失败、`SafeERC20` / `safeTransfer` / `safeTransferFrom`、非标准代币、收税代币（Fee-on-transfer）、变基代币（Rebasing）、黑名单 / 冻结、可暂停、转账钩子（ERC-777）、可升级、余额差、按实收记账、拒绝服务（DoS）、推送 vs 拉取式支付、无界循环、`approve` / allowance、approve 竞态、`safeDecreaseAllowance`、`forceApprove`、无限授权、`permit`、任意 calldata、回调校验。
- **成立条件、例外与风险**：
  - "call 无代码地址返回成功"只对低级调用成立；高级调用（按接口调）会在调用前检查代码。讲稿只讲低级调用，画面不要泛化。
  - 余额差方案假设代币不收转账手续费；Tether 在 TRON 上保留了开启手续费的能力（seg3 L18）。
  - TRON USDT 只影响推送方向（`transfer`）；拉取方向 `transferFrom` 不受影响。
  - 按实收记账要配合重入锁，否则回调能扭曲前后两次读数。
  - 拉取式支付不是没有代价：收款人要自己来取（seg4 只说"收款人自己来取"）。
  - `forceApprove` 只解决 USDT 类代币要先归零的兼容问题，不解决竞态。
  - 快递比喻在一处不成立：快递员一次只出一种错，外部合约可以同时撒谎、回调、耗尽 gas（seg2 L15–L16 已说）。
- **不确定之处 / 口径**（屏幕上用灰标签标出）：
  - Qubit 约 8000 万美元 = 公开报道；五步根因 = SlowMist 公开分析（第三方分析）。
  - TRON USDT 成功返回 false = OpenZeppelin 2026 年对 Across 协议 TRON 部署的审计报告（第三方审计）。
  - Akutars"超过 11539 个 ETH 被永久锁定""直接原因是第二个缺陷" = BlockSec 分析（第三方分析）。原始数字是 11539.5 ETH，画面可写"11539.5 ETH"。
  - Sushi 约 330 万美元 = 公开分析（第三方分析）。
  - 存 100 实收 98（2% 税）、Alice/Bob 100 改 50、100 个包裹 = 示例，挂灰标签"示例"。
  - seg5b L9–L11 属于解读，挂灰标签"解读"。
  - 只讲机制，不画真实攻击交易、地址、哈希；Qubit 的"资源 ID"只画成一张卡片，不写真实值。

## 2. 世界与主角（全片固定）

一个连续的等距世界，叫"**收发站**"：我们的合约在中心，对外发出的每一次调用都是一根管道，通向别人的机器。从左到右：

1. **中心·我们的合约**（全片主角）：ep01 `vending`（招牌 "OUR CONTRACT"，只是质感；要读的字用 `wlab`"我们的合约"）。它 +u 侧摆一张**发货登记台**（新补 `dispatchDesk`），台上一本 kit `ledgerBook` = "登记簿"，每次外部调用回来都在这里落一笔。登记台旁边站一个**快递员**（kit `person` engineer）推着包裹（新补 `parcel`），只在比喻镜头出现。
2. **左区·调用码头**（seg1、seg2）：从售货机伸出四根 ep01 `pipe`，分别通往：
   - 一台正常的 ep01 `miniVend`（token）；
   - 一块**荒地**（新补 `emptyLot`）= 无代码地址 / 零地址；
   - 一台吐出巨量纸带的 ep03 `contractMachine`（返回数据炸弹，纸带用 ep04 `punchCard` tape 款）；
   - 一台带 ep03 `gasGauge` 的 miniVend（gas 不足）。
   每根管子的回程口都吐出一张**回执签**（新补 `returnTag`）：绿"true"、红"false"、或灰"空"。
3. **中区·代币陈列架**（seg3）：一排八枚**怪代币**（新补 `oddCoin`，立在小底座上的大硬币，每枚币面一个拟物图标），下面一台**到账台秤**（新补 `scale`）读前后余额；收税用一个**过路收费夹**（新补 `tollClip`）夹在管子上剪走一小截金币。
4. **右区·拍卖场与分发线**（seg4）：一座**拍卖台**（新补 `auctionStand`）；ep04 `pickupLocker`（拉取式支付）；ep01 `sorter` 当批量分发线；ep05 `iceShell` 冻住一个收件人；ep03 `gasGauge` 和 kit `hourglass`（TRON 80 毫秒）。
5. **远景·跨链桥与路由**（seg1、seg2 Qubit；seg5a Sushi）：ep01 `bridge` 两岸，左岸 kit `chain`"以太坊"，右岸 kit `chain`"BNB Chain"；右岸一台 ep03 `contractMachine`"借贷池"。Sushi 用一台 ep03 `contractMachine`"路由"，背后一排用户钱包（kit `hotWallet` 缩小）用 ep05 `keycard`（授权卡）插在路由上。

开场镜头在远景跨链桥（Qubit），结尾回到跨链桥，形成闭环。

## 4. 各段分镜（按句写；句号见 timing.json 的 lines，从 0 开始）

### seg1 ① 没收到的钱（56.7 秒）
目标：观众能说出"Qubit 桥没收到 ETH 却记了一笔存款"，以及"低级 call 一个没有代码的地址，返回 true 且返回数据为空"。
- L0 Qubit 出事：镜头在远景跨链桥，ep01 `bridge` 横跨河面；事件卡"2022 年 1 月 · Qubit 跨链桥"。
- L1 以太坊没收到 ETH：左岸 kit `chain`"以太坊"，桥头一台合约机器"桥 · 以太坊侧"，它的金库口打开，里面空空的；标签"ETH 没到"（红）。
- L2 BNB Chain 铸出 qXETH：右岸 kit `chain`"BNB Chain"，对岸合约机器出件槽一枚接一枚吐出青蓝凭证币（标"qXETH"），越吐越多。
- L3 约 8000 万：事件卡加大字"约 8000 万美元"，灰标签"公开报道"。
- L4 相信了外部调用：从以太坊侧机器伸出一根 ep01 `pipe`，回程口弹出一张回执签（`returnTag`，灰"空"），旁边一个绿勾被盖上——**本段关键画面之一**：一张空白回执被打上"成功"。
- L5 猜题：画面清场到收发站左区，主角"我们的合约"（ep01 `vending`）亮相，标签"我们的合约"。
- L6 call 无代码地址：一根管子从售货机伸向荒地（`emptyLot`），管子上标"低级 call"；荒地门牌空白，地基虚线淡淡亮起。
- L7 true 还是 false：回程口上方两个空卡位并排"true ?"、"false ?"，管内流动虚线推进。
- L8 true，返回数据空：回执签弹出，状态 `ok`"true"；下方紧跟一个空白数据盒（灰虚线框"返回数据：空"）。
