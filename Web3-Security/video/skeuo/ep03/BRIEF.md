## 1. 本集骨架

- **一句话核心观点**：EVM 是一台单线程的栈式计算机，每个合约有自己的代码和存储；合约之间靠消息调用通信，每次调用都可能把控制权交给别人。看懂"谁在调用、改的是谁的存储、失败时谁回滚"，才看得懂后面所有漏洞。
- **支撑结构**：
  1. 钩子：`tx.origin` 鉴权被钓鱼合约借用身份（手册开场的示例场景）。
  2. 账户与调用上下文：两类账户 + EIP-7702 带来的变化；四个上下文变量；call / delegatecall / staticcall。
  3. 存储布局：五条槽位规则 + 打包例子；四个存储布局安全场景；EIP-1967。
  4. 八个易误解特性 + storage/memory。
  5. Gas 与回滚、编译器版本；回到核心观点。
- **关键术语**：EOA、合约账户、`tx.origin`、`msg.sender`、`msg.value`、`address(this)`、call、delegatecall、staticcall、存储槽（slot）、打包、mapping、动态数组、函数选择器、回滚（revert）、冒泡、调用帧、瞬态存储。
- **成立条件、例外与风险**：
  - "合约账户不能主动发起交易"在 EIP-7702 之后有例外：EOA 委托后可以有代码，所以查代码大小或比较 `msg.sender == tx.origin` 不再可靠。
  - 打包规则按"剩余空间能否放下"判断；`constant`、`immutable` 不占槽。
  - selfdestruct 的 EIP-6780 只在已启用该规则的链上生效。
  - 低级 call 失败不冒泡，只返回 false；`try/catch` 接不住本合约内部失败，目标无代码或解码失败时也接不住。
  - `transfer`/`send` 的 2300 gas 写法在 gas 调整后会让合约钱包收款失败。
  - 比喻（政务大厅）在"重入"处不成立，讲稿已说明。
- **不确定之处 / 口径**：
  - 开场是手册的**示例场景**，不是真实事件，屏幕挂灰标签"示例"。
  - Poly Network（2021 年 8 月，约 6.1 亿美元）用手册第 12 章 4.3 节的口径，屏幕标"手册第 12 章复盘"。
  - BSC 0.45 秒（2026 年 1 月 Fermi）、Pectra 2025 年 5 月、Cancun 2024 年都是手册写的版本信息，链上参数会变，标"截至手册核对日"。
  - seg5a 最后两句、seg5b 的"金库问错了问题"属于解读，屏幕可加灰标签"解读"。

## 2. 世界与主角（全片固定）

一个连续的等距世界，从左到右：

1. **左区·用户侧**：管理员（`person` signer）+ 笔记本（`laptop`），屏幕可换成钓鱼页（`browserWin` 改红色版"领空投"）。
2. **中区·调用链大道**：一条路上依次排开三台**合约机器**（A、B、C），每台机器背后是它自己的**存储抽屉柜**。消息调用 = 一只信封（`envelope`，信封上贴"calldata"）沿路从一台机器送到下一台。
3. **金库**：中区的 C 位置在 seg1 是"金库"：`safe` 前面加一个关卡（`checkpoint`），岗亭门牌写"权限检查"。
4. **右区·链上**：`chain` 区块链，seg2 讲 EIP-7702 时用。
5. 远景：seg3 推到某台机器背后的抽屉柜特写；seg4 在大道旁立八块告示牌；seg5a 在机器旁加 gas 油表和"调用帧"堆叠。

## 4. 各段分镜（按句写；句号见 timing.json 的 lines，从 0 开始）

### seg1 ① 借来的身份（56.2 秒）
目标：观众能说出"`tx.origin` 是整笔交易的发起人，中间隔几层合约都不变，所以拿它鉴权会被钓鱼合约借用身份"。
- L0 示例场景：镜头在左区；管理员人物 + 笔记本，灰标签"示例场景"挂在左上角直到 L5。
- L1 钓鱼页面：笔记本屏幕换成红色描边的浏览器页"领取空投"（`KIT.swap` 换屏）。
- L2 以为领空投、实际调用攻击者合约：管理员点按钮，一只信封从笔记本飞出，落进一台**红色合约机器**（攻击者合约），机器齿轮转起来。标签"攻击者合约"（lab-rs）。
- L3 紧接着调用金库：红色机器吐出第二只信封，沿大道飞向金库（保险柜 + 关卡）。镜头跟随右移。
- L4 只有一句检查：代码卡 A 从右上滑入（避开胶囊），`require(tx.origin == owner)` 这一行与关卡岗亭之间画红色虚线。岗亭门牌"权限检查"。
- L5 能通过吗：道闸停在落下状态，岗亭上方一个大问号（墨色），停留到 L6。
- L6 能：道闸抬起（`KIT.arm` up），岗亭亮绿灯——注意这里的绿是"检查通过"的字面意义，但信封是红色的，矛盾感就是钩子。
- L7 tx.origin 是发起整笔交易的外部账户：从信封上拉出一张"身份卡"标签"tx.origin = 管理员"，一条青蓝虚线从金库一路回指到最左边的管理员。
- L8 中间经过多少合约都不变：在管理员和金库之间再插两台灰色合约机器（共三台），信封依次穿过；"tx.origin = 管理员"卡片一直不变，每穿过一台就闪一下。
- L9 没偷私钥、借用身份：管理员身边一把钥匙（`key`）+ 挂锁，钥匙仍在、绿勾；红色机器上方弹出标签"借用身份"（lab-r）。**本段关键画面**：钥匙完好 vs 道闸被红信封通过。
- L10 先看懂这台机器 EVM：镜头拉远，整片大道被一个淡青蓝的大框罩住，框角标"EVM"。
- L11 三件事：三个青蓝标签沿大道依次弹出："谁在调用"（贴在信封上）、"数据存在哪"（贴在一个抽屉柜上，柜子此刻从金库背后长出）、"语言里的坑"（贴在路边一块空告示牌上）。段尾静止。

### seg2 ② 调用上下文（166.6 秒）
目标：观众能说出两类账户的区别和 EIP-7702 的影响；在 A→B→C 中指出 C 看到的四个变量；分清 call、delegatecall、staticcall 各改谁的存储。
- L0 定义：大道上三台合约机器 A、B、C 从地面长出，每台背后长出自己的抽屉柜；机器上铭牌"代码"，柜子上铭牌"存储"。屏幕关键词："单线程 · 栈式"。
- L1 消息调用、控制权交出：一只信封从 A 飞到 B，A 的齿轮停转、B 的齿轮转起——同一时刻只有一台在转（单线程）。标签"控制权 → B"。
- L2 两类账户：镜头左移到用户侧，人物 + 笔记本（EOA）与一台合约机器并排。
- L3 EOA：人物上方标签"EOA · 私钥控制 · 能发起交易"，手里一把钥匙。
- L4 合约账户：机器上方标签"合约账户 · 代码控制 · 只能被调用"，机器的投信口亮起（只能被动接收）。
- L5 EIP-7702：右区区块链上一个块亮起，标签"Pectra · 2025 年 5 月 · EIP-7702"；人物（EOA）背后长出一台小号合约机器，用青蓝虚线连着人物，标签"委托执行合约代码"。
- L6 不能再判断普通用户：两个检测器（放大镜）分别对准人物："有没有代码？""msg.sender == tx.origin？"，两个结果都变成红叉 + 标签"不可靠"。
- L7 A→B→C：回到大道；用户 → A → B → C，信封接力，路面上画出三段箭头。
- L8 站在 C 的位置：镜头推近 C，C 的机器正面出现一块四行仪表板（像加油站的计价表），四行先空着。
- L9 tx.origin：第一行亮起"tx.origin = 用户"，一条细线连回最左边的用户。
- L10 msg.sender：第二行"msg.sender = B"，细线连回 B。
- L11 msg.value：第三行"msg.value = B 转来的数量"，B 到 C 的路上信封旁边有几枚硬币（点阵，示意）。
- L12 address(this)：第四行"address(this) = C"，C 自身轮廓描一圈青蓝。
- L13 金库该看 msg.sender：仪表板上 msg.sender 那一行变绿勾，tx.origin 那一行变灰并标"不用于鉴权"。小窗回放 seg1 的关卡：门牌下方的读数从 tx.origin 换成 msg.sender，红信封被道闸拦下。
- L14 三种方式：A、B 两台机器之间出现三条平行轨道，分别标 call / delegatecall / staticcall，代码卡 C 滑入。
- L15 call：信封走第一条轨道，B 的齿轮转，**B 的**抽屉柜某个抽屉被拉出写入（亮青蓝）。卡 C 第一行连虚线到 B 的柜子。
- L16 delegatecall：B 的规程手册（蓝皮手册）沿第二条轨道**飞到 A 这边**；A 的齿轮按手册转，**A 的**抽屉柜被拉出写入。卡 C 第二行连虚线到 A 的柜子。**本段关键画面**：手册是 B 的，被改的柜子是 A 的。
- L17 msg.sender、msg.value 不变；代理和库依赖它：A 的仪表板上 msg.sender、msg.value 两行保持原值并各打一个小锁图标；旁边弹出两个标签"代理合约""库合约"。
- L18 比喻·政务大厅：画面淡入一层比喻：三台机器上方各套一个"科室"门牌，大道前方只有一个窗口（柜台），标签"比喻"（灰）。
- L19 call 是去 B 的窗口办事：一个小人拿着材料走到 B 的窗口。
- L20 delegatecall 借手册：小人从 B 那里拿回一本手册，走回 A，在 A 的档案柜前翻开照做。
- L21 清空 0 号抽屉：手册翻开的一页写"清空 0 号抽屉"；A 的 0 号抽屉被拉出、里面的格子清空（变成空格，红色闪一下），B 的 0 号抽屉完好。
- L22 比喻不成立：比喻层上盖一个灰色印"比喻在这里不成立"，窗口前的队伍画一条"不能插队"的隔离带。
- L23 重入：B 办到一半（B 的齿轮转到一半停住），一只信封从 B 反向飞回 A；A 的上一件事还挂着（A 头顶一个未完成的进度条，停在一半），A 同时又被调用。标签"重入"（lab-rs）。比喻层淡出，回到准确的机器画面。
- L24 staticcall：信封走第三条轨道，B 的抽屉柜外罩上一层玻璃罩（只读），B 试图拉抽屉 → 红叉，整个调用回滚（信封退回）。
- L25 低级 call 失败只返回 false：A 调 B 失败，B 那边红叉；回到 A 的只是一张小纸条"false"，A 的齿轮照常转——卡 C 第三行连虚线到纸条。标签"不自动回滚"。段尾静止。

### seg3 ③ 存储槽（142.7 秒）
目标：观众能用打包规则算出例子里 `total` 在 2 号槽、改成 88 位后在 1 号槽；说出 mapping 和动态数组的位置规则；举出两个存储布局造成的漏洞。
- L0 数据存在哪：镜头从 seg2 结尾推到 A 背后的抽屉柜，柜子占画面左半。
- L1 巨大键值表、32 字节、槽位：柜子往上无限延伸（顶部淡出，暗示"巨大"）；每个抽屉编号牌亮起；标签"键 = 槽位""值 = 32 字节"。
- L2 抽屉柜比喻：拉出 0 号抽屉，里面露出 32 个小格（一排点阵，每格 = 1 字节），标签"32 格 = 32 字节"。
- L3 规则一·按声明顺序：右侧代码卡 B 滑入（先只显示前四行），四行代码依次亮起，对应的字节块排队站在柜子前。
- L4 规则二·打包：屏幕关键词"相邻 · 合计 ≤ 32 字节 → 同一槽"。
- L5 owner 20 字节进 0 号槽：20 格长的青蓝块滑进 0 号抽屉，占 20 格；卡 B 第 1 行虚线连到这个块。
- L6 paused 1 字节挤进：1 格绿块挤进 0 号抽屉，剩 11 格空。
- L7 fee 12 字节放不下：12 格墨色块试图挤进 0 号抽屉，超出 1 格，超出部分红色闪烁，大号算式"20 + 1 + 12 = 33 > 32"。
- L8 fee 去 1 号、total 去 2 号：fee 块弹回、滑进 1 号抽屉；total 32 格灰块整块进 2 号抽屉。卡 B 注释同步。
- L9 改成 88 位：卡 B 的 `uint96` 被划掉改成 `uint88`；fee 块缩成 11 格，滑回 0 号抽屉，正好填满（0 号抽屉亮绿边，"20 + 1 + 11 = 32"）。
- L10 total 挪到 1 号；代理升级会错位：total 块从 2 号抽屉滑到 1 号抽屉。**本段关键画面**：并排显示"旧布局 / 新布局"两列抽屉，total 的位置差一格，用红色虚线箭头连起来，标签"升级后全部错位"。
- L11 规则三·mapping：3 号抽屉拉出是空的（标签"mapping 本身 · 空"）；哈希漏斗出现，投入"键 k"和"槽号 3"两张卡，吐出一张卡飞向柜子很远处的一个抽屉（镜头沿柜子快速上摇），标签"keccak256(k, 3)"。
- L12 规则四·动态数组：另一个抽屉里写"长度"；漏斗投入槽号，吐出起点，后面连续几个抽屉依次亮起（i = 0, 1, 2）。
- L13 规则五·常量不占槽：两个块"constant""immutable"走到柜子前，被一道细线拦下，转身贴到合约机器上（写在代码里），标签"不占槽"。
- L14 四个场景：镜头拉远，柜子旁边立起四块小告示牌（编号 1–4，暂时空白），画面关键词"存储布局 = 漏洞的藏身处"。
- L15 场景一·代理与实现顺序不一致：左边代理机器的柜子 0 号抽屉写"implementation"，右边实现合约的手册写"0 号 = owner"；delegatecall 把手册借到代理这边，写 owner 的动作落在代理的 0 号抽屉，"implementation"被覆盖变红。标签"手册第 10 章"。
- L16 场景二·中间插入新变量：一个新块挤进柜子中间，后面的块全部下移一格，一个"余额"块落进标着"地址"的格子，变红、标签"余额被当成地址读"。
- L17 场景三·private 存密码：一个抽屉上贴"private"小锁贴纸，但柜子正面是玻璃的，一个人物用放大镜（RPC 节点旁边）从外面直接读出抽屉里的"密码"字样。标签"存储完全公开"。
- L18 场景四·delegatecall 不受信任的合约：一台红色合约机器的手册被借到你的机器上，手册翻开后你的柜子所有抽屉同时被拉出、乱翻；最后机器上出现红色"自毁"警示。
- L19 EIP-1967：哈希漏斗投入一张写着长字符串的卡（只写"eip1967.proxy.implementation"），吐出一个远在柜子高处的抽屉编号（显示成截断的"0x3608…bbc"），这个抽屉贴青蓝标签"实现地址槽 · 固定"，与下方 0、1、2 号抽屉隔着很远——"不冲突"。段尾静止。

### seg4 ④ 八个误解（161.2 秒）
目标：观众能对八个特性各说出一句"事实"；记住 private 不保密、转 ETH 会执行代码、余额可被强制转入、选择器只有 4 字节。
- 版式：大道旁一排八块告示牌（编号 1–8），镜头从左到右逐块推近；每块的三行按"误解 → 事实 → 影响"翻出：误解行出现时是墨色，讲到事实时被红色删除线划掉，事实行出现，影响行是青蓝标签。讲完一块，告示牌顶部亮一个小灯，镜头移到下一块。
- L0 八个特性：八块空告示牌从地面长出，屏幕关键词"误解 · 事实 · 影响"。
- L1–L2 private：告示牌 1；旁边那个玻璃抽屉柜（seg3 的）再出现，抽屉上的"private"锁贴纸只挡住了另一台合约机器伸过来的机械臂（"调用被拒"红叉），但人物从外面照样看见内容。影响标签"不能存秘密"。
- L3–L4 receive / fallback：告示牌 2；一枚 ETH 硬币投进合约机器的投信口，机器齿轮立刻转起来、伸出一只信封往回走（向调用者回调）。影响标签"重入入口"。
- L5–L6 selfdestruct：告示牌 3；一台合约机器上方一个"拆除"按钮；时间线卡"2024 · Cancun · EIP-6780"；按下按钮：只有标着"同一笔交易内创建"的机器被拆掉，另一台老机器没被拆，只是里面的金币倒了出去。影响标签"强制转入 ETH 仍可发生"。
- L7–L9 合约余额：告示牌 4；合约机器旁一个透明储钱罐写"余额"，正常入口是机器的投信口；另外两条路径从侧面把硬币直接倒进罐子："selfdestruct""出块奖励地址"。罐子上方的账本数字和罐子实际数字对不上（红）。影响标签"余额记账可被捐赠打乱"。
- L10–L11 检查型算术：告示牌 5；一个计数器表盘滚到最大后，在"0.8 以后"时变红并回滚（绿勾表示"会被拦住"）；然后三个小门"unchecked""类型转换""除法截断"，数字从这三个门里穿过、没有任何报警（门口无灯）。影响标签"见手册第 6 章"。
- L12–L13 block.timestamp：告示牌 6；一只闹钟（`clock`），出块者人物伸手把分针拨动一点点；L2 一侧，闹钟由一个标"排序器"的盒子控制。影响标签"不做随机数 · 不做秒级判断"。
- L14–L16 block.number：告示牌 7；一条区块链，块与块之间的间距原本标"3 秒"，压缩成"0.45 秒"（标"BSC · 2026 年 1 月 Fermi"）；旁边一个"锁定期 = 100 块"的沙漏，沙子在块变快后流得更快，提前流完（红）。影响标签"按区块数算利息/锁定期会错"。
- L17–L18 函数选择器：告示牌 8；两把**选择器钥匙**，手柄上写不同的函数名，钥匙齿只有 4 个齿、形状完全一样；两把钥匙都能插进同一把锁。屏幕关键词"前 4 字节"。
- L19–L20 Poly Network：一张事件卡"2021 年 8 月 · Poly Network · 约 6.1 亿美元"，灰标签"手册第 12 章复盘"；一个红色构造出来的函数名钥匙，插进一把锁，锁旁的门牌写"替换验证者公钥"。只画机制，不画具体签名字符串。**本段关键画面**：名字不同、齿形相同的两把钥匙打开同一把锁。
- L21 storage 与 memory：八块告示牌都亮灯，镜头拉远；代码卡 D 滑入。
- L22 引用 vs 副本：一个抽屉（storage）被直接拉出修改，修改写回柜子（绿勾）；另一边，从抽屉里复印出一张纸（memory 副本），在纸上修改，柜子里不变。卡 D 两行分别连虚线到抽屉和复印纸。
- L23 写错一个词：余额抽屉里的数字没变；一个人物拿着领取单反复领取（同一张单盖了多次章，章是红色），标签"余额没扣 → 重复领取"。段尾静止在八块亮灯的告示牌。

### seg5a ⑤ 回滚与Gas（96.5 秒）
目标：观众能说出 require 冒泡、低级 call 不冒泡；知道 63/64 和 2300 gas 的含义；带走本章核心观点。
- L0 gas 和回滚：A、B、C 三台机器回到画面，A 旁边长出 gas 油表，指针在 F；机器上方出现调用帧堆叠托盘（A 一层）。
- L1 每条指令消耗 gas、用完回滚：机器齿轮每转一下，油表指针往 E 走一格；指针到 E，最上层托盘翻倒、托盘上的改动清空（抽屉被推回原状）。
- L2 require 冒泡：托盘叠到 A/B/C 三层；C 里 require 失败，C 的托盘翻倒，然后 B、A 的托盘依次翻倒（向上冒泡，用一串向上的红色箭头）。
- L3 低级 call 不冒泡：同样三层，C 失败只翻倒 C 的托盘；B 收到一张"false + 返回数据"的小纸条，B 和 A 的托盘稳稳不动——和上一个镜头左右对照。
- L4 try catch：B 外面套一个接网（catch），C 掉下的失败被网接住（绿）；但 B 自己内部掉下的东西穿过网（红），标签"接不住本合约内部失败"。
- L5 63/64：A 的油表旁边分出两块：大的一块 63 份流向 B（点阵 64 个点，63 个流走、1 个留下）；B 的油表耗尽变红，A 剩下那 1 个点让 A 的齿轮再转一下"收尾"（绿）。标签"EIP-150"。
- L6 transfer / send 2300 gas：一个很小的油罐写"2300 gas"，曾经挂着一个"防重入"的旧牌子（灰色、褪色）。
- L7 gas 价格改过、合约钱包收款失败：油罐送到一台合约钱包（`hotWallet` 变体或合约机器）门口，钱包还没开门油就用完，转账红叉。标签"EIP-1884 · EIP-2929"。
- L8 推荐做法：改用一根粗管（call）送 ETH；门口加一把重入锁（`padlock`）+ 一块告示牌"CEI"；绿勾。标签"见手册第 4 章"。
- L9 gas 规则还在变：油表表盘上的刻度被换掉一圈，旁边两张时间卡"Fusaka""Glamsterdam · 尚未上线"，旧牌子"固定 gas 够用"被划掉。
- L10 编译器 0.8 以前：一台"编译器"机器（合约机器的变体，铭牌"solc"）旁边一条版本时间轴：< 0.8 段标"不检查溢出 · 需要 SafeMath"。
- L11 0.8.24 瞬态存储：时间轴走到 0.8.24，出现一个"只在本交易有效"的临时抽屉（半透明、带沙漏），它被用作重入锁；旁边灰标签"跨链部署前确认目标链支持"。
- L12 本章那句话：镜头拉远到全景：用户 → A → B → C，信封一路传递，每传一次，"控制权"标签跟着移动；一句大号关键词"每次调用都可能交出控制权"。
- L13 交给谁、谁的存储、谁回滚：三个青蓝问号标签分别贴到信封（交给谁）、抽屉柜（谁的存储）、托盘（谁回滚）。灰标签"解读"。段尾静止。
