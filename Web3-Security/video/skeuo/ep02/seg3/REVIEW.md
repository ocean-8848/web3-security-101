# REVIEW · ep02 / seg3「③ 熵不够」

## 做法
- 一个连续世界、一台镜头：生产线（照抄 seg2 layout）→ 攻击者 GPU 工作台 → 前方三块案例区 → 教训区。
- 屏幕层：左上四格步骤条（L0–L5）→ 三张案例卡（L6–L14）→ 教训一/二/三标题（L15–L17）；日历卡只在 L8、L10、L13 出现。
- 事实层级：金额都带"约 / 至少约"，并加灰标签"事发时估值"；Milk Sad 文档警告标"项目方称"。屏幕上没写手册之外的日期（Ledger 的报告和修复日期只写"几天内修复"）。

## 自审（逐句中点 + 0.8 s + 段尾，见 review/ 拼图）
第一轮问题及修正：
1. P0 案例区离生产线太近，案例镜头里混进攻击者和摇奖机 → 案例区移到 v = 3200，各区相距 2400。
2. P0 L1 的 PRNG 太小、标签出现太晚 → st1 镜头倍率 1.15 → 1.9，标签提前到"伪随机数"。
3. P0 "警告"贴纸开场就可见 → `.stk` 初始透明。
4. P0 L8 日历翻页文字叠在一起（content_overlap）→ 新页翻入时旧页立即隐藏。
5. P1 L4 比对镜头的展柜标签压住步骤条、攻击者压住字幕卡 → 重算比对镜头。
6. P1 L5 CSPRNG 摇奖机挡住带红叉的 PRNG → 摇奖机移到 (−620, 300)。
7. P1 L13/L14 金额标签和钱包压到字幕区 → 标签放到钱包上方，L14 收起钱包。
8. P1 世界坐标改为和 seg2 一致（生产线 v = 0、展柜、链、签名支线、三台 GPU、攻击者位置），开场镜头与 seg2 的 wide 相同。
9. P2 字号：案例卡、日历条小字提到 28 px；步骤条灰字加深。
