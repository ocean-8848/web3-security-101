## 1. 本集骨架

- **一句话核心观点**：合约的每个状态修改函数都要回答"谁可以调用我"；答案是"任何人"时，必须证明任何人调用都安全。权限不只会"没装锁"，还会被借走、被交错人、被集中在一把私钥上。
- **支撑结构**：
  1. 钩子：Parity 库合约 2017 年 11 月没人初始化 → 被接管 → `kill` → 约 51 万 ETH 冻结。
  2. 一句话 + 写字楼比喻（及不成立处）+ 五类攻击者；六种缺陷的前三种：缺少检查、`tx.origin`、未保护的初始化。
  3. Parity 7 月事故引出 delegatecall；后三种：任意 call/delegatecall、单步所有权转移、签名鉴权写错；三个易漏判断。
  4. 账户层权限：TRON 的 Owner / Active / Witness、权重与阈值；"多签诈骗"路径；对开发者的含义。
  5. 防御：最小权限角色拆分（暂停要快、升级要慢）、多签 + 时间锁 + 守护者及其局限；Ronin、BNB Token Hub、Mantle 三个权限案例；收尾。
- **关键术语**：访问控制、修饰器（`onlyOwner`、`onlyRole`）、`tx.origin` / `msg.sender`、`initialize` / `initializer` / `_disableInitializers`、delegatecall、allowance（授权）、`Ownable2Step` / `acceptOwnership`、`ecrecover`、`renounceOwnership`、`extcodesize`、最小权限、多签、时间锁、守护者、Owner / Active / Witness 权限、权重、阈值、中继者（Relayer）。
- **成立条件、例外与风险**：
  - 写字楼比喻在"换锁"处不成立：合约不能升级时，锁装错就永远错（讲稿 seg2 L5–L6 已说）。
  - 多签只防"单个私钥被盗"，防不了"所有签名人看到同一个被篡改的界面"。
  - 阈值的意义取决于签名人的独立性（Ronin 4 把钥匙同属一家机构）。
  - 角色表里的延迟（48 小时、24 小时）是手册给的**示例**，不是标准（讲稿 seg5a L4 已说）。
  - 暂停权限"不加延迟"的前提是暂停只能止损、不能转走资金。
  - TRON 上"一个地址 = 一把私钥"不成立；EVM 链上的 `extcodesize == 0` 也不能证明是 EOA。
- **不确定之处 / 口径**：
  - Parity 11 月：约 51 万 ETH 冻结，口径为手册引 Parity 官方复盘（项目方称）与 IBTimes 报道。屏幕挂灰标签"Parity 复盘"。
  - Parity 7 月：约 153,037 ETH（讲稿说"约 15.3 万"），约 3,000 万美元，手册第 05 章 6.1 节。屏幕标"手册 6.1 节"。
  - Ronin：9 选 5、其中 4 把同属一家机构、1 把来自未撤销授权、约 6.2 亿美元，口径为手册第 12 章 4.1 节（公开复盘）。屏幕标"手册第 12 章"。
  - BNB Token Hub：100 BNB 注册中继者、凭空铸造 200 万 BNB、Moran 硬分叉改白名单，手册第 05 章 6.3 节、第 12 章 4.2 节。
  - Mantle：14 人里 6 人签名即可无延迟升级 L1 桥，第三方分析（L2BEAT，截至 2026 年 11 月），会变化。屏幕标"L2BEAT · 截至 2026 年 11 月"。
  - TRON 权限模型：TRON 官方文档与安全公司公开资料（项目方称 + 第三方）。"多签诈骗"路径是手册对一类骗局的归纳，不是某个具体事件，屏幕标"骗局类型"。
  - 解读（屏幕加灰标签"解读"）：seg2 L26"缺的正是这一步"、seg3 L13"权限没有被偷，是被借走了"、seg4 L18 后半句"设成 owner 前先查权限配置"、seg5b L9。
  - seg2 L26 有一处要小心：2017 年的 Parity 库没有 OpenZeppelin 的 `_disableInitializers`。讲的是"锁死实现合约本身"这个做法，画面不要暗示当年漏写了这个函数名。

## 2. 世界与主角（全片固定）

一个连续的等距世界，叫"权限街区"。从左到右：

1. **左区·用户侧**：管理员 / 签名人（`person` signer）+ 笔记本（`laptop`），钓鱼页用 `browserWin` 红色版。
2. **中区·按钮台大道**：主角是一台**合约机器**（`contractMachine`，ep03），机器正面前方立一张**函数按钮台**（新补 `funcPanel`），按钮就是函数：`mint`、`initialize`、`kill`、`upgrade`、`pause`。每个按钮上方可以装一个**读卡器护罩**（新补，按钮台的部件）= 修饰器。这是全片"谁有权按这个按钮"的核心视觉。
3. **Parity 角落**（中区左侧）：一台"库合约"机器（`contractMachine` name "Library"），前面一排三四个 `hotWallet` 当"依赖它的钱包"，钱包和库之间用 ep01 `pipe` 相连（delegatecall 管道）。
4. **右区·TRON 街区**（seg4）：一个**账户门禁柜**（新补 `accountSafe`）+ **阈值刻度柱**（新补 `thresholdMeter`）。
5. **后区·钥匙管理处**（seg5a）：**角色门卡挂板**（新补 `roleBoard`）、时间锁传送带（ep02 `conveyor` + ep01 `timeLock` + kit `doc`）、守护者（`person` engineer）、远处 ep01 `bridge`（Ronin、Token Hub、Mantle 都用它）。

### 从库里复用

- kit：`person`、`laptop`、`browserWin`、`safe`、`hotWallet`、`checkpoint`、`envelope`、`doc`、`key`、`padlock`、`seal`、`chain`、`magnifier`、`shield`、`hourglass`、`clock`、`beacon`、`knifeSwitch`、`rpc`。
- ep01/kit-ext：`pipe`（delegatecall 管道）、`miniVend`（kind `token`，代币合约）、`letter`、`bridge`、`timeLock`、`signBoard`、`firewall`（不用也行）。
- ep02/kit-ext：`addrPlate`（新 owner 的地址信箱，小旗 = acceptOwnership）、`conveyor`（时间锁排队带）、`vitrine`（"公开排队"玻璃罩）。
- ep03/kit-ext：`contractMachine`、`manual`（delegatecall 借来的代码手册）、`signboard`（三个易漏判断用）。

**注意（制作前先处理）**：ep01 和 ep03 的 `runtime-ext.js` 都写 `window.KITX`，开头都是 `if (window.KITX) return;`。同一段同时内联两者时，后加载的那一套助手不会注册（例如 ep03 的 `KITX.spin` 和 ep01 的 `KITX.countdown` 不能同时可用）。ep05 的 kit-ext 应当提供一个合并加载的办法（例如先内联 ep03，把 `window.KITX` 暂存后删除，再内联 ep01，然后用 `Object.assign` 合并，并检查两边同名的助手如 `dash`、`fly`）。seg1、seg3、seg5a 都会碰到。

## 4. 各段分镜（按句写；句号见 timing.json 的 lines，从 0 开始）

### seg1 ① 没人初始化（45.5 秒）
目标：观众能说出"Parity 库合约部署后没人初始化，任何人调用初始化就成了 owner，再调用 kill，依赖它的钱包约 51 万 ETH 被冻结；攻击者没破解任何东西"。
- L0 2017 年 11 月：深夜色调略压暗的纸底；镜头在 Parity 角落远景。左上灰标签"2017 年 11 月 · 以太坊"。一台"Library"合约机器，前面三四个 `hotWallet` 用 `pipe` 接到它身上，管道里青蓝虚线缓慢流动（钱包都在用它的代码）。
- L1 调用库合约的初始化函数：机器前方的 `funcPanel`（按钮 `initialize`、`kill`）长出。一个普通用户（`person` signer，非红色）走到按钮台前，伸手按 `initialize`。按钮台上方 `initialize` 处是**裸按钮**（`guard:"none"`）。
- L2 Parity 多签钱包共用的代码：镜头稍拉开，标签"Parity 多签钱包 · 共用库合约"贴在机器上，管道依次闪一下（"共用"）。
- L3 从来没有人初始化过：机器的小屏显示"owner = 空"（灰），一层薄灰尘落在按钮台上（无人碰过），标签"部署后从未初始化"。
- L4 他成了 owner：按钮按下，机器小屏换成"owner = 这名用户"（`KIT.swap`），一张写着 owner 的门牌从机器飘到用户手上。
- L5 调用 kill、销毁：用户按 `kill`（同样是只认 owner 的按钮，护罩上的读卡器亮绿——他确实是 owner）。机器 `KIT.broke`：红虚线框 + 红叉，一团灰色烟尘淡出。**本段关键画面之一**。
- L6 钱包失去代码逻辑：管道里的青蓝虚线一节节熄灭；每个 `hotWallet` 的指示灯从绿变灰。
- L7 约 51 万 ETH 冻结：`iceShell` 从下往上冻住每个钱包；钱包上方点阵（每点 = 1 万 ETH，共 51 点，最后一点半透明表示"约"）。大号数字"约 51 万 ETH · 冻结"，灰标签"Parity 复盘"。
- L8 没破解密码、没偷私钥：用户身边浮出 kit `padlock` 和 `key`，两者完好（绿勾），旁边"破解：无""私钥：未被盗"。
- L9 只调用了一个没有权限检查的函数：镜头推近按钮台，`initialize` 按钮上方出现红虚线空位（`guard:"broken"`），红色标签"没有权限检查"。**本段关键画面**：完好的钥匙 vs 没有护罩的按钮。
- L10 这一集讲访问控制：镜头拉远，按钮台从 Parity 角落"复制"到中区大道，变成主角按钮台（5 个按钮）。屏幕关键词"访问控制"。
- L11 谁有权按它：五个按钮上方依次冒出墨色问号，最后合成一行大字"谁有权按这个按钮？"。段尾静止。

### seg2 ② 门没装锁（131.0 秒）
目标：观众能复述本章那句话；说出写字楼比喻在哪不成立；对前三种缺陷各说出修复：加 `onlyRole`、改看 `msg.sender`、`initializer` + 构造函数锁死实现合约。
- L0 每个修改状态的函数都要回答：中区大道，合约机器 + 按钮台；每个按钮旁边立起一张小卡"谁可以调用我？"。
- L1 任何人 → 证明安全：其中一个按钮（例如 `deposit`，临时换铭牌）标"任何人"，旁边弹出一张 `doc`"安全论证"并盖绿章（`seal`）。
- L2 写字楼：灰标签"比喻"出现，画面淡入一栋等距写字楼剖面（用两个 kit `box` 组成的两层小楼即可，前墙切开），覆盖在按钮台上方。
- L3 public = 大堂的门：一层大门敞开，几个小人随意进出。标签"public"。
- L4 onlyOwner = 机房的门要刷卡：二层侧门挂读卡器，一个人刷 `keycard`，LED 绿，门开。标签"onlyOwner"。
- L5 比喻不成立、写字楼能换锁：一个人拿新锁换掉机房门锁（绿勾），标签"写字楼：可以换锁"。
- L6 合约不能升级、锁装错永远错：比喻层淡出，回到合约机器；机器接缝处显出一排铆钉（ep01 `vending` 的 `rivets` 质感，可以直接在 `contractMachine` 上加铆钉线），读卡器被"焊死"，标签"不可升级：装错就永远错"。灰标签"比喻在这里不成立"。
