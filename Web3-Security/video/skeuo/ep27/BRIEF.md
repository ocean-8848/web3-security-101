# ep27 分镜：审计、测试与开发流程：把安全写进流水线

统一视觉（画面、物件、颜色、字幕、术语卡、结束卡、版面分区、独立成片）见 `PIPELINE.md` 第 0 节，这里不重抄。讲稿 `script.json`，多音字表 `pron.json`。

## 1. 本集骨架

- **一句话核心观点**：审计不是安全的起点，也不是终点；它是流水线上的一个关口，之前要有规格和测试，之后要有安全部署、监控和应急。"审计过"只对审计时的那个提交哈希成立。
- **支撑结构**：
  1. 钩子：2021 年 5 月 PancakeBunny 被攻击，约 4500 万美元；审计方事后说明，被利用的是审计之后才上线的版本。预测题：能用"我们通过了审计"证明线上代码安全吗？
  2. 准确表述（审计是一个关口）→ 造飞机比喻（不成立处：飞机能召回，不可升级的合约不能改）→ 八个关口 → 越左越便宜、③④⑤ 每次提交都跑、静态分析告警要有结论、审计发现补成测试、局限（只查想到的；经济攻击要经济审计）。
  3. 测试三层：先写规格（前后置条件、不变量、特权角色最大破坏力）→ 单元测试 → 模糊测试（金库存取不获利，舍入偏向金库）→ 不变量测试（银行偿付）→ 预测题（重入需要调用顺序）→ 只查写下的不变量（Euler）→ 形式化验证。
  4. 审计与上线：冻结代码与提交哈希、文档、多家审计、竞赛、修复复审、编译器版本（Vyper 2023）、审计后不改 → 脚本部署、部署和初始化同一笔交易、验证源码与参数、权限移交多签和时间锁 → 链特定测试（BNB Chain、TRON、Mantle）→ 测试网或主网分叉跑完整测试。
  5. 监控与应急：漏洞赏金、六类监控告警 → 应急六步 → mETH 在 Bybit 事故中追回 cmETH 的三样东西 → 应急能力要事先设计进合约。
  6. 写进流水线：对照八个关口 → 开发者、审计者、负责人各一件事 → 回答预测题（不能；只对提交哈希成立，还要证明线上字节码一致、改动都经审查）→ 收束。
- **关键术语**：审计、提交哈希、威胁模型、静态分析、形式化验证、漏洞赏金、不变量、模糊测试、不变量测试、舍入、重入、回调、健康因子、多签、时间锁、主网分叉、锁仓总量、闪电贷、预言机、守护者、作战室、白帽救援、字节码。
- **成立条件、例外和风险**：比喻不成立处 seg2 L9–L12。seg1 L5、seg5 L18、seg6 L10 是解读（灰标签"解读"）。seg5 L3–L7 的阈值是示例（灰标签"示例"），不是标准。**只讲机制与防御**：PancakeBunny 不画攻击步骤，只画"审计版本 ≠ 上线版本"；seg3 L15 的重入只画调用顺序（存款 → 回调 → 转账）和测试能否抓到，不画利用合约代码。
- **不确定之处**：seg1 L2 资料只写"审计方事后说明"，没写审计方名称，来源卡用类型标签"审计方说明"。seg1 L4 "攻击发生在那个没被审过的版本上"是对"被利用的是审计之后才上线的版本"的改写。seg1 L6 "项目上线时常常会说一句"是常识性铺垫，不是统计。seg3 L20 Euler 只用资料里的不变量原话，不讲事故经过和金额；"健康因子不低于 1"由资料"健康因子 ≥ 1"改写。seg4 L6 资料只写"Vyper 2023 事故"作为"记录并审查编译器版本的已知 bug"的例子，讲稿写"就出在编译器上"，没写更多细节，来源卡用"公开报道"。seg4 L16 出块间隔 0.45 秒是资料写的"2026 年 1 月 Fermi"之后的数值，画面小字注"Fermi 升级后"。seg4 L18 Mantle 一句由资料"`msg.value` 和 `address(this).balance` 是 MNT；ETH 是 ERC-20（BVM_ETH）"改写，未提 Arsia 费用模型。seg5 L2 漏洞赏金一句由资料关口⑧和术语表改写。seg5 L16–L17 mETH 只有 The Block 报道这一处口径，没写金额。seg6 L2–L4 三件事由资料反思题改写。

## 2. 世界与主角（全片固定）

一个连续的等距世界，叫"**一条安全流水线**"。最左是一块独立的事故展台（A）；从 B 开始，一条长传送带（E02 `conveyor`，分区段铺，首尾相接）沿 u（左→右）贯穿 B–E，传送带上方依次横跨八道关卡（kit `checkpoint`，门牌 ①–⑧，只写门牌号，旁边小牌写动作名）。传送带上运送的是**代码版本卡**（E04 `punchCard`，`title` 写"版本"类名称，不写真实哈希）：它就是本集的主角，过一道关卡就在卡面右上角亮一个绿点。传送带后方（−v 侧）一条青蓝虚线从 E 区末端折回 B 区 ①（"发现问题 → 回到规格"），seg2 L21 画出。

合约一律用 E01 `vending`（售货机，资金在橱窗里）；攻击者 kit `person` role attacker；开发者、审计员、值班人员 role engineer；项目负责人 role signer。每区地面一块区牌（原生 SVG），上方一块 E01 `signBoard` plate。
