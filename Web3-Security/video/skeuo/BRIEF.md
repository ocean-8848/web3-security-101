# 第 29 章开场样片：共用制作说明

同一段 47.16 秒的开场（同一条配音、同一套字幕）做成 6 种画面风格，让频道主挑选。各风格的基调统一，只有画面语言不同。

## 1. 讲什么（事实，全部来自手册第 20、29 章，不许增加未列出的事实）

- 2025 年 2 月 21 日，Bybit 的以太坊冷钱包被转走约 15 亿美元（FBI 口径，事发时估值）。
- 私钥没有泄露。多签签名人按流程逐个确认。
- 攻击者此前篡改了 Safe{Wallet} 前端托管在 AWS S3 上的 JS，只针对 Bybit 冷钱包。签名人屏幕上看到的是一笔普通转账。
- 实际签下的交易：`operation = 1`（DELEGATECALL，正常转账是 0 = CALL），`to` 是攻击者合约，`data` 是 `transfer(address,uint256)`。目标合约的代码在 Safe 的存储上运行，把参数写进 slot 0，也就是 Safe 代理的实现合约地址。结果是钱包被换成攻击者的实现合约。
- 本章主线：签名路径的七道关。① 业务意图 ② 请求构造 ③ 风控与审批 ④ 显示与解码 ⑤ 签名 ⑥ 广播 ⑦ 链上状态。Bybit 断在 ④。
- 不要编造：具体地址、交易哈希、签名人人数、ETH 数量都不要出现。需要示意时用 `0x…` 截断或"攻击者合约"这样的文字。屏幕上的地址、哈希若出现必须标"示例"。
- 只讲防御视角，不演示攻击步骤。

- 字体已在 `index.html` 里声明，场景里直接用：`"Noto Sans SC"`（100–900）、`"Noto Serif SC"`（200–900）、`"LXGW WenKai"`（手写感楷体，500）、`"Smiley Sans"`（得意黑，倾斜粗黑展示体）。英文和代码可用内置的 Inter、JetBrains Mono、IBM Plex Mono、Space Mono 等。只有 GB2312 常用字，生僻字会缺字。

## 4. 统一基调（6 种风格共同遵守）

- 讲师口吻的技术讲解，冷静、准确，不煽情、不恐吓。
- 画面跟着话一层层长出来：说到哪个词，那个东西才出现。一个画面里只有一个焦点。
- 屏幕上的字不逐字重复配音（字幕已经在了）。画面写关键词、数字、字段、图示标签。
- 一个强调色，只给最关键的东西：`operation = 1` 是全片唯一的高潮，必须是最强的视觉时刻（约 20.8–22.4 秒），之前留出 0.3–0.7 秒的停顿感。
- 标题和正文字号：标题 ≥ 72 px，要读的字 ≥ 30 px。
- 结尾片头卡统一文字：主标题「攻击者不再偷私钥」，副标题「第 29 章 · 签名路径」。用你风格的方式落定，最后 2.5 秒完全静止。
- 第 0 帧不能是空白：开场就有画面（例如日期或冷钱包已在场）。
- 禁止（除非你的风格本身就是这种媒介）：黑色或深蓝虚空里漂浮小元素、发光/霓虹/粒子、紫蓝渐变、玻璃卡片、三张卡片并排、每个元素都淡入上滑、标题落定后还在漂、角标/边框/HUD 装饰。
- 不需要背景音乐和音效（本机没有可用的音乐来源）；配音已经在。

## 5. 交付

1. `SPEC.md`：按 `references/spec.md` 的模板写你这版的具体数字（底色 hex、字体字号、缓动、每个镜头的帧范围）。
2. 画面完成后跑 `npx hyperframes check --json`，修掉所有 error，认真看 warning。
3. `npx hyperframes snapshot --review`，按 `references/review.md` 自查，至少检查 3、10、16、21.5、27、35、41、46 秒这几帧，写 `REVIEW.md`（发现了什么、改了什么）。
4. 渲染：`npx hyperframes render` 输出到项目里的 `renders/`，然后把成片复制为 `../out/<你的目录名>.mp4`。渲染完用 `ffprobe` 确认时长约 47 秒、有音轨。
5. 最终回复里给：成片路径、3 张代表帧路径、一段 3 句话的风格说明、你觉得这个风格适合哪类章节（比如漏洞机制、事故复盘、实操）、仍存在的问题。

不要修改其他风格的目录，不要动 `template/`、`shared/`。不要提交 git，不要联网发布。
