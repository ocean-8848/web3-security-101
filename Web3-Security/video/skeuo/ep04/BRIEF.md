全片约 11.0 分钟（659.6 秒）（不含段间间隔），6 个工程：seg1、seg2、seg3、seg4、seg5a、seg5b（都在 `hf/ep04/` 下）。讲稿 `script.json`，逐句时间见各段 `timing.json`。统一视觉、颜色语义、字号、运动、段首段尾规则见 `../PIPELINE.md` 第 0、4 节和 `../ep29/BRIEF-FULL.md` 第 2、3、5 节，这里不重抄。

## 1. 本集骨架

- **一句话核心观点**：合约在更新自己的账本之前，把控制权交给了外部地址；外部地址趁账本还是旧的，再次调用合约。防御就是把顺序写对（CEI），再用锁兜底，并认清锁的边界。
- **支撑结构**：
  1. 钩子：The DAO + "Bank 10 ETH、你余额 1 ETH，调一次 withdraw 最多取多少"（手册先猜再看题）。
  2. 定义、柜员比喻及其局限（嵌套不是并发）；两个前提；六类交出控制权的操作；TRON / Mantle 回调入口差异。
  3. 四种重入：单函数（调用栈逐层）、跨函数（Fei Rari）、跨合约、只读（dForce）。
  4. 防御：CEI、重入锁及边界、瞬态存储锁、拉取式支付、纵深防御四条、修复前后都要验证；Curve / Vyper：源码对 ≠ 字节码对。
  5. 回调入口扩展：ERC-777 钩子（imBTC / Lendf.Me）、BNB Chain 分叉项目任意代币上架、Penpie；审计 REN-1/2/3；角色行动；回到开头。
- **关键术语**：重入、外部调用、控制权、receive / fallback、钩子、调用栈、单函数 / 跨函数 / 跨合约 / 只读重入、`view` 函数、CEI（Checks-Effects-Interactions）、`nonReentrant` 重入锁、瞬态存储锁（EIP-1153）、拉取式支付、不变量测试、字节码。
- **成立条件、例外与风险**：
  - 开场题成立的前提：Bank 先转账后清零，且调用者是合约（能在收款时执行代码）。
  - 递归深度受 gas 和调用深度 1024 限制。
  - 锁只保护加了锁的函数；不防只读重入；跨合约要共享同一把锁。
  - 瞬态存储锁需要目标链支持 EIP-1153。
  - CEI 在复杂函数里难以做到"所有交互都在最后"，所以要纵深防御。
  - 修复验证要"修复前失败、修复后通过"两个结果。
  - 回调入口因链而异：TRON 系统转账 TRX 不触发 fallback，`TriggerSmartContract` 附带 callValue 才触发；Mantle 上 ETH 是 ERC-20（BVM_ETH），转原生币 MNT 才触发 receive。
  - 柜员比喻在"并行"处不成立，讲稿已说明。
- **口径 / 不确定之处**：
  - 开场的 Bank 10 ETH 是手册的**示例题**，屏幕挂灰标签"示例"。The DAO 是真实事件：约 360 万 ETH，事发时约 6000 万美元，标"手册口径 · 事发时价格"。
  - Fei Rari 约 8000 万美元、Penpie 约 2700 万美元：手册第 04 章与 C00 一致；C00 写明 Fei Rari 依据 CertiK 公开分析，标"第三方分析"。
  - Curve / Vyper 约 7000 万美元：手册写"多方公开复盘"，标"第三方分析"。
  - imBTC / Lendf.Me 约 2500 万美元（事发时估值）、资金已归还：标"媒体报道 · The Block"。
  - dForce 约 360 万美元（事发时估值）：标"第三方分析 · The Block / CertiK"。
  - BNB Chain 分叉项目是**模式**，不是单一事件，不给金额、不点名项目，标"常见模式"。
  - seg5b"把顺序写对，第二层读到的就是 0"是手册 3.1 节读图要点的复述；"回到开头"的答案句可挂灰标签"解读"。

## 2. 世界与主角（全片固定）

一个连续的等距世界，像一条"银行街"，从左到右：

1. **左区·攻击者工位**：攻击者人物（`person` role attacker）+ **攻击合约**：ep01 `miniVend({kind:"attacker"})`（红色、正面红色回调箭头）。它的"receive"用新补的**回调弹簧臂**表示（见物件表）。
2. **中区·Bank 合约**（主角）：ep01 `vending({sign:"BANK"})`，橱窗库存 = 金库里的 ETH（10 枚硬币，`KITX.dispense` 吐出），按钮面板上的按钮代表函数（btn-0 = withdraw、btn-1 = transfer、btn-2 = deposit 等，用 `wlab` 标函数名）。机身 −u 侧挂一本 kit `ledgerBook` 账本，账本上一格嵌 ep02 `rollCounter` 作为"攻击者余额"读数（显示 1 → 0）。
3. **Bank 上方·调用栈**：ep03 `frameStack`，每层托盘标"withdraw #1 / #2 / #3…"，嵌套一层叠一层，返回时一层层撤掉。
4. **右区·第三方协议**：借贷协议 = kit `safe`（贷款金库）+ ep01 `miniVend({kind:"oracle"})` 表盘（读价格）；AMM 池 = ep01 `miniVend({kind:"dex"})`，几台机器之间用 ep01 `pipe` 连接（可组合性）。
5. **远景 / 段内**：seg2 柜员比喻场景（新补柜台）；seg2 结尾三条链用 kit `chain` 三小段 + ep01 `signBoard` 标"以太坊 / TRON / Mantle"；seg4 编译器工位；seg5a 上架闸口（kit `checkpoint`，门牌"上架"）。

## 3. 代码卡（每张只放关键 3–6 行，JetBrains Mono，白底墨字（kit 代码卡样式，与 ep29 相同），红色虚线从某一行连到场景物件）

- **卡 A 漏洞版**（seg1 L3、seg3 L2–L7）：
  ```
  function withdraw() external {
      uint256 amt = balances[msg.sender];
      (bool ok, ) = msg.sender.call{value: amt}("");  // ① 交出控制权
      require(ok);
      balances[msg.sender] = 0;                       // ② 太晚了
  }
  ```
- **卡 B 攻击合约 receive**（seg1 L9、seg3 L4）——只画结构，不给可直接复用的攻击合约：
  ```
  receive() external payable {

          bank.withdraw();     // 在 ② 之前再次进入
  }
  ```
- **卡 C 跨函数**（seg3 L10–L14）：
  ```
  function withdraw() external nonReentrant { ... }
  function transfer(address to, uint256 amt) external {  // 没有加锁
      require(balances[msg.sender] >= amt);
      ...
  }
  ```
- **卡 D CEI 修复版**（seg4 L1–L4）：
  ```
  uint256 amt = balances[msg.sender];   // Checks

  ```

## 4. 各段分镜（按句写；句号见 timing.json 的 lines，从 0 开始）

### seg1 ① 顺序写反了（62.4 秒）
目标：观众能说出"Bank 先转账后清零、调用者又是合约时，调一次 withdraw 能把整个金库取空；这叫重入"。
- L0 The DAO：镜头在世界上空；一块事件卡"2016 年 6 月 · The DAO · 约 360 万 ETH"立在中区，ETH 用点阵（一个点 = 10 万 ETH，36 个点）。
- L1 约 6000 万美元：事件卡下多一行"事发时约 6000 万美元"，灰标签"手册口径"。
- L2 合约没有被破解：Bank（vending）出现，保险柜式的门、锁都完好，绿勾；标签"未被破解"。
- L3 两行顺序写反：代码卡 A 只露 call 和 `balances = 0` 两行；两行之间出现一个红色双向箭头"顺序"，红色虚线从第 ② 行连到 Bank 侧面的账本。**本段关键画面**。
- L4 先猜一道题：灰标签"示例题"挂左上角到 L8；屏幕中央大问号。
- L5 金库 10、余额 1：Bank 橱窗里 10 枚硬币（点阵 10 个点，标"金库 10 ETH"）；账本上一格 rollCounter 显示"攻击者余额 1"。
- L6 一次调用最多取走多少：攻击者人物按一下 Bank 的 withdraw 按钮（btn-0 闪一下），问号停在橱窗上方。
- L7 全部 10 个：10 枚硬币依次从出货口吐出（`KITX.dispense`，红色），落到攻击合约的托盘；点阵"10 / 10"变红。
- L8 两个前提：两张小卡并排弹出："先转账 · 后清零""调用者是合约"；攻击者人物淡出，换成红色攻击合约（miniVend attacker）站在 Bank 前。
- L9 收款那一刻再调一次：一枚硬币落进攻击合约托盘的瞬间，**回调弹簧臂**弹出，小手再按一次 withdraw 按钮；卡 B 从右上滑入，`bank.withdraw()` 一行虚线连到弹簧臂。
- L10 清零在所有嵌套调用返回之后：Bank 上方的 `frameStack` 叠到 3 层后依次撤掉，最后一层撤掉时账本读数才从 1 滚到 0（`KIT.count`），此时金库已空。
- L11 这就是重入：大号关键词"重入 Reentrancy"，红色标签"最常复发"。
- L12 三件事：三个青蓝标签依次贴到场景："控制权在哪交出"（贴在出货口）、"有哪几种"（贴在调用栈）、"怎样写对"（贴在代码卡）。段尾静止。

### seg2 ② 交出控制权（133.9 秒）
目标：观众能复述一句话定义、说出比喻在哪不成立（嵌套不是并发）、两个前提，以及至少三类会交出控制权的操作。
- L0–L2 定义：Bank 账本还是"1"；出货口吐出硬币时，一个青蓝标签"控制权 → 外部地址"沿管道移到攻击合约；攻击合约随即按回 Bank 按钮，账本上"旧值 1"闪红。
- L3 严格定义：屏幕关键词"函数未结束 · 被再次进入"；frameStack 上 withdraw #1 托盘标"未结束"，#2 托盘压上来。
- L4 比喻·取 100 元：画面淡入比喻层（灰标签"比喻"）：**银行柜台**，柜员 + 账本"余额 100"。顾客人物站在窗口前。
- L5 先递钱后改账：现金从递钞槽滑出给顾客；柜员的笔还悬着没落下。
- L6 同伴在旁边说再取：旁边窗口站着同伴人物，头上气泡"再取 100"。
- L7 账本还是 100：柜员低头看账本（放大镜高亮"100"），又递出一叠现金。
- L8 一直取到金库见底：现金一叠叠滑出，柜台后的小金库库存条降到 0（变红）。
- L9 比喻不成立·可同时接待：比喻层盖灰印"比喻在这里不成立"；两个窗口同时亮灯，标"现实：两人同时接待"。
- L10 单线程，嵌套不是并发：比喻层淡出回到 Bank；时间轴横条：上面一条"并发"两段并排（灰、划掉），下面一条"嵌套"——第二段完整套在第一段里面（青蓝外框套红内框）。
- L11 第二次取款发生在第一次中间：frameStack 两层托盘，#2 完整地放在 #1 的"中间"（#1 托盘上半已执行的格子亮、下半"清零"格子还暗）。**本段关键画面**。
- L12 两个前提：两块编号牌 1、2 立起。
- L13 前提一：外部调用 + 对方受攻击者控制：Bank 伸出的管道接到红色攻击合约，管口标"外部调用"，攻击合约标"受攻击者控制"。
- L14 前提二：状态未更新到最终值：账本读数"1"旁标"未到最终值"，读数闪烁。
- L15 六类操作：Bank 周围一圈六个"出口"（管口）依次亮起，编号 1–6，标题"交出控制权的位置"。
- L16 call 转 ETH：出口 1 一枚硬币流出，接收方是合约机器，机器上标"receive / fallback"亮起。
- L17 代币 transfer：出口 2 连到一台红色 miniVend token，标"攻击者部署的代币 · 代码任意"。
- L18 ERC-777 钩子：出口 3 的代币到达接收方时，接收方身上一只小钩子（回调弹簧臂缩小版）弹起，标"tokensReceived"。
- L19 NFT 安全转账 / 安全铸造：出口 4，一张卡片（NFT）送到接收方，接收方回弹一个信封，标"onERC721Received"。
- L20 闪电贷回调：出口 5 连到 ep01 `flashDesk` 闪电贷柜台，借款人人物接过控制权标签，标"设计上就是交出控制权"。
- L21 任意用户提供的地址：出口 6 分叉成三根管，分别标"路由器""钩子""预言机"。
- L22 换一条链不一样：镜头右移，三段 kit `chain` 并排，木牌"以太坊""TRON""Mantle"。
- L23 TRON 系统转账不触发：TRON 那段旁边一枚 TRX 硬币进入合约机器，机器齿轮不转，标"TransferContract · 不执行 fallback"。
- L24 附带 callValue 才执行：再来一枚硬币走另一个入口，齿轮转起来，标"TriggerSmartContract + callValue"。
- L25 Mantle：Mantle 段一枚"ETH（ERC-20）"硬币进机器，齿轮不转；"MNT"硬币进机器，齿轮转起来。屏幕小字"来源：手册引 TRON 官方开发文档"。段尾静止。

### seg3 ③ 四种重入（161.8 秒）
目标：观众能用调用栈讲清单函数重入；说出跨函数重入为什么"锁了 withdraw 还不够"；区分跨合约重入；说出只读重入出错的是第三方、锁挡不住。
- 版式：Bank 上方 frameStack 是全段的"调用栈"；四种重入各配一块编号牌（1–4，ep01 `signBoard` plate 款），讲到哪块亮哪块。
- L0 按调用栈看：frameStack 放大，空托盘架；四块编号牌依次立起。
- L1 单函数：牌 1 亮。
- L2 三步：代码卡 A 滑入，三行分别标①读余额 ②转账 ③清零（青蓝小号）。
- L3 读 1、转过去：托盘 #1 压上；账本读数"1"被读出（细线到托盘 #1）；1 枚硬币沿管道送到攻击合约。
- L4 receive 被触发、再调取款：回调弹簧臂弹出按 withdraw；卡 B 连线；托盘 #2 压上。
- L5 第二层读到的还是 1：托盘 #2 上的读数"1"与托盘 #1 的"1"之间画红色等号；卡 A 第 ③ 行变灰并标"还没执行"。**本段关键画面之一**。
- L6 一层套一层直到余额不够：托盘 #3、#4……快速叠高；橱窗硬币逐枚减少到 0，最后一层的 require 亮红"金库余额不足"，递归停止。
- L7 各层返回、依次清零：托盘从上到下逐层撤掉，每撤一层，"清零"格亮一下；账本读数最后才滚到 0；橱窗已空（红）。

- L21 只读：牌 4 亮，关键词"最隐蔽"。

- L28 dForce：事件卡"2023 年 2 月 · dForce · Arbitrum、Optimism · 约 360 万美元"，灰标签"事发时估值 · 第三方分析"。

### seg4 ④ CEI与锁（140.6 秒）
目标：观众能写出 CEI 的顺序、说出重入锁的三个边界、知道瞬态锁和拉取式支付的取舍、记住纵深防御四条、记住"源码正确 ≠ 字节码正确"。
- L0 首选 CEI：回到 Bank；大号关键词"CEI"。
- L1 三个词：三块小牌依次落下"Checks 检查""Effects 修改状态""Interactions 外部交互"，排在 Bank 前的路面上，箭头从左到右。
- L2 只改一处：卡 A 滑入，第 ② 行（`balances = 0`）被抓起，挪到 call 之前，卡 A 变成卡 D（三行注释亮起）。**本段关键画面**。
- L3 重入时读到 0、回滚：重放 seg3 的场景：弹簧臂再按 withdraw，托盘 #2 读到账本"0"，require 红叉，托盘 #2 翻倒（回滚），硬币只出了 1 枚（绿勾）。
- L4 交互放最后、账本已一致：账本读数 0 和攻击合约托盘里 1 枚硬币之间画绿色等号，标"账本一致"。
- L5 第二道防线：withdraw 按钮扣上**函数锁扣**，卡 E 滑入。
- L6 再次进入加锁函数就回滚：弹簧臂按 withdraw，锁扣挡住，信封退回（红叉在攻击方一侧，Bank 绿）。
- L7 三个边界：锁旁三张小卡依次弹出：①"只保护加了锁的函数"（transfer 按钮光着闪一下）②"不防只读重入"（池子 view 按钮闪一下）③"跨合约要共享同一把锁"（锁扣伸出铁链连到另一台机器的锁扣，`shared:true`）。
- L8 瞬态存储锁、gas 更低：锁扣换成**瞬态锁**（半透明 + 沙漏），旁边 gasGauge 指针少走一格。
- L9 EIP-1153、部署前确认：瞬态锁旁三段 `chain` 小图标，一段打勾、一段问号，标"目标链必须支持 EIP-1153"。
- L10 拉取式支付：Bank 旁边放一台**取件柜**；Bank 不再从出货口推硬币，而是把金额写进某一格门上的小屏。
- L11 用户自己来取、多一步：一个人物走到取件柜，打开格子取走硬币；标签"多一步"（灰）。
- L12 CEI 的局限：一张长长的代码卡（灰）里交互散在中间几处（几个红点），标"复杂函数难以全部放最后"。
- L13 纵深防御四条：Bank 周围立起四根柱子（编号 1–4），像围栏。
- L14 一·CEI 默认：柱 1 牌"CEI 默认"。
- L15 二·同一把锁：柱 2 牌"共享状态入口 · 同一把锁"，所有相关按钮被一根铁链串到同一把锁扣上。
- L16 三·不暴露中间状态价格：柱 3 牌"view 不给中间价"；池子价格按钮旁亮一个小灯"锁状态可查"。
