# REVIEW · s1-paper（纸面数据图解）

## 创作决定
- 全片是一张纸、不切镜：开场页（日期 / Bybit / 约 15 亿美元 / 锁好的钥匙）→ 缩到左页边 → 中间长出 Safe 字段三线表 → 表缩到左侧、右侧长出代理存储 slot 0 → 两张表收拢成一张"文件"，钥匙从页边放大回来 → 文件缩成小纸片，沿七格签名路径走 → 片头卡压在路径上方。
- 朱红只用在两处：operation 的 1（+手写圈 +DELEGATECALL），和七道关的 ④（+"Bybit 断在这里"）。"攻击者合约"的改写、划线、印章都用墨色，不分走高潮。
- 高潮前 20.6–20.82 s 整帧静止约 0.7 s（其余字段已压成铅笔灰、箭头已指向 operation），随后 rotationX 翻牌。
- 没做的方向：手写板书逐笔写出全部文字（太慢）、真实 Safe 界面截图（不能出现真实地址）。

## 测量与查看
- `check --json`：0 error。剩 1 条 warning `text_below_floor`：39.6–43.1 s 的"文件"缩成 0.2 倍的小纸片，作为路径上的图标，不需要读，有意保留。早先的 `content_overlap`（15 亿美元撞到钥匙标签）已把金额从 220 px 降到 170 px 解决；压暗字段的 `contrast_aa_failure` 把铅笔灰从 #b9b1a3 改成 #8b857b 解决；`gsap_timeline_set_initial_hide` 改用 `gsap.set` + CSS 初始态解决（否则第 0 帧会露出表格线和朱红 1）。
- 看过的帧：0、3、10、12.8、14.2、14.6、16、20.5、20.9、21.2、21.5、27、29.5、31.6、31.8、32.2、35、40.5、41、41.7、42.8、46、46.91；`snapshot --review` 的节拍表和手机宽度表（360 px 下标题、字段名、七格标签都能读，图注较小）。
- 成片：ffprobe 时长 47.17 s，h264 + aac 音轨。声音只测了有没有，没人听过。

## 发现与修改
- t=14.6s · 标题"屏幕上的交易"和尚未缩小的日期重叠 → 页边收缩提前到 13.5 s（l2 与 l3 之间的空档），14.40 标题落在干净的位置。
- t=31.6s · 表格缩小时和新出现的"文件"、钥匙三层叠影 → 旧表 0.35 s 内先淡出，文件推迟到 31.85 s 上墨。
- t=40.5s · "一笔交易"到"提出"之间画面只有标题和一个很小的纸片 → 纸片放大到 0.2 倍并放在路径起点上方，路径主线提前到 40.0 s 开始画。
- 第 0 帧：日期以铅笔灰在场（#a39b8c），0.70 s 上墨。

## 仍存在的问题
- 最弱的镜头：l6（31–37 s）钥匙与文件的对比偏"图标化"，"盖在"这个动作只是箭头加印，没有真正的盖章动作。时间多的话让钥匙移到文件上、压出印。
- 页边缩小的开场页（14–27 s）字号只有约 37–64 px 的视觉比例，日期还好，"Bybit"偏小；它只是上下文，不需要读。
- 图注在 0.75 倍缩放后约 22 px，手机上偏小。
- LXGW WenKai 的阿拉伯数字比较规整，"手写大数字"的感觉不如参考片强。
- 字幕与画面同在纸面上、无底色，表格最低处（约 800 px）与字幕（约 936 px 起）间距足够，但 l5 的 slot 表若再长会碰到。
