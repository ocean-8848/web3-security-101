# ep18 分镜：钱包与密钥管理：钥匙放在哪里

统一视觉（画面、物件、颜色、字幕、术语卡、结束卡、版面分区、独立成片）见 `PIPELINE.md` 第 0 节，这里不重抄。讲稿 `script.json`，多音字表 `pron.json`。

## 1. 本集骨架

- **一句话核心观点**：私钥就是资产，谁能让私钥签一笔交易，谁就拥有这笔资产；密钥方案的强度取决于最弱的环节（一台设备、一行日志、一个签名人的眼睛），而最常被忽视的是"使用"这一步：钥匙安全地留在设备里，却签下了攻击者构造的交易。
- **支撑结构**：
  1. 钩子：WazirX 2024 年 7 月，六把钥匙要四把的多签冷钱包，约 2.3 亿美元；公开材料没说任何私钥被导出；预测题：六把私钥都没泄露，攻击者能转走资金吗？
  2. 准确表述：私钥、助记词；五种放法（软件钱包、硬件钱包、多签、MPC、HSM）、盲签、链上可验证的门槛；保险柜钥匙比喻（不成立处：私钥被复制不留痕迹）。
  3. 生命周期每一步都有事故：生成（Profanity → Wintermute，转走余额不等于撤销权限）、存储（Slope 日志；Trust Wallet 发布链路）、备份与分片（Multichain 名义上的 MPC）。
  4. 关键洞见（使用这一步）：WazirX 详情与争议；多签只保证"足够多的人同意某个哈希"；独立算哈希、硬件屏幕清晰签名、操作类型 CALL / DELEGATECALL、带外确认、签名人不共用；局限：共用解码工具。
  5. 防御（交易所）：热温冷三层、水位与限额；HSM 预测题；风控引擎放在 HSM 之前，按原始字节判断；审批顺序与事后比对。
  6. 按角色一件事 + 用户侧 → 回答开头 → 收束。
- **关键术语**：私钥、助记词、软件钱包、浏览器扩展、硬件钱包、多签、Safe、MPC 门限签名、分片、HSM、盲签、清晰签名、冷 / 温 / 热钱包、靶号地址、GPU、遥测、GitHub secrets、CI、合约升级、交易哈希、CALL、DELEGATECALL、单点、水位、风控引擎、白名单、多因素认证、轮换密钥。
- **成立条件、例外和风险**：多签和 MPC 只在签名人 / 分片真正独立时成立（seg2 L20、seg3 L26、seg4 L18、seg6 L13）；"独立解码"在所有签名人共用同一工具时退化为单点（seg4 L19）；保险柜比喻不成立处在 seg2 L21–L22；HSM 不判断交易内容（seg2 L14、seg5 L12）。
- **不确定之处**：WazirX 根因有争议（WazirX 称 Liminal 界面数据不一致；Liminal 称受害方 3 台机器被注入恶意载荷），未见最终独立报告；画面不给任何一方打叉，两张来源卡并列。seg1 L5"攻击者没有偷走钥匙"依据的是"公开材料没有说任何一把私钥被导出"，来源卡写"公开材料"，画面不写"已确认"。资料另写美国和韩国把此案归因于朝鲜（美日韩联合声明），配音不展开。Multichain"外部攻击还是内部转移"有争议，没有官方定性；金额各报道在 1.25–1.3 亿美元之间，配音取约 1.26 亿。Trust Wallet 的入侵路径是项目方称（来源卡"Trust Wallet 公告"）。Slope 钱包数"约 9231 个"取 Solana 官方通报。

## 2. 世界与主角（全片固定）

一个连续的等距世界，叫"**钥匙街**"。一条浅灰石板路沿 u（左→右）贯穿，从左到右：**方案陈列馆**（五种放法）、**钥匙流水线**（生命周期）、**冷钱包金库**（开场，居中）、紧挨着金库右侧的**签名台**（核对流程）、最右是**交易所三层钱包**（防御 + 收尾）。开场从中间的金库起，seg2 向左摇到陈列馆，seg3 往右回到流水线，seg4 回到金库旁的签名台（"回到开头的冷钱包"自然成立），seg5 继续往右到交易所。

全片的主角是 kit `hwWallet`（"硬件钱包"）：它在每个区出现，屏幕内容（`screenText`）承担论证，正常时显示可读字段（绿），盲签时只显示一串哈希（灰）或"无法解析"（红）。"钥匙"一律画成 kit `key`（黄铜），被复制或失窃时 `state` attacker（红）。"签名"一律画成 kit `seal` 落章（ID-stamp 下压）。交易一律用 E01 `letter`，攻击者构造的交易用红色 `letter`。

## 4. 各段分镜（按句写；句号见 timing.json 的 lines，从 0 开始）

### seg1 ① 钥匙都在
目标：观众能说出"2024 年 7 月，WazirX 六把钥匙要四把的多签冷钱包损失约 2.3 亿美元，公开材料没说任何私钥被导出"，并带着"私钥都没泄露，攻击者能不能转走资金"往下看。
副标题：钥匙都在，钱没了
**关键画面**：L6 A 区：六把黄铜 `key` 全部亮着绿色地光、一把不少，金库门却敞开、柜内金条点阵飘空。
镜头：起于 A（`CAMS.vaultA`），止于 A（`CAMS.walletsA`）。
- L0 WazirX 多签冷钱包，约 2.3 亿美元：镜头 A 近景；`safe` gold "WazirX 冷钱包"；右上事件卡"WazirX · 2024 年 7 月"；来源卡"Halborn 分析"；23 点红点阵从金库飘出，图例"每点约 1000 万美元"。
- L1 冷钱包放大部分资产，多签不让一把钥匙说了算：signBoard"冷钱包 · 大部分资产"；一把 `key` 单独靠近金库，`thresholdMeter` 不动、灯红。
- L2 六把钥匙，要四把：六个 `person` signer 半圆排开，各自身旁一把 `key`；`thresholdMeter` 刻度"6 选 4"亮起。
- L3 没说任何私钥被导出：六把 `key` 各弹出绿色小勾；来源卡改"公开材料"。
- L4 一个一个签了名：`thresholdMeter` 液位 1→2→3→4 逐格上升，每格对应一个签名人前的 `seal` 落章；签名人前方出现 `browserWin`"签名界面"。
- L5 让钥匙替他签了字：`person` attacker 出现在画面边缘，不碰任何钥匙；一封红 `letter` 从 `browserWin` 后方滑入金库。
- L6 钥匙都在，钱没了：六把 `key` 绿色地光齐亮；金库门开（`open` 105），柜内空。**关键画面**。
- L7 多数大额事故不是私钥被数学破解：`comboDial` 小图标出现在金库旁，转盘完好、绿勾"没被破解"；来源标签"解读"。
