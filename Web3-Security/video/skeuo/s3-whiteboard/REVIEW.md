# REVIEW · s3-whiteboard

成片：`renders/s3-whiteboard.mp4` → `../out/s3-whiteboard.mp4`（ffprobe：47.17 s，h264 + aac）。
`compositions/story.html` 由 `tools/gen-story.mjs` 生成（手抖坐标来自固定正弦表，不用随机数）；改画面请改生成器再 `node tools/gen-story.mjs`。

## 创作取舍
- 白板是一张 3900 px 宽的"世界"，从左到右：签名人 | 保险柜 + 金额 | 纸 | 屏幕。镜头只做 5 次 0.8 s power2.inOut 平移/推拉，画完的东西自身不动。
- 第 0 帧保险柜已画在板上（满足"第 0 帧不空"），日期从 0.70 s 开始写。
- 高潮：operation = 写完后停 0.46 s，镜头在停顿中推到 1.2 倍，让纸上的 `operation =` 和屏幕上的蓝色「转账 ✓」同框，然后红 1 → 红圈 → 箭头 → DELEGATECALL。全片唯一的大红笔画在这里。
- 红色范围：operation = 1 及其衍生（l5 红箭头、红线划掉 实现合约、红字 攻击者合约）和 ④ 红圈。蓝色只给"看到/批准"的东西（勾、屏幕内容）。
- 没做的方案：每句一块新白板（擦了重画）——更像板书但会丢掉"钥匙和纸同框对比"的主线；单屏不平移——放不下 7 个对象。

## 发现与修改
- P0 t=39.5–41.5 · 七格路径 · 多段 path 用一个 pathLength 时 Chrome 的虚线在每个子路径重新计数，七个方格同时冒出来，不是"一笔画" → 生成器把每个子路径拆成单独 `<path>`，D() 按长度分配时长逐笔接力。所有物体（保险柜、签名人、屏幕）因此也按笔画顺序画出。
- P0 t=21.9–23 · 红 1 · 红 1 与红圈压住 `operation =` 的等号，圈顶压到 `(…)` → 1 右移 45 px，圈缩为 74×88 并下移。
- P1 t=21–23 · 推镜 · 第一版 1.35 倍推镜，左边露出半截「亿美元」、右边露出半截屏幕 → 改为 1.2 倍，取景改成纸 + 屏幕「转账 ✓」同框，变成"看到的 vs 签下的"对比；「签名人看到的」挪进屏幕内，避免被上沿裁掉。
- P1 t=24–37 · 柜+纸全景 · 0.85 倍时 slot 0、FBI 口径等小字缩到 26–29 px，画面下半空 → 镜头改 0.9 倍、y+80；小字改为 36–40 px。
- P1 t=33–37 · 「钥匙 ✓」的勾压在「匙」上 → 勾右移 30 px。
- P1 t=18.9 · l4 左边缘露出「元」 → 镜头 x 从 -1990 改 -2060。
- P2 t=0–5 · 保险柜原本到 3.6 s 才补画内仓、密码盘 → 整只柜第 0 帧完整在场，3.60 只写「冷钱包」。

## 仍存在的问题
- 最弱的一段：l1–l2（0–13.5 s）镜头不动，左半边前 9.5 s 只有日期，构图偏右。有更多时间会让 l1 推近保险柜、l2 再拉开给签名人。
- 推镜 1.2 倍时右侧屏幕被裁掉右缘（有意保留屏幕内容，但框不完整）。
- 「风控与审批」「显示与解码」在 190 px 方格里贴边（32 px 字），手机宽度下方格内字偏小。
- 擦除带是一块平的板色，板擦只是两层圆角矩形，近看像个灰块。
- 37 个 clip-path 写字元素接近重叠层阈值；再加字建议改成"板色遮罩 scaleX"写法。
