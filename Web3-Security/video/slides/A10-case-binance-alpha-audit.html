能发现什么？发现不了什么？
  1. 大家好，欢迎来到评估篇第10集，也是评估篇的最后一集，一个实例分析。打开钱包，点开一个代币，有一个 Audit 标签。上面写着风险等级低，一排绿勾。全部绿勾，就能上币吗？
  2. 要回答这个问题，先要知道这些信息从哪里来，它能发现什么，发现不了什么。本集用币安钱包的 Audit 页做实例。先说明，下面标已公开的，来自公开文档和公告；标推断的，是我们根据这些材料的推断。相关产品会更新，请以最新的公开资料为准。

  1. 先打个比方。Audit 页像机场的安检门。它能快速发现金属物品，对应貔貅盘、过高的税率、可以增发这类典型特征。
  2. 它查不出藏在行李里的新型危险品，对应业务逻辑漏洞，以及规则还没收录的后门写法。
  3. 过了安检门，不等于这个乘客可信。没过，就大概率值得多看一眼。
  4. 比喻不准的地方在于，安检是即时的。代币合约在你检查之后，项目方还能升级、改税率、限制流动性。今天通过，不等于明天通过。

五层结构

层级字段含义
是否有结果hasResult · isSupported两者都为真，结果才有效

  1. 先看页面上有什么。币安在公开的技能库里，有一份查询代币审计的接口文档，给出了字段结构，可以分五层。第一层，是否有结果。两个字段，有没有审计数据，这个代币支不支持审计。两者都为真，结果才有效。
  2. 第二层，总体等级，低、中、高三档，对应0到5的数值。第三层，附加信息，买入税、卖出税，以及合约源码是否已验证。
  3. 第四层，风险分为三类，合约风险、交易风险和骗局风险。第五层，每一条细则有是否命中，以及严重程度，分为风险和警告两种。
已公开 · 文档给出的指引 · 示例代币为虚构

等级四档，税率三档

数值等级文档指引
0–1LOW谨慎推进，自己研究
2–3MEDIUM仔细看每个命中项
4HIGH避免交易
5HIGH阻止交易
  1. 等级怎么读？文档给出的指引是这样的。0到1是低，谨慎推进，自己做研究。2到3是中，要仔细看每一个命中项。4是高，避免交易。5也是高，直接阻止交易。
  2. 税率也有口径。卖出税或买入税高于10%属于严重，5%到10%是警告，低于5%可以接受。
  3. 来看一个虚构的示例代币。买入税3%，在可接受范围。卖出税12%，超过10%，属于严重。
  4. 算一下影响。用户买入1000美元，扣3%，到手970美元的代币。如果价格不变就卖出，再扣12%，只剩约853美元，一买一卖损失了接近15%。卖出税远高于买入税，往往是貔貅盘的前兆。
  5. 文档里还有一句很重要的话。低等级不等于安全，结果只是某个时刻的快照。
数据链路 · 已公开 与 推断

从链上数据，到你看到的绿勾

  1. 信息从哪里来？起点是链上和公开的数据，合约的字节码和已验证的源码，交易和持仓的历史，以及部署者的历史地址。
  2. 这些数据进入一个自动化的扫描引擎。它用一组风险规则去检查，有些检查还会模拟交易，比如模拟一次买入再卖出。
  3. 扫描结果通过钱包的安全接口返回，最后显示在 Audit 标签页上，变成绿勾、红标和说明文字。
  4. 扫描能力从哪里来？已公开的是，2025年7月，CertiK 发布公告，说币安钱包集成了它的 Skynet 代币扫描，在代币页新增了 Audit 标签。
  5. 需要注意的是，币安的接口文档没有写明数据供应商。所以，所有链、所有代币，包括 Alpha 代币的结果，是不是都由这一家产生，有没有同时使用别的数据源，都属于推断，不能当作已确认的事实引用。

别混淆

这里的 "Audit" 是扫描，不是审计报告

自动扫描

广度：每个代币都能跑
规则驱动，秒级出结果
时间点快照
不对结论承担审计责任

人工审计报告

深度：一个项目、一个版本
人工审查业务逻辑
有范围、方法、发现、假设
见 A07 的读法
Audit 页是用户保护提示，不代表交易所对该代币做了人工审计背书。Alpha 与主站上币的审核流程也不同。
  1. 这里要特别注意一个用词。页面上叫 Audit，但它是自动扫描，不是审计报告。自动扫描是广度覆盖，每个代币都能跑，规则驱动，秒级出结果，是一个时间点的快照。
  2. 人工审计报告是深度覆盖，针对一个项目的一个版本，人工审查业务逻辑，有范围、方法、发现和假设，读法在第7集讲过。两者的深度、范围和责任完全不同。
  3. 所以，Audit 页是给用户的保护提示，不代表交易所对这个代币做了人工审计背书。另外，Alpha 是早期项目的发现和交易入口，它和主站上币的审核流程也不一样。
能发现什么 · 对照 A05

八条红线，扫描能覆盖几条？

A05 红线扫描通常能否发现说明
可无限增发且无时间锁通常能时间锁是否真实有效，要人工看
貔貅盘通常能文档明确列出的检查项
owner 可冻结任意地址通常能属于中心化风险
隐藏后门 / 升级后门部分代理的实现可后续替换，扫描只看当前版本
升级权为单签个人地址部分能读地址类型；看不出"多签其实一人控制"
锁仓 / 流动性锁是假的较弱要核验锁仓合约与解锁条件
地址与官网不一致不能要人工比对官方渠道
字节码与源码不一致部分"已验证"≠"和审计版本一致"
  1. 把扫描能力对照第5集的八条红线。前三条，可无限增发、貔貅盘、owner 可冻结任意地址，扫描通常能发现。但增发有没有真实有效的时间锁，还要人工看。
  2. 后门和升级后门，只能部分发现。代理合约的实现可以以后再替换，扫描只能看到当前版本。升级权的持有方，扫描能读出地址类型，却看不出一个多签其实由一个人控制。
  3. 锁仓和流动性锁是否真实，扫描能力较弱，要人工核验锁仓合约和解锁条件。合约地址和官网是否一致，扫描不能发现，必须人工比对官方渠道。
  4. 最后，源码已验证，只说明有一份验证过的源码，不等于它和审计报告里的版本一致。八条里，扫描能可靠覆盖的大约三条。
结构性盲区

四个盲区，不是哪一家的问题

1快照
只反映检查时刻
2规则覆盖
只发现已知模式；经济攻击、新写法不在其内
3缺少上下文
看不到项目方的私钥管理和签名流程
4没有结果
"不支持"或"无数据"不能当作"没风险"
  1. 任何自动扫描，都有四个结构性盲区，这不是哪一家产品的问题。第一是快照。比如上午10点检查，等级低，税率为零。下午2点，项目方升级合约，把卖出税改成99%。上午的绿勾已经失效。
  2. 第二是规则覆盖。扫描只能发现已知的模式。新的后门写法，复杂的业务逻辑漏洞，以及第10章讲的经济攻击，都不在其内。
  3. 第三是缺少上下文。扫描看不到项目方的私钥怎么管理、签名流程怎样，而第6集讲过，这是损失最大的来源。
  4. 第四是没有结果的情形。显示不支持审计，或者没有数据时，没有任何结论。千万不能把它当作没有风险。
怎样用在尽调里

扫描结果是分诊，不是结论

  1. 那么评估人员该怎么用它？把它当作尽调的第0步分诊，放在流程的最前面。拿到上币申请，先看扫描结果。
  2. 命中严重项，可以快速按红线处理。但要独立复现，比如读源码，在分叉环境里模拟买卖，因为扫描也会误报。
  3. 没有命中，只说明通过了最低门槛，仍然要走完第5集的全流程，权限、链上数据、运营和经济四个维度。
  4. 显示不支持或者无数据，就当作未评估，必须人工评估。三条路最后都汇到评分卡，结论由你签字。把扫描结果直接当上币依据，等于把交易所的责任外包给一个你无法控制、也没看过规则的黑盒。
对扫描的每类结论，用自己的方法再确认

七项独立验证

1源码与字节码
浏览器验证 + 比对部署字节码
2权限地址
owner、admin、minter；多签阈值、时间锁
3代理实现槽
可否升级、谁可升级
4模拟买卖
分叉环境小额，核对实际税率
5部署者历史
是否部署过被标记的合约
6持仓与流动性
前 10 / 前 50 集中度、流动性锁
7存证带时间
扫描结果、查询时间、链上读数一起放进证据附录
  1. 对扫描给出的每一类结论，都用自己的方法再确认一遍。第一，在区块浏览器确认源码已验证，并比对部署的字节码。第二，读出 owner、admin 和 minter，看是个人地址还是多签，阈值和时间锁是多少。
  2. 第三，查看代理的实现槽，确认能不能升级，谁能升级。第四，在分叉环境里小额模拟买入再卖出，核对实际税率和扫描结果是否一致。
  3. 第五，查部署者地址的历史，是否部署过已被标记的合约。第六，查持仓前10和前50的集中度，以及流动性的锁定。
  4. 第七，存证要带时间。扫描是快照，所以把扫描结果、查询时间和链上读数，一起放进证据附录。

  1. 最后练一练。一个代币的 Audit 页显示等级低，全部绿勾。但它是一个可升级的代理合约，管理员是一个单签的个人地址。按第5集，你的结论是什么？Audit 页为什么没有拦住它？

评估篇 · 完结

本集三件事

  • 先问信息从哪来：区分已公开与推断；回答不了，就只能当提示。
  • 扫描 ≠ 审计；快照要带时间；"无结果"归入未评估。
  • 扫描是第 0 步分诊；结论由你按评分卡得出并签字。
