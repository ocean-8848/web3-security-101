合约安全 · 评估篇 · A09

事故中最稀缺的，
是时间

  1. 大家好，欢迎来到评估篇第9集，应急响应。前面八集都在防止事故。这一集假设，防线已经被突破了。先记住一句话，事故中最稀缺的，是时间。
  2. 算一个示例。一个合约被攻击，攻击者每分钟能转走50万美元。如果你在5分钟内发现并暂停，损失是250万。
  3. 如果60分钟后才发现，损失是3000万，差了12倍。而能在几分钟内暂停合约、联系对的人、做出决定，这些能力必须平时准备好。事故中，来不及临时发明。

  2. 还要平时做演习，真起火时，大家的动作才是肌肉记忆。对应的是桌面推演。

准备阶段 · 写进上线门禁 T04

七个准备项

准备项要求
暂停能力有紧急暂停开关，且与升级权限分离
暂停权限持有人少数可信角色，24 小时可响应
链上限额单笔、单位时间的提取与铸造上限
监控与告警每条告警有负责人和响应时限
联系人清单值班、审计方、安全公司、交易所、发行方、桥、预言机
预案手册角色、权限、决策树、沟通模板
紧急密钥流程紧急操作的密钥保管与启用流程
  1. 上线之前，有七项必须就绪，它们都写进上线门禁。第一，暂停能力。有紧急暂停开关，而且和升级权限分离，下一页专门讲为什么。第二，暂停权限的持有人，少数可信角色，24小时都能响应。
  2. 第三，链上限额，单笔和单位时间的提取、铸造上限。第四，监控和告警，每一条告警都有负责人和响应时限。
  3. 第五，联系人清单。内部值班、外部审计方、安全公司，还有交易所、稳定币发行方、跨链桥和预言机的运营方。出事时没有时间去找邮箱。
  4. 第六，预案手册，写清角色、权限、决策树和沟通模板。第七，紧急密钥的保管和启用流程。不要在事故中，才发现关键的密钥找不到。
设计要点 · 示例配置

一个要快，一个要慢

暂停 · 要快

目的止血，可逆持有人小多签，如 2/4 值班延迟无延迟恢复需要更高门槛

升级 · 要慢

目的改变合约逻辑持有人大多签 + 时间锁延迟如 48 小时可见性公开，用户可退出
混在一起：要么暂停要等 48 小时，要么升级也能秒级完成 —— 两头都不安全。
  1. 为什么暂停和升级要分离？因为它们一个要快，一个要慢。暂停的目的是止血，而且可逆。示例配置是一个小多签，比如4个值班人里任意2个，没有延迟。恢复则需要更高的门槛。
  2. 升级的目的是改变合约逻辑，影响巨大，不可轻易撤回。示例配置是大多签加上48小时时间锁，公开可见，让用户有时间退出。
  3. 如果两者混在一起，要么暂停也要等48小时，事故中完全来不及；要么升级也能秒级完成，攻击者拿到这个权限就能改写一切。两头都不安全。
监控与告警

七类信号，发现要比攻击者快

监控项触发条件 · 示例对应风险
大额转出单笔或单位时间超阈值资金被盗
权限变更owner、admin、签名人、实现地址变化夺权、后门
升级与初始化任何 upgrade、initialize 事件升级攻击
价格异常与参考价偏离、喷价操纵
供应异常增发、桥两侧供应不一致伪造铸造
授权激增大量用户授权给同一陌生地址前端被劫持
冷钱包异动任何一笔交易签名被骗
  1. 监控什么？七类信号。大额转出，单笔或单位时间超过阈值，对应资金被盗。权限变更，owner、管理员、签名人或者实现地址发生变化，对应夺权和后门。
  2. 升级和初始化事件，任何一次都要告警。价格异常，和参考价偏离，或者突然喷价，对应操纵。
  3. 供应异常，代币增发，或者跨链桥两侧的供应量对不上，对应伪造铸造。授权激增，大量用户突然授权给同一个陌生地址，往往意味着前端被劫持了。
  4. 最后是冷钱包异动。冷钱包平时几乎不动，任何一笔交易都应该告警。还要记住，告警发到没人看的频道，等于没有告警。每条告警都要有负责人和响应时限。
响应阶段 · 决策树

先止血，后调查

  1. 告警来了，按决策树走。第一个问题，是真实事件吗？目标是5到15分钟内判断。是误报，记录下来并调整阈值。
  2. 是真实事件，或者无法排除，就问第二个问题，能暂停吗？能，立刻暂停合约，先止血。暂停几乎总是对的第一步，它的代价是业务中断，通常远小于继续失血。
  3. 不能暂停，就降低暴露。比如撤出流动性、撤销授权，或者让交易所下架充提。
  4. 然后评估范围和损失，再问，资金还在被转走吗？如果是，马上联系交易所、稳定币发行方和桥，请求冻结和监控。被盗资金要变现，通常要经过它们。
  5. 之后是沟通与调查，再决定是否与攻击者谈判，最后修复、复审、恢复，以及事后复盘。注意，确认真实这一步不要拖太久。宁可暂停后发现是误报，也不要观望到资金流出。
数字为示例

发现要快，限额要在

  1. 把开场的数字画出来。横轴是时间，纵轴是累计损失。攻击者每分钟转走50万，没有任何限额。
  2. 5分钟发现并暂停，损失250万。60分钟才暂停，损失3000万。
  3. 现在加上一条链上限额，示例里每小时最多转出500万。同样是60分钟才发现，损失也不会超过500万。
  4. 这就是喷淋的意义。人工响应决定你能多快止血，限额决定最坏的情况是多少。两者都要有。
预先回答的问题

暂停不是终点

暂停期间能提款吗？
同时冻结提款，可能引发恐慌
谁有权恢复？条件是什么？
恢复前要完成哪些验证
是否需要补偿或分期恢复？
积压请求一次放开会冲垮流动性
白帽协议：链上留言，提出"归还大部分、保留一笔赏金、不追究"。
是否这样做、怎样措辞 —— 法务与管理层决定，提前沟通，不由技术人员临时决定。
对方若是有组织的国家级团队，谈判成功率低 → 重点转向追踪与联合冻结。所有沟通留痕。
  1. 暂停不是终点。有三个问题要在预案里预先回答。暂停期间，用户能不能提款？如果同时冻结提款，可能引发恐慌。谁有权恢复，条件是什么，恢复前要完成哪些验证？是否需要补偿，或者分期恢复？积压的请求一次放开，可能冲垮流动性。
  2. 还有一个问题，要不要和攻击者沟通。部分事故中，项目方会在链上给攻击者留言，提出白帽协议。通常是归还大部分资金，保留一笔赏金，并承诺不追究。这是常见做法，但是否这样做、怎样措辞，是法务和管理层的决定。要提前沟通好，不能由技术人员临时拍板。
  3. 另外，如果对方是有组织的国家级团队，谈判的成功率很低，重点要转向链上追踪和联合冻结。所有沟通都要留痕。
沟通对象与原则

只说已确认的事实，固定更新节奏

对象内容时机
内部值班与管理层事实、已采取措施、下一步立即
用户已知情况、风险提示、建议操作（如撤销授权）、下次更新时间确认后尽快
合作方与相关协议影响范围、需要它们做的动作尽早
监管与执法法务主导按合规要求
公众事后复盘事态稳定后
原则：已确认的才说 · 不确定就说"正在调查" · 没有证据不指责具体对象 · 固定更新节奏，如每 2 小时
  1. 技术之外还有沟通。对内部值班和管理层，立即同步事实、已采取的措施和下一步。对用户，确认后尽快发布，说清已知情况、风险提示和建议操作，比如撤销对某个合约的授权，并承诺下一次更新的时间。
  2. 对合作方和相关协议，尽早说清影响范围，以及需要它们做什么。监管和执法由法务主导。公众层面的完整复盘，等事态稳定后再发。
  3. 沟通有四条原则。只陈述已确认的事实。不确定的，明说正在调查。没有证据时，不指责具体对象。固定更新的节奏，比如每两小时一次，并且做到。
演练 · 60 到 90 分钟

不动真实系统，围着桌子"演"一次事故

  1. 预案要靠演练才能保持可用。性价比最高的是桌面推演，不动真实系统，大家围着桌子演一次事故，60到90分钟。第一步，选一个场景。比如，监控发现冷钱包向陌生地址发起一笔大额转账，签名人说自己没有操作。
  2. 第二步，主持人逐步释放信息，每10分钟一条新情况。资金还在转吗？前端被改了吗？有人说自己可能被钓鱼了。
  3. 第三步，参与者按预案行动，并说出理由。谁拉暂停，联系谁，对用户怎么说。
  4. 第四步，记录卡点。谁不知道联系人在哪，谁没有权限，预案哪里没写。第五步，复盘后更新预案，每一项指定负责人和期限。
  5. 右边是一个题库，可以轮流演。冷钱包异常转出，代币被升级后增发砸盘，接入的第三方协议被攻破，前端被劫持，预言机喂价异常，关键开发者的电脑被入侵。
Post-mortem · 目的是学习，不是追责

七个部分，最后一部分最重要

1摘要
发生了什么，影响多大
2时间线
精确到分钟：检测、决策、行动
3根因
技术根因 + 流程根因
4影响
资金、用户、业务
5做得好 / 不好
6改进项
每项有负责人和截止日期
7回流到评估体系
暴露了哪个缺失的检查项？更新 A01 清单与 T01
  1. 事故处理完，要写复盘。目的是学习，不是追责。一份合格的复盘有七个部分。摘要，发生了什么，影响多大。时间线，精确到分钟，包括检测、决策和行动。
  2. 根因，分技术根因和流程根因。流程根因回答的是，为什么没有被提前发现。然后是影响，资金、用户和业务。
  3. 做得好的和做得不好的。改进项，每一项都有负责人和截止日期。
  4. 最后一部分最重要，回流到评估体系。这起事故暴露了哪个缺失的检查项？更新评估清单和资料清单。无论是自家的事故还是行业的事故，每一起都应该至少产生一个新的检查项或者不变量。否则，复盘只是一份文档。
练一练 · 暂停视频想一想

凌晨 3 点，冷钱包异动告警，值班人联系不上签名人

预案里缺了什么？
先自己想三条
参考
· 每个签名人有备份联系人与轮值表
· 暂停权限不依赖冷钱包签名人
· 冷钱包大额转出有时间锁，给人留出反应时间
· 推演里从未演过"夜间 + 联系不上"
  1. 来练一练。凌晨3点，监控发出冷钱包异动告警。值班人员打电话给签名人，一个都联系不上。你的预案里缺了什么？可以先暂停想一想。
  2. 参考答案。每个签名人要有备份联系人和轮值表。暂停权限不应该依赖冷钱包的签名人。冷钱包的大额转出要有时间锁，给人留出反应时间。还有，桌面推演里，可能从来没演过夜间加联系不上这种情况。下一次推演，就演它。
小结

记住三件事

  • 能力在上线前备好：暂停与升级分离、限额、有人响应的告警。
  • 先止血，后调查；宁可误停，不要观望。谈判由法务和管理层决定。
  • 推演保持预案可用；复盘必须回流成新的检查项。
