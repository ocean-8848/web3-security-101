本集边界：只分析已公开的事故、验证防御。不对未授权的合约做任何尝试。
  1. 大家好，欢迎来到评估篇第8集，事故分析与防御性验证。先说结论。评估人员不需要会发起攻击，需要会读懂攻击，以及证明防御。

  3. 证明一个修复有效，等于给上线门禁加了一条硬证据。

一句话理解 · 打个比方

消防员不放火，他们复盘火灾

到现场看
起火点、蔓延路径、哪道门没关
→ 读攻击交易，还原时间线
复盘后做两件事
写进检查表 · 演练验证新措施
→ 新检查项 + 防御性测试
比喻不准的地方：火灾现场会被破坏；链上现场永久公开、可逐笔回放。所以更容易"事后诸葛"——要问的是事前有什么信号。
  1. 打个比方，这像消防员复盘火灾。他们不会为了学习去放火，而是到现场看起火点、蔓延路径，哪道防火门没关。
  2. 复盘之后做两件事。把起火点写进检查表，以后专门查同类隐患。再做演练，验证新措施有效。
  3. 比喻不准的地方在于，火灾现场会被破坏，链上现场却永久公开，可以逐笔回放。所以复盘比消防更精确，也更容易事后诸葛亮。你要问的不是当时为什么没想到，而是事前有什么信号。
方法 · 拿到一个交易哈希之后

五步，从"发生了什么"到"我怎么提前发现"

  1. 拿到一个攻击交易的哈希，按五步读。第一步，定位。交易在哪个区块，发起人是谁，受害的是哪个合约。
  2. 第二步，看资金流。谁付出了，谁收到了，多少。发起地址的资金来源，常常是混币器或者刚创建的新地址。前两步只需要区块浏览器。
  3. 第三步，看调用树。哪个函数被调用，顺序和深度是什么。这一步需要交易追踪工具，或者浏览器自带的内部交易视图。看调用树，比看反编译代码快得多。
  4. 第四步是核心，找出不该发生的那一步。用一句话写出，协议原本假设了什么，这个假设在哪里不成立。
  5. 第五步，翻译成检查项。我的评估，怎样能提前发现它。没有这一步，复盘只是看热闹。
示例 · 简化自公开复盘的借贷事故 · 结构示意

在调用树里找"不该发生的一步"

  1. 来看一棵简化的调用树，结构来自一起公开复盘过的借贷事故。最外层是攻击合约的入口，它先借了一笔闪电贷。
  2. 接下来是一串对借贷协议的正常调用。存入、借出，每一步单独看都合法，余额和事件也都符合预期。
  3. 然后出现了这一步，调用捐赠函数，把一部分抵押品捐给储备金。注意它后面没有任何健康因子的检查。账户从这里开始资不抵债。
  4. 这就是不该发生的一步。写成一句话，协议假设所有减少抵押品的路径都会检查健康，而这个新函数打破了它。之后的清算和归还闪电贷，只是把这个缺口兑现成利润。

修复补上检查
  1. 每起事故用同一张表记录。表头固定，才能把不同事故横向比较。以刚才那起为例。事故是 Euler Finance，2023年3月，损失约1.97亿美元。漏洞类别是缺少健康检查。
  2. 被打破的假设，任何减少抵押品的路径最后都检查健康因子。事前信号，这是一个新增的函数。
  3. 对应的检查项，是第4集借贷清单的第三项。对应的不变量，任何操作之后，账户健康因子不小于1。
  4. 事前信号这一栏最难填，也最有价值。很多事故的信号其实早就公开了，比如未审计的新代码，单签权限，过短的时间锁，被忽视的审计发现。修复一栏反而最简单。
不变量 · 任何操作序列后都必须成立

几乎每起事故，都是一条被打破的不变量

事故类型被打破的不变量（业务语言）
重入外部调用返回时，账本余额与实际余额一致
金库通胀每份价值不会因一笔捐赠而大幅跳变
借贷坏账任何操作后，健康因子不低于清算线
预言机操纵同一区块内价格偏离参考价不超过阈值
桥伪造目标链铸造总量 ≤ 源链锁定总量
权限只有授权角色能改权限和升级实现
AMM每次交换后恒定乘积不减
  1. 不变量，是任何操作序列之后都必须成立的条件。几乎每一起事故，都能翻译成一条被打破的不变量。重入，打破的是外部调用返回时，账本余额和实际余额一致。金库通胀，打破的是每份价值不会因一笔捐赠而大幅跳变。
  2. 借贷坏账，健康因子不低于清算线。预言机操纵，同一区块内价格偏离参考价不超过某个阈值。
  3. 跨链桥伪造，目标链铸造的总量，不超过源链锁定的总量。这条特别好，它和代码怎么写无关，只和账能不能对上有关。
  4. 权限类，只有授权的角色能修改权限和升级实现。AMM，每次交换后恒定乘积不减。第1集的 Uranium，正是这一条。
写不变量

先用业务语言写一句话

1先业务语言，再代码断言
写不出一句话，说明还没理解协议
2覆盖所有入口函数
不只是你担心的那一个 · Euler 的问题就在"另一个"函数
3不依赖实现细节
描述"什么必须永远为真"，不是"这行怎么写"
  1. 写不变量有三条规则。第一，先用业务语言写一句话，再翻译成代码断言。如果你写不出这一句话，说明你还没理解这个协议。
  2. 第二，不变量要覆盖所有入口函数，而不是只覆盖你担心的那一个。Euler 的问题，恰恰出在另一个函数上。
  3. 第三，好的不变量不依赖实现细节。它描述的是什么必须永远为真，而不是这一行代码应该怎么写。这样，代码重构了，不变量依然有效。
不变量测试 · 示意

你负责把性质写对，工具负责乱调用

  1. 写好不变量之后，交给模糊测试器。它会随机地组合调用各个入口函数，随机的参数，随机的顺序。
  2. 每一次调用之后，它都检查一遍你写的不变量。成千上万条序列跑下去，大部分都是绿的。
  3. 某一条序列里，不变量突然不成立了。工具会把这条序列保存下来，并且自动缩短，找出最短的那几步。这几步，就是一条需要你分析的发现。
  4. 注意分工。你的工作是把性质写对，而不是手工构造攻击步骤。这正是防御性验证和写攻击程序的区别。
验证修复 · 最小流程

"已修复"需要证据

1读补丁差异

没有回归
3补一条回归测试

4不变量持续运行
覆盖修复周围的路径
5分叉环境核对配置
已部署合约的权限、参数、实现地址
6复审入档
报告里标明验证方式
  1. 项目方说已修复，你需要证据。最小流程有六步。第一，读修复补丁，只看相对审计版本的差异。补丁是否只改了必要的部分，有没有顺手改了别的。第二，跑原有测试，确认没有回归。
  2. 第三，补一条针对这个发现的回归测试，用断言表达这个性质现在成立。这条测试应该在修复前失败，修复后通过。下一页专门讲为什么。
  3. 第四，让不变量和模糊测试跑足够久，覆盖修复周围的路径。第五，对已经部署的合约，在主网分叉环境里读取权限、参数和实现地址，确认和预期一致。
  4. 第六，复审结论入档，写进报告的修复状态一栏，并标明是用什么方式验证的。
关键 · 回归测试的标准

只"修复后通过"的测试，可能什么都没测到

修复前的代码
修复后的代码
测试 A
测试 B
  1. 为什么强调修复前失败、修复后通过？看两条测试。
  2. 测试 A，在修复后的代码上跑，通过了。项目方说，你看，测试是绿的。
  3. 但把测试 A 拿到修复前的代码上跑，它也通过了。这说明什么？说明它根本没有触及那个问题。它是绿的，和修复无关。
  4. 测试 B，在修复前的代码上失败，在修复后的代码上通过。只有这样，才能证明测试确实捕捉到了这个问题，而修复确实解决了它。
  5. 最后提醒一个局限。测试只能证明你想到的性质成立。它不能证明不存在其他问题。所以复审不是测试全绿就结束。
验证等级

不同风险，需要不同强度的证据

验证等级含义用在哪
已读代码人工审查，认为已修复低风险发现
已回归测试修复前失败、修复后通过中、高风险
已不变量验证对应性质被持续测试覆盖高危、严重
已分叉验证已部署合约在分叉环境确认上线门禁
未验证只有项目方声明门禁中视为未关闭
  1. 报告里写已修复时，要写清验证到什么程度。最弱的是已读代码，人工看过，认为修好了，用于低风险发现。
  2. 中高风险至少要已回归测试，有一条修复前失败、修复后通过的测试。高危和严重的发现，要已不变量验证，对应的性质被持续的测试覆盖。
  3. 上线门禁，还要已分叉验证，在分叉环境里确认已部署合约的配置和行为。
  4. 最后一种是未验证，只有项目方一句口头声明。它必须在报告里明确标注，并且在门禁里视为没有关闭。

练一练 · 不看结果，只看事前信息

如果是你做评估，会怎么判？

案例事前可见的信息你的评估结论
Nomad 桥 · 2022一次升级把某个初始化值设成了零值初始化参数评审：零值会不会被当作"已证明"

Bybit · 2025Safe 多签，签名人依赖网页界面展示交易签名流程：独立解码、带外确认
  1. 最后练一练事前信号。规则是不看结果，只看事前能看到的信息。第一个，Nomad 桥，2022年。一次升级里，把某个初始化值设成了零值。你的评估结论应该是，初始化参数要评审，特别是零值会不会被当作已经证明。
  2. 第二个，Ronin，9选5，多把钥匙由同一机构控制，一份临时授权没有撤销。结论是签名人独立性不足。
  3. 第三个，Bybit，Safe 多签，签名人依赖网页界面来展示交易内容。结论是签名流程缺少独立解码和带外确认。用手册的事故浏览器按类别筛选，对比同类事故的事前信号，比记住单个案例更有用。
小结

记住三件事

  • 五步读交易，核心是找出被打破的假设，并写回检查项。
  • 把事故翻译成不变量；你写性质，工具找序列。
  • 修复的证据是修复前失败、修复后通过；未验证即未关闭。
