合约安全 · 评估篇 · A05

五个工作日，
判断一个币能不能上

审不完
代码几万行，时间只有几天
改不了
你没有权力让项目方改代码
对方可能就是攻击者
貔貅盘、跑路盘、后门
  1. 大家好，欢迎来到评估篇第5集，上币与合作项目尽调。设想一个场景。业务方转来一个上币申请，给你五个工作日，要一个结论，能不能上。
  2. 你面对两个限制。审不完，对方代码可能几万行，时间只有几天。改不了，你没有权力让项目方修改代码。
  3. 还有一点和审计完全不同。你要假设，项目方本人就可能是攻击者。所以尽调的任务不是证明代码安全，而是用有限的时间判断，上了这个币，用户和交易所会不会遭受不可接受的损失。

比喻不准的地方：租客一般不会主动害你。尽调要假设项目方就是攻击者本人。
  1. 打个比方，尽调像房东查租客。房东不会把租客的人生查个底朝天，他没那个时间，也没那个权力。他只查几件决定性的事。能不能按时付租，对应经济模型。有没有前科，对应链上的劣迹。
  2. 这房子他会不会转手就卖了，对应代币能不能增发、所有权能不能转移。钥匙还在谁手里，对应权限和锁仓。
  3. 任何一条踩红线，直接拒绝，不需要查完其余。
  4. 比喻不准的地方在于，租客一般不会主动伤害你。上币尽调却要假设，项目方可能就是攻击者本人。
尽调结构

先过红线，再打分

  1. 尽调有四个维度。第一是合约权限，谁能动代币和资金。第二是链上数据，部署时间、持仓、流动性和历史。
  2. 第三是团队与运营，身份、安全实践和审计。第四是经济模型，代币分配、释放和用途。四个维度的证据来源不同。权限和经济看代码和文档，链上数据看区块浏览器，团队运营靠问卷和公开信息。
  3. 注意顺序。红线检查在打分之前。任何一个维度踩了红线，直接否决，不进入评分。
  4. 没有红线，才用评分卡打分，得出风险结论。还有一点，尽调结论有时效。代币可以升级、可以增发时，今天的结论明天可能失效，这本身就是一个高风险项。
红线 · 任一命中即否决或暂缓

八条红线：前四条

1可无限增发，且无时间锁读 mint 权限，看 owner 和 minter
2貔貅盘：能买不能卖分叉环境模拟买入再卖出；查转账税、黑名单、暂停
3owner 可冻结任意地址包括交易所的热钱包
4隐藏的所有权转移或升级后门代理、delegatecall、未初始化、自毁
  1. 来看八条红线，任一命中就否决或暂缓。第一条，代币可以无限增发，而且没有时间锁。项目方可以随时稀释，等于随时跑路。读一下增发函数的权限，看 owner 和 minter 是谁。
  2. 第二条，貔貅盘，就是能买不能卖。怎么查？在分叉环境里模拟一次买入，再模拟卖出。同时检查转账税、黑名单和暂停开关。
  3. 第三条，owner 可以暂停或冻结任意地址的转账。这包括交易所的热钱包。用户充进来的币，可能某天就提不出去了。
  4. 第四条，隐藏的所有权转移或者升级后门。检查代理合约、delegatecall、未初始化的合约和自毁函数。合约的行为可以被悄悄改变，就是红线。
红线 · 任一命中即否决或暂缓

八条红线：后四条

5升级权是单签个人地址读实现槽、管理槽；无延迟可升级
6锁仓或流动性锁是假的核验锁仓合约、解锁时间、LP 是否真锁
7地址与官网、审计报告不一致逐一核对
8字节码与已验证源码不一致部署的不是审计的
所有检查都在对方给出的部署地址上做，不是在 GitHub 仓库上做。
  1. 第五条，代理合约可以升级，而且升级权是一个单签的个人地址，没有延迟。这把私钥一旦被盗，或者项目方作恶，就能全盘失控。
  2. 第六条，锁仓或流动性锁是假的。要核验锁仓合约的地址、金额和解锁时间，以及流动性代币是不是真的被锁住。
  3. 第七条，合约地址和官网、审计报告里的不一致，这是常见的调包手法。第八条，链上部署的字节码和已验证的源码不一致，部署的根本不是审计的那份代码。
  4. 注意，红线检查要在对方给出的部署地址上做，不能在 GitHub 仓库上做。用户交互的是部署在链上的合约，不是仓库里的代码。
真实案例 · 2021-11 · SQUID 代币 · 据公开报道

价格一路上涨，因为没人能卖

  1. 来看一个真实案例，以下据公开报道。2021年秋天，一个借热门剧集名字的代币 SQUID 上线。几天内，价格从不到1美分，涨到2800多美元。
  2. 价格为什么能一直涨？因为合约限制了卖出，普通持有人只能买，不能卖。没有卖盘，价格自然只涨不跌。
  3. 11月1日，开发者把流动性池里的资金全部取走，价格在几分钟内跌到接近零。据报道，开发者卷走约338万美元。
  4. 这正是第二条红线。用一次模拟就能发现。在分叉环境里买入一小笔，再尝试卖出。卖出失败，或者卖出税高得离谱，尽调到此结束，结论是否决。
评分卡 · 权重为示例

没有红线，再给四个维度打分

  1. 红线全部通过，再用评分卡打分。示例权重是这样的。合约权限占30%，看增发、暂停、升级权限由谁持有，是个人地址、多签、时间锁，还是已经放弃。
  2. 链上数据占25%，看部署时长、持仓集中度、流动性深度和锁定，以及历史异常交易。
  3. 团队与运营占25%，看身份公开程度、私钥和多签实践、审计情况和漏洞赏金。经济模型占20%，看代币分配、解锁曲线，以及收益来源是否可持续。
  4. 注意，权重是示例。交易所应该按自己的风险偏好和上币层级来设定，然后固定下来。评分卡的价值在于一致性，不同项目用同一把尺子，而不在于绝对数值。
锚点示例 · 合约权限 · 升级权限持有方

每个分数都要对应一个具体情形

4不可升级，或升级权已放弃
3多签 + 时间锁 48 小时以上
2多签没有时间锁，或时间锁较短
1单签多方，或时间锁少于 24 小时
0单签个人地址，可无延迟升级 已是红线
  1. 打分不能凭感觉，每个分数都要对应一个具体情形，这叫锚点。以合约权限里的升级权限为例。4分，合约不可升级，或者升级权已经放弃。
  2. 3分，多签加上48小时以上的时间锁。2分，多签但没有时间锁，或者时间锁较短。
  3. 1分，单签多方，或者时间锁少于24小时。0分，单签的个人地址，可以没有延迟地升级。这其实已经命中第五条红线了。
  4. 有了锚点，两个不同的评估人给同一个项目打分，结果会基本一致。这就是评分卡要的一致性。
计算示例 · 数字为示例

从各项得分到结论

维度权重各项得分得分率加权
  1. 算一个示例。合约权限有两项，升级权2分，增发和暂停权3分，合计5分，满分8分，得分率62.5%，乘以权重30，得18.75分。
  2. 链上数据三项，部署时长1分，持仓集中度2分，流动性2分，合计5分，满分12分，得分率约41.7%，乘以25，约10.4分。
  3. 团队运营三项，合计6分，得分率50%，加权12.5分。经济模型两项，合计5分，得分率62.5%，加权12.5分。
  4. 四项加起来，约54.2分。示例规则是75分以上可以上线，55到75附条件，55以下暂缓。54分，结论是暂缓，列出需要补充的材料和整改项。
  5. 再强调一次。如果这个项目命中任何一条红线，哪怕综合分是90分，结论也是否决。红线优先于分数。
链上取证 · 最省时、最难造假

七项链上证据

查什么怎么查关注
部署信息创建交易、创建者、时间刚部署几天，风险高
源码验证浏览器验证状态；比对字节码未验证或不一致
持仓集中度前 10 / 前 50 地址占比高度集中 → 砸盘风险
流动性池子深度；LP 代币持有与锁定浅池易被操纵
权限地址读 owner、admin、minter个人地址减分
历史行为关联地址；是否与已知劣迹地址交互跑路史、黑客地址
锁仓真实性锁仓合约、金额、解锁时间假锁仓
  1. 尽调中最省时间、也最难造假的证据，来自链上。第一，部署信息。看创建交易、创建者和时间。刚部署几天的项目，风险高。第二，源码验证状态，再比对一下字节码。
  2. 第三，持仓集中度，看前10和前50个地址的占比。高度集中，意味着砸盘风险。第四，流动性，看池子深度，以及流动性代币在谁手里，有没有锁。浅池子很容易被操纵价格。
  3. 第五，权限地址。读出 owner、admin 和 minter，看它们是个人地址还是多签。第六，历史行为，看关联地址的历史，有没有跑路史，有没有和已知黑客地址交互过。
  4. 第七，锁仓的真实性，核验锁仓合约、金额和解锁时间。另外，对方提供的审计报告也要独立核验。审计方可不可信，审的是不是这个版本，报告里有哪些已确认但没修的风险。
团队与运营 · T05 问卷

答不上来，本身就是风险信号

私钥与多签
签名人几个？是否独立？硬件钱包、MPC、HSM？
部署与升级
流水线谁能改？CI 密钥怎么管？
前端与域名
托管、DNS、npm 依赖的保护
社会工程
假招聘、假承包商的防范
应急能力
有暂停开关吗？有预案吗？
合作越深 —— 共同部署、共享金库、提供流动性 —— 对方的运营安全越会传导给交易所。
  1. 团队与运营这一维，主要靠问卷。问五类问题。私钥和多签怎么管理，签名人有几个，是否独立，用不用硬件钱包。部署和升级的流水线，谁能改，持续集成的密钥怎么管。
  2. 前端托管、域名解析和依赖库怎么保护。团队对假招聘、假承包商这类社会工程，有没有防范。
  3. 还有应急能力，有没有暂停开关，有没有预案。
  4. 问卷答案很难完全核实。但答不上来，或者没有任何措施，本身就是风险信号。还要注意，合作越深，比如共同部署、共享金库、提供流动性，对方运营上的薄弱，就越会传导给交易所。

3上线条件

附条件示例：先进观察区 · 单用户单日充值上限 · 监控 owner 与实现地址变更 · 项目方 30 天内补交审计
  1. 尽调的交付物短小、可执行。第一是一页结论，上、附条件上、暂缓或者否决，加一句话理由。第二是评分卡，四维得分和红线检查结果。
  2. 第三是上线条件，只在附条件时需要。举个示例，先进观察区，设单用户单日充值上限，监控 owner 和实现地址的变更，要求项目方30天内补交审计报告。
  3. 第四是证据附录，包括链上地址、权限读数、持仓截图和问卷答案。证据要带时间，因为链上状态会变。
练一练 · 暂停视频想一想

综合分 88，但升级权是一个单签个人地址

经济模型漂亮、团队公开、两家审计、持仓分散。

唯独：代理合约的升级权在一个单签个人地址，没有时间锁。
否决或暂缓

第五条红线命中。
其余 88 分都建立在"合约不会被改"的前提上 —— 而这个前提由一把私钥决定。
  1. 来练一练。一个项目综合评分88分。经济模型漂亮，团队公开，有两家审计，持仓也分散。唯独代理合约的升级权，在一个单签的个人地址上，没有时间锁。结论是什么？
  2. 结论是否决，或者暂缓到对方整改。因为第五条红线命中了。为什么一条红线能推翻88分？因为其余的分数，全都建立在合约不会被改这个前提上。而这个前提，由一把私钥决定。升级一次，审计、经济模型、持仓分布，全部可以作废。
小结

记住三件事

  • 尽调的结论是风险能否接受，不是代码是否安全。
  • 红线优先于分数；所有检查在部署地址上做。
  • 评分卡靠锚点保证一致；附条件就写清限额与监控。
