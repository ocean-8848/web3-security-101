一句话理解 · 打个比方

智能合约像广场中央的自动售货机

装着真金白银
→ 合约余额
电路图贴在外壳
→ 代码公开
谁都能来拍打
→ 任何人可调用
装好就不能维修
→ 不可变；维修门的钥匙成了目标
吐错钱没客服
→ 交易不可逆
比喻不准的地方：售货机一次服务一个人；合约在一笔交易里可以被同一个人反复调用、嵌套调用，还能和几十台"售货机"组合使用。
  1. 打个比方。智能合约像一台放在广场中央的自动售货机。机器里装着真金白银，就是合约的余额。机器的电路图贴在外壳上，谁都能看，因为合约代码是公开的。
  2. 全世界的人都可以全天候来投币、按按钮、拍打机器，因为任何人都可以调用公开函数。
  3. 机器一旦装好，就不能打开维修，合约默认不可变。如果留了一扇维修门，也就是升级功能，那么维修门的钥匙本身就成了攻击目标。
  4. 机器吐错了钱，没有客服可以追回，因为交易不可逆。
  5. 比喻不准的地方在于，真实的售货机一次只服务一个人。合约在一笔交易里，可以被同一个人反复调用、嵌套调用，还可以和其他几十台售货机组合使用。这种可组合性，正是很多漏洞的来源。
对比

没有防火墙，不能回滚，攻击几乎不要本钱

维度Web2 后端CEX智能合约
代码是否公开通常不公开不公开字节码一定公开
谁能调用鉴权用户KYC 用户任何地址、任何合约
出错能否回滚改数据库改内部账本不可逆
修复速度分钟级热修复分钟级要有升级权限
攻击成本绕过防火墙盗号或攻破内部系统一笔交易的 gas
失败后果数据泄露平台赔付资金被转走，通常无赔付
  1. 和 Web2 后端、中心化交易所相比，合约有几个根本不同。第一，代码公开。合约的字节码一定公开，源码通常也公开。攻击者和你看的是同一份代码。
  2. 第二，谁都能调。Web2 的接口要先鉴权，交易所要先做身份认证。合约的公开函数，就是对全世界开放的接口，任何地址、任何合约都能调用。没有边界防火墙。
  3. 第三，不能回滚。Web2 出错可以改数据库，交易所可以改内部账本。合约交易不可逆，修复只能靠升级，没有升级权限就修不了。
  4. 第四，攻击成本极低。攻击者只需要一笔交易的 gas 费。失败的后果也不同，资金被直接转走，通常没有赔付。下面算一算，为什么连本金都不需要。
闪电贷 · 数字为示例

一笔交易里，借一个亿

  1. 闪电贷，是在同一笔交易内借出、并且必须归还的无抵押贷款。交易结束时没还上，整笔交易回滚，就像什么都没发生过。
  2. 来算一个示例。攻击者借1亿美元的稳定币，示例手续费是万分之五，就是5万美元。
  3. 他用这1亿去推动一个价格，或者撑大一个余额，在同一笔交易里，从某个协议里取出比应得更多的钱，然后归还1亿，加5万手续费。
  4. 如果失败呢？交易回滚，他只损失 gas 费。成功了，赚走差价。所以，凡是按当前余额或当前价格计算的量，在攻击者眼里都是可控的输入。这在第7集详细讲。
一笔交易经过哪些环节

红色是信任边界，漏洞最集中

  1. 一笔交易从发出到执行，会经过这些环节。用户或攻击者的账户，先经过钱包和前端的签名界面，然后进入内存池公开排队，再由区块构建者或者排序器决定顺序，最后到达目标合约。
  2. 目标合约会调用外部合约，比如代币、DEX 和预言机。注意这条回来的箭头，外部合约可以在你的函数执行中途调回来。重入就发生在这里。
  3. 目标合约可能是一个代理，背后有升级权限。它还可能通过跨链桥，把消息发到另一条链上的合约。
  4. 红色的节点是信任边界，数据和控制权在这里跨越，漏洞最集中。签名界面、内存池、外部合约、升级权限和跨链桥。还要注意，这张图没画链本身的共识层。链被攻破时，合约代码再正确也没用。

  1. 漏洞可以分六大类。第一类，控制流，外部调用让攻击者插队执行，比如重入和回调。第二类，权限，不该调用的人调用了，比如缺少修饰器、用了交易发起人做鉴权，或者合约没初始化。
  2. 第三类，数学，数字算错了，比如溢出、精度损失、舍入方向和金库通胀。第四类，数据可信度，合约相信了可以被操纵的数据，比如现货价格、闪电贷撑大的余额、被重放的签名。
  3. 第五类，经济设计，代码完全按规格执行，但规格本身可以被套利，比如治理攻击和清算漏洞。第六类，系统与运营，代码之外的环节失守，比如跨链验证、多签私钥、前端篡改，甚至编译器的 bug。真实事故通常是多类叠加，所以审计不能只按清单逐项打勾。
威胁建模的起点 · 默认假设

攻击者能做到的七件事

默认能
  1. 用任意参数调用任意公开函数
  2. 部署自己的合约，让你调用它
  3. 在一笔交易内借到巨额资金
  4. 看到内存池，在别人交易前后插队
  5. 不经你的函数，直接向你转入代币
  6. 读取你合约的全部存储，包括 private
  7. 在另一条链、另一个合约上重放你的签名
通常不能
  • 伪造他人签名 除非私钥泄露或验证写错
  • 修改已确认的区块 除非共识被攻破
  • 让 msg.sender 变成别人 除非用了 tx.origin
  1. 威胁建模的起点，是攻击者能做什么。对任意一个合约，默认攻击者能做到七件事。第一，用任意参数调用任意公开函数。第二，部署自己的合约，让你的合约去调用它，比如恶意代币和恶意回调。
  2. 第三，在一笔交易内借到巨额资金。第四，看到内存池里待确认的交易，在它前后插入自己的交易。
  3. 第五，不经过你的函数，直接向你的合约转入代币。很多合约把余额当作账本，这一条就会打破它。第六，读取你合约的全部存储，包括声明为 private 的变量。第七，在另一条链或另一个合约上，重放你签过的消息。
  4. 攻击者通常不能做到的有三件。伪造别人的签名，除非私钥泄露或者签名验证写错了。修改已经确认的区块，除非链的共识被攻破。让消息发送者变成别人，除非你的代码用了交易发起人来鉴权。
示例 · 第六件事

private 只限制其他合约调用，不限制任何人读取

uint256 private secret = 42; // slot 0address private owner; // slot 1
  1. 来看第六件事的一个示例。一个合约声明了一个私有变量，值是42，放在存储的第0个槽位。
  2. private 这个关键字，只是不让其他合约通过函数读取它，并不是加密。
  3. 任何人都可以调用节点的一个标准接口，读取这个合约第0个槽位的原始数据。返回的值，末尾是十六进制的2a，也就是42。
  4. 所以，永远不要把密码、随机数种子或者私钥放在合约存储里，哪怕声明为 private。链上没有秘密。
方法 · 不变量是锚点 · 数字为示例

先写出"必须恒成立的式子"

1资产清单
2入口函数 · 谁能调
3不变量
4外部调用前状态更新了吗
5外部数据能被操纵吗
6特权私钥在谁手里
  1. 知道了攻击者的能力，就可以做威胁建模，一共六步。第一，列出合约持有的资产，比如用户存入的 USDT 和协议手续费。第二，列出每个改变资产的函数，标注谁可以调用。
  2. 第三步最关键，写出不变量，也就是任何操作之后都必须成立的式子。比如，合约的 USDT 余额，不小于所有用户存款之和。示例里三个用户分别存了100、250和50，合计400，合约余额也是400，成立。
  3. 假如某个提款函数有 bug，让一个用户多提了50。账本上存款之和还是400，合约余额却只剩350。不变量被打破，问题就暴露了。不变量是整个安全工作的锚点，所有测试最终都在验证它。
  4. 后三步，对每个函数问三个问题。外部调用之前，状态更新了吗？价格、余额、签名这些外部数据，一笔交易内能被操纵吗？每个特权角色的私钥在谁手里，被盗后最大损失是多少？
据公开报道 · 金额为事发时估值

从代码漏洞，转向桥和运营

  1. 看损失的趋势，以下据公开报道和安全公司统计。早期事故集中在代码漏洞。2016年 The DAO 是重入。2017年 Parity 多签库被自毁，约51万个 ETH 被永久冻结，根因是初始化和权限。
  2. 2021到2022年，最大的事故转向跨链桥。Poly Network 约6.1亿美元，后来归还了。Ronin 约6.2亿美元。BNB Chain 的 Token Hub 被凭空增发了200万个 BNB。
  3. 2023年，Euler 约1.97亿美元，是业务逻辑问题。2025年，Bybit 约14.6亿美元，问题在签名界面，代码审计覆盖不到。
  4. 同在2025年，成熟协议 Balancer 因为舍入问题损失约1.28亿美元。所以数学精度类漏洞并没有消失。编译器和库成熟后，简单的代码漏洞少了，但最大的损失转向了跨链桥和运营安全。
扩展视角 · 链专题 C00–C03

"EVM 兼容"不等于"行为一致"

链类型和以太坊的关系学习重点
以太坊L1 · EVM 原件参照环境多数漏洞模式的首发地
BNB Chain独立 L1 · EVM 兼容字节码兼容，参数不同分叉项目改参数、低流动性预言机
TRON独立 L1 · TVM可编译，部分语义不同USDT 返回值、能量、账户权限
Mantle以太坊 L2原生 gas 是 MNTmsg.value 是 MNT、L2 信任假设
  1. 本系列的扩展案例以以太坊为参照，再延伸到三条链。以太坊是一层网络，EVM 的原件，绝大多数漏洞模式都在这里首发。
  2. BNB Chain 是独立的一层网络，EVM 兼容，字节码兼容，但出块时间等参数不同。重点是分叉项目改参数出错，以及低流动性的预言机。
  3. TRON 用的是 TVM，Solidity 可以编译，但部分操作的语义不同。重点是 USDT 的返回值、能量模型和账户权限。
  4. Mantle 是以太坊的二层网络，原生 gas 代币是 MNT，所以合约里收到的原生币是 MNT，不是 ETH。把以太坊上审计过的合约原样部署到另一条链，审计结论不能直接复用。
练一练 · 暂停视频想一想

为一个借贷协议写出三个不变量

1偿付
协议持有的资产 + 未偿借款 ≥ 用户存款总额
2健康
任何操作后，每个账户的健康因子 ≥ 1，否则交易回滚
3守恒
份额总量 = 每个用户份额之和；没有凭空增减
  1. 来练一练。为你熟悉的借贷协议写出三个不变量。先暂停想一想。
  2. 参考答案。第一，偿付，协议持有的资产加上未偿还的借款，不小于用户存款总额。第二，健康，任何一次操作之后，每个账户的健康因子都不小于1，否则交易回滚。第三，守恒，份额总量等于每个用户的份额之和，不会凭空增加或减少。后面每一集讲的漏洞，几乎都是在打破这样的某一条式子。
小结

记住三件事

  • 合约是公开、不可撤回、直接控制资金的代码，任何人可用任意参数调用。
  • 从攻击者能控制什么出发建模；链上没有秘密，闪电贷让本金不是门槛。
  • 不变量是锚点；最大的损失正在转向跨链桥和运营。
