舍入误差被批量放大
  1. 大家好，欢迎来到主线第6集，算术与精度。一句话理解，EVM 只有整数，每一次除法都会丢掉余数。丢掉的余数归谁，决定了谁能从协议里慢慢抠出钱。
  2. 看三起事故，以下据公开报道。2018年，BEC 代币的一次乘法溢出，结果回绕成零，攻击者凭空增发了天量代币。
  3. 2023年，KyberSwap 损失超过4800万美元。一处本该向上取整的地方，写成了向下取整。
  4. 2025年，成熟协议 Balancer 损失约1.28亿美元。单步可以忽略的舍入误差，在批量交换里被放大了。
一句话理解 · 打个比方

一张披萨切 8 块，你付了 1/3 张的钱

给 2 块还是 3 块？
8 × 1/3 = 2.67
→ 舍入方向
店员总往多了给
聪明顾客反复买 1/3 张
→ 往返套利
整张只切 1 块，再塞进 100 张
下个顾客付 99 张，分不到一块
→ 金库通胀攻击
比喻不准的地方：披萨店会被投诉。合约里，每次多拿 1 个最小单位的操作，可以在一笔交易里重复几千次。
  1. 打个比方。一家披萨店按块卖，一张披萨切8块。你付了三分之一张的钱，8乘以三分之一是2.67块。店员必须决定，给你2块还是3块。这就是舍入方向。
  2. 如果店员总是往多了给，聪明的顾客就会反复买三分之一张，每次多拿一点。这就是往返套利。
  3. 更狠的是，第一个顾客买下整张披萨，只让切成1块，然后往盒子里偷偷塞进100张披萨。下一个顾客付了99张的钱，因为1块的价值是101张，他一块也分不到。这就是后面要讲的金库通胀攻击。
  4. 比喻不准的地方在于，披萨店会被投诉。合约里，每次多拿一个最小单位的操作，可以在一笔交易里重复几千次。

五类缺陷

缺陷例子后果
① 溢出 / 下溢0.8 之前的 a × b；之后的 unchecked回绕成极大值或 0
② 类型截断uint128(x)、有符号转无符号静默丢掉高位
③ 先除后乘a / b × c精度损失被放大 c 倍
④ 舍入方向错误存款时份额向上取整每次操作泄漏 1 单位
⑤ 单位不一致6 位精度当 18 位算偏差 10¹² 倍
  1. 数学缺陷可以分五类。第一，溢出和下溢，比如0.8版本之前的乘法，或者0.8之后写在 unchecked 块里的运算，结果会回绕成极大值或零。第二，类型截断，比如把一个大整数转成128位，高位被静默丢掉。
  2. 第三，先除后乘，精度损失会被放大。第四，舍入方向错误，比如存款时份额向上取整，每次操作都向用户泄漏一个单位。
  3. 第五，单位不一致，比如把6位精度的 USDT 当成18位来算，偏差是10的12次方倍。下面一类一类用数字看。
真实案例 · 2018-04 · 据公开报道

2 × 2255 = 2256，回绕成 0

// Solidity 0.4，无溢出检查uint256 amount = cnt * _value;require(balances[msg.sender] >= amount);balances[msg.sender] -= amount;for (...) balances[r[i]] += _value;
  1. 先看溢出。2018年的 BEC 代币有一个批量转账函数。它先算出总金额，等于接收人数乘以每人金额，检查发送者余额够不够，扣掉总金额，再给每个接收人加上金额。
  2. 攻击者传入2个接收地址，每人金额是2的255次方。2乘以2的255次方，等于2的256次方。256位整数的上限是2的256次方减1，所以结果回绕成了零。
  3. 零小于等于任何余额，检查通过。发送者被扣掉零。
  4. 然后循环给两个接收人，每人加上2的255次方。凭空铸出了天量代币，多家交易所因此暂停了充提。0.8以后默认检查溢出，但 unchecked 块、内联汇编和类型转换仍会静默回绕，审计时要逐一检查这三处。
精度 · 数字为示例

除法要放在最后

  1. 第二个例子，先除后乘。本金1950，年利率5%，用基点表示是500。错误的写法是，本金先除以100，再乘以500，再除以100。
  2. 一步步算。1950除以100，整数除法得19，余数50被丢掉了。19乘以500除以100，得95。
  3. 正确的写法是先乘后除，1950乘以500，再除以10000，得97.5，向下取整是97。差了2。看起来不多，但这个误差被乘数放大了，而且每笔都发生。
  4. 更好的做法是用 mulDiv 函数。它的中间结果有512位，不会溢出，还可以显式指定舍入方向。
精度 · 以链上合约 decimals() 为准

同一个"USDT"，小数位不同

链代币decimals()
以太坊Tether USD6
BNB ChainBinance-Peg BSC-USD18
TRONTether USD (TRC-20)6
  1. 第五类，单位不一致。同一个 USDT，在不同链上精度不同。以太坊和 TRON 上是6位小数，BNB Chain 上的 BSC-USD 是18位。
  2. 算一下会发生什么。用户在 BNB Chain 上存入100个 USDT，链上记录的数字是100乘以10的18次方。
  3. 如果代码是从以太坊搬过来的，写死了按6位精度换算，它会把这个数理解成100乘以10的12次方个 USDT，也就是一百万亿。放大了10的12次方倍。
  4. 所以，永远从合约读取精度，不要写死。跨链桥两端精度不同时，要在桥合约里显式换算，并且处理换算后的余数。
规则只有一条

余数归协议，不归调用者

操作用户给出用户得到取整方向理由
deposit(资产)资产份额向下少给份额
mint(份额)资产（算出）份额向上多收资产
withdraw(资产)份额（算出）资产向上多扣份额
redeem(份额)份额资产向下少给资产
方向反了 → 往返套利：反复 mint 1 份再 redeem，每次净赚 1 单位；没有手续费时一笔交易可循环上千次。
  1. 舍入方向的规则只有一条，余数归协议，不归调用者。看金库的四个操作。存款，用户给资产、得份额，份额向下取整，少给份额。铸造指定份额，算用户要付多少资产，向上取整，多收资产。
  2. 提取指定资产，算要扣多少份额，向上取整，多扣份额。赎回份额，算给多少资产，向下取整，少给资产。记住一个口诀，给用户的向下，收用户的向上。
  3. 方向反了会怎样？攻击者可以做往返套利，反复铸造1份再赎回，每次净赚一个单位的舍入误差。单次很小，但没有手续费时，一笔交易里可以循环上千次。
案例 · 据公开分析

Balancer 与 KyberSwap

  1. 舍入误差为什么能造成上亿美元的损失？因为它可以被批量放大。看 Balancer V2，以下据多家安全公司的公开分析。2025年11月，一种稳定池的批量交换函数存在舍入误差。
  2. 攻击者在一笔批量交换里，串联了大量小额交换，让每一步的舍入都朝对自己有利的方向累积。单步只差一点点，几千步累积下来，池子的不变量和份额价格就被操纵了。损失约1.28亿美元，涉及多条链上的部署。
  3. 再看 KyberSwap，2023年11月，以下据 BlockSec 的公开分析。一处流动性计算用了向下取整，而代码注释写着应该向上取整。这个偏差让池子在价格已经越过某个刻度时，误判为没有越过，同一段流动性被计算了两次。损失超过4800万美元。
  4. 两条教训。第一，舍入误差在单步测试里可以忽略，在可批量、可循环的路径里会被放大，所以要对重复 N 次同一操作做模糊测试。第二，代码和注释不一致时，要把它当作漏洞线索，而不是文档瑕疵。
ERC-4626 · 数字为示例

份额 = 资产 × 总份额 ÷ 总资产，向下取整

步骤总资产总份额
  1. 现在看金库通胀攻击。金库标准 ERC-4626，份额等于存入的资产乘以总份额，再除以总资产，向下取整。问题在于，总资产通常直接读合约的代币余额，而任何人都可以直接转账增加它。
  2. 金库刚部署，是空的。攻击者先存入1个最小单位，拿到1份。
  3. 然后不走存款函数，直接向金库转入10000 USDC。总份额还是1，总资产变成约10000。
  4. 受害者存入9999 USDC。份额等于9999乘以1，再除以约10000，结果小于1，向下取整得零。受害者拿到零份。
  5. 攻击者赎回他的1份，取回金库全部资产，约19999 USDC。受害者的存款，被捐赠给了这1份。攻击者通常会抢跑受害者的第一笔存款交易。这个攻击只在金库几乎为空时有效。
防御 · 数字为示例

让捐赠变得不划算

方案做法
虚拟份额与偏移计算时加入 10^偏移 个虚拟份额
初始存款销毁部署时存一笔，份额发给死地址
内部记账状态变量记总资产，不读余额
最小份额检查份额为 0 就回滚；用户设最小份额
  1. 防御有四种。第一种是虚拟份额和偏移，OpenZeppelin 4.9以后的金库默认支持。计算份额时，总份额额外加上10的偏移次方个虚拟份额，总资产加1。
  2. 效果是什么？偏移为3时，攻击者要造成同样的损失，需要捐赠大约1000倍的资金。原来捐1万就够，现在要捐1000万，攻击变得不划算。手册里的金库实验，可以拖动偏移滑块，看着攻击者的利润从正变负。
  3. 第二种，部署时先存入一笔资金，把份额发给一个死地址，让金库永远不为空。第三种，内部记账，用状态变量记录总资产，不读余额，捐赠就不会改变份额价格。
  4. 第四种，最小份额检查。份额为零就回滚，用户侧再设一个最小份额参数，受害者的交易会失败，而不是拿到零份。Uniswap V2 用的也是类似思路，首次添加流动性时，永久锁定1000份 LP 代币。

借贷协议算利息时，对借款人的应还金额向下取整

攻击者可以怎样利用？
提示：把一笔大借款拆成很多笔小借款
参考
把借款拆成许多极小的头寸，让每笔的利息都向下取整为 0 → 长期零利息借款。
修复：对借款人应还金额向上取整；设最小借款额。
  1. 来练一练。一个借贷协议计算利息时，对借款人的应还金额向下取整。攻击者可以怎样利用？提示一下，把一笔大借款拆成很多笔小借款。
  2. 参考答案。攻击者把借款拆成许多极小的头寸，让每一笔的利息都向下取整为零，相当于长期零利息借款。修复是对借款人的应还金额向上取整，收用户的向上，并且设一个最小借款额。
小结

记住三件事

  • 先乘后除，用 mulDiv；unchecked、汇编、类型转换逐一检查。
  • 给用户的向下，收用户的向上；对"重复 N 次"做模糊测试。
  • 精度从合约读取，不写死；金库要防首存者通胀。
