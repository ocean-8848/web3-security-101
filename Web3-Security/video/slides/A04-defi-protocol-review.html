一处舍入方向的偏差
  1. 大家好，欢迎来到评估篇第4集。这一集讲第二类对象，DeFi 协议。DeFi 协议的评估分两层。第一层，代码会不会被攻破。第二层，规则会不会被套利。
  2. 看三个例子，以下据公开报道。2023年，借贷协议 Euler 损失约1.97亿美元。根因是一个函数在减少抵押品后，漏了健康检查。
  3. 2022年，稳定币协议 Beanstalk 损失约1.8亿美元。攻击者用闪电贷借来大量代币，换成投票权，在同一笔交易里通过并执行了恶意提案。每一步都符合规则。
  4. 2023年，KyberSwap 损失约4800万美元，根因是集中流动性计算里一处舍入的偏差。第一类问题有清单可查。第二类问题，要把整个协议和它依赖的市场一起建模。
一句话理解 · 打个比方

评估 DeFi 协议像检查水坝

坝体有没有裂缝
混凝土、钢筋
→ 代码漏洞：重入、权限、溢出
设计能不能扛洪水
上游暴涨、上游垮坝
→ 经济安全与外部依赖
谁能开闸
几个人同意才能开
→ 权限与治理
比喻不准的地方：水坝的上游是固定的。DeFi 的"上游"—— 预言机、被依赖的协议、抵押资产 —— 会变，要假设它们将来会恶化。
  1. 打个比方，评估 DeFi 协议像检查一座水坝。首先看坝体有没有裂缝，对应代码漏洞，比如重入、权限和溢出。
  2. 然后看设计。上游水位暴涨时，泄洪能力够不够。上游另一座坝垮了，会不会连锁。这对应经济安全和外部依赖。
  3. 坝体完好、设计也对，还要看谁能开闸，开闸要几个人同意。这是权限和治理。
  4. 比喻不准的地方在于，水坝的上游是固定的。DeFi 协议的上游，比如预言机、被依赖的协议和抵押资产，都会变。评估要假设它们将来会恶化。

C00–C03链差异
目标链的行为和以太坊一样吗？
  1. 先看通用清单，所有协议都查，一共九类，每类对应手册里的一章。前三类是重入、权限和算术。比如外部调用之前，状态更新了没有。每个修改状态的函数，谁能调用。舍入方向是不是对协议有利。
  2. 中间三类是外部调用、预言机、MEV 和签名。返回值有没有检查，能不能处理非标准代币。价格能不能在一笔交易内被推动。交换有没有设置最小成交量和截止时间。
  3. 后三类是升级、经济和链差异。存储布局对不对，有没有时间锁。偿付能力的不变量成不成立。部署到目标链后，行为和以太坊是否一样。这张清单是底线。在它之上，每类协议还有自己的高发点。
分类型清单 · 借贷 · 数字为示例

所有减少抵押或增加债务的路径，最后都要检查健康

1
抵押品估值用什么价格？低流动性资产有供应上限？
2
极端行情下清算仍有利可图？坏账谁承担？
3
所有减少抵押或增加债务的路径都检查健康因子？
4
分叉自哪个项目？改了哪些地方？
  1. 先看借贷协议。前两项，抵押品估值用什么价格，低流动性的资产有没有供应上限。极端行情下，清算是不是仍然有利可图，坏账由谁承担。
  2. 第三项最关键。所有减少抵押品、或者增加债务的路径，最后都要检查健康因子。注意是所有路径，不是主要路径。用数字看一下。
  3. 示例账户存了100个单位的抵押品，抵押率是80%，借了75。健康因子等于100乘以0.8，再除以75，约等于1.07，大于1，安全。
  4. 现在有一个新函数，比如把抵押品捐给储备金，它减少了30个抵押品，却没有检查健康因子。抵押品剩70，乘以0.8是56，除以75，健康因子只有0.75，账户已经资不抵债，坏账留给了协议。据公开复盘，Euler 的问题就出在这样一个新增的函数上。
  5. 第四项，协议是不是分叉自 Compound 或 Aave 这类项目，改了哪些地方。改动的地方，往往就是新漏洞的地方。
分类型清单 · DEX / AMM

不变量、舍入、回调，三个高发点

1
每次交换后，恒定乘积或对应的不变量是否成立？
Uranium：校验弱了 100 倍（A01）
2
集中流动性的价格区间边界、再投资计算，舍入方向对吗？
KyberSwap：边界处的舍入偏差被放大
3
交换回调是否校验调用者就是计算出的真实池子？
Sushi RouteProcessor2：伪造池子回调，划走授权给路由的代币
4
能否把池子储备直接当作价格？收税、变基代币会不会破坏记账？
储备一笔交易就能推动，不能直接当预言机
  1. 再看 DEX 和 AMM，也就是自动做市商。第一项，每次交换后，恒定乘积或者对应的不变量是否成立。第1集讲的 Uranium，就是这个校验弱了100倍。
  2. 第二项，集中流动性的价格区间边界，以及手续费再投资的计算，舍入方向对不对。据公开复盘，KyberSwap 的问题就出在边界处一个很小的舍入偏差，被反复放大。
  3. 第三项，交换回调。池子在交换中会回调调用方，让它付款。回调函数必须确认，调用它的就是按工厂地址计算出来的真实池子。据公开报道，Sushi 的一个路由合约没有这样做，攻击者伪造了一个池子来回调，划走了用户授权给路由的代币。
  4. 第四项，不能把池子储备直接当价格用，储备一笔交易就能推动。还要看收税代币、变基代币会不会破坏池子的记账。
分类型清单 · 金库 ERC-4626 · 数字为示例

份额价格能被一笔捐赠拉高吗？

步骤总资产总份额每份价值
  1. 金库协议有一个经典问题，首存者通胀。份额等于存入的资产，乘以总份额，再除以总资产，结果向下取整。来看一个示例。
  2. 第一个存款人只存了1个最小单位，拿到1份。然后他不通过存款，而是直接向金库转入10000 USDC。总资产变成约10000，总份额还是1。
  3. 第二个用户存入19999 USDC。他的份额等于19999乘以1，再除以约10000，约等于1.9999，向下取整，只拿到1份。
  4. 现在金库有约30000 USDC，2份。每份价值约15000。第二个用户存了19999，只值15000，约5000被第一个人拿走。
  5. 评估要查三件事。有没有虚拟份额或者首存锁定。总资产是不是直接读余额，能被捐赠操纵。策略合约能不能被替换。手册里的金库实验可以拖动数字，亲手看到这个过程。

验证方式与多签独立性
未证明消息不能当已证明

  1. 接下来三类放在一起看。稳定币，看锚定机制，极端脱锚时的清算和赎回路径，抵押品价格的熔断上下限，以及谁能铸造。特别注意，抵押品如果和稳定币本身相关，价格下跌会互相强化，形成死亡螺旋。
  2. 质押和再质押，看凭证会不会脱锚，赎回有没有延迟队列，延迟期内谁能暂停。质押、再质押、再拿去抵押，层层叠加时，一层出事会传导到每一层。还要看罚没的损失怎样传导给凭证持有人。
  3. 跨链桥，看消息格式是否包含源链、源合约、目标和序号，并逐项校验。验证方式是多签还是证明，多签是否独立。未证明的消息，绝不能被当作已证明。最后还要有限额和两侧供应量的对账。

经济安全 · 代码清单查不出来

每一步都合法，组合起来却致命

1
写出协议级不变量，用不变量测试验证
2
把外部市场纳入模型：某个依赖出极端情况会怎样
3
闪电贷视角：攻击者在一笔交易内有无限本金
4
治理视角：投票权能被借吗？提案能同交易执行吗？
5
参数边界：抵押率、费率、上限在极端值下仍安全
  1. 代码清单查不出经济攻击，要单独做。第一，写出协议级的不变量，比如总负债不超过总资产，并用不变量测试去验证。第二，把外部市场纳入模型。假设某个预言机、某个被依赖的协议、某个抵押资产出现极端情况，协议会怎样。
  2. 第三，闪电贷视角。攻击者在一笔交易内可以借到几乎无限的本金，只要在交易结束前还上。所以任何按当前余额或当前价格计算的量，都是攻击者可以控制的输入。
  3. 第四，治理视角。来看 Beanstalk，以下据公开复盘。攻击者用闪电贷借入巨额资金，换成治理代币，一下拿到了多数投票权。
  4. 它在同一笔交易里，投票通过并执行了一个恶意提案，把协议资金转走，然后归还闪电贷。投票权能被临时借来，提案又能当场执行，两个设计叠加，就成了漏洞。修复是投票权按历史快照计算，提案执行前要有延迟。
  5. 第五，参数边界。抵押率、费率、清算折扣和供应上限，在边界值和极端值下是否仍然安全。经济评估要问的不是这一步对不对，而是把这些步骤按攻击者喜欢的顺序和规模组合起来，会怎样。
外部依赖评估

依赖出事，协议跟着出事

依赖失效会怎样要评估什么
预言机价格错误或停更时效、上下限、备用源、排序器状态
被集成的协议对方被攻破或暂停回调、价格、暂停、升级等集成点
代币被暂停、拉黑、升级、脱锚代币自身的权限；是否映射资产
库库本身有 bug版本锁定；关注已知问题
编译器编译器 bug版本锁定 · 2023 年 Vyper 编译器重入锁失效
基础设施节点、索引、keeper 中断降级路径
  1. 协议依赖的东西出了问题，协议会跟着出问题。所以要列一张依赖表。第一类是预言机，失效表现为价格错误或者停更。评估时效检查、上下限、备用数据源，以及二层网络的排序器状态。
  2. 第二类是被集成的协议，对方可能被攻破或暂停。评估每一个集成点，回调、价格、暂停和升级。第三类是代币本身，它可能被暂停、拉黑、升级或者脱锚。
  3. 第四类是库和编译器。2023年，Vyper 编译器某些版本的重入锁失效，导致多个池子被攻击。所以版本要锁定，并持续关注已知问题。第五类是基础设施，节点、索引服务和自动执行任务的服务，都要有降级路径。
两种评估目标 · 数字为示例

接入第三方：继承全部风险，却没有修复能力

自研协议

  • 能改代码
  • 全量评估：代码 + 经济 + 依赖
  • 上线前把问题修掉
  • 交付：完整报告 + 门禁

接入第三方

  • 不能改代码
  • 评估集成点 + 对方的信任假设
  • 对方出事时我们受什么影响
  • 交付：接入评估 + 限额 + 退出预案
示例：理财资金接入一个收益协议 · 单协议敞口 ≤ 2,000 万$ 且 ≤ 对方 TVL 的 5% · 对方暂停或 TVL 单日降 30% → 触发退出
  1. 最后，DeFi 评估有两种目标。评估自研协议，我们能改代码，所以要全量评估，代码、经济和依赖都看，上线前把问题修掉，交付完整报告和门禁。
  2. 评估接入第三方协议，比如把交易所的理财资金放进一个外部收益协议，情况完全不同。我们不能改它的代码，继承了它的全部风险，却没有修复能力。评估重点是集成点和对方的信任假设，关键问题是，对方被攻破、暂停或者跑路时，我们的资金和用户受什么影响，怎么退出。
  3. 所以接入评估的结论，一定带着限额和退出预案。举个示例，单个协议的敞口不超过2000万美元，同时不超过对方锁仓总额的5%。对方暂停，或者锁仓总额单日下降30%，就触发退出。不要依赖它看起来很大、很成熟。
练一练 · 暂停视频想一想

一个借贷协议新增"一键循环杠杆"

功能：用户存入抵押品 → 借出 → 自动换成抵押品再存入 → 重复 N 次，一笔交易完成。
健康检查
循环中途是否有不检查的状态？最后一次检查覆盖全部吗？
价格
自动兑换用的价格和抵押估值用的价格，能否被同一笔交易推动？
清算
高杠杆仓位集中，极端行情下清算能否及时、是否仍有利可图？
  1. 来练一练。一个借贷协议新增了一键循环杠杆功能。用户存入抵押品，借出资产，自动换成抵押品再存进去，重复多次，全部在一笔交易里完成。你会重点检查什么？
  2. 参考三个方向。第一，健康检查，循环中途有没有不检查的状态，最后一次检查能不能覆盖全部变化。第二，价格，自动兑换用的价格和抵押估值用的价格，能不能被同一笔交易推动。第三，清算，高杠杆仓位集中起来，极端行情下清算能不能及时，是否仍然有利可图。为什么循环杠杆是高风险功能？因为它把借贷、兑换和价格三个高发点，压进了同一笔交易。
小结

记住三件事

  • 通用清单是底线，分类型清单抓每类协议的命门。
  • 经济安全单独评估：闪电贷视角、治理视角、参数边界。
  • 接入第三方：继承风险、无法修复 → 限额 + 退出预案。
