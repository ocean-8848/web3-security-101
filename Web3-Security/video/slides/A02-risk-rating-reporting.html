同一个发现，
为什么两个人评出两种等级？

发现：攻击者需要控制 5 把多签私钥中的 3 把，才能无限增发代币。
评估人甲：低危"拿到三把私钥？几乎不可能。"
评估人乙：严重"增发等于清零所有持有人。"
  1. 大家好，欢迎来到评估篇第2集，风险评级与报告。先看一个真实工作中常见的场景。
  2. 有一条发现。攻击者需要控制5把多签私钥里的3把，才能无限增发代币。
  3. 评估人甲说，这是低危。拿到三把私钥，几乎不可能。
  4. 评估人乙说，这是严重。增发等于把所有持有人的价值清零。两个人都有道理，问题出在哪？出在他们各自只看了一个维度。本集就讲怎样用两个维度定级，怎样写报告，以及不修的风险由谁签字。
一句话理解 · 打个比方

定级像分诊：病情多重 × 恶化多快

分诊护士

不治病，只决定谁先进抢救室
→ 定级不修漏洞，只决定修复顺序

两个依据

病情多重 → 影响
恶化多快、多容易触发 → 可能性
大出血即使暂时稳定也优先；轻微擦伤即使在流血也排后面。
比喻不准的地方：病情是客观的；漏洞的影响依赖攻击者能力假设。定级必须写清假设。
  1. 打个比方，定级像医院分诊。分诊护士不治病，她只决定谁先进抢救室。定级也一样，它不修漏洞，只决定修复的顺序和上线的门槛。
  2. 分诊看两件事。病情多重，这是影响。恶化多快、多容易触发，这是可能性。
  3. 大出血的病人，即使暂时稳定，也要优先。轻微擦伤，即使正在流血，也排在后面。
  4. 比喻不准的地方在于，病情是客观的。漏洞的影响，却依赖你假设攻击者有什么能力，有多少钱，能不能抢跑。所以定级时必须把假设写清楚，否则同一个发现，在不同人手里会评出不同等级。

盗取未领取收益

中

功能不可用
偷 gas

低

偏离规格但无价值损失
  1. 先看第一个维度，影响。影响回答的问题是，如果被成功利用，最坏会怎样。严重级包括，直接盗取用户或协议的资金，资金被永久冻结，协议资不抵债，未授权增发，以及治理被夺取。
  2. 高级包括，盗取用户还没领取的收益，临时冻结资金，或者部分用户受损。
  3. 中级通常是功能不可用，偷 gas，或者在特定条件下造成有限损失。低级是不造成资金损失的异常，比如偏离规格，但没有价值损失。

被利用的门槛有多高

中

注意：闪电贷让"需要大量资本"在一笔交易内成为现实 —— 资本门槛往往比看起来低。
  1. 第二个维度是可能性，就是被利用的门槛。高可能性是指，任何人，用一笔交易，不需要特殊前提就能触发。比如一个公开函数缺少权限检查。
  2. 中等可能性需要一些条件，比如一定的资本，特定的市场条件，抢跑，或者多个步骤。
  3. 低可能性需要特权角色，或者极端条件，或者已经被其他机制部分缓解了。比如开场那个例子，需要多签私钥。
  4. 这里有个容易低估的地方。闪电贷让攻击者在一笔交易内借到巨额资金，用完马上还。所以需要大量资本这个门槛，往往比看起来低得多。
评级矩阵 · 例子为示例

两个维度一交叉，等级就出来了

  1. 把两个维度交叉，就得到这张矩阵。横轴是影响，纵轴是可能性。右上角，影响严重、可能性高，是严重级。左下角，影响低、可能性低，只是信息项。
  2. 来定第一个例子。一个已经部署的空投合约，任何人调用领取函数，都能领走不属于自己的份额。奖池里有100万美元。
  3. 影响是什么？直接盗取资金，最多100万美元，属于严重。可能性呢？任何人，一笔交易，没有前提，属于高。矩阵给出严重级，立即处理。
  4. 第二个例子，就是开场那条。增发的影响是严重。需要5把里的3把私钥，可能性按表应该是低。矩阵给出中危。
  5. 但矩阵只是起点。假如我们发现，这5把私钥里有3把，由同一个团队保管在同一类电脑上，那么拿到三把并不比拿到一把难多少。
  6. 这时可能性要上调一档到中，等级就变成高危。所以开场的甲和乙都不全对。定级要结合运营安全的实际情况，并且在报告里写清这个判断依据。
常见误区

四种定级错误，最后都会变成上线事故

1按修复难度定级
"改一行就好，算低危"
→ 等级只看后果和门槛，不看修起来难不难
2因为"已知"而降级
"以前审计说过，项目方知道"
→ 已知不等于已缓解
3假设攻击者很穷
"要一亿资金才能操纵"
→ 闪电贷一笔交易就能借到
4只看链上
"合约没问题，所以安全"
→ 签名界面、前端同样有严重级
  1. 定级有四种常见错误。第一种，按修复难度定级。有人说，这个改一行就好，算低危吧。不对。等级只看后果和门槛，不看修起来难不难。一行就能修的严重漏洞，仍然是严重。
  2. 第二种，因为已知而降级。以前的审计说过，项目方也知道。可是已知不等于已经缓解。只要还能被利用，等级就不变，最多走风险接受流程。
  3. 第三种，假设攻击者很穷。比如说，要操纵这个价格，需要一亿美元资金，所以可能性低。但闪电贷可以在一笔交易里借到这些钱，门槛几乎为零。
  4. 第四种，只看链上。合约没问题，就认为整体安全。可是签名界面和前端同样有严重级。下面我们就看外部口径怎么分。

为什么要对齐：内部定级和赏金计划用同一把尺子，白帽报告来了才不会争论等级。
  1. 内部定级最好和外部口径对齐。业界常用的参照，是漏洞赏金平台 Immunefi 的严重度分级，公开资料目前是2点3版。它按资产类型分别给出示例。先看智能合约。
  2. 严重级包括直接盗取用户资金，永久冻结资金，协议资不抵债，未授权增发，以及治理投票被操纵。高级包括盗取或永久冻结还没领取的收益，以及临时冻结资金。中级和低级，主要是不造成直接价值损失的问题。
  3. 为什么要对齐？因为你上线后会运行漏洞赏金计划。内部定级和赏金计划用同一把尺子，白帽提交报告时，双方才不会为等级争论。
外部口径 · 网站与应用 · 摘录

前端和后端，有自己的严重级

等级网站与应用的代表影响
严重执行任意系统命令 · 读取服务器私钥 · 替换交易参数或合约地址 · 代替用户执行操作
高持久内容篡改 · 一键修改他人敏感信息 · 泄露用户机密信息
中一键修改他人非敏感信息 · 反射型注入 · 开放重定向
近年最大的损失多来自这一类：前端被注入、签名界面被篡改。评估范围不覆盖链下，等于只验收了主体结构，没验收门锁。
  1. 同一套分级里，网站与应用是独立的一类。严重级里有一条特别值得注意，替换交易参数或者合约地址。还有读取服务器上的私钥，以及代替用户执行改状态的操作。
  2. 为什么强调这一类？因为近年交易所和协议最大的损失，很多来自这里。比如前端被注入恶意脚本，签名界面被篡改。如果评估范围只覆盖合约，不覆盖链下，就等于只验收了大楼的主体结构，没验收门锁。这部分在第6集详细讲。

  1. 定好级，要写成报告。每条发现有八个字段。第一是标题，一句话说清问题。第二是等级，同时标出影响和可能性各是多少。
  2. 第三是位置，文件、行号、函数，还有提交哈希。第四是描述，解释为什么现有代码会出错。
  3. 第五是影响，用具体数字或场景，并写明攻击者能力假设。第六是证据。严重和高危，要附一个能运行的证明，比如一条回归测试，或者链上读数。否则容易被开发者一句理论上不可能驳回。
  4. 第七是修复建议，要具体到代码层面。第八是状态，待修复、已修复、部分修复，或者风险接受，并附上复核记录。
写报告的三条原则 · 反例 → 正例

可复现 · 可决策 · 可执行

"存在重入风险"
→
withdraw 先转账、后清零余额；外部合约可在回调中再次进入，取走全部 ETH。附回归测试。
"k 值检查失效"
→
交换后校验弱了 100 倍：池子约 九成储备可被取走（示例池 100 万$ → 约 90 万$）。
"建议加强权限控制"
→
setFeeTo 缺少权限修饰器，任何人可改手续费接收地址；加 onlyRole(ADMIN)。
  1. 写报告有三条原则。第一是可复现。存在重入风险，这句话等于没说。正例是，指出哪个函数，先转账后清零，外部合约可以在回调里再次进入，后果是取走全部 ETH，并附一条回归测试。
  2. 第二是可决策。影响要写给不懂技术的决策者看。k 值检查失效，管理层看不懂。换成池子约九成储备可以被取走，示例里100万美元的池子，损失约90万美元，决策者马上就明白了。
  3. 第三是可执行。建议加强权限控制，开发者不知道改哪里。正例是，指出哪个函数缺少权限修饰器，后果是什么，再直接给出应该加的那一行。
风险接受 · 不是所有发现都要修

不修可以，但要走正式流程

  1. 有些发现不修也能上线，但必须走正式流程，不能口头略过。第一个问题是，能在上线前修复吗？能，就修复，复核，关闭。
  2. 修不了，就问第二个问题，剩余风险可以接受吗？不可接受，阻断上线。
  3. 可以接受，就进入风险接受。注意三件事。第一，签字的是业务负责人，也就是有权承担后果的人，不是评估人员。
  4. 第二，要记录缓解措施，比如限额、监控或保险。第三，要写复查日期，到期重新评估，并纳入监控。
  5. 为什么评估人员不能自己签？评估人员的职责是把风险说清楚，并给出建议。接不接受，是业务决策。两者分开，责任才清楚。如果同一个人既评估又接受，就没有任何制衡。

摘要版 · 放最前面，一页以内

剩余风险 · 上线条件
回答一个问题：能不能上，有什么条件

技术版

读者：开发、审计全部发现 · 代码位置
证据 · 修复建议 · 复核记录
诚实写出未覆盖的范围和接受的风险。把问题藏起来的报告，比没有报告更危险。
  1. 最后是报告的结构。一份报告有两类读者，所以分两个版本。摘要版放在最前面，一页以内，给管理层和业务看。它只回答一个问题，能不能上，有什么条件。
  2. 技术版给开发和审计看，包括全部发现、代码位置、证据、修复建议，以及复核记录。
  3. 两个版本都要诚实，特别是诚实写出本次没覆盖的范围，和已经接受的风险。一份把问题藏起来的报告，比没有报告更危险，因为它给了决策者虚假的安全感。

练一练 · 暂停视频，先自己定级

三道题，答案在讲解里

1价格操纵
借贷协议用一个浅池子的现货价给抵押品估值。池子深度约 50 万$。
影响严重 × 可能性高 → 严重
2管理员改费率
owner 可把手续费设到 100%，owner 是 3/5 多签 + 48 小时时间锁。
影响高 × 可能性低 → 中，写清假设
3事件缺失
修改关键参数时不发事件，监控无法发现变更。
低，但列入监控需求
  1. 来练一练，可以先暂停视频，自己定级。第一题。一个借贷协议，用一个浅池子的现货价格给抵押品估值。这个池子的深度大约50万美元。
  2. 第二题。合约的管理员可以把手续费设到百分之百。管理员是5选3的多签，改费率要经过48小时时间锁。
  3. 第三题。合约修改关键参数时不发出事件，所以监控系统无法发现参数被改了。
  4. 来看参考答案。第一题，闪电贷可以轻松推动50万美元深度的池子，抵押品价值被虚高，可以超额借出。影响严重，可能性高，是严重级。第二题，影响是高，但多签加时间锁让可能性低，定中危，并写清楚依赖多签和时间锁这个假设。第三题本身是低危，但要写进上线的监控需求里。
小结

记住三件事

  • 定级 = 影响 × 可能性；矩阵是起点，结合运营实际调整，并写清假设。
  • 好的发现可复现、可决策、可执行；口径对齐外部分级，链下也有严重级。
  • 风险接受由业务负责人签字，带缓解措施和复查日期。
