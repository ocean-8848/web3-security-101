1. 一句话理解

审计员的工作是：在攻击者之前，找到代码里"能让钱流向错误地址"的路径。

智能合约部署后通常不能修改。合约直接持有资金。代码中的一个错误，就是一张公开的提款单。审计员读代码、建模型、写攻击证明（PoC），然后给出修复建议。

🎯 打个比方：智能合约像一台放在广场上的自动售货机。任何人都能投币、按按钮，也能拆开外壳看电路图（源码公开）。售货机里放着所有人的钱。审计员就是开业前的验收工程师：他用尽各种奇怪的投币顺序，试图让机器多吐钱。

2. 知行合一：学习要有输出，输出要有实践

3. 守正出奇：底线与黑客思维

3.1 守正：三条底线

  • 遵守法律：不攻击未授权的目标。不利用漏洞获利。
  • 保守秘密：客户代码和未修复漏洞属于保密信息。审计期间不公开、不交易相关代币。
  • 负责任的披露：发现线上漏洞时，先私下通知项目方，给出修复时间，再公开。

FIRST（Forum of Incident Response and Security Teams）道德守则是行业参考。它要求：保护信息、尊重隐私、协调披露、避免伤害。

3.3 出奇：黑客思维

开发者问"这个功能能不能用"。审计员问"这个功能能不能被滥用"。黑客思维有四个习惯：

习惯问题模板例子
反向思维如果我是攻击者，我最想改哪个变量？价格、份额、权限、时间戳
边界思维输入为 0、1、最大值、自己时会怎样？转账给自己、借 0 元、第一个存款人
顺序思维如果我改变调用顺序、在回调里再调用一次会怎样？重入、抢跑、闪电贷
组合思维如果我同时使用另一个协议会怎样？用 AMM 价格操纵借贷协议的预言机

🎯 打个比方：开发者像设计门锁的工程师，他测试"钥匙能不能开门"。审计员像开锁师傅，他测试"不用钥匙能不能开门"——撬、拆铰链、从窗户进。

4. 团队意识：为什么审计要多人协同

一个人的知识面有限。研究显示，不同审计员找到的漏洞重合度不高。团队审计用两种方式提高覆盖率：

  • 协同审计流（技术手段）：例如慢雾的 MistPunk 审计工作台。它把检查项、批注、发现集中在一个平台，并把经验沉淀为检查清单。
  • 审计工作流（管理手段）：交叉审计、内部复核、报告审核。每个发现至少两人确认。
  • Hacking Time 文化：团队成员随时分享新思路和新攻击手法，对齐团队能力。

1. 一句话理解

区块链是一串用哈希值首尾相扣的区块。每个区块记录一批交易。全网节点各自保存一份副本，并按共识规则决定下一个区块。

🎯 打个比方：一个班级用一本公共日记记账。每一页的页脚写着"上一页内容的指纹"。如果有人偷改第 3 页，第 4 页页脚的指纹就对不上，第 5 页、第 6 页也全部对不上。全班每人都有一本副本，所以改一本没有用。

比喻的局限：真实区块链里没有"班长"。谁来写下一页，由共识机制（工作量证明或权益证明）决定。

2. 区块与哈希链

哈希函数（Hash Function）：把任意长度的数据变成固定长度"指纹"的函数。输入改一个比特，输出完全不同。以太坊使用 Keccak-256，比特币使用 SHA-256。

  • 每个区块的哈希值覆盖它自己的内容，也覆盖上一个区块的哈希值。
  • 改动任何历史区块，后面所有区块的哈希值都要重算。攻击者需要追上全网的算力或质押。
  • 局限：链只保证"已经记下的东西不被改"。它不保证"记下的东西是对的"。错误的合约逻辑也会被永久记录。

3. 共识：谁来写下一个区块

机制代表出块权来源审计关注点
工作量证明 PoW比特币算力：先算出满足难度的哈希51% 攻击、链重组，影响确认数设置
权益证明 PoS以太坊（2022 年 9 月合并后）质押 32 ETH 成为验证者，随机选出提议者提议者能决定区块内交易顺序 → MEV；block.prevrandao 可被提议者影响

以太坊 PoS 中，一个时隙（slot）为 12 秒，32 个时隙为一个纪元（epoch）。区块在约 2 个纪元（约 12.8 分钟）后进入"最终确定"（finalized）状态。

6. Gas 与 EIP-1559

Gas：EVM 执行每条指令消耗的计算单位。它防止死循环，也给计算定价。

2021 年伦敦升级引入 EIP-1559。每个区块有一个基础费（baseFee），由协议根据上一个区块的拥堵程度自动调整（每块最多 ±12.5%）。基础费被销毁。用户另付小费（priorityFee）给提议者。

有效单价 = min(maxFeePerGas, baseFee + maxPriorityFeePerGas)
用户支付 = gasUsed × 有效单价
销毁     = gasUsed × baseFee
提议者得 = gasUsed × (有效单价 − baseFee)
如果 maxFeePerGas < baseFee → 交易留在内存池，不被打包

7. 审计员需要的区块链知识清单

  • 区块时间不精确：block.timestamp 由提议者设置，只能在小范围内偏移。不要用它做秒级判断或随机数。
  • 链重组（reorg）：最新几个区块可能被替换。跨链桥和交易所的确认数依赖这一点。
  • 交易顺序可被操纵：同一区块内的交易顺序由构建者决定。
  • 所有链上数据都公开：private 变量也能被任何人读取（eth_getStorageAt）。

1. 一句话理解

智能合约是一段存在链上的程序，加上一块只属于它的永久存储（storage）。任何人都能调用它的 public / external 函数。

不同的链使用不同的合约语言：Solidity、Vyper（EVM）；Rust（Solana、NEAR、CosmWasm）；Move（Aptos、Sui）；Cairo（Starknet）；C++（EOS）。Solidity 用户最多，入门最容易。审计员应该完整读完 Solidity 官方文档。

    address public owner;                 // 状态变量 → 存在 storage slot 0
    mapping(address => uint256) public balances; // slot 1（数据在 keccak 派生位置）

    event Deposit(address indexed user, uint256 amount); // 事件：写入日志，合约读不到
    error NotOwner();                     // 自定义错误：比字符串省 Gas

    modifier onlyOwner() {                // 修饰器：函数前置检查
        if (msg.sender != owner) revert NotOwner();
        _;                                // 被修饰函数的函数体插入这里
    }

    constructor() { owner = msg.sender; } // 只在部署时执行一次

    function deposit() external payable { // payable：允许接收 ETH
        balances[msg.sender] += msg.value;
        emit Deposit(msg.sender, msg.value);
    }

    function sweep(address to) external onlyOwner {
        (bool ok, ) = to.call{value: address(this).balance}("");
        require(ok, "send failed");       // 必须检查底层 call 的返回值
    }

    receive() external payable {}          // 接收纯 ETH 转账（无 calldata）
    fallback() external payable {}         // 没有匹配函数时执行
}

1. 一句话理解

ERC（Ethereum Request for Comments）是合约之间的"插座标准"。协议之间能组合，是因为大家都按同一个接口说话。审计员的工作是检查：实现是否真的符合标准，以及调用方是否对"不标准的实现"有防御。

🎯 打个比方：ERC20 像国标插座。大多数电器都能插。但总有几个"山寨插头"：有的不回报成功（USDT 的 transfer 不返回 bool），有的插上去会自动扣电费（转账收费代币），有的电压会自己变（rebase 代币）。协议如果只按国标设计，就会被山寨插头烧坏。

4. ERC-4626 首存者通胀攻击

金库公式：shares = assets × totalSupply / totalAssets（向下取整）。

攻击步骤：

  1. 金库刚部署，没有存款。
  2. 攻击者存入 1 wei，得到 1 份额。
  3. 攻击者直接向金库转账（捐赠）大额资产。totalAssets 变大，totalSupply 仍是 1。
  4. 受害者存入资产。由于取整，受害者得到 0 份额（或很少）。
  5. 攻击者赎回 1 份额，拿走全部资产，包括受害者的存款。

防御方案：

  • 虚拟份额与偏移（OpenZeppelin 4.9+ 默认）：计算时加上虚拟份额 10offset 和虚拟资产 1，攻击成本放大 10offset 倍。
  • 死份额：部署时铸造一部分份额给零地址（Uniswap V2 的 MINIMUM_LIQUIDITY = 1000 是同一思路）。
  • 内部记账：用内部变量记录 totalAssets，不读 balanceOf(this)，捐赠无效。
  • 滑点保护：存款时要求 minShares。

同类事件：Compound V2 分叉的"空市场"攻击——Hundred Finance（2023 年 4 月，约 700 万美元）、Sonne Finance（2024 年 5 月，约 2,000 万美元）。攻击者在新上线、totalSupply 极小的市场里抬高汇率，再借空其他市场。

💡 项目实例：C5 ERC-4626 金库：取整方向与集成清单。

5. approve 竞态

Alice 已授权 Bob 100 代币，现在想改成 50。她发出 approve(Bob, 50)。Bob 在内存池看到这笔交易，抢先用掉 100，等新授权生效后再用掉 50，共拿走 150。

缓解：先 approve(0) 再设新值；或使用 increaseAllowance / decreaseAllowance（OpenZeppelin 5.x 已从核心合约移除，改为推荐 SafeERC20.forceApprove）；前端只授权所需数额，不做无限授权。

1. 一句话理解

代理合约保存状态和资金，并把所有调用 delegatecall 给实现合约。升级 = 把实现合约地址换掉。

🎯 打个比方：代理合约是一辆车的车壳和油箱（地址、余额、存储）。实现合约是发动机（代码）。升级就是换发动机。风险在于：新发动机的油管接口位置如果和旧的不一样（存储布局不同），油就会灌进错误的管子里。

2. 代理的工作原理

sequenceDiagram
  participant U as 用户
  participant P as Proxy（存储 + 资金）
  participant I as Implementation V1
  participant I2 as Implementation V2
  U->>P: deposit(100)
  P->>P: fallback()：读取实现地址（ERC-1967 槽）

  I-->>P: 在 Proxy 的存储上执行，写 balances

  I2-->>P: 仍然在同一块存储上执行
读图要点
  • 状态永远在 Proxy 里。V1 和 V2 必须对"哪个变量在哪个槽"达成一致。
  • 实现合约的 constructor 只修改实现合约自己的存储，代理看不到。所以代理模式用 initialize() 代替构造函数。
  • 风险点：升级权限是整个系统的"总钥匙"。谁能升级，谁就能拿走全部资金。

  Note over D,P: 修复 部署与 initialize 放在同一交易
  Note over P,A: 实现合约本身用 _disableInitializers() 锁死
读图要点
  • 出错点：部署和初始化分成两笔交易，中间就留出了抢跑窗口。
  • 风险：攻击者成为 owner 后，可以控制升级，拿走全部资金。
  • 关键：initializer 只能调一次，谁先调谁就是 owner。
  • 部署代理和调用 initialize 不在同一笔交易 → 攻击者抢先初始化，成为 owner。
  • 继承链里的父合约 __X_init 没调用 → 某些变量保持默认值。
  • V2 新增 reinitializer(2) 函数，但没有权限控制。

4.3 函数选择器冲突

函数选择器 = 函数签名 Keccak-256 的前 4 字节。不同签名可能产生相同选择器。例如 burn(uint256) 和 collate_propagate_storage(bytes16) 的选择器都是 0x42966c68（3.1 章 LAB 可验证）。如果代理有一个管理函数与实现合约的业务函数选择器相同，用户调用会被代理"截胡"。透明代理通过"管理员只能调管理函数"解决这个问题；编译器会拒绝同一合约内的冲突，但不能检查代理与实现之间的冲突。

    require(balances[msg.sender] >= amount, "insufficient");  // Checks
    balances[msg.sender] -= amount;                           // Effects
    (bool ok, ) = msg.sender.call{value: amount}("");        // Interactions
    require(ok);
}

6. delegatecall 注入与 selfdestruct

  • 如果 delegatecall 的目标地址或 calldata 由用户控制，用户能执行任意代码改写存储（Ethernaut Delegation、Preservation）。
  • EIP-6780（2024 年 Cancun）之后，selfdestruct 只在"创建合约的同一交易中"才删除代码。其他情况只转出余额。但旧链和部分 L2 行为不同，审计时要确认目标链版本。
  • 库合约（被 delegatecall 的合约）如果自己可以被初始化并自毁，所有依赖它的代理都会失效（Parity 2017）。

3. 整数：溢出、截断、精度

3.1 溢出与回绕

Solidity 0.8 之前，uint8(255) + 1 == 0，不报错。0.8 起默认检查，溢出时 revert。但以下情况仍然会回绕：unchecked {} 块、内联汇编、类型强转（uint8(uint256 x) 直接截断高位）、移位运算（<< 不检查溢出）。

  M --> O["Solidity 0.8 之前不报错<br/>乘积溢出为 0"]

读图要点
  • 出错点：错在先乘后检：检查的是溢出后的 0，而不是真实总额。
  • 风险：检查被绕过后，凭空铸出的代币直接打进攻击者地址。
  • 局限：0.8 的默认检查管不到 unchecked、汇编、强转和移位。

案例：2018 年 4 月 BEC 代币的 batchTransfer：uint256 amount = cnt * _value;。攻击者传入 2 个地址和 _value = 2²⁵⁵，乘积溢出为 0，通过余额检查，每个地址收到 2²⁵⁵ 代币。

案例：2025 年 5 月 Sui 链 Cetus 协议（约 2.2 亿美元，其中约 1.6 亿美元被验证者冻结）：数学库的 checked_shlw 溢出检查条件写错，左移溢出没有被拦截。攻击者用极少代币获得巨额流动性。

3.2 精度与取整

  • 先除后乘：a / b * c 丢失精度，应写 a * c / b（注意乘法溢出，可用 mulDiv）。
  • 取整方向：存款给份额时向下取整，取款收份额时向上取整。原则是"取整永远有利于协议"。方向反了，攻击者可以通过大量小额操作积累利润。
  • 小数位不一致：USDC 6 位，WETH 18 位，Chainlink USD 价格 8 位。混合计算前必须统一。
  • 精度损失被放大：2023 年 11 月 KyberSwap Elastic（约 4,800 万美元）：攻击者把价格推到 tick 边界，利用取整误差让流动性被重复计算。

  • secp256k1 曲线上，(r, s) 和 (r, n − s) 都是合法签名。如果合约用"签名本身的哈希"做去重标记，攻击者翻转 s 就能重放。用 nonce 去重可以避免这个问题。

5. 随机数与时间戳

  • block.timestamp、blockhash、block.prevrandao 对同一区块内的所有合约都相同。攻击者合约在同一交易中先算出结果，再决定是否参与（Ethernaut Coin Flip）。
  • blockhash(n) 只能读最近 256 个区块；更早的返回 0（Capture the Ether：Predict the block hash）。
  • PoS 下，提议者可以选择"不出块"来放弃一个不利的 prevrandao。
  • 安全方案：Chainlink VRF（链下生成随机数 + 链上验证证明）；commit-reveal（两阶段提交）。

6. 其他经典弱点（SWC 补充）

  • 状态变量遮蔽（SWC-119）：子合约声明了与父合约同名的变量，两者是不同的槽。
  • 未初始化的存储指针（SWC-109）：0.5 之前的局部 struct 默认指向 slot 0。
  • 短地址攻击（DASP 9）：calldata 长度不足时 EVM 补零。现代编译器会检查 calldata 长度。
  • 错误的继承顺序、错误的构造函数名（Solidity 0.4 时期构造函数与合约同名，拼写错误变成公共函数：Ethernaut Fallout）。

1. 一句话理解

区块构建者决定交易顺序。只要顺序能改变结果，就有人付钱买顺序。这部分利润叫 MEV（最大可提取价值，Maximal Extractable Value）。

🎯 打个比方：你在拍卖会上举牌前，大声念出了自己的出价。坐在旁边的人抢先举一个更高一点的价，等你买下后再以更高价卖给你。内存池就是那个"大声念出"的地方。

前置章节2.1
交互实验AMM 工作台（4 个标签：恒定乘积 / 夹击 / 无常损失 / StableSwap）

1. 一句话理解

AMM（自动做市商）用一个数学公式代替订单簿。池子里两种代币的数量决定价格。任何人都能和公式交易。

🎯 打个比方：一个跷跷板两端放着苹果和橙子。你从一端拿走苹果，就必须往另一端放橙子，让"苹果数 × 橙子数"保持不变。拿得越多，每个苹果越贵。

💡 项目实例：C1 Uniswap V2 完整审计底稿。

2. Uniswap V2：恒定乘积

不变量:   x · y = k
买入 dx（扣 0.3% 手续费后为 dx' = dx · 0.997）
得到:     dy = y · dx' / (x + dx')
现货价格: P = y / x
价格影响: 交易后价格 / 交易前价格 − 1

V2 的关键实现细节（审计时逐一核对）：

  • swap() 先转出代币，再检查 balance0Adjusted × balance1Adjusted ≥ reserve0 × reserve1 × 1000²。这支持"闪电兑换"：先拿币，在 uniswapV2Call 回调里付款。
  • lock 修饰器防止重入。
  • price0CumulativeLast 累积价格，用于链上 TWAP（见 2.4）。
  • MINIMUM_LIQUIDITY = 1000 份额在首次添加流动性时永久锁定，防止首存者攻击。
  • skim() 和 sync() 处理余额与储备不一致。转账收费代币与 rebase 代币会触发这类不一致。

3. Uniswap V3：集中流动性

  • LP 只在一个价格区间 [Pa, Pb] 内提供流动性。资本效率更高。
  • 价格用 sqrtPriceX96（Q64.96 定点数）表示，区间边界用 tick 表示：P = 1.0001tick。
  • 价格穿越 tick 时，激活或停用对应流动性。tick 边界的取整是精度漏洞高发区（KyberSwap 2023）。
  • LP 头寸是 NFT。手续费按头寸单独累计。
  • 审计关注：slot0 的现货价格可被单笔交易操纵，不能直接当预言机；手续费增长量的溢出是"有意的"（依赖差值回绕），改写到 0.8 版本时必须放进 unchecked。

4. Curve StableSwap

Curve 用于锚定资产（USDC/USDT、ETH/stETH）。它把恒定和（x + y = 常数，零滑点但会被抽干）与恒定乘积混合，放大系数 A 控制混合比例。

A·nⁿ·Σxᵢ + D = A·D·nⁿ + Dⁿ⁺¹ / (nⁿ·Πxᵢ)
D: 池子在平衡状态下的总价值
求解: 没有闭式解，合约用牛顿迭代计算 D 和 y（最多 255 轮）

审计关注：牛顿迭代的收敛条件与取整；A 值渐变（ramp）期间的价格跳变；get_virtual_price() 在 remove_liquidity 回调中可被读取（只读重入）；Vyper 编译器版本。

5. 无常损失

当价格比值变为 r 倍时，相对于持有：IL = 2·√r / (1 + r) − 1。价格翻倍时 IL 约 −5.7%；价格变为 5 倍时约 −25.5%。集中流动性在区间内放大收益，也放大 IL。

6. AMM 审计检查清单

  • 所有 swap 入口是否有 minOut 和 deadline？
  • 协议是否把 AMM 现货价格当预言机？
  • 是否支持转账收费、rebase、ERC777 代币？储备与余额如何同步？
  • 首次添加流动性是否有最小锁定？
  • 手续费计算是否在整数边界上可被反复利用？

3. 核心公式

健康因子 HF = Σ(抵押物ᵢ × 价格ᵢ × 清算阈值ᵢ) / 总债务价值
HF < 1  → 可被清算
清算价格（单一抵押物）= 债务 / (抵押数量 × 清算阈值)
清算人收益 = 偿还债务 × 清算奖励（例如 5%）

利率拐点模型（Aave / Compound 通用思路）
利用率 U = 总借款 / 总存款
U ≤ U_opt: 借款利率 = base + slope1 × U / U_opt
U > U_opt: 借款利率 = base + slope1 + slope2 × (U − U_opt) / (1 − U_opt)
存款利率 = 借款利率 × U × (1 − 储备因子)

3. Chainlink 正确用法

function getPrice() public view returns (uint256) {
    // L2：先检查排序器是否在线（Sequencer Uptime Feed）
    (, int256 up, uint256 since, , ) = sequencerFeed.latestRoundData();
    require(up == 0, "sequencer down");
    require(block.timestamp - since > GRACE_PERIOD, "grace period");

    (uint80 roundId, int256 answer, , uint256 updatedAt, ) = feed.latestRoundData();
    require(answer > 0, "invalid price");
    require(updatedAt != 0 && block.timestamp - updatedAt <= HEARTBEAT, "stale");
    // 不同喂价的 decimals 不同：USD 对通常为 8，ETH 对通常为 18
    return uint256(answer) * 1e18 / (10 ** feed.decimals());
}
  • 不要用已弃用的 latestAnswer()：它不返回更新时间。
  • 每个喂价的心跳不同。不要对所有资产用同一个 HEARTBEAT 常量。
  • 部分聚合器有 minAnswer / maxAnswer 熔断边界。价格跌破下限时，喂价停在下限，而不是真实价格（2022 年 LUNA 崩盘时，有协议因此按错误价格接受抵押）。
  • 考虑喂价失效时的降级：try/catch 包裹，切换备用价格源或暂停，而不是让清算全部 revert。
  • 拉取式预言机（Pyth、Chainlink Data Streams）由用户在交易中提交签名价格。要检查价格时间戳和置信区间，防止用户挑选对自己有利的旧价格。

4. VRF：可验证随机数

2. 奖励累计算法（多个协议通用）

Synthetix StakingRewards 的"每代币奖励累积"算法被 Convex、Sushi MasterChef 等大量复用：

rewardPerTokenStored += (now - lastUpdate) * rewardRate * 1e18 / totalSupply;
earned[user] = balance[user] * (rewardPerTokenStored - userPaid[user]) / 1e18 + rewards[user];
// 任何改变 balance 或 totalSupply 的操作之前，必须先 updateReward(user)
  • 在 stake / withdraw / transfer 前忘记 updateReward → 新用户领到历史奖励。
  • totalSupply == 0 时奖励去向未定义 → 奖励永久卡在合约里。
  • rewardRate 精度：奖励代币小数位低（例如 USDC 6 位）且总质押量大时，每秒奖励被取整为 0。

5. 存储布局规则

  • 静态变量按声明顺序从 slot 0 开始。相邻变量总大小不超过 32 字节时打包在同一槽，从低位开始放。
  • mapping(K => V) 位于 slot p：键 k 的值在 keccak256(pad32(k) ‖ pad32(p))。
  • 动态数组位于 slot p：p 存长度；元素 i 在 keccak256(pad32(p)) + i。
  • 短 string / bytes（31 字节以内）：数据和 长度 × 2 存在同一槽；长的存长度 × 2 + 1，数据在 keccak256(p)。
  • struct 和定长数组总是从新槽开始。

4. Gas 安全：63/64 规则

EIP-150 规定：一次 CALL 最多转发当前剩余 Gas 的 63/64。父调用至少保留 1/64。

  • 攻击：中继者给一笔元交易提供"刚好不够"的 Gas。内层调用耗尽 Gas 失败，外层用剩下的 1/64 完成执行，并把请求标记为"已处理"。用户的操作永远丢失。
  • 防御：在调用前检查 gasleft() >= requiredGas * 64 / 63 + buffer；或在内层失败时整体 revert。
  • ERC-4337 和跨链消息协议的执行器都要考虑这个问题。

4. 操纵成本 vs 收益

攻击可行 ⇔ 收益 > 成本
成本 = 推动价格所需的滑点损失 + 手续费 + 维持时间的资金成本 + 套利者反向交易的损失
收益 = 借款上限提高部分 / 清算收益 / 套利收益
关键变量: 池子流动性深度、预言机窗口长度、借款上限、协议 TVL

审计时给出一个数字："以当前流动性，操纵价格 20% 约需 X 美元成本，可借出 Y 美元。"这比"价格可能被操纵"有说服力得多。

from slither.detectors.abstract_detector import AbstractDetector, DetectorClassification

class UnprotectedSetter(AbstractDetector):
    ARGUMENT = "unprotected-setter"
    HELP = "public setter writes a state variable without a modifier"
    IMPACT = DetectorClassification.HIGH
    CONFIDENCE = DetectorClassification.MEDIUM
    WIKI = "internal"
    WIKI_TITLE = WIKI_DESCRIPTION = WIKI_EXPLOIT_SCENARIO = WIKI_RECOMMENDATION = "see handbook 1.7"

    def _detect(self):
        results = []
        for c in self.compilation_unit.contracts_derived:
            for f in c.functions_entry_points:
                if f.name.startswith("set") and f.state_variables_written and not f.modifiers:
                    results.append(self.generate_result([f, " writes state without access control\n"]))
        return results

5. 不变量

  1. K 值不减：每次 swap 后，扣除 0.3% 输入费后的余额乘积 ≥ 交易前储备乘积。
  2. 储备 ≤ 余额：任何函数结束时，reserve ≤ balanceOf(pair)（多出部分可被 skim）。
  3. 份额公平：mint 给出的份额不超过存入资产占比的较小值。
  4. 重入隔离：所有修改储备的函数共享同一把 lock。

5. 清算参数的审计要点

实战 · J3

面试题库：30 道常见问题

用法先自己回答，再展开参考答案。答案要能说清"原理 + 例子 + 修复"。

基础

1. msg.sender 和 tx.origin 有什么区别？

msg.sender 是直接调用者；tx.origin 是发起交易的 EOA。用 tx.origin 鉴权会被中间合约利用。EIP-7702 之后，EOA 也可以有代码，基于 tx.origin 的"非合约"判断不再可靠。

2. call、delegatecall、staticcall 的区别？

call 在被调用方上下文执行；delegatecall 用被调用方代码、在调用方存储上执行，msg.sender 不变；staticcall 禁止修改状态。代理合约依赖 delegatecall。

3. Solidity 0.8 之后还会有溢出问题吗？

会。unchecked 块、内联汇编、类型强转截断、移位运算不检查溢出。

4. private 变量安全吗？

不保密。任何人可以用 eth_getStorageAt 读取存储。

5. 存储布局规则是什么？mapping 的值存在哪里？

按声明顺序从 slot 0 开始，小于 32 字节的相邻变量打包。mapping 在 slot p，键 k 的值在 keccak256(pad(k) ‖ pad(p))。

6. CREATE 和 CREATE2 的地址如何计算？

CREATE：keccak256(rlp(sender, nonce))；CREATE2：keccak256(0xff ‖ sender ‖ salt ‖ keccak256(initCode))。都取后 20 字节。

7. EIP-6780 改变了什么？

selfdestruct 只在创建合约的同一交易中删除代码；其他情况只转出余额。

漏洞

8. 重入有哪几种？如何防御？

单函数、跨函数、跨合约、只读重入。防御：CEI 模式；共享的重入锁；view 函数检查锁状态；集成方检查被读协议的锁。

9. 什么是只读重入？举一个例子。

第三方协议在回调期间读取了某协议 view 函数的中间状态。例：读取 Curve 池在移除流动性回调中的虚拟价格。

10. ERC4626 首存者问题是什么？如何防御？

份额取整与捐赠结合，使后续存款人得到过少份额。防御：虚拟份额和偏移、死份额、内部记账、最小份额参数。

11. 签名方案要包含哪些字段？

nonce、chainId、verifyingContract、deadline；限制 s 低半区；检查恢复地址非零；合约钱包用 ERC-1271。

12. 为什么不能用 AMM 现货价格做预言机？

单笔交易可以改变储备比例，闪电贷让这种改变几乎零成本。应使用 Chainlink 或足够长、足够深的 TWAP。

13. Chainlink 要做哪些校验？

answer 大于 0；updatedAt 在心跳内；L2 检查排序器状态和宽限期；处理小数位；考虑熔断边界和失效降级。

14. 代理合约有哪些常见问题？

存储冲突、实现合约未初始化、初始化可被抢先、UUPS 升级函数缺失或无权限、选择器冲突、实现合约中的 immutable。

15. 什么是怪代币？列举 5 种。

不返回 bool、失败返回 false、转账收费、rebase、ERC777 钩子、黑名单、可暂停、小数位非 18、多入口地址。

16. 什么是 63/64 规则？有什么安全影响？

CALL 最多转发剩余 Gas 的 63/64。中继场景下内层调用可能因 Gas 不足失败而外层继续执行，需要检查 gasleft。

17. 推送支付和拉取支付的区别？

推送由合约主动转账，接收方失败会阻塞流程；拉取由用户自己提款，单个失败不影响其他人。

18. 取整方向的原则？

取整永远有利于协议：给用户的向下取整，从用户收的向上取整。

DeFi 与经济

19. 健康因子如何计算？

Σ(抵押 × 价格 × 清算阈值) / 债务价值。小于 1 可被清算。

20. 闪电贷对审计假设有什么影响？

不能假设攻击者资金有限。任何依赖资金量的逻辑都要按"无限资金、单交易"评估。

21. 治理系统如何抵抗闪电贷？

投票权快照在提案创建之前；执行时间锁；合理的法定人数；提案内容不可修改。

22. 什么是无常损失？

LP 相对于单纯持有的价值差：2√r/(1+r) − 1，r 为价格比值变化。

23. 奖励累积算法中最常见的错误？

修改余额前没有更新奖励；totalSupply 为 0 时奖励去向未定义；精度不足导致每秒奖励为 0。

方法与实践

24. 拿到一个陌生协议，你的前两个小时做什么？

读文档写下资产、角色、公式；编译和跑测试；画合约关系图；列出入口函数表和状态变量读写表；写下初步不变量。

25. 如何给一个发现定级？

按影响 × 可能性，参考客户或平台的标准；说明前提条件；用 PoC 证明影响。

26. 静态分析、fuzz、形式化验证各自的局限？

静态分析误报多、看不懂业务；fuzz 依赖不变量质量，不能证明没有问题；形式化验证只证明符合规范，规范可能不完整。

27. 如何写一条好的发现？

标题说后果；描述说根因和位置；影响量化；PoC 可运行；建议可执行。

28. 发现线上漏洞后怎么做？

只在本地 fork 复现；通过私密渠道（项目方、赏金平台、安全团队）报告；协调修复后再公开。

29. 修复复查要注意什么？

修复是否完整覆盖所有同类位置；是否引入新问题；是否改变了存储布局或接口。

30. 审计报告"无高危"能说明什么？

只说明在给定范围、给定时间、给定代码版本内没有发现。不覆盖运维、私钥、前端和未来升级。
