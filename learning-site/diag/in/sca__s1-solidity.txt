## 1. 一句话理解

智能合约是一段存在链上的程序，加上一块只属于它的永久存储（storage）。任何人都能调用它的 public / external 函数。

不同的链使用不同的合约语言：Solidity、Vyper（EVM）；Rust（Solana、NEAR、CosmWasm）；Move（Aptos、Sui）；Cairo（Starknet）；C++（EOS）。Solidity 用户最多，入门最容易。审计员应该完整读完 Solidity 官方文档。

## 2. 一个合约的解剖图

Bank.sol · 带注释
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;                 // 编译器版本：0.8 起默认检查溢出

contract Bank {
    address public owner;                 // 状态变量 → 存在 storage slot 0
    mapping(address => uint256) public balances; // slot 1（数据在 keccak 派生位置）

    event Deposit(address indexed user, uint256 amount); // 事件：写入日志，合约读不到
    error NotOwner();                     // 自定义错误：比字符串省 Gas

    modifier onlyOwner() {                // 修饰器：函数前置检查
        if (msg.sender != owner) revert NotOwner();
        _;                                // 被修饰函数的函数体插入这里
    }

    constructor() { owner = msg.sender; } // 只在部署时执行一次

    function deposit() external payable { // payable：允许接收 ETH
        balances[msg.sender] += msg.value;
        emit Deposit(msg.sender, msg.value);
    }

    function sweep(address to) external onlyOwner {
        (bool ok, ) = to.call{value: address(this).balance}("");
        require(ok, "send failed");       // 必须检查底层 call 的返回值
    }

    receive() external payable {}          // 接收纯 ETH 转账（无 calldata）
    fallback() external payable {}         // 没有匹配函数时执行
}

## 3. 审计员必须熟悉的语法点

 |  | 语法 | 含义 | 安全含义

 | public / external | 任何人可调用 | 每个 public/external 函数都是攻击入口。先列出全部入口。

 | internal / private | 只能合约内部（及子合约）调用 | private 不等于"保密"，存储数据链上可读。

 | view / pure | 不修改状态 | view 函数仍可能返回被操纵的数据（只读重入，见 1.6）。

 | storage / memory / calldata | 数据位置 | Struct storage s = ... 是引用，修改会写回；memory 是副本，修改不会写回。写错位置 = 状态没更新。

 | msg.sender / msg.value | 直接调用者 / 附带 ETH | 在循环里重复使用 msg.value 会"一份钱用多次"（multicall 漏洞）。

 | unchecked { } | 关闭溢出检查 | 块内的加减乘可能回绕。

 | try / catch | 捕获外部调用失败 | catch 不捕获所有错误（例如 Gas 耗尽、返回数据解码失败）。

 | 继承与 super | C3 线性化顺序 | 多重继承时，修饰器或初始化可能没被执行。

 | immutable / constant | 写在字节码里，不占 storage | 代理模式下，实现合约的 immutable 值属于实现合约，不属于代理。

## 4. 三种调用方式：最容易出事故的地方

合约调用另一个合约有三种底层方式。它们的区别是：代码用谁的，存储改谁的，msg.sender 是谁。

[已有图]
flowchart LR
  U["用户 EOA"] -- "调用" --> A["合约 Astorage A"]
  A -- "call" --> B1["合约 B 代码改 storage Bmsg.sender = A"]
  A -- "delegatecall" --> B2["合约 B 代码改 storage Amsg.sender = 用户"]
  A -- "staticcall" --> B3["合约 B 代码禁止改任何状态"]
[/已有图]

读图要点

- delegatecall 把别人的代码"借"过来，在自己的存储上执行。代理合约靠它工作（见 1.4）。

- 风险点：如果 A 对一个用户可控的地址做 delegatecall，攻击者的代码就能改写 A 的全部存储，包括 owner。

- 2017 年 Parity 多签钱包事件：钱包通过 delegatecall 调用共享库。库的初始化函数没有保护。第一次（7 月）被盗约 15 万 ETH；第二次（11 月）有人初始化了库合约本身并调用 selfdestruct，约 51 万 ETH 被永久冻结。

## 5. 底层调用的返回值

// ❌ 错误：忽略返回值。转账失败时，代码继续执行
payable(to).send(amount);
to.call{value: amount}("");

// ✅ 正确：检查返回值
(bool ok, ) = to.call{value: amount}("");
require(ok, "ETH transfer failed");

// 💡 transfer/send 只转发 2300 Gas。接收方是合约钱包时可能失败。
//    推荐用 call + 重入保护。

⚠️ 警告：对一个没有代码的地址执行 call，返回 true。如果你用低级 call 调用代币合约，又没有检查目标是否有代码，"转账成功"可能什么都没发生。OpenZeppelin 的 SafeERC20 和 Address 库会做这个检查。

## 6. 与合约交互：JSON-RPC 与客户端库

钱包、前端和脚本都通过 JSON-RPC 与节点通信。常用方法：eth_call（只读模拟）、eth_sendRawTransaction、eth_getStorageAt、eth_getLogs、debug_traceTransaction。

 |  | 库 | 语言 | 特点

 | ethers.js | JS/TS | 使用最广，v6 API 与 v5 不兼容

 | viem | TS | 类型安全、体积小，新项目常用

 | web3.py | Python | 数据分析、脚本常用
