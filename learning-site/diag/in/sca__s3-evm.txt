## 1. 一句话理解

EVM 是一台 256 位字长的栈式虚拟机。Solidity 只是它的"高级外衣"。漏洞有时只在字节码层面可见（编译器 bug、内联汇编、存储布局）。

🎯 打个比方：EVM 像一个只有一叠盘子的厨师。每道指令从盘子顶端拿 1–3 个盘子，处理后再放回一个。他还有一块用完就擦掉的白板（memory）、一个上锁的永久保险柜（storage）、和一张客人递来的点菜单（calldata，只读）。

读图要点

- "Stack too deep" 编译错误来自"只能访问顶端 16 项"这个限制。

- 存储读写最贵，Gas 优化的核心是减少 SLOAD/SSTORE（见 3.2）。

- 瞬态存储适合做重入锁和单交易内的临时记账。风险：如果在 multicall 或同一交易的多次调用中忘记清理，值会"泄漏"到后续调用。

## 4. 函数分发与 ABI 编码

transfer(address,uint256) 的 calldata：
a9059cbb                                                          ← 选择器 = keccak256("transfer(address,uint256)")[0:4]
000000000000000000000000ab5801a7d398351b8be11c439e05c5b3259aec9b  ← address 左补零到 32 字节
0000000000000000000000000000000000000000000000000de0b6b3a7640000  ← uint256 = 1e18

动态类型（bytes / string / 数组）：头部放偏移量，尾部放长度 + 数据

编译后的合约开头是一段分发器：读取 calldata 前 4 字节，与每个函数选择器比较，跳转到对应代码。没有匹配时进入 fallback。

## 5. 存储布局规则

- 静态变量按声明顺序从 slot 0 开始。相邻变量总大小不超过 32 字节时打包在同一槽，从低位开始放。

- mapping(K => V) 位于 slot p：键 k 的值在 keccak256(pad32(k) ‖ pad32(p))。

- 动态数组位于 slot p：p 存长度；元素 i 在 keccak256(pad32(p)) + i。

- 短 string / bytes（31 字节以内）：数据和 长度 × 2 存在同一槽；长的存长度 × 2 + 1，数据在 keccak256(p)。

- struct 和定长数组总是从新槽开始。

Ethernaut 19 关 Alien Codex：动态数组长度下溢为 2²⁵⁶ − 1 后，数组覆盖全部存储空间。攻击者计算出 slot 0 对应的数组下标，改写 owner。

## 6. 合约创建

 |  | 方式 | 地址公式 | 安全含义

 | CREATE | keccak256(rlp(sender, nonce))[12:] | 地址可预测（Ethernaut Recovery）；跨链同 nonce 部署得到同地址，但内容可能不同（2022 年 Optimism 上 Wintermute 2,000 万 OP 事件）

 | CREATE2 | keccak256(0xff ‖ sender ‖ salt ‖ keccak256(initCode))[12:] | 部署前就可以向地址转账；Cancun 之前可配合 selfdestruct 在同一地址部署不同代码（变形合约）

创建时执行的是 initcode（构造函数 + 返回运行时代码）。构造期间 extcodesize(this) == 0，这就是 1.7 中"是否为合约"判断失效的原因。
