## 章节正文

# A1 测试网动手：以太坊 Sepolia 部署一个代币

学习目标：做完本附录，你能——

- 用 Foundry 编译、测试、部署 MinimalToken 到 Sepolia 测试网。

- 在 Sepolia Etherscan 上完成源码验证，并找到 Transfer 事件。

- 用 cast 读余额、发转账，并用 cast sig 对照 03 章的函数选择器。

前置章节：03 EVM 执行模型、04 合约生命周期、06 代币标准
示例合约：examples/02-MinimalToken.sol ｜ 预计用时：60–90 分钟 ｜ 花费：0 元（只用测试币）

## 1. 你将完成什么

一句话：把 04 章的 MinimalToken 从源码变成 Sepolia 上一个已验证的代币合约，并亲手转一笔账。

完成后，你在 sepolia.etherscan.io 上能看到：

 | 

 | 位置
 | 你会看到

 | 合约地址页
 | 一笔 "Contract Creation" 交易；Contract 标签旁有绿色对勾（已验证）

 | Token Transfers 标签
 | 两条记录：铸造（from 为 0x000…000）和你发的一笔转账

 | Contract → Read Contract
 | name、symbol、balanceOf 等只读函数，可以直接点按钮调用

 | 交易详情 → Logs
 | Transfer 事件，topic0 为 0xddf252ad…

Sepolia：以太坊官方维护的应用开发测试网，链 ID 11155111。测试网（Testnet）上的币没有市场价值，只用来练习。

🎯 打个比方：Sepolia 像驾校的练车场。

- 路口、红绿灯、交规和真实道路一样 = 同样的 EVM、同样的交易格式。

- 练车场的油免费领 = 测试 ETH 从水龙头领取。

- 撞了杆不赔钱 = 部署失败只浪费测试币。

比喻的局限：

- 练车场比真实道路空旷。Sepolia 的 Gas 价格和拥堵程度不代表主网。

- 练车场会先换新设施。Sepolia 常比主网先升级（例如 Glamsterdam 于 2026-10-06 在 Sepolia 激活，主网未定）。测试网通过的行为，主网可能还不支持。

  B --> C["Sepolia RPC<br/>交易进入区块"]

读图要点：

- 左边两格全在本机完成，不花任何测试币。只有"签名部署交易"之后才上链。

- 验证（E）和调用（F）互不依赖。不验证源码，合约照样能用，只是别人看不到源码。

- 会出错的地方：B 步需要私钥和测试 ETH；E 步需要编译参数和构造参数完全一致。

## 2. 准备

 | 

 | 项目
 | 要求
 | 获取方式

 | 操作系统
 | macOS、Linux，或 Windows 的 WSL
 | Foundry 不支持 PowerShell / CMD

 | Foundry
 | 1.x 稳定版（本附录在 forge 1.5.1 上实测）
 | curl -L https://getfoundry.sh/install \| bash，重开终端后运行 foundryup

 | 测试钱包
 | 一个新建的、只用于测试网的 EVM 地址
 | cast wallet new 生成，或在 MetaMask 新建账户

 | Sepolia ETH
 | 0.05 个足够（示例估算）
 | 水龙头，见第 3 步

 | RPC 地址
 | 任一 Sepolia RPC
 | 公共节点，例如 https://ethereum-sepolia-rpc.publicnode.com；或 Alchemy / Infura 免费账户

 | Etherscan API Key
 | 一个 API V2 Key
 | 在 etherscan.io 注册后，到 API Keys 页面创建

Etherscan API V2：Etherscan 的统一接口。一个 Key 加一个 chainid 参数，覆盖 60 多条 EVM 链。Etherscan 官方链列表显示 Sepolia（11155111）在免费档可用（截至 2026 年 10 月）。

⚠️ 警告：只用新建的测试钱包。永远不要把主网助记词或主网私钥填进任何工具、脚本、网页或 .env。测试网工具链会把私钥写进命令历史、日志和配置文件。一旦泄露，同一组助记词派生的全部主网地址都会暴露（派生原理见 08 章）。

⚠️ 警告：私钥只放在本地 .env 文件里，并把 .env 加入 .gitignore。先提交 .gitignore，再创建 .env。私钥被推到 GitHub 后，机器人通常几分钟内就会扫走地址上的资产。

💡 注意：更稳妥的做法是用 Foundry 的加密密钥库：cast wallet import sepolia-dev --interactive，之后用 --account sepolia-dev 代替 --private-key。本附录为了步骤简单，使用 .env。

## 3. 步骤

### 3.1 建项目、编译、测试（全部离线，不花测试币）

以下命令在 forge 1.5.1 上实测通过。

- 
安装 Foundry 后确认版本。
   bash
   forge --version
   预期看到：forge Version: 1.x.x-stable。

- 
在一个新目录里初始化项目。
   bash
   forge init mt-lab && cd mt-lab
   预期看到：Installed forge-std 和 Initialized forge project。目录里有 src/、test/、script/、foundry.toml。

- 
删除模板自带的 Counter 示例。
   bash
   rm src/Counter.sol test/Counter.t.sol script/Counter.s.sol

- 
把手册的示例合约复制进 src/。
   bash
   cp <手册路径>/Contract/examples/02-MinimalToken.sol src/MinimalToken.sol

- 
新建 test/MinimalToken.t.sol，写入下面的最小测试。
   ```solidity
   // SPDX-License-Identifier: MIT
   pragma solidity ^0.8.20;
   import {Test} from "forge-std/Test.sol";
   import {MinimalToken} from "../src/MinimalToken.sol";

contract MinimalTokenTest is Test {
       MinimalToken token;
       address alice = makeAddr("alice");

   function setUp() public {
       token = new MinimalToken("Lab Token", "LAB", 1_000_000e18);
   }

   function test_InitialSupply() public view {
       assertEq(token.balanceOf(address(this)), 1_000_000e18);
   }

   function test_Transfer() public {
       assertTrue(token.transfer(alice, 100e18));
       assertEq(token.balanceOf(alice), 100e18);
   }

   function test_RevertWhen_BalanceTooLow() public {
       vm.prank(alice); // 下一笔调用以 alice 身份发出，alice 余额为 0
       vm.expectRevert(
           abi.encodeWithSelector(MinimalToken.InsufficientBalance.selector, alice, 0, 1)
       );
       token.transfer(address(this), 1);
   }

}
   ```

- 
编译。
   bash
   forge build
   预期看到：Compiler run successful。可能出现几条 forge-lint 提示（例如建议常量 decimals 改成大写）。lint 提示不是错误，可以忽略。

- 
运行测试。
   bash
   forge test
   预期看到：3 行 [PASS]，最后一行 3 tests passed, 0 failed。

- 
（可选）本地模拟部署，查看 Gas 用量。先建 script/Deploy.s.sol：
   ```solidity
   // SPDX-License-Identifier: MIT
   pragma solidity ^0.8.20;
   import {Script, console} from "forge-std/Script.sol";
   import {MinimalToken} from "../src/MinimalToken.sol";

contract Deploy is Script {
       function run() external {
           vm.startBroadcast(); // 用命令行传入的账户签名
           MinimalToken token = new MinimalToken("Lab Token", "LAB", 1_000_000e18);
           vm.stopBroadcast();
           console.log("MinimalToken:", address(token));
       }
   }
   ``
   然后运行forge script script/Deploy.s.sol。预期看到：Script ran successfully，Gas used约 78.5 万（实测值，未开优化器）。不带--rpc-url` 时，它只在内存里模拟，不上链。

### 3.2 准备测试钱包和测试币

- 
生成一个新的测试私钥。
   bash
   cast wallet new
   预期看到：一行 Address: 0x… 和一行 Private key: 0x…。把地址记下来。私钥只写进下一步的 .env。

- 
创建 .gitignore 和 .env。
    bash
    echo ".env" >> .gitignore
    cat > .env <<'EOF'
    SEPOLIA_RPC_URL=https://ethereum-sepolia-rpc.publicnode.com
    PRIVATE_KEY=0x你的测试私钥
    ETHERSCAN_API_KEY=你的Etherscan_V2_Key
    EOF
    source .env
    预期看到：git status 里不出现 .env。

- 
领取 Sepolia ETH。常见水龙头（截至 2026 年 10 月；额度与门槛以页面为准）：

- Google Cloud Web3 水龙头：cloud.google.com/application/web3/faucet/ethereum/sepolia，需要 Google 账号。

- Alchemy 水龙头：alchemy.com/faucets/ethereum-sepolia，需要注册，通常要求地址在主网持有少量 ETH。

- PoW 水龙头：sepolia-faucet.pk910.de，浏览器挖矿换币，不要求主网余额。

预期看到：几分钟内到账。

- 
确认余额到账。
    bash
    cast balance <你的测试地址> --ether --rpc-url $SEPOLIA_RPC_URL
    预期看到：大于 0 的数字，例如 0.050000000000000000。

### 3.3 部署、验证、调用

- 
部署合约。构造参数依次是名称、符号、初始供应（最小单位）。
    bash
    forge create src/MinimalToken.sol:MinimalToken \
      --rpc-url $SEPOLIA_RPC_URL --private-key $PRIVATE_KEY --broadcast \
      --constructor-args "Lab Token" "LAB" 1000000000000000000000000
    预期看到：Deployer:、Deployed to: 0x…、Transaction hash: 0x…。把合约地址存成变量：export TOKEN=0x…。

💡 注意：Foundry 1.x 的 forge create 不带 --broadcast 时只做模拟。--constructor-args 接收多个值，必须放在命令最后。

替代写法（脚本部署，适合多步部署）：
bash
forge script script/Deploy.s.sol --rpc-url $SEPOLIA_RPC_URL \
  --private-key $PRIVATE_KEY --broadcast

- 
在 Etherscan 验证源码。
    bash
    forge verify-contract $TOKEN src/MinimalToken.sol:MinimalToken \
      --chain sepolia --verifier etherscan --etherscan-api-key $ETHERSCAN_API_KEY \
      --constructor-args $(cast abi-encode "constructor(string,string,uint256)" \
        "Lab Token" "LAB" 1000000000000000000000000) \
      --watch
    预期看到：Submitted contract for verification，随后 Contract successfully verified。

💡 注意：forge 1.5.1 的 --verifier 默认值是 sourcify。要在 Etherscan 显示绿色对勾，请显式写 --verifier etherscan。Foundry 1.x 使用 Etherscan API V2 统一端点；旧版报 "V1 deprecated" 时运行 foundryup 升级。

- 
读余额（只读调用，不花 Gas）。
    bash
    cast call $TOKEN "balanceOf(address)(uint256)" <你的测试地址> --rpc-url $SEPOLIA_RPC_URL
    预期看到：1000000000000000000000000 [1e24]。

- 
再生成一个收款地址（cast wallet new，只记地址），然后转 100 个代币。
    bash
    cast send $TOKEN "transfer(address,uint256)" <收款地址> 100ether \
      --rpc-url $SEPOLIA_RPC_URL --private-key $PRIVATE_KEY
    预期看到：回执里 status 1 (success)，logs 里有一条日志。100ether 是 cast 的单位写法，等于 100 × 10¹⁸。代币和 ETH 都是 18 位小数，所以可以借用。

- 
对照 03 章的选择器。
    bash
    cast sig "transfer(address,uint256)"            # 0xa9059cbb
    cast sig "balanceOf(address)"                   # 0x70a08231
    cast sig-event "Transfer(address,address,uint256)"
    # 0xddf252ad1be2c89b69c2b068fc378daa952ba7f163c4a11628f55a4df523b3ef
    预期看到：注释里的值（本机实测）。它们和 03 章 3.6 节 的手算结果一致。

## 4. 验证：在 Sepolia Etherscan 上核对

打开 https://sepolia.etherscan.io/address/<TOKEN>，逐项打勾：

 | 

 | 检查项
 | 在哪里看
 | 应该是什么

 | 部署交易
 | Transactions 标签第一条
 | Method 显示 "Contract Creation"；To 为空，显示新合约地址

 | 铸造事件
 | Token Transfers 标签
 | From 为 0x0000…0000，To 为你的地址，数量 1,000,000 LAB

 | 你的转账
 | Token Transfers 标签
 | From 为你，To 为收款地址，数量 100 LAB

 | 事件原文
 | 点开转账交易 → Logs
 | Topics[0] = 0xddf252ad…；Topics[1]、[2] 是补零后的 from、to；Data 是数量

 | 调用数据
 | 交易详情 → Input Data → View Input As Original
 | 以 0xa9059cbb 开头，后接两个 32 字节参数

 | 源码验证
 | Contract 标签
 | 绿色对勾；Compiler 版本与本地一致（本机实测 0.8.33，优化器关闭）

 | 只读函数
 | Contract → Read Contract
 | 输入收款地址调用 balanceOf，返回 100000000000000000000

你也可以在命令行查事件：

cast logs --from-block <部署区块号> --address $TOKEN \
  "Transfer(address,address,uint256)" --rpc-url $SEPOLIA_RPC_URL

💡 注意：浏览器的"代币持有人"和"Token Transfers"页面完全依赖 Transfer 事件。如果合约改余额却不发事件，浏览器就看不到转账。这正是 04 章 3.4 节 读图要点讲的情况。

## 5. 无命令行替代路线：MetaMask + Remix

适合只想"看一遍流程"的读者。用时约 20 分钟。

- 在 MetaMask 里新建一个账户，只用于测试网。

- 在 MetaMask 网络列表打开"显示测试网络"，切换到 Sepolia。

- 从第 3 步第 11 条的水龙头领取 Sepolia ETH。

- 打开 remix.ethereum.org，新建 MinimalToken.sol，粘贴示例合约全文。

- 在 Solidity Compiler 面板选择 0.8.20 以上版本，点击 Compile。

- 在 Deploy & Run 面板，Environment 选 "Injected Provider - MetaMask"。

- 在 Deploy 旁的参数框依次填 "Lab Token"、"LAB"、1000000000000000000000000，点击 Deploy。

- 在 MetaMask 弹窗核对网络是 Sepolia，再点确认。

- 在 Deployed Contracts 区域调用 balanceOf 和 transfer。

- 验证源码：在 Etherscan 合约页点 "Verify and Publish"，按 Remix 编译器设置填写；或使用 Remix 的合约验证插件（以 Remix 当前界面为准）。

⚠️ 警告：Remix 的 Environment 如果显示的网络不是 Sepolia，不要点确认。主网部署会花真钱。

## 6. 常见错误排查表

 | 

 | 错误信息（节选）
 | 原因
 | 解决

 | command not found: forge
 | 安装后没有重开终端，PATH 未生效
 | 重开终端，或 source ~/.zshrc；再运行 foundryup

 | insufficient funds for gas * price + value
 | 测试地址没有 Sepolia ETH，或领到了别的测试网的币
 | 用 cast balance 确认；换水龙头再领

 | Error: Failed to get EIP-1559 fees / 连接超时
 | 公共 RPC 限流或暂时不可用
 | 换一个 RPC，或注册 Alchemy / Infura 免费 Key

 | forge create 只打印信息，不出合约地址
 | 缺少 --broadcast，只做了模拟
 | 加上 --broadcast

 | Invalid character / 构造参数解析失败
 | --constructor-args 后面又写了别的参数
 | 把 --constructor-args 放在命令最后

 | Bytecode does not match / 验证失败
 | 构造参数、编译器版本、优化设置与部署时不同
 | 用同一个项目、同一份 foundry.toml 验证；用 cast abi-encode 重新生成构造参数

 | Invalid API Key / Missing or unsupported chainid
 | Key 填错，或工具版本仍走 V1 接口
 | 检查 .env；运行 foundryup 升级到最新稳定版

 | 验证成功但 Etherscan 不显示对勾
 | 用了默认的 sourcify 验证器
 | 加 --verifier etherscan 重新验证

 | cast send 回执 status 0 (failed)
 | 余额不足、收款地址为 0 地址
 | 用 cast run <交易哈希> --rpc-url … 查看回滚原因；错误名应为 InsufficientBalance 或 ZeroAddress

 | nonce too low
 | 同一地址连续快速发交易，上一笔尚未确认
 | 等上一笔确认后重发

 | 合约在测试网正常，换工具后报 invalid opcode
 | 工具的 EVM 版本与测试网硬分叉不匹配
 | 升级 Foundry；必要时在 foundry.toml 设置 evm_version
