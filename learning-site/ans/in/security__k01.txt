# C01 BNB Chain：合约安全专题

学习目标：读完本章，你能——

- 说出 BNB Smart Chain（BSC）与以太坊在共识、出块、代币精度上的 4 项差异，以及它们对合约的影响。

- 复盘 5 起 BSC 代表性事故的攻击路径和根因代码。

- 用"迁移检查清单"评估一个以太坊合约能否直接部署到 BSC。

前置章节：05 算术与精度、06 外部调用与代币兼容性、07 预言机与闪电贷、11 跨链桥安全交互实验：chain-porting-lab.html、oracle-manipulation-lab.html

## 1. 一句话理解

BSC 的字节码和以太坊兼容，但"参数"不同：出块更快、代币精度不同、验证者更少、分叉项目更多。漏洞往往藏在"我以为一样"的地方。

🎯 打个比方：BSC 像一座按照以太坊城市同一套图纸建造的新城。

- 街道布局一样（EVM 字节码兼容），所以以太坊的"车"（合约）可以直接开进来。

- 但红绿灯的节奏快了 16 倍（出块从 12 秒级到 0.75 秒），按"每个路口等多久"计时的司机会算错时间。

- 同名的商店卖的东西规格不同（BSC-USD 是 18 位精度，以太坊 USDT 是 6 位）。

- 城里有很多"山寨店"——照抄名店的装修，却改了几处细节（分叉项目）。

- 交通管理局人少，出了事能很快封路（验证者可协调暂停链），但封路的权力也集中。

比喻的局限：城市可以慢慢改规则。BSC 的参数通过硬分叉一次性改变，所有依赖旧参数的合约同时受到影响。

读图要点：

- PoSA（Proof of Staked Authority）：质押权益 + 授权验证者的混合共识。验证者数量远少于以太坊，所以协调速度快。

- 系统合约由硬分叉升级。2022 年 Token Hub 事故的修复就通过 Moran 硬分叉完成。

- Binance-Peg 代币（例如 BSC-USD、BTCB 等）是托管型映射资产。它们的安全依赖发行方的托管和铸造权限，而不只是合约代码。

- 局限：图中没有画 opBNB（BSC 的 L2）和 BNB Greenfield。它们有各自的信任假设。

### 3.1 区块数计时：一个真实的风险

许多 BSC 农场合约分叉自 SushiSwap 的 MasterChef，按"每区块奖励"发放代币：

uint256 public rewardPerBlock = 10e18;   // 设计时假设 3 秒一个块：每天约 28.8 万枚
function pendingReward(address user) public view returns (uint256) {
    uint256 blocks = block.number - lastRewardBlock;
    return blocks * rewardPerBlock * userShare / totalShare;
}

出块间隔从 3 秒降到 0.75 秒后，同样的参数每天发放约 115 万枚——排放速度变为 4 倍。如果奖励来自固定预算的国库，国库会提前耗尽；如果奖励是增发，代币通胀率翻 4 倍。借贷协议中"每区块利率"也有同样问题。

⚠️ 警告：硬分叉改变出块间隔时，所有依赖 block.number 的经济参数都需要同步调整。这不是攻击，但造成的经济损失可能和攻击一样大。

## 4. 案例深潜

### 4.1 Uranium Finance（2021 年 4 月）：分叉改常数

- 背景：Uranium 分叉自 Uniswap V2，计划把手续费从 0.3% 改为 0.16%（公开分析报告）。

- 攻击路径：攻击者在每个交易对中投入极少量代币，调用 swap() 取走约 99% 的储备。

- 根因代码：

// ❌ 余额调整项放大到 10000，右侧 k 仍按 1000**2 比较
uint balance0Adjusted = balance0.mul(10000).sub(amount0In.mul(16));
uint balance1Adjusted = balance1.mul(10000).sub(amount1In.mul(16));
require(balance0Adjusted.mul(balance1Adjusted) >= uint(_reserve0).mul(_reserve1).mul(1000**2), 'UraniumSwap: K');
// ✅ 右侧应为 .mul(10000**2)

- 损失：约 5,000 万美元。

- 教训：常数必须集中定义（uint constant FEE_DENOMINATOR = 10000;），不能散落在多处。分叉代码的每一处改动都要做差异审计和不变量测试（x × y ≥ k 在每次 swap 后成立）。

读图要点：

- 铸造器按池子储备给 LP 和收益估值。储备在同一交易里被改写。

- 攻击者铸造的 BUNNY 被抛售，BUNNY 价格从约 146 美元跌到约 6 美元（REKT 报道），损失约 4,500 万美元。

- 教训：奖励铸造是"无中生有"的操作，它的输入必须完全抗操纵（07 章）。

### 4.5 BSC Token Hub（2022 年 10 月）：系统级跨链桥

[图]
flowchart LR
  A["攻击者支付 100 BNB<br/>注册为中继者"] --> B["伪造跨链包<br/>（区块高度 110217401 的证明）"]
  B --> C["IAVL 证明校验缺陷<br/>伪造证明被接受"]
  C --> D["铸造 2 × 100 万 BNB"]
  D --> E["存入借贷协议作抵押<br/>借出稳定币等资产"]
  E --> F["跨链转出约 1 亿多美元"]
  C --> G["约 3 小时后验证者暂停 BSC"]
  G --> H["Moran 硬分叉：<br/>修复 IAVL 校验、中继者白名单、<br/>区块头顺序检查"]
[/图]

读图要点：

- 被攻击的不是某个 DeFi 协议，而是链的系统合约（BSC 与 BNB Beacon Chain 之间的跨链 Token Hub）。

- 攻击者把凭空铸造的 BNB 存入 BSC 上的借贷协议作抵押，借出其他资产再跨链转走。系统层的漏洞会传导到应用层：借贷协议代码正确，却接收了"凭空铸造"的抵押品。

- 停链是一种只有小规模验证者集合才能执行的应急手段。它冻结了大部分资金，也引发了关于去中心化的讨论。

- 公开资料显示，2024 年完成 BC Fusion 后，BNB Beacon Chain 已退役，Token Hub 这条跨链路径也随之成为历史。但"注册即可成为中继者"和"证明校验缺陷"两类教训仍然适用于所有跨链桥。

## 5. 分叉项目的权限风险

BSC 上大量农场和 DEX 分叉自 SushiSwap / PancakeSwap，常见的高危权限：

 | 

 | 函数 / 设计
 | 风险
 | 审计时要问

 | setMigrator()（MasterChef 早期版本）
 | owner 可以把所有用户的 LP 迁移到任意合约
 | 是否删除？是否经过时间锁？

 | mint() 由 owner 直接调用
 | 无限增发
 | 增发权是否只授予农场合约？

 | setRewardPerBlock()
 | 参数可被瞬间改到极端值
 | 是否有上限和时间锁？

 | 可升级 + 单签 owner
 | 随时替换实现
 | 升级权限归属？

 | 代币合约带黑名单 / 交易税开关
 | owner 可阻止卖出（貔貅盘）
 | 税率上限？黑名单是否存在？

⚠️ 警告：低 gas 成本让 BSC 上的"垃圾代币"和"貔貅盘"（只能买不能卖的代币）数量很多。协议如果允许任意代币上架或作为抵押品，就要把这类代币当作攻击工具来建模（03 章 5.3 节、06 章）。

## 6. 迁移检查清单：以太坊 → BSC

-  所有代币精度从合约读取；稳定币相关的常数已检查（BSC-USD 为 18 位）。

-  所有基于 block.number 的时间、奖励、利息计算已改为基于时间戳，或参数可治理调整。

-  价格来源：BSC 上的 DEX 池深度是否足够？是否有可用的链下聚合喂价？

-  映射资产（Binance-Peg）的冻结、暂停、脱锚风险已披露。

-  分叉代码的所有改动点已做差异审计；修改过的常数已集中定义。

-  高危 owner 函数（migrator、mint、参数设置）已删除或置于时间锁之后。

-  跨链组件的两侧代码都在审计范围内。

-  主网分叉测试已在 BSC 上运行。

去 chain-porting-lab.html 选择 "BNB Chain"，勾选你的代码假设，生成迁移风险清单。
