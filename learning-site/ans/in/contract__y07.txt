## 0. 一句话理解

Polymarket 是一个预测市场：它把"某件事会不会发生"拆成"是"和"否"两种代币，让用户用美元稳定币买卖；事件结束后，猜对的代币兑付 1 美元，猜错的归零。

预测市场（Prediction Market）：参与者买卖与未来事件结果挂钩的合约。合约的价格反映市场对事件发生概率的集体判断。

🎯 打个比方：Polymarket 像一个"天气彩票柜台"。柜台把"明天下雨"和"明天不下雨"两张票订在一起，合售 1 美元。你可以把两张撕开，只留自己相信的那张，另一张卖给看法相反的人。明天一过，柜台按实际天气兑付中奖票 1 美元。
比喻的局限：

- 彩票柜台自己定赔率，并从中抽成。Polymarket 的价格由买卖双方在订单簿上报价形成，平台不做对手方。

- 天气有气象站的权威记录。很多事件（例如"某人是否穿了西装"）没有唯一权威来源，"谁来判定结果"本身会成为争议，见第 1.5 节和第 5 节。

- 彩票在开奖前不能转卖。Polymarket 的代币在事件结束前可以随时买卖。

## 1. 产品机制

### 1.1 价格 = 市场隐含概率

一个二元市场（Binary Market）只有两个结果："是"（Yes）和"否"（No）。

- 如果事件发生，每份"是"兑付 1 美元，每份"否"兑付 0。

- 如果事件不发生，每份"否"兑付 1 美元，每份"是"兑付 0。

因此，一份"是"的公平价格等于"事件发生的概率 × 1 美元"。如果"是"成交在 0.62 美元，市场的集体判断就是：事件发生的概率约为 62%。

公式：

隐含概率 P(是) ≈ 价格(是) ÷ 1 美元
价格(是) + 价格(否) ≈ 1 美元          （否则存在无风险套利，见 1.3）
买入成本 = 份数 × 价格
获胜兑付 = 份数 × 1 美元
获胜利润 = 份数 × (1 − 价格)
失败亏损 = 份数 × 价格

💡 注意："价格 = 概率"是一个近似。它忽略了资金的时间价值（钱锁到结算日的机会成本）、手续费和风险偏好。距离结算越远、市场越冷门，这个近似越粗。

### 1.2 完全集合：拆分与合并

完全集合（Complete Set）：同一个市场里每个结果各 1 份代币的组合。在二元市场里，1 份"是"+ 1 份"否"= 1 个完全集合。

完全集合的价值永远是 1 美元，因为无论结果如何，恰好有一份兑付 1 美元。所以合约可以安全地做两件事：

- 拆分（Split）：用户存入 1 USDC，合约铸造 1 份"是"和 1 份"否"。

- 合并（Merge）：用户交回 1 份"是"和 1 份"否"，合约销毁它们，退回 1 USDC。

事件结束后还有第三件事：

- 兑付（Redeem）：用户交回获胜一方的代币，每份领取 1 USDC。

- 资金只有一个入口（拆分）和两个出口（合并、兑付）。CTF 合约里托管的 USDC 总数，始终等于流通中完全集合的数量。

- "是"和"否"的价格可以剧烈波动，但两者之和被套利拉回 1 美元附近。平台不需要自己的资金做担保。

- 出错点在兑付环节：合约只按预言机报告的结果分钱。预言机报错，钱就分错，见 1.5 节。

### 1.3 为什么"是 + 否"会被拉回 1 美元

假设"是"的卖价 0.63 美元，"否"的卖价 0.39 美元，合计 1.02 美元（示例）。

- 套利者存入 1 USDC，拆分得到 1 份"是"+ 1 份"否"。

- 套利者以 0.63 美元卖出"是"，以 0.39 美元卖出"否"。

- 套利者收回 1.02 美元，每个完全集合赚 0.02 美元，不承担事件风险。

反过来，如果两者买价之和低于 1 美元，套利者就买入两边，再合并换回 1 USDC。这个"拆分卖出 / 买入合并"的动作，把两个价格锁在一起。

🎯 打个比方：完全集合像一张可以撕成两半的 1 美元钞票。两半各自的价格随人们的看法变化，但两半加起来总能换回一张完整的钞票。
比喻的局限：真钞票撕开就作废。完全集合撕开后，两半各自是合法代币，可以分别转账、交易，事后还能再拼回去。

### 1.4 数值示例：买入 100 份"是"（示例）

某市场"是"的成交价为 0.62 USDC（示例）。不计手续费和 Gas。用 Python 验算：

p, n = 0.62, 100
cost   = p * n            # 62.0 USDC
payout = n * 1.0          # 获胜兑付 100 USDC
profit = payout - cost    # 38.0 USDC
roi    = profit / cost    # ≈ 0.613，即约 61.3%
loss   = cost             # 失败时损失 62 USDC
implied_prob = p          # 隐含概率 62%

- 结算前你可以随时卖出。如果"是"涨到 0.80，卖出可锁定 18 USDC 利润，不必等结果。

### 1.5 结果由谁裁决：机制概览

链上合约不知道"谁赢得了选举"。它需要一个预言机（10 章 第 2.2 节）把事件结果写到链上。Polymarket 选用 UMA 的乐观预言机：

- 提议：任何人（实际多为专业提议者）提交一个结果，例如"是"，并缴纳保证金（Bond）。

- 挑战期：如果在挑战期内无人反对，提议自动生效。Polymarket 的适配器文档称挑战期"目前约 2 小时"（官方 GitHub）。

- 争议：任何人缴纳同额保证金即可发起争议。

- 投票：争议升级到 UMA 的数据验证机制（DVM, Data Verification Mechanism），由质押 UMA 代币的持有人投票裁决。输的一方没收保证金。

乐观（Optimistic）的含义：系统默认提议是对的，只在有人反对时才启动昂贵的投票。它和乐观 Rollup 的思路相同（09 章）。完整时序见 2.3 节。

读图要点：

- 撮合在链下，结算在链上。运营方只负责"把两张已签名的订单配对"，它不托管用户资金。资金在合约里原子交换：要么两边都成交，要么都不成交（官方 ctf-exchange 仓库称其为"混合去中心化"模型）。

- CTF 合约只认一个"预言机地址"。Polymarket 把这个地址设为 UMA CTF 适配器。适配器再去问 UMA。所以真正的裁决权在 UMA 的提议者、争议者和投票者手里。

- 运营方仍是单点：如果撮合服务停机或拒绝某些订单，用户无法在订单簿交易，但可以直接调用 CTF 合约合并或兑付。

- NegRisk 适配器服务"多选一"市场（例如"谁会赢得选举"有 10 个候选人）。它允许把一个候选人的"否"转换成其他所有候选人的"是"，提高资金效率。

### 2.2 条件代币框架（CTF）

条件代币框架（CTF, Conditional Tokens Framework）：Gnosis 开发的一组合约，用 ERC-1155 表示"某个条件下某个结果"的头寸。ERC-1155 的基本结构见 06 章第 3.5 节。

三个身份标识，层层派生：

 | 

 | 标识
 | 计算方式（简化）
 | 含义

 | conditionId
 | keccak256(oracle, questionId, outcomeSlotCount)
 | 一个问题：谁来裁决、问什么、有几个结果

 | collectionId
 | 由 conditionId 和结果索引集（indexSet）派生
 | 这个问题的哪一组结果，例如"是"=0b01、"否"=0b10

 | positionId
 | keccak256(collateralToken, collectionId)
 | 用哪种抵押品押注哪一组结果；它就是 ERC-1155 的 tokenId

所以，"是"和"否"在链上是同一个 ERC-1155 合约里的两个 tokenId。用户钱包里看到的"100 份是"，就是 balanceOf(user, positionId_yes) = 100 × 10^6（USDC 精度 6 位）。

核心函数（Gnosis ConditionalTokens 合约，节选示意）：

// 由市场创建方调用：登记一个问题
function prepareCondition(address oracle, bytes32 questionId, uint outcomeSlotCount) external;

// 拆分：存入抵押品，按 partition 铸造各结果代币
// 二元市场 partition = [1, 2]，即 [0b01 是, 0b10 否]
function splitPosition(IERC20 collateralToken, bytes32 parentCollectionId,
    bytes32 conditionId, uint[] calldata partition, uint amount) external;

// 合并：销毁各结果代币各 amount 份，退回抵押品
function mergePositions(IERC20 collateralToken, bytes32 parentCollectionId,
    bytes32 conditionId, uint[] calldata partition, uint amount) external;

// 只有 oracle 能调用：写入结果，例如 [1, 0] 表示"是"获胜
function reportPayouts(bytes32 questionId, uint[] calldata payouts) external;

// 兑付：按 payouts 比例把持有的头寸换回抵押品
function redeemPositions(IERC20 collateralToken, bytes32 parentCollectionId,
    bytes32 conditionId, uint[] calldata indexSets) external;

读代码要点：

- reportPayouts 用 msg.sender 和 questionId 重新计算 conditionId。只有登记时指定的 oracle 地址能写结果。这是"谁裁决"在合约层面的唯一答案。

- payouts 不必是 [1, 0]。写 [1, 1] 表示两边各兑付 0.5 美元。Polymarket 用它处理"无法判定"的市场（官方规则称为 50-50 结算）。

- parentCollectionId 允许嵌套条件（"如果 A 赢，B 会不会怎样"）。Polymarket 的普通市场传 bytes32(0)。

💡 注意：CTF 本身不含订单簿，也不含价格。它只做"拆、合、兑"三件事。价格来自交易所合约上撮合的订单。

读图要点：

- 第一次争议不直接投票，而是重置并重新提议。适配器文档称这样做是为了防止"明显错误的争议"拖慢结算。只有第二次争议才进入 DVM，DVM 约 48–72 小时返回结果（官方 GitHub）。

- DVM 投票用"提交-揭示"（Commit-Reveal）两阶段：先提交加密投票，再公开。至少 65% 的质押 UMA 投向同一结果才算结论。不投票或投少数方的质押者会被罚没，罚没部分分给多数方（UMA 官方文档）。

- UMA 称约 99.8% 的请求不需要升级到 DVM（公开资料）。争议虽少，却集中在交易量最大、规则最模糊的市场。

- 局限：DVM 的安全假设是"腐败成本 > 腐败收益"。如果一个市场的交易额远大于操纵 UMA 投票所需的成本，这个假设就会被质疑，见 5.1 节。

🎯 打个比方：UMA 乐观预言机像足球比赛的"边裁 + VAR"。边裁（提议者）先举旗，比赛照常继续。只有球员（争议者）押上保证金申诉，才调 VAR（DVM）复看。
比喻的局限：VAR 由中立裁判操作。DVM 的"裁判"是 UMA 代币持有人，他们可能同时在被裁决的市场里持有头寸。

## 5. 风险与争议

### 5.1 裁决争议：规则文本 vs 代币投票

 | 

 | 案例（时间）
 | 争议点
 | 结果（公开报道）

 | 乌克兰矿产协议市场（2025 年 3 月）
 | 协议是否在截止日前"达成"。市场按"是"结算，部分用户认为协议当时尚未签署
 | 公开报道称结算后有人质疑大户 UMA 持有人影响投票；Polymarket 表示这不属于市场故障，不予退款

 | 泽连斯基"是否穿西装"市场（2025 年 7 月）
 | 他在北约峰会的着装是否算"西装"；规则以"可信报道的共识"为准
 | 交易额约 2.37 亿美元（Decrypt 报道）。UMA 最终按"否"结算，推翻了最初被挑战的"是"，理由是可信报道未形成共识

这两个案例暴露了三个结构性问题：

- 规则文本模糊。"达成""西装""共识"都需要解释。合约只能执行投票结果，不能解释文字。

- 裁决者与利益相关。DVM 投票者可能同时持有被裁决市场的头寸。投票是代币加权的，少数大户的票数占比高。

- 安全预算不匹配。批评者指出，单个市场的交易额可以超过 UMA 代币的市值规模，"腐败成本 > 腐败收益"的假设因此受到质疑。公开报道称截至报道时，没有证实存在操纵。

⚠️ 警告：在预测市场下注前，先读市场页面的"结算规则"全文，而不是只看标题。标题写的是问题，规则写的才是答案的判定标准。

业界的缓解做法（公开资料）：

- UMA 推出"受管理的乐观预言机"，限制只有白名单提议者能提议，减少恶意提议。

- 平台给模糊市场加"澄清说明"（Clarification），在结算前补充判定标准。

## 8. 思考题

- "是"的买价 0.60、卖价 0.62；"否"的买价 0.37、卖价 0.39（示例）。是否存在无风险套利？如果把"否"的买价改为 0.41 呢？写出你的拆分 / 合并步骤和每个完全集合的利润。
