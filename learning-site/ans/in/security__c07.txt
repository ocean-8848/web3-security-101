## 1. 一句话理解

如果合约用"同一笔交易里可以被改变的数据"来定价，攻击者就会先借一大笔钱改变它，再按错误的价格和合约做交易，最后把钱还回去。

预言机（Oracle）：把链外或其他合约中的数据（通常是价格）提供给合约使用的机制。

闪电贷（Flash Loan）：借款、使用、还款都在同一笔交易里完成的贷款。如果交易结束时没有还款，整笔交易回滚，所以出借方没有风险，也不需要抵押。

🎯 打个比方：一家当铺按"隔壁菜市场的最新成交价"给黄金估价。

- 你从朋友那里借来 1 亿（闪电贷）。

- 你在菜市场以离谱的高价买下全部黄金（推高现货价）。

- 你拿 1 克黄金去当铺，当铺按刚才的成交价估值 100 万，借给你 75 万。

- 你把黄金卖回菜市场，还给朋友 1 亿。

- 你净赚 75 万减去交易损耗。当铺手里只剩 1 克普通价格的黄金。

比喻的局限：现实中这些步骤需要几天。链上它们发生在同一个区块的同一笔交易里，没有人来得及反应。

## 2. 威胁模型

攻击者在一笔交易内能做到：

- 借到几乎无限的资金（闪电贷池的全部流动性）。

- 把任何 AMM 池子的现货价格推到任意位置（只要付得起滑点）。

- 直接向合约转入资产，改变 balanceOf 类读数。

- 把以上操作和对目标协议的调用任意组合。

因此，任何在一笔交易内可变的读数都是攻击者的输入参数：

 | 

 | 读数
 | 一笔交易内可变？

 | AMM 池子储备比例 reserve1 / reserve0
 | 是

 | LP 代币价格（按储备直接计算）
 | 是

 | 金库份额价格 totalAssets / totalSupply（totalAssets 读余额）
 | 是（捐赠）

 | 代币的 balanceOf(合约)
 | 是

 | Uniswap V2/V3 TWAP（时间加权平均价）
 | 当前区块影响很小；多区块持续操纵可以

 | Chainlink 类链下聚合价格
 | 否（但可能过时或触及上下限）

## 3. 漏洞机制：AMM 现货价

恒定乘积 AMM（x × y = k）中：

现货价 P = y / x
买入 Δx 需要支付 Δy = y × Δx / (x − Δx)   （忽略手续费）

// ❌ 漏洞：用 AMM 储备直接计算价格
function getPrice() public view returns (uint256) {
    (uint112 r0, uint112 r1, ) = pair.getReserves();
    return uint256(r1) * 1e18 / r0;
}
function borrow(uint256 collateralAmt) external {
    uint256 value = collateralAmt * getPrice() / 1e18;
    uint256 maxBorrow = value * 75 / 100;   // LTV 75%（示例）
    ...
}

- 攻击者的利润 = 借出金额 − 两次交换的滑点和手续费 − 闪电贷费用。

- 局限：如果借贷协议使用 TWAP 或链下聚合价格，第 5 步读到的价格几乎不变，攻击失败。

## 5. 安全读取链下预言机

(uint80 roundId, int256 answer, , uint256 updatedAt, ) = feed.latestRoundData();
require(answer > 0, "invalid price");
require(block.timestamp - updatedAt <= MAX_DELAY, "stale price");   // 按喂价心跳设置
require(uint256(answer) > MIN_BOUND && uint256(answer) < MAX_BOUND, "out of bounds");

- 出错点：排序器宕机时喂价无法上链，价格停留在宕机前。
- 风险：恢复后的第一批区块里，能从 L1 强制提交交易的少数人占优。
- 局限：部署前要确认目标 L2 上确实有排序器在线状态喂价。

### 5.1 L2 上的额外检查：排序器是否在线

在 Mantle 这样的 L2 上，交易由排序器（Sequencer）打包。排序器宕机时：

- 喂价交易无法上链，价格停留在宕机前。

- 恢复后的第一批区块里，普通用户和清算机器人同时涌入。能通过 L1 强制提交交易的少数人占优。

业界通用做法：读取"排序器在线状态"喂价（Chainlink 在多条 L2 上提供 Sequencer Uptime Feed）。排序器恢复后设置一段宽限期（例如 1 小时，示例），宽限期内暂停清算或新借款。部署前要确认目标 L2 上是否有此喂价。

💡 注意：根据 L2BEAT 截至 2026 年的页面，Mantle 排序器宕机时，用户可以通过 L1 强制提交交易，延迟最长 12 小时。见 C03。

### 5.2 熔断上下限：Venus 与 LUNA（2022 年 5 月，BNB Chain）

- 公开报道：Chainlink 的 LUNA/USD 喂价设置了最低价（minAnswer）0.10 美元。

- LUNA 崩盘到远低于 0.10 美元时，喂价停在下限附近。

- BNB Chain 上的 Venus 协议仍按约 0.1 美元给 LUNA 抵押品估值。有人在市场上低价买入 LUNA，存入 Venus 借出其他资产，协议损失约 1,100 万美元（公开报道）。

- 教训：读取价格时，检查是否触碰上下限；为抵押资产设置供应上限和紧急下架流程。

以太坊上的对照案例：

- bZx（2020 年 2 月）：最早被广泛报道的闪电贷价格操纵之一，两次合计约 95 万美元。

- Cream Finance（2021 年 10 月）：攻击者通过向 yUSD 金库"捐赠"抬高份额价格，而 Cream 用份额价格给抵押品估值，损失约 1.3 亿美元。

- Harvest Finance（2020 年 10 月）：金库份额价格依赖 Curve Y 池中的稳定币价格。攻击者用闪电贷反复"压价存入、抬价赎回"，取走约 3,380 万美元。

- Inverse Finance（2022 年 4 月）：攻击者没有使用闪电贷，而是投入自有资金持续推高浅池中的 INV 价格，并用垃圾交易抑制套利，使 TWAP 预言机输出虚高价格，借走约 1,560 万美元。TWAP 挡不住有资本的多区块操纵。

以上以太坊案例的完整路径见 C00 以太坊专题 4.5、4.6 节。

⚠️ 警告：LP 代币不能用 储备 × 现货价 / 总供应 定价。应使用"公平储备"法：用外部预言机价格和不变量 k 反推出公平储备，再计算 LP 价值。

## 7. 防御清单

- 不用 AMM 现货价、balanceOf 或可被捐赠改变的份额价格作为关键定价依据。

- 如果必须用 AMM 价格，使用足够长窗口的 TWAP，并评估池子深度。

- 读取链下预言机时，检查正值、时效、上下限、精度；L2 上检查排序器状态。

- 关键资产使用多源价格，源之间偏离超过阈值时暂停。

- 对低流动性抵押品设置供应上限（Supply Cap）和更低的抵押率。

- 把"一笔交易内借款 + 还款"的模式纳入监控告警（12 章）。
