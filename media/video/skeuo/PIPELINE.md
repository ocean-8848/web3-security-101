# 手册章节讲解视频：制作手册

每一章做一集 8–12 分钟的讲解视频。第 29 章（`ep29/`）是定稿样板，风格、节奏、完成度都以它为准：成片 `ep29/out/ep29-full.mp4`，分镜写法见 `ep29/BRIEF-FULL.md`，讲稿见 `ep29/script.json`。

## 0. 定稿的风格与规则（频道主已确认，不要改）

- **画面**：等距实物世界：暖米色纸底 #efebe3 + 等距网格 #e2ddd3；一台镜头在一个连续的世界里移动，不硬切。
- **物件要拟物**：从 `kit/objects.mjs` 取（保险柜、笔记本、硬件钱包、服务器机柜、加密机、RPC 节点、检查站、广播塔、区块链、浏览器、S3 桶、工位、手机、人物、熔断闸刀、警报灯、沙漏、时钟、盾牌、放大镜、公章、文件、账本、信封）。库里没有的，按同一投影自己补，也要拟物（例如合约 = 带齿轮的机器或保险柜锁芯，预言机 = 带表盘的报价机，跨链桥 = 真正的桥）。
- **讲解手法**：代码卡的某一行用红色虚线连到场景里对应的物件；坏掉的东西画成红色虚线框加红叉；数字做成点阵（每个点 = 一个单位）；右上角章节胶囊；字幕放在白色圆角卡片里。
- **颜色语义**：绿 #1f9d55 表示正常或通过；红 #e0453a 表示失败、攻击者、被攻破；青蓝 #2aa3c9（实底 #1d93ba）表示中性组件和标签；墨色 #1c1c1c。不用黄色荧光笔；金条可以用金色。
- **字幕**：不出现句号（逗号也不出现）。要断句就换到下一条字幕。这一条由 `tools/tts.py` 自动保证。
- **配音**：阿里云百炼 `qwen-audio-3.0-tts-plus`，音色龙安鲁风（频道主 2026-11-14 确认）。第 1 段（钩子）用「低沉悬疑的深夜电台腔」，其余段用「专业科普讲解，轻重缓急清楚」（`tools/tts.py` 自动处理，`script.json` 每段可用 `"style"` 覆盖）。需要环境变量 `QWEN_AI_API_KEY`，它写在 `~/.zshrc` 里，所以要用 `zsh -ic 'cd …/video/skeuo && python3 tools/tts.py epNN'` 运行，命令里不要打印密钥。**多音字必须检查**（见第 3 步）。
- **时间**：百炼不返回逐词时间，`timing.json` 的 `words` 是逐字的估算值，做法是先检测停顿、再按字数分配。画面里按词语查时间，用 `kit/timing.mjs` 的 `wordAt(T, "词语")` 和 `lineAt(T, i)`，不要自己在 words 里找整词。
- **讲解结构**（AI 解读）：
  - 推进顺序：钩子 → 铺垫 → 逐步构建 → 关键洞见 → 回顾。
  - 一个镜头只讲一个想法。
  - 画面承担论证；屏幕上只写关键词、数字和字段，不念字幕。
  - 先给准确表述，再给比喻；比喻在哪里不成立要说一句。
  - 事实分层标注：项目方称、第三方分析、监管或执法口径、未确认、解读（解读者自己的判断）。
- **独立成片**（频道主 2026-11-15 要求）：每集都是独立的学习素材，不需要看过别的集，也不需要读过手册。
  - 讲稿、画面、字幕里都不出现"手册""本书""本章""本节"，也不出现"第 N 章 / 节 / 集"这类编号。结束卡和标题卡只写主题名。
  - 不许诺本集以外的内容：不写"以后单独讲""另一集会讲"。结尾用一句本集收束，加"下一集讲<主题>"。
  - 来源标签写出具体发布方，例如"FBI 公告""Binance 初步报告""SlowMist 分析""CoinDesk 报道"。发布方只取手册原文和它引用的链接里明确写出的；没写的，用类型标签（官方复盘、项目方称、公开报道、第三方分析、监管口径）。示例、解读、比喻照常标。
  - 画面里不写 REN-1、MPC-2 这类检查清单编号，只写动作本身。ERC-20、EIP-7702 这类标准名照写。
- **术语卡**：术语第一次出现、配音又没有当场解释时，画面弹出术语卡。一律用 `kit/screen.mjs` 的 `termCards()`，不要自己写样式；它负责位置（左上，左上被占时 `low: true` 放左下）、时长（3.6 秒，至少 3 秒）、同一时间只出一张，并在 `report` 里写出被推迟或偏短的卡。定义不超过 24 字，可以用常识说法或手册其他章节的定义（频道主 2026-11-15 确认）。
- **结束卡**：一律用 `kit/screen.mjs` 的 `endCard()`：本集标题、一句收束、"下一集 · 主题"，最后 2.5 秒静止。
- **事实**：只用手册该章（及其链接的手册章节）写到的事实，不编造地址、哈希、人数。金额加"约"，并写明口径。
- **只讲防御**：讲漏洞机制、根因和修复，不演示针对真实系统的攻击步骤。
- **版面分区**（`kit/screen.mjs` 的 `ZONE`）：胶囊在右上；术语卡在左上（备选左下）；事件卡、来源卡在右上胶囊下方；字幕在底部居中（渲染后叠加）。其余标签和代码卡留在 x 60–1860、y 100–900 之内。

## 0.5 成本预算（2026-11-15 实测后定）

前 8 集每集约 1.6 亿 token，主要花在：每段一个代理且上下文很大、每段平均看 31 张截图、主会话被后台通知反复唤醒、事后两轮返工。新流程的目标是每集 4000 万以内。规则：

- **看图有上限**：每段最多看 6 张图（缩到一半的拼图算一张）。重叠、出框、截字用 `node tools/layout_lint.mjs <段目录>` 查，它出文字报告，约 10 秒。截图只用来确认"物件认不认得出、画面是否在讲这句话"。
- **选物件看目录**：读 `kit/OBJECTS.md`（一行一个物件）和 `kit/objects-sheet*.png`（缩略图），不读 `kit/objects.mjs` 和各集 kit-ext 的源码；只有确定要用的几个物件，才去看它们的参数。
- **改代码用 Edit**：小改动用 Edit 改 `build-story.mjs`，不要整份重写。
- **段代理不渲染**：段代理只做到 check 没有 error、版面检查通过、抽帧确认为止。渲染、叠字幕、拼接、预览由统筹用 `tools/make_ep.py` 一次跑完。
- **后台任务只通知一次**：统筹把一集的渲染放进一个后台进程（`make_ep.py`），跑完再看结果，不要每段一个监视器。
- **不许用 pkill / killall**：会杀掉别的集正在排队的渲染。要停就停自己启动的那个进程。
- **模型分工**：编剧和分段画面用强模型；纯机械的活（按清单改标签、grep 核对、重配几句、跑脚本）交给便宜的模型或直接用脚本。
- **规则先写全**：新要求先补进本文件，再开工，避免返工。

## 1. 目录约定

`hf/epNN/`（NN 是两位章号）：
- `script.json`：讲稿。
- `pron.json`：本章的多音字补充表。
- `BRIEF.md`：本章分镜。
- `audio/`、`timing/`：配音和逐词时间。
- `segN/`：每段一个 HyperFrames 工程。
- `out/`：各段成片和完整版。

共用的东西：
- `hf/kit/`：拟物物件库。选物件读 `kit/OBJECTS.md` 和 `kit/objects-sheet*.png`（由 `node tools/catalog.mjs` 生成，新增物件后重跑）；坐标约定读 `kit/README.md` 的"坐标约定"一节；屏幕层组件在 `kit/screen.mjs`。
- `hf/tools/`：脚本。
- `hf/template/`：工程模板。

## 2. 编剧：讲稿 + 分镜（每章一人）

1. 完整读完手册这一章（`handbook/NN-*.md`），并写出骨架：
   - 一句话核心观点
   - 支撑结构（3–5 步）
   - 关键术语
   - 成立条件、例外和风险
   - 不确定之处
2. 分成 4–6 段（右上角胶囊就是段名，每个段名 2–7 个字）：
   - 第 1 段是钩子：用本章最具体的一个案例或场景开场，约 45–75 秒。
   - 中间几段是铺垫和逐步构建，各 1.5–3 分钟。
   - 倒数第 2 段讲关键洞见或防御。
   - 最后一段收尾，约 1 分钟：先按角色给"今天就能做的一件事"，或者给用户侧防护；再回到开头的问题，给出答案和成立条件；最后用一句本集收束，加"下一集讲<主题>"（不提手册，不写编号）。
3. 写 `script.json`，格式照抄 `ep29/script.json`：
   - 顶层字段：`ep`（"ep01"）、`title`（整集标题）、`sections`（胶囊名数组）、`segments`。
   - 每段字段：`id`（seg1…）、`pill`（段号）、`title`（段名）、`chapter`（成片章节名，如"① 钩子标题"）、`lines`（每句一行）。
   - 全片 2300–3200 字。短章节可以少一些，但不少于 1600 字。
   - 句子要短，口语化；一句话里的每个小句不超过约 20 字，因为字幕按标点切分。
   - 数字直接写阿拉伯数字（如 2025 年 2 月、约 15 亿美元）。英文缩写照写。
   - 讲稿里不要写需要读成特殊读音的符号，比如"2-of-5"要写成"五个人里两人签名"。
4. 写 `BRIEF.md`：
   - 统一视觉部分直接引用本文件第 0 节，不要重抄。
   - 第 4 节"各段分镜"照 `ep29/BRIEF-FULL.md` 的写法，按句写：L0、L1……每句配什么画面、出现什么物件、什么状态变化、哪个是本段的关键画面。
   - 每段写一句"目标"：观众看完这段能说出什么。
5. 多音字：见第 3 步，由编剧负责。
6. 配音和工程：
   - 在 `hf/` 目录运行 `python3 tools/tts.py epNN`。
   - 再运行 `python3 tools/scaffold.py epNN`。
   - 检查每段时长，全片应在 8–12 分钟（短章节至少 6 分钟）。
   - 抽查 `timing/*.json` 的 captions：字幕里不能有标点；有 "EIP7702" 这类丢了连字符的，确认已自动恢复。

## 3. 多音字检查（必须做）

1. 运行 `python3 tools/polyphone_scan.py epNN`，逐条判断标"?"的位置。
2. 判断标准：配音引擎在这个词里会不会读错。下面是常见的错法：
   - 助词"地"（诚实地、悄悄地）被读成 dì
   - 了（liǎo）、行（háng）、长（zhǎng）、重（chóng，如重新、重放、重入）
   - 还（huán）、调（diào，如调用）、处（chǔ）、为（wèi）、角（jué，如角色）
   - 待（dāi）、校（jiào，如校验）、量（liáng）、数（shǔ）、差（chā）、供（gòng）
3. 处理方法，二选一：
   - 在 `epNN/pron.json` 加一条 `[显示写法, 同音写法]`。同音写法只给配音引擎读，字幕显示原文。例如 `["诚实地","诚实的"]`、`["角色","决色"]`、`["调用","掉用"]`。
   - 直接改讲稿，换成不会读错的说法。例如"改变不了"改成"无法改变"，"重算"改成"重新计算"。
4. 通用的条目加在 `tools/pron.json`。改动后重跑 tts；如果画面已经做好，只重配改过的句子，用 `python3 tools/tts.py epNN --fix`（新录音会拉伸到原句长度，画面时间不变）。
5. 交付说明里列出处理过的每一处。
6. 运行 `python3 tools/audition.py epNN`，生成 `out/polyphone-audition.wav` 和 `.md`：每个风险词只取第一次出现的那一句，交给频道主试听。频道主报出读错的编号后，修正 pron.json，再运行 `tts.py epNN --fix`。

## 4. 分段制作（每段一人，可并行）

先运行 `python3 tools/new_seg.py epNN [segN …]`（scaffold.py 之后），它为每段写一份基于 `kit/segbase.mjs` 的起稿。段代理读 `kit/SEGBASE.md`，**不读别段的 build-story**。其他只读这些：本章 `BRIEF.md` 里本段那一节、`shared/layout.mjs`、用到的 kit-ext 的 `README.md`、`kit/OBJECTS.md` 里要用的那几行。要点：

- 画面用 `src/build-story.mjs` 生成 `compositions/story.html`，只填 `// SHOTS` 和物件、标签、卡片。下面几项都由 segbase 处理，不要自己写：胶囊、标题卡或小标签、起始镜头、术语卡、结束卡、kit.css（内联，并复制到 `assets/`）、时间线注册。
- 各章补充物件的动画助手挂在 `window.KITX<章号>`（如 `KITX01`、`KITX03`），同时也合并进 `window.KITX`；一段里同时用两章的物件库时，请用带章号的名字调用。新章节补物件时照此命名。
- 章节胶囊用 `kit/pills.mjs` 的 `pills(段号, { sections: script.json 的 sections })`。
- 段首 0–1.6 秒放章节标题卡（"② 段名"加副标题），胶囊切到本段。若和上一段属于同一章节，就用小标签过渡，不出大标题卡。
- 段尾最后约 1 秒画面落定、静止。
- 道路、场景布局需要和相邻段衔接时，第一段在 `SPEC.md` 里记录世界坐标，后面各段对齐它。
- 术语卡和结束卡用 `kit/screen.mjs`（见第 0 节）；字幕不用管，渲染后自动叠加。
- 有意叠放的元素（如调用栈层层叠起）加 `data-layout-allow-overlap`，版面检查会跳过。
- 自审（按顺序，前一步过了再做下一步）：
  1. `npx hyperframes check` 没有 error。
  2. `node ../../tools/layout_lint.mjs .` 没有问题；有问题按报告里的时刻和元素名改，再跑一次。
  3. 抽帧：用 `npx hyperframes snapshot --at <时刻,…>` 取本段的关键画面，拼成一到两张图看，总共不超过 6 张图。只看文字检查查不出来的东西：物件是否拟物、一眼认得出；画面是否在讲这句话；颜色语义；事实是否与讲稿一致。
  4. 写 `REVIEW.md`：改了什么、`termCards().report` 的那一行、版面检查结果、还有什么没解决。
- 段代理不渲染。交回统筹时说明 check 和版面检查都已通过。

## 5. 合成与总审（统筹）

1. 在 `hf/` 目录后台运行 `python3 tools/make_ep.py epNN`（只改了几段就写段 id）。它依次做：生成画面、check、版面检查、渲染不带字幕的画面、叠字幕、拼接、720p 预览、字幕核对，结果写在 `out/BUILD.md`。改了字幕或配音文字、但画面和时间没变时，加 `--caps-only`，不用重渲。
2. 衔接：每两段之间，看前一段最后一帧和后一段第一帧，画面不应跳变。
3. 用 ffmpeg 检查：没有黑帧；不应有超过 4.5 秒的静音（段间约 3.4 秒属正常）；整片响度约 −16 LUFS。
4. 每隔约 30 秒抽一帧看；字幕里不应有句号、逗号或丢失的连字符。
5. 事实口径标签逐一核对。
