# ep15 分镜：账户抽象与新钱包：账户变成了合约

统一视觉（画面、物件、颜色、字幕、术语卡、结束卡、版面分区、独立成片）见 `PIPELINE.md` 第 0 节，这里不重抄。讲稿 `script.json`，多音字表 `pron.json`。

## 1. 本集骨架

- **一句话核心观点**：旧模型里签名的意思是"转这笔钱"，账户抽象之后签名的意思是"允许这段代码替我做事"。签名的含义变大，签错的后果也变大；每一处新边界（哈希覆盖哪些字段、Paymaster 签名、账户验证逻辑、7702 委托、会话密钥范围、Solver 授权、Permit2 链下签名）都要单独看清"它允许什么"。
- **支撑结构**：
  1. 钩子：Binance 内部签名服务被控制，热钱包被设了 7702 委托；关了提现服务，委托会自动失效吗？
  2. 准确表述 + 授权书比喻（及其不成立处）；ERC-4337 的角色：用户操作、Bundler、EntryPoint、智能账户、Paymaster；验证与执行分离。
  3. 4337 的三个签名边界：用户签名覆盖的哈希（Alchemy 打包漏洞）、Paymaster 签名（链 ID、nonce、有效期）、账户验证逻辑（Coinbase Smart Wallet 跨链重放、Biconomy）。
  4. EIP-7702：授权三要素、委托 = 地址上的链上状态；三层风险（恶意合约、链 ID 填 0、合法委托上的恶意批量）；案例（GoPlus 约 14.6 万、ScamSniffer 约 100 万 / 154 万、Wintermute 扫币合约统计）；开发者三个坑；EIP-7702 原文警告。
  5. 范围与边界：Passkey 与社交恢复、Session Key（Cardex）、意图与 Solver（CoW Swap、1inch Fusion v1）、Permit2（PEPE 持有者）。
  6. 按角色一件事 + 用户侧 → 回答开头 → 收束。
- **关键术语**：账户抽象、EIP-7702 委托、热钱包、智能账户、用户操作、Bundler、EntryPoint、Paymaster、哈希、nonce、重放、抢跑、owner、会话密钥、Pectra、EVM、扫币合约、初始化、命名空间存储、交易发起者、Passkey、社交恢复、意图、Solver、Resolver、无限授权、Permit2。
- **成立条件、例外和风险**：授权书比喻只说明"授权范围决定后果"，不成立处是纸质授权书要公证、能去银行撤销，链上委托立刻生效、可能多链同时生效（seg2 L8–L9）；链 ID 填 0 的授权"所有链有效"的前提是那条链上 nonce 对得上（seg4 L9）；Passkey 保护登录，不保护签名内容（seg5 L2–L3）。
- **不确定之处**：Binance 事件资料没有写明复盘发布方，来源卡用类型标签"公开复盘"；"50 个连续 nonce 授权"有两种说法，本集不提。GoPlus 把 2025 年 5 月那起归因于 Inferno Drainer，只上屏为"GoPlus 归因"，配音不念。Wintermute 的统计是"绝大部分"，没有百分比，画面不写数字。1inch 案的"大部分经谈判退回"没有比例，不画点阵拆分。Cardex 的"约 9000 个钱包"是资料原文的数字，只上屏、不画点阵。
