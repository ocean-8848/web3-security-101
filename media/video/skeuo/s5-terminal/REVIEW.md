# REVIEW · s5-terminal

## 创作取舍
- 整片是"一个终端里的一次核查"：一个窗口、六条教学子命令（`./verify.sh incident / check-keys / show --ui / decode --raw / trace storage / path`），每次换话题用瞬时清屏（Ctrl+L 语义），不做场景交叉淡化。
- 唯一的镜头运动有三处：高潮推近（1.08）、l6 缩到左侧让出桌面大标题、片尾窗口退场。其余全靠"打字 + 整行输出"推进，信息跟着锚点词出现。
- 琥珀只出现两次：`+ operation: 1 (DELEGATECALL)`（21.85 s 数字 1 反显）与第 ④ 关；红只给 diff 删除行与"攻击者合约"。
- 没做的方向：滚动式长终端（信息太密、焦点不唯一）；终端内打印片头卡（BRIEF 要求在桌面落定）。

## 量了什么
- `hyperframes check --json`：0 error，ok=true。保留 3 条 warning：
  - `line_unread #c-r7`（`- operation: 0 (CALL)` 0.87 s 后被压暗）：故意，高潮时把旧值压暗到 0.32 让唯一焦点给琥珀行；它并未离场，仍可读。
  - `text_below_floor`：l6 窗口缩到 0.5 倍时终端内的字有效 14–19 px。窗口此时是"证据背景"，可读信息由右侧 168 px 大标题承担。
  - `line_unread span.caret`（`↑ Bybit 断在这里` 1.24 s）：片头卡需要 ≥2.5 s 静止，只能把 F 屏延到 43.60；与配音"七道关"同步出现，已比初版延长 0.4 s。
- 渲染文件：ffprobe 时长 47.167 s，h264 1920×1080 + aac 音轨；`hyperframes audio` 测到信号 0.81–42.9 s（声音只测量，没有人听）。
- 看过的帧：0、3、4.6（打字中光标跟随）、8.9、10、12.6、15、16、16.5、19、20.5（停顿：光标在空行闪）、21.5、22.3、27、29、32、35、35.6、36、40、41、42.5、43.7、46、46.91，以及 `snapshot --review` 的 beat sheet 和 360 px 手机 sheet。

## 发现与修改
- P1 · 全片 · 终端 34 px 字在 1650 宽窗口里显得空、手机端偏小 → 改为 38 px / 行高 54，光标宽 23、高 44，字宽常数 22.8。
- P1 · 20.5 s 等 · JetBrains Mono 连字把 `---`、`--raw`、`+++` 画成连线，diff 头不像 diff → 关闭 `liga`/`calt`。
- P1 · 42.4–43.2 s · `↑ Bybit 断在这里` 只停 0.83 s → F 屏延到 43.60，窗口退场 43.62–43.97，主标题 44.00 起逐字，副标题 44.38 起，44.59 后完全静止 2.57 s。
- 检查：✓/≈/→/①–⑦/… 字形都正常渲染（无缺字豆腐块）；窗口底边全片 ≤ 887 px，字幕始终落在浅色桌面上。

## 最弱的镜头 / 还能改的
- 41 s 前后：七个空框只有编号，标签在 41.13 后才点亮，前 1.5 s 偏空；手机端方框里的 32 px 中文仍偏小，可考虑把路径拆成两行、放大到 40 px。
- l6 缩小后的终端内容无法阅读，只是氛围；若要更"终端"，可在终端里同步打印 `keys ✓ / payload ✗` 两行代替纯缩小。
- 终端下半部常有空白（每屏 5–10 行），是这个媒介的真实样子，但画面重心偏上。
- 高潮推近 1.08 会裁掉标题栏上沿，这是有意的镜头推近。
